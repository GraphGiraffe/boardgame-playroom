# ХОД · приложение и движок

Версия **0.13.0**. Самостоятельное офлайн-приложение для настольных игр: боты, игра по очереди на одном устройстве, скрытые руки, история ходов, сохранения и повторы. Поддерживаются мышь, касания, свайпы, перенос компонентов, вертикальный и горизонтальный телефон, полный экран, анимации и звук.

Игры устанавливаются отдельными паками. Их исходники и релизы находятся в [boardgame-playroom-paks](https://github.com/GraphGiraffe/boardgame-playroom-paks). Оба репозитория могут выпускаться независимо.

## Готовая версия

В [релизе приложения](https://github.com/GraphGiraffe/boardgame-playroom/releases) скачайте `playroom.html`, откройте в браузере и перейдите в **«Паки игр»**. Скачайте нужный `.playroom-pack.json` из [релиза паков](https://github.com/GraphGiraffe/boardgame-playroom-paks/releases), выберите файл в приложении и подтвердите установку. После загрузки файлов интернет для игры не нужен.

`playroom-all-games.html` — удобная дополнительная сборка с пятью начальными играми. Она использует тот же механизм паков; встроенные игры тоже можно обновлять отдельно. `SHA256SUMS` содержит контрольные суммы файлов релиза.

Пак содержит исполняемый JavaScript. Устанавливайте код авторов, которым доверяете: проверка формата и совместимости не является изолированной средой исполнения.

## Раздельные обновления

- **Приложение:** замените `playroom.html` новой версией, сохраняя тот же адрес/место открытия в том же браузере. Установленные паки и партии хранятся в браузере отдельно от HTML.
- **Игра:** установите файл с новым номером версии пака. Новые партии используют текущую версию. Старые партии и завершённые повторы сохраняют привязку к прежней версии; она остаётся доступной.
- Один номер опубликованной версии нельзя использовать для другого содержимого. Несовместимый API, повреждённый файл или ошибка сохранения не должны заменять установленный пак.
- Данные браузера относятся к адресу приложения. Другой браузер, устройство, новый origin или изменение поведения `file:`/`content:` на телефоне не обеспечивают автоматический перенос данных. Не очищайте данные браузера для обновления.

Версия приложения, версия пака, версия API движка и версия состояния игры — разные понятия. Для текущих пяти паков: `engineApi: 1`, `stateVersion: 1`, версия пака `0.1.0`. Автоматическая загрузка обновлений из интернета и миграции правил уже начатых партий пока не реализованы.

## Сборка

Нужен Python 3.9+; npm и CDN для запуска приложения не требуются.

```sh
./build.sh
```

В `dist/` появятся автономное приложение без игр, архив исходников, архив движка и контрольные суммы. Все паки и их ресурсы отсутствуют в базовой сборке.

Для совместной разработки расположите репозитории рядом:

```sh
git clone https://github.com/GraphGiraffe/boardgame-playroom.git playroom
git clone https://github.com/GraphGiraffe/boardgame-playroom-paks.git playroom-paks
cd playroom
./build.sh --packs-dir ../playroom-paks/packs --prepare-dev --all-games
```

Теперь можно открыть `index.html` или раздать рабочую папку обычным статическим сервером. Дополнительная сборка `dist/playroom-all-games.html` переносится на телефон одним файлом. `--output-dir` задаёт другую папку экспорта; `./build.sh --help` перечисляет параметры.

## Проверки

Node.js 22+, Chrome/Chromium и dev-зависимость Playwright. После подготовки пяти внешних паков:

```sh
npm ci
npm test
```

Тесты находят Chrome/Chromium в PATH либо браузер, установленный Playwright; явный путь задаётся `CHROME_BIN`. `bash scripts/codex/setup.sh` подготавливает зависимости и браузер. Для уже установленного вне проекта Playwright можно указать `PLAYWRIGHT_MODULE`. Проверка автономной сборки использует `PLAYROOM_URL=file:///absolute/path/to/dist/playroom-all-games.html`.

CI этого репозитория запускает те же `scripts/codex/setup.sh` и `check.sh`: базовую сборку, синтаксис и независимые проверки приложения. Он не получает доступ к соседнему приватному репозиторию. Полный совместный прогон выполняется с обоими checkout; результат конкретного релиза описан в [отчёте](docs/qa-report.md).

## Звуковое подключение (кандидат 0.15.0-rc.2)

В меню комнаты хост выбирает «Подключить устройство» и «Передать звуковое приглашение». Другой игрок нажимает «Присоединиться к комнате → Слушать звуковое приглашение», принимает Offer через микрофон и передаёт Answer звуком. Далее обычная игра идёт по Wi-Fi через WebRTC. Без RoomHub и без обязательной сети Интернет. Нужны доступ к микрофону и звук между близкими устройствами.

Выбор адреса и Tx protocol остаётся за пользователем. Список показывает **все раскрытые браузером ICE-маршруты** (в том числе LAN, VPN-подобные, IPv6, mDNS), дополнительный WebRTC-поиск и ручной IPv4. Тестовый адрес `192.0.2.1` не выбирается автоматически. **Звук, QR и ссылки теперь используют один компактный PR3-пакет** — изменение выбранного IP обновляет их вместе. Для несовместимых кандидатов остаётся полный PR2 и QR/Share fallback. VPN может работать с прямым Wi-Fi при разрешённом LAN-маршруте; микрофон для `content://` не гарантирован, предпочтителен HTTPS/PWA. Если браузер (особенно при открытии Android `content://`) показывает только служебный `192.0.2.1`, IP Wi-Fi необходимо указать самостоятельно. Поле ввода не подставляет чужие адреса; выбранный вручную IP можно сохранить в списке на этом устройстве. После ввода валидного IPv4 тот же компактный `PR3` используется в звуке, QR и ссылке. Для микрофона рекомендуется HTTPS/PWA. Адреса `0.0.0.0` и `::` не являются вариантами подключения и больше не выводятся. На Android `content://` обычно не даёт использовать микрофон: для полноценного звука откройте HTTPS/PWA и разрешите микрофон. Когда микрофон хоста недоступен, можно **отправить звуковое приглашение без прослушивания**, а ответ получить QR/Share/ссылкой. Документация и проверка устройств: [ACOUSTIC-PAIRING.md](docs/ACOUSTIC-PAIRING.md).

## Быстрое подключение QR и возвращение игрока (RC6)

В диалогах «Присоединиться к комнате» и «Подключить устройство» добавлен **встроенный QR-сканер через системную камеру** и выбор изображения из галереи. Фотография сканируется локальным jsQR, без CDN, без внешнего QR-приложения и без доступа к видеопотоку. Android content:// поддерживает этот способ при разрешённом открытии системной камеры. Сохраняется прежний PR3/PR2, а QR-генератор также поставляется офлайн.

После первого входа в комнату выдаётся защищённый, привязанный к участнику ключ возвращения. Если клиент потерял связь, хост создаёт новое PR3 приглашение, и клиент может **вернуться на своё место** (даже в начатой партии), предъявив сохранённый ключ **после установления WebRTC**, а не в QR. Возвращаются прежний идентификатор игрока и личная проекция. При этом перезапуск браузера хоста и автоматическое восстановление без повторного QR пока НЕ поддержаны, требуются последующие LAN-01/03.

[Схема QR и возврата игрока](docs/QR-PAIRING-AND-RESUME.md).

## Текущая multiplayer-разработка

Целевой продукт — **одно браузерное приложение** на ПК, телефоне и планшете. Отдельного приложения или Node-сервера для ПК-хоста нет. В сетевой партии браузер создателя комнаты владеет `SessionAuthority`, а остальные браузеры подключаются через заменяемый transport. Интерфейс самой партии общий для ботов, hot seat и WebRTC: `app/game-screen.js` компонует игроков, поле, управление и историю из доступной проекции, не дублируя сетевой экран. Сетевая личная игра использует `combined` renderer пака, публичный Стол — `table`.

Для LAN-first версии используется `RTCDataChannel`. Пока нет внешнего rendezvous-сервиса, первичное WebRTC-согласование выполняется локально через обмен offer/answer (в интерфейсе это будет QR/копирование). После установления канала игровые команды идут браузер ↔ браузер. Короткий номер комнаты сам по себе не может найти неизвестный браузер-хост без discovery/signalling, поэтому это удобный alias уже найденной комнаты, а глобальный room service отложен.

У каждого клиента остаётся собственная библиотека и разрешённая история сетевой партии в браузерном хранилище. Полный `Session` хранится только у браузера-хоста; клиент получает только свою проекцию.

Актуальная архитектура и последовательность работ: [UNIFIED-WEB-APP-PLAN.md](docs/UNIFIED-WEB-APP-PLAN.md). Контракт authority/projection: [MULTIVIEW.md](docs/MULTIVIEW.md).
