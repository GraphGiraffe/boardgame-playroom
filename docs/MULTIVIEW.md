# Исполнитель партии, клиентские проекции и миниатюры

Экспериментальная реализация ветки `feature/authority-responsive-preview`, 7 октября 2026. Основное приложение сохраняет локальные режимы solo/pass и формат сохранений; комнаты и долговечное сетевое хранилище не объявляются готовыми.

## Роли и границы

`SessionAuthority` владеет полной `Session`, проверяет и упорядочивает команды. `connect(viewer)` — **доверенная операция организатора**, не метод, доступный удалённому клиенту. Результат — фасад `snapshot/dispatch/history/subscribe/close`, привязанный к одному месту. `viewer=-1` означает публичный стол без команд. Номер игрока не принимается из команды. Исполнение ботов принадлежит authority; локальная оболочка может отдельно применять прежнюю политику паузы при открытии меню.

`surface` задаёт только компоновку (`combined`, `table`, `player`) и не повышает полномочия. Не записывайте её в `Session.options.mode`: там по-прежнему `solo/pass`. Телефон не загружает Session, сохранение или модуль игровых правил. Общий экран, исполнитель и организатор — разные роли.

Основная локальная оболочка — доверенный хост. Она использует новый исполнитель для действий и ботов, но по-прежнему владеет Session для сохранений и анимаций. Изолированная клиентская оболочка `app/shared-views.js` не имеет этого доступа. Не называйте весь старый app.js перенесённым на удалённый клиент.

## Команды и подтверждения

```js
const authority = new SessionAuthority(session);
const connection = authority.connect(0); // Только на стороне организатора.
const snapshot = connection.snapshot();
const command = PlayroomProtocol.command(snapshot, snapshot.actions[0], 'client-unique-id');
const receipt = connection.dispatch(command);
```

Envelope: `protocolVersion:1`, `sessionId`, `authorityEpoch`, `commandId`, `expectedRevision`, `action`. Ревизия — `state.move`, в том числе для реакций вне очереди. Сначала проверяются версия протокола, партия и эпоха, затем уже обработанный ID, затем ожидаемая ревизия новой команды. Повтор возвращает прежнее подтверждение и свежую проекцию без второго действия. Повтор ID с другим содержимым отклоняется. Ошибочные команды тоже получают стабильную квитанцию. Клиент после потери подтверждения хранит **тот же** envelope до явного повтора.

`ClientSnapshot` содержит game/packVersion, место, разрешённое состояние, разрешённые действия, события, число снимков истории и безопасные эффекты. В нём нет options, seed, RNG, полного экспорта сессии или чужих закрытых ID. Пак отвечает за фильтрацию дополнительных собственных закрытых полей через `project`. UNO скрывает `uno.pending`; оболочка не использует его для подсказки момента ручного выкрика.

История проектируется для того же места. Footer, подписи истории, уведомления и callback оформления локальной оболочки используют разрешённые данные, а не полный журнал. Звуки/эффекты повторного снимка не запускаются второй раз; новый клиент не воспроизводит весь прошлый журнал автоматически.

Текущая область дедупликации — живой authority, до 20 000 принятых идентификаторов; перезапуск меняет epoch. Долговечные квитанции, восстановление серверной партии и передача роли исполнителя пока отсутствуют. HTTP-стенд опрашивает актуальное состояние, а не является высокопроизводительным игровым сервером.

## Представления пака

```js
PlayroomViews.register('my-game', renderCombined, renderCover, {
  surfaces: {table: renderTable, player: renderPlayer}
});
```

Сигнатуры прежние: `(projectedState, viewer, allowedActions, ui)`. `ui.surface` сообщает компоновку; `ui.selected` — локальный выбор. Таблица получает пустой список действий. Отсутствующая optional-surface не заменяется совмещённой молча. Загрузка JSON, переключение точной версии и rollback сохраняют весь набор функций. Старый вызов `register(id,render,cover)` остаётся действительным для combined.

`TabletopPacks.exportView(id,version)` выдаёт только manifest, view.js, обработанные стили/ассеты, текст правил и описание звуков. Это **не** экспорт правил или состояния. Просмотр должен совпадать с точной версией партии. Установленный старый пак не заменяется новым под тем же номером.

UNO реализует table/player/combined. Минимальный независимый пример `examples/private-counter` находится в репозитории паков; сборщик паков проверяет его отдельно от коллекции пяти игр.

## Пропорциональные рисунки и compact fallback

`PlayroomViews.helpers.art({main, compact?, width, height}, variant)` создаёт единый SVG viewport с `preserveAspectRatio="xMidYMid meet"` и каноническим HTML-artboard. `main` и `compact` — доверенная разметка пака, а не интерактивные кнопки. В SVG допускается вложенный SVG или изображение из `PlayroomPack.asset`. Внешний button остаётся единственным источником действий/aria-label/tooltip; внутренний artboard имеет `aria-hidden` и не перехватывает жесты.

```js
const face = H.art({
  main: '<div class="my-face">...</div>',
  compact: '<div class="my-compact-face">...</div>', // Необязательно.
  width: 72, height: 103
}, context?.variant);
```

Основной и компактный рисунки используют одинаковые канонические размеры и пропорции. `H.opponents` передаёт renderer третий аргумент `{variant:'compact',surface:'opponent',interactive:false}`; старые двухаргументные функции продолжают работать. Если compact отсутствует, используется main. Рамка, углы, номинал и масть рисуются на artboard и масштабируются вместе, а не отдельными CSS-переопределениями. Для крошечных размеров compact может убрать декор и увеличить номинал, но не менять смысл карты. Рубашки тоже используют общий artboard.

В паке следует оборачивать рисунок внешним классом `art-card` и не задавать вторую рамку вокруг него. Размер слота в руке, перекрытие и зона касания остаются механизмами приложения. Не уменьшайте интерактивную кнопку ниже 44 px только из-за маленького изображения. Нечитаемый основной рисунок требует осмотра/выдвижения либо compact, а не дополнительного сжатия текста.

## Проверки и ограничения стендов

`tests/authority.test.cjs`, `preview-server.test.cjs`, `view-contract.test.cjs` входят в независимый набор. `shared-preview.test.cjs` с установленными паками проверяет HTTP-клиенты, публичность, ручные действия, размеры и поворот; по умолчанию это настоящая HTTP-навигация Chromium. `PLAYROOM_RENDER_ONLY=1` — отдельно помеченный fallback для окружений, в которых навигация браузера запрещена: реальные DOM/жесты, но HTTP-вызовы мостом через Node. Он не заменяет полный браузерный сетевой прогон.

Пакеты по-прежнему исполняют доверенный JavaScript. Протокол проекций не изолирует вредоносный пак. MessagePort-стенд одного origin не доказывает изоляцию localStorage; отдельный origin и серверный authority — разные уровни проверки. LAN: обычный HTTP, только доверенная сеть, без проброса портов. Инструкции пользователя — [PREVIEW-TESTING.md](PREVIEW-TESTING.md).
