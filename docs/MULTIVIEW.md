## Стол

**Стол — это Зритель, на котором игроки могут совершать публичные действия.** Видимость данных одинакова; право выполнить действие проверяется отдельно. Выбор surface не выдаёт права игрока.

- Поле, фишки, кубики, публичные перемещения и события видны на Столе.
- Руки присутствуют как у Зрителя: рубашки/количество при закрытых руках, лица при общем режиме открытых рук. Собственной приватной руки у Стола нет.
- В Морском бое во время партии обе расстановки скрыты, видны публичные выстрелы и их результаты. Открытые руки карточных игр не открывают корабли. Завершённая партия следует существующей политике раскрытия пака.
- Публичный ход можно выполнить со своего устройства или на Столе. Выбор закрытой карты и приватная расстановка выполняются с личного устройства.
- Публичность должна включать доступность и аргументы команды **до её выполнения**. Публичный результат не делает приватный выбор публичным: например, список номиналов в руке нельзя передавать Столу для запроса карты.
- Архив и повтор не предоставляют управление. Обычный Зритель остаётся read-only.

## Реализация и границы текущего среза

`GameModel.projectTable(position, actor)` берёт данные/события из зрительской проекции, сохраняет viewer=-1 и добавляет только команды с явным visibility='public'. `commandFor(..., 'table')` повторно проверяет доступность. Временный адаптер предоставляет `TabletopCore.projectTable/applyTableAction`; вызывающий application controller обязан проверить право использовать actor. Эти функции сами не аутентифицируют соединение.

Крестики-нолики engineApi 3 объявляют публичную постановку знака. Пятый срез подключает её к сетевому Столу. Неперенесённые паки по-прежнему показываются как зрителю и не получают управления автоматически: их публичные команды нужно объявить при переносе правил.

Пак регистрирует render и при необходимости surfaces.table/player. Рендерер возвращает api:2, family, playerContent и elements; GameScreen размещает их. Player descriptors индексированы исходными playerIndex. Личные hand controls исключаются со Стола; публичные controls передаются только из разрешённой проекции. Удаление кнопки не заменяет фильтрацию данных.

SessionAuthority выдаёт snapshots/history для закреплённого viewer. SharedViews использует GameScreen/Input; архивный просмотр не dispatch-ит команды. Live effects, replay и результаты различаются; итог партии сохраняется при выборе начального кадра. Production authority работает в браузере хоста.


## Сетевая привязка в разработке 0.18

`application/session-access.js` — переносимая политика сопоставления участника комнаты с игровым подключением. Она читает host-owned room snapshot, сохраняет явные playerIndex восстановленных мест, отличает роли player/spectator/table. Удалённому участнику без подтверждённой личности подключение к authority не выдаётся. Одна политика применяется при старте, на устройстве хоста и после authenticated resume.

`SessionAuthority.connectTable(actors)` — порт только хоста. Он создаёт неизменяемое разрешение для перечисленных игровых индексов и viewer=-1. Ни role, ни список разрешённых акторов не принимаются клиентской командой. Snapshot имеет role=table, audience=public, viewer=-1 и actor текущего разрешённого игрока; бот не получает ручного управления. Snapshot Зрителя имеет role=spectator и пустые actions. Layout не выдаёт полномочий.

Команда Стола передаёт отдельный actor вместе с обычными sessionId/authorityEpoch/commandId/expectedRevision/action. Хост проверяет grant, отсутствие бота, ревизию, публичность и легальность через tableCommand, затем использует тот же Session.prepare → durable commit → commitPrepared → ACK. Запрос actor от обычного player connection отклоняется. Паузой через эту capability управлять нельзя: это отдельное право управления сессией; host stop остаётся отдельным портом.

Для повторной доставки actor берётся из исходной команды: смена хода не меняет её идентичность. Поиск прежней квитанции предшествует проверке актуальной ревизии; при восстановлении authority старый epoch разрешает только уже записанное подтверждение. Квитанция всегда содержит проекцию **подключения**, поэтому ACK Стола остаётся публичным. В прежней схеме IndexedDB поле receipts.viewer хранит индекс исполнителя команды, для Стола — actor; это не viewer=-1 публичного snapshot. Схема БД не менялась. При переносе CommandProcessor/journal это временное имя должно стать явным actor/receipt scope.

History не содержит действий ни в outer actions, ни в modelProjection/tableActions. Client/reconcile и SharedViews сверяют роль вместе с viewer; совпадение viewer=-1 не превращает Spectator в Table. В архиве reader всегда read-only. Закрытие RTC и перезапуск браузера не создают автоматического rendezvous: существующая политика нового приглашения сохраняется.

Web renderer разрешает ввод только по текущему live snapshot, без паузы/pending/history/показа предыдущего хода. Проверено обычное лобби → WebRTC → команды со Стола и личного устройства в трёх браузерных контекстах; отдельно реальные IndexedDB и перезагрузка хоста. Это desktop Chrome/loopback, не приёмка физических телефонов/NAT. Декларации публичных действий остальных 11 паков и публичные реакции нескольких акторов вне очереди будут добавляться при их переносе; UI сейчас показывает публичные команды текущего игрока.
