# Локальная сборка 0.20.0-preview.14

Кандидат для ручной проверки, без публикации. Ветки и удалённые окружения не переключаются. Production остаётся прежним; успешные локальные тесты не подтверждают применение миграций в живом Supabase или работу через мобильные сети.

## Файлы

- `playroom-all-games.html` — приложение с прежними точными паками и новым UNO 0.6.7-preview.1, открывается как файл.
- `playroom-pwa.zip` — PWA для localhost/HTTPS.
- `setup-supabase.sql` — полный актуальный setup: supabase → social → signaling → online → host-transfer → push → cloud-saves → account-sync. Сохраняет существующие данные; применяется в SQL Editor тестового проекта при необходимости.
- `playroom-source.zip` — исходники кандидата; `SHA256SUMS` — контрольные суммы сборки.
- `../REPORT.md` — результаты сетевых проверок и ограничения. Минимальный fix-direct-invite.sql уже применён через MCP к тестовому Supabase; для другой установки используйте полный setup из сборки.

## Сборка

Из `playroom/`:

```sh
python3 build.py --packs-dir ../tmp_files/online-video-review-020/packs-candidate --all-games --pwa --output-dir ../tmp_files/pwa-staged-020/build
```

Запуск локальной PWA из корня workspace:

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory tmp_files/pwa-staged-020/build/pwa
```

Открыть `http://127.0.0.1:4173/`. Для проверки другого устройства нужен доступный этому устройству HTTPS-адрес; loopback доступен только на компьютере запуска.

## Облачные сохранения

SQL `server/cloud-saves.sql` и `server/account-sync.sql` уже применены через MCP к тестовому проекту. Для другой установки используйте полный setup из сборки. [Настройка и семантика](CLOUD-SAVES.md).

## Ручная проверка

1. Обновить SQL из сборки для переключателя пароля. Проверить вход по номеру/ссылке при выключенном пароле и запрос пароля после включения. Создать/восстановить тестовый аккаунт; открыть друзей, диалог и группу. Проверить приглашение, отклонение и закрытую комнату.
2. Написать `:time:`; выбрать реакцию при пустом активном поле, внутри текста и без фокуса. Проверить удержание, удаление, многострочный ввод и снятие фокуса.
3. Проверить сообщения двух клиентов, прокрутку старой истории, непрочитанные сообщения и возврат из чата в исходное окно.
4. В комнате проверить общий/командный чат и баблы в лобби/партии. Соперник не должен получать командные сообщения.

Web Push реализован локально: сервер подключается по [инструкции](../server/push/README.md), фоновые сценарии требуют живой приёмки. Новая TURN-инфраструктура и окончательная приёмка 0.20 остаются отдельными этапами. Таймеры/паузы относятся к 0.21.

Сборка этого этапа: `tmp_files/web-push-020/build/`; рядом лежат журнал выбранных проверок, скриншоты и инструкция подключения. Автономный HTML открывается как файл, но Web Push доступен только через Service Worker на localhost/HTTPS.

Этап передачи хоста: локальный кандидат находится в `tmp_files/host-transfer-020/build/`. [Инструкция этапа](HOST-TRANSFER.md). Передача запускается из настроек работающей сетевой партии; аварийного выбора нет.

## Preview.13: темы и компактные настройки

Темы переключаются мгновенно одной кнопкой солнца/луны в настройках. Отдельного редактора и кнопки «Темы» внизу главного экрана нет; две страницы занимают всю панель. Тёмная тема использует чёрный фон. Аватары показывают только персонажей; геометрические источники остаются в репозитории паков. Игровые скины выбираются прямо в настройках партии, без отдельного окна.

Манифест всегда задаёт чёрные `background_color` и `theme_color`, ранняя веб-загрузка также чёрная. ID, start_url и scope сохранены. Нативную заставку уже установленной Android PWA нужно проверить физически после обновления WebAPK: Chrome применяет новый манифест по своему расписанию, обновление Service Worker само по себе этого не доказывает.

На приветственном экране доступен облачный аккаунт и игра без облака. Без полного входа отключён онлайн-режим; ручное сетевое подключение по Wi-Fi и локальные партии доступны. Возврат из аккаунта сохраняет введённое имя. Ручные операции с облачными копиями, выход, сброс и удаление требуют предметного подтверждения.

«Рука веером» — включённый по умолчанию чекбокс; прежнее сохранённое значение сохраняется. «Недавняя игра», «Быстрый ход», «Обучение» используют короткие подписи. У обучения есть справка и две кнопки 32 px в одной строке. Справки выбранных параметров правил доступны в верхней карточке каждого пака; снизу сохранены полные пояснения и переход по значку книги.

Кнопки карточек паков слева направо: удаление у левого края; вверх, вниз, видимость и избранное сгруппированы у правого. На узком экране размеры сохраняют один ряд.
Видимость и избранное без выбора используют обычный фон кнопки. Скрытый пак отмечается синим перечёркнутым глазом, избранный — жёлтой заполненной звездой; стрелки остаются обычными.

Строки действий используют общий `ui-action-row`: опасное действие слева, остальные справа; ведущая подпись сохраняется. Это относится к облачным копиям, аккаунту, другу/группе и карточкам партий.

Обычные быстрые действия — квадратные 44 px со скруглением; на ширине до 360 px используются компактные круглые варианты. Обучение сохраняет отдельные кнопки 32 px. Импорт пака и экспорт сохранения находятся справа от заголовка; импорт показывает стрелку из документа к нам, экспорт — от нас в документ.

Счётчики памяти компактны: общий объём — монохромная иконка приложения; системные файлы — шестерёнка; паки — стопка; сохранения — дискета. Облако: иконка и `0,1/10 МБ`. Остальные значения — КБ/МБ, один десятичный знак до 10, далее целые. Полные названия остаются в tooltip/aria-label.

Строка «Обучение»: подпись со справкой, красный сброс, список, чекбокс у общего правого края. Сброс подтверждается отдельно.

Никнейм редактируется без кнопки сохранения: черновик фиксируется при закрытии или переходе из настроек. Для участника комнаты переименование отправляется фоновым запросом; ответ не открывает лобби поверх текущего экрана и отбрасывается после смены соединения. Пустой черновик сохраняет прежнее имя.
