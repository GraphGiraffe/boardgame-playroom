# Локальный масштаб и дискретные настройки

Область применения: приложение **0.21.0** и коллекция **0.9.0**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; актуальное приложение доступно на [сайте](https://graphgiraffe.github.io/playroom-hod-test/).


## Поведение

В настройках громкость и скорость анимаций — два небольших дискретных слайдера в одной строке. Под ними расположена шкала масштаба 50–150%, шаг 10%, исходное значение 100%. Все позиции отмечены точками, включая недоступные. Серый участок линии обозначает недоступные значения; pointer, touch и клавиатура ограничены последней разрешённой позицией. Полная шкала и крайние подписи остаются видимыми.

Громкость: «Без звука», «Тихо», «Средне», «Громко». Отдельного переключателя звука нет. Нулевая позиция отключает звук, но не блокирует сам слайдер. Остальные позиции включают звук и задают прежние значения .3/.6/1. Настройка последней ненулевой громкости сохраняется при отключении. Скорости используют прежние пресеты instant/fast/normal/slow и прежнюю политику reduced motion.

Масштаб меняется после отпускания ползунка, чтобы его положение не уезжало во время перетаскивания. Подпись и ограничение значения обновляются сразу. Параметры сохраняются в playroom.settings.v1 на этом устройстве. Масштаб не является командой партии, не передаётся другим игрокам и не изменяет сохранение Session.

## Граница безопасного увеличения

platform/web/interface-scale.js нормализует целый процент и рассчитывает верхнюю границу по размеру окна. При увеличении с 110% проверяется непрерывная последовательность шагов; первое небезопасное значение завершает диапазон. Портрет сохраняет минимум 320×640 логических px. Landscape сохраняет минимум 340 px высоты и 800 px ширины, либо 600 px ширины при логической высоте меньше 430 px. Значения ниже 100% доступны на всей шкале; исходный интерфейс остаётся базовым пределом на очень маленьком окне.

Примеры границ: 320×640 — 100%; 390×844 — 120%; 844×390 — 110%; 1024×768 — 120%; 1440×900 — 150%. Это консервативный предел приложения, а не системное масштабирование браузера. При resize/повороте применяется меньший из запрошенного масштаба и текущего предела. Запрошенное предпочтение сохраняется, чтобы восстановиться после возврата подходящего размера. Выбор другого значения пользователем заменяет это предпочтение.

## Дискретные стандартные размеры

В локальном кандидате sizes.1 масштаб выбирает значения из [единого каталога](SIZE-SYSTEM.md). Корни приложения, окон и уведомлений больше не используют CSS zoom. `--interface-scale` равен 1; `applied`/подпись шкалы хранят выбранную ступень. `layoutRect` и ввод используют экранные px. Поворот пересчитывает размерные роли и явно разрешённую геометрию, обычный ход — нет.

Основные карты имеют одинаковую ширину во всех паках: при 100% — 50px в portrait телефона, 60px в landscape, 80px при ширине от 1000px. Масштаб выбирает ближайшее значение ряда 20/30/…/120; равное расстояние разрешается в меньшую сторону. Миниатюры соперников и ограниченная сетка — отдельные роли. Доски выбирают стандартный помещающийся размер; клетки и исключающие области скинов производны от него.

Controls, typography, spacing, radii and windows use named size families. Граница viewport 320px и media breakpoints не масштабируются. Предпочтение остаётся локальным и не меняет Session, правила, semantic IDs или опубликованные старые паки.

## Дополнительные исправления

На коротком landscape кнопка передачи устройства и игровые действия делят один ряд. Пустая область действий больше не отнимает у костяшек лишние 44 px; рука сохраняет нормальный размер и прокрутку. При autoplay локальной истории звуковые события передаются в общую очередь так же, как в живой партии; stop/выход отменяют источник. Состояние Session не меняется.

Старые сценарии UI теперь явно выбирают ручной режим для проверок выбора перед ходом и отключают автоматическую передачу в проверке инспекции своей руки. Два кубика ЗиЛ+ выполняют одну и ту же команду броска; тест нажимает один из них. Геометрия display:contents проверяется по всем реальным группам мест, а не по нулевому прямоугольнику контейнера. После поворота проверка ждёт два кадра рендера для завершения штатного ResizeObserver, затем измеряет все области; проверки неподвижности поля во время ходов продолжают снимать покадровые значения. Строгие границы, 44 px и проверки звука/сохранений сохранены.
