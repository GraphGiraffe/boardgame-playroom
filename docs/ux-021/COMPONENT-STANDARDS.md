# Стандартные исполнения интерфейса 0.21

Обновлено 11 ноября 2026. Последние указания владельца имеют приоритет. Стандарт означает общий компонент и правила его использования; он не требует одинаковой плотности у игрового поля и формы параметров.

В этой итерации общая фабрика вкладок подключена к Настройкам, Оформлению, Данным и Аккаунту. Контекстные game/social/room tabs используют общую CSS-основу; их специализированные обработчики не заменяются универсальным навигационным состоянием. Семантика экранов не определяется случайным совпадением имени CSS-класса.

## Проверка и ограничения

Проверяется не только совпадение скриншотов: родительский DOM, ввод, фокус, роль/аккаунт и актуальность async-результата должны сохраняться. Параметры и Оформление имеют числовую проверку одинаковых осей/вкладок в portrait/landscape; группы — retained rows/height при held refresh/error; карточки — квадратность, типы и минимальный размер арта; drag — нативные события отдельно от controlled pointer fixtures.

Полный набор proof и точный кандидат фиксируются в LOCAL-CANDIDATE.md и отчётах ревизии. Общий lifecycle подключён к ModalController, уведомлениям, предложению хоста, toast, окну реакций и игровому чату. Нативный popover сохраняет браузерный transition/starting-style механизм; ему не добавляется второй искусственный вход. Физическая приёмка и понятность новым пользователям не заменяются headless-проверкой.

### Контракт одноразового появления

`prepareVisualEntry(node,{target,document})` подготавливает вход перед подключением DOM и возвращает `start`/`finish`. После подключения вызывается `start`. `enterVisual(node)` — сокращение для уже подключённого элемента; возвращённая очистка принадлежит только этому входу. `finishVisualEntry(node)` завершает активный вход конкретного узла.

Длительность задаёт CSS. Завершение/отмена собственной анимации, reduced motion, скрытие или удаление расходуют вход и освобождают временные слушатели/observer. Дочерняя анимация не завершает родительскую. Позднее завершение старого входа не меняет переиспользованный DOM. При выходе сначала считывается текущая поза, затем освобождается вход.

Keyed-обновление существующего уведомления не является новым появлением. Обновление текста показанного toast не является новым показом. Новый элемент/новый показ могут анимироваться; восстановление normal motion у старого — нет.


## Общий акцент приложения

Настройка «Акцент приложения» действует через семантическую палитру AppearanceWeb: action.primary, interaction.available, selected/hover/raised surfaces и borders. Старые --green/--accent/--lime остаются алиасами общей палитры, отдельные экраны не подбирают свой акцент. Цвет поля следует этому выбору. Canvas, player-slot цвета и feedback success/error не перекрашиваются. Для выбранного нестандартного акцента тон основного действия обеспечивает контраст >=4.5 к тексту кнопки и фонам основных UI-поверхностей в обеих темах. null восстанавливает точные встроенные цвета. AppearanceService хранит accentColor, читает прежний fieldColor при отсутствии нового поля; новые записи не дублируют настройку. Выбор не пересоздаёт сцену и не меняет authority.


## Маркер выбора оформления

Выбранная тема имеет галочку в правом верхнем углу карточки. Выбранный компонент имеет такую же галочку в правом верхнем углу самого образца; маркер не занимает отдельную строку и не меняет размеры содержимого. Положение задаётся общей appearance-choice-current, а не индивидуальными вариантами колод.


## Dropdown и взаимодействия панели

GameScreen.openSelectChoice — единственная реализация выбора из списка. Динамически созданные select используют этот же механизм; сетевой выбор добавляет только своё действие удаления адреса. HTML-select остаётся форменным портом значения, а OS picker не вызывается. Панель использует ModalController, bindSurfaceDismiss, общий заголовок и сохранение source capability. Фокус и aria-controls связываются с актуальным источником, выбранный неизменившийся вариант не создаёт input/change. Строки оставляют6px для полного фокуса внутри scrollport.

bindPanelGesture закрывает только активную панель по законченному тапу по свободному фону снаружи или направленному pull к её краю. --surface-dismiss-edge:bottom/right/left задаёт ось: нижняя вниз, боковая наружу. Body начинает pull только с верхней границы вертикального scrollport; при scrollTop>0 работает native scroll/inertia, после захваченного браузером pan нужен новый жест. Inputs/ranges/editable, выделение, pinch и поперечный scroller защищены. data-surface-pull-through у preview-кнопки разрешает drag панели, сохраняя обычный одиночный tap/cycle; слабый/cancelled pull возвращает её, закрытие использует общий Back без Save. Подробные границы нативного Chromium/CDP и WebKit controller-проверок — PHONE-FEEDBACK-1111.md. Явные кнопки, ссылки, поля и другие действия за немодальным чатом выполняют собственное действие; дочернее окно сохраняет DOM чата, черновик и выделение для возврата. Drag/scroll, дочерний popover и последующие жесты отделены. Завершённый перенос/свайп потребляет compatibility click через PlayroomDOM.consumePointerReleaseClick; новый pointerdown и keyboard activation независимы. OrderUI скрывает tooltip при фактическом захвате drag, не создавая второй алгоритм подсказок. Игровой CoreInput сохраняет собственное pointer ownership и ждёт фактического конца отменённого жеста.

Заголовки лобби создаются через modalHead с дополнительным className. updateModal сохраняет ID существующего heading до patchChildren: пассивная перерисовка не должна временно переставлять focused actions и терять фокус.

В каталоге нет отдельной строки «Все / Любимые»: избранные игры поднимаются вверх. Фильтры — кнопка с иконкой и доступным названием рядом с выбором вида, с индикацией активного фильтра; «В комнату» остаётся в том же toolbar; при нехватке ширины или увеличенном тексте переносится целая группа, без обрезания действий и уменьшения44px областей. Компактный toolbar segmentedcontrol сохраняет44px кнопки и общий shared-page-tabs механизм без дополнительных внешних полей. Звук/анимация собраны в «Эффектах» с одинаковыми slider→toggle блоками.


### Внутренний возврат аккаунта

Обычный Back активной app-owned поверхности сначала вызывает необязательный синхронный beforeBack. true означает один внутренний переход без удаления frame, false — обычный pop. Принудительный reset проходит напрямую. Аккаунт использует этот порт для подписанного пользователя в формах имени, смены пароля и запроса восстановления: сначала обзор, затем исходный экран. Отдельная view revision отсекает устаревший feedback формы, не отменяя реальный credential request и busy guard. См. [проверку](ACCOUNT-INNER-BACK-1103.md).


### Отступы, центровка и масштабирование

При увеличении текста сначала сохраняются целые слова: галерея уменьшает число колонок, footer переносит целую кнопку, общий заголовок переносит группу действий на следующий ряд. Уменьшение шрифта и разрыв обычной подписи посреди слова не заменяют reflow. Обычный размер сохраняет прежнюю компоновку. [Проверка оформления и общего заголовка](APPEARANCE-TEXT-REFLOW-1103.md).

- Общие поля экрана, панели, заголовка и фиксированного действия берутся из одного исполнения. Внутренние поля задаются padding, расстояние между соседями — gap; случайные margin/translate для отдельного экрана не заменяют общий контракт. Семейства размеров остаются в core/size-tokens.json и platform/web/element-sizes.js.
- Фиксированный заголовок совпадает с осями своего layout-slot в координатах viewport; резерв системной полосы прокрутки не учитывается дважды. Минимальная ширина оболочки ограничена доступной шириной, а не создаёт скрытый выход за неё. Проверяются реальные границы каждой кнопки, поскольку document.scrollWidth не обнаруживает все случаи обрезания.
- Проверяется итоговая геометрия после каскада CSS: поля слева/справа, выравнивание подписей, центр контролов и рисунков SVG, отсутствие обрезания фокуса. Центр CSS-бокса не гарантирует центр несимметричного глифа. Нижняя панель сохраняет свой якорь, а не искусственно центрируется как диалог.
- Область нажатия отделена от размера рисунка. Принятый базовый контроль44px сохраняется; рекомендация web.dev48px/8px применяется с учётом плотности и соседних целей, а не как автоматическая замена всей сетки.
- Масштаб браузера не запрещается. Перестроение при узком CSS viewport, пользовательский размер шрифта, браузерный zoom, pinch и внутренняя плотность игры учитываются раздельно; один тест не выдаётся за остальные. Увеличение текста не должно скрывать подписи или функции, фиксированный footer — перекрывать ввод.
- Сверка рекомендаций и текущие результаты: [WEB-DEV-AUDIT-1103.md](WEB-DEV-AUDIT-1103.md). Источники: [Spacing](https://web.dev/learn/css/spacing), [Flexbox](https://web.dev/learn/css/flexbox), [Responsive accessibility](https://web.dev/articles/accessible-responsive-design).


Типографические значения каталога размеров остаются базовыми числами для корня16px; runtime выдаёт bindings семейства type в rem. Размеры рисунков, границ и физических областей остаются в CSS px. Обычный текст не подгоняется уменьшением шрифта при увеличении пользовательской настройки. Код и границы проверок — [геометрия](WEB-DEV-GEOMETRY-SCALING-1103.md), [клавиатура и формы](WEB-DEV-KEYBOARD-FORMS-1103.md).


Фоновая доступность обновления использует общий верхний app-notice с role=status и явным действием. Не открывает экран и не перерисовывает hub; одинаковый build ID не повторяется, новый cache ID отличает превью одного version. Действие/закрытие44px, rem-текст, достаточная ширина сообщения и перенос действий вниз; исходный фокус сохраняется и возвращается после Back. Обычные краткие сообщения сохраняют свой таймер, уведомление с действием не исчезает по нему. Это не пассивный toast без взаимодействия. [Реализация и доказательства](UPDATE-NOTIFICATION-FOLLOWUP-1103.md).


### Крупный текст в навигации

Размеры читаемых nav/Room/badge подписей относительны пользовательскому шрифту; рисунок icon-only не считается подписью. Навигация выбирает balanced4/2/1 по доступной ширине и rem minimum; rail учитывает min-content целых слов. Отступ основного содержимого и индикатор берутся из фактических размеров; собственная прокрутка rail сохраняет выбранный пункт видимым. Проверяются каждый word Range и target bounds, а не только scrollHeight. ResizeObserver использует существующую rAF очередь для layout writes; errors не подавляются. [Проверки](RULES-REFLOW-AND-TYPE-1103.md).


### Точечное обновление игровой сцены

Ход/выбор/эффект обновляет затронутые данные и DOM; общий пересчёт всей сцены не используется как fallback. Изменённые области получают явную инвалидацию замеров. Первичное размещение и resize контейнера выделены отдельно; одинаковые геометрические входы не измеряются повторно. Отдельный статус готовности/подсказки обновляется без render/layout игрового поля. Кэш геометрии не переносит приватные данные между viewer/session.

Повторная активация того же пака не переписывает неизменившийся stylesheet. Проекция не копирует закрытые данные, сырые события и RNG, которые затем отбрасываются перед отдельной авторизованной проекцией. Обязательные неизменяемые model-снимки и визуальные копии сохраняются. Внутри одной визуальной копии повторно используются уже прочитанные стили/список потомков; изменение видимости источника требует свежего чтения. Между снимками не переиспользуется чужая геометрия или приватный рисунок.

Сверка с [web.dev: layout и layout thrashing](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing) и [rendering pipeline](https://web.dev/articles/rendering-performance): ограничивать затронутую работу и отделять чтение от записи. Это принцип реализации; фактическую задержку доказывает профиль конкретного действия, а не наличие правила в документации.

Уточнение04.11: способ ввода публикуется в `html[data-input-modality]` только при изменении фактического значения. Повторное подключение восстанавливает атрибут после удаления; touch/мышь/клавиатура и игровые выделения сохраняют свои различия. Доказательства: [COMMUNITY-RETAINED-HOST-1104.md](COMMUNITY-RETAINED-HOST-1104.md).

Уточнение04.11 по выходу поверхности: логическое закрытие проверяется состоянием исходного frame, его отсутствием в активном/приостановленном стеке и inert-состоянием допустимой выходной визуализации. Глобальный count CSS-класса не различает живое окно и visual exit; действия направляются в актуальную активную поверхность. [Проверки](CHAT-FLOWS-COVERAGE-1104.md).

| Пояснение | Help у подписанного объекта | Popover не переключает значение/не закрывает родительскую форму, Escape закрывает свой слой |
| Disclosure | Подписанный разворачиваемый пункт/chevron | aria-expanded и реальное раскрытие; не использовать такой же вид для немедленного destructive действия |
| Измеренный прогресс | PlayroomStatusMeter (`app/status-meter.js`) | progressbar/meter/status; bytes/files/ratio только при известных value/max, иначе indeterminate без выдуманного процента; error/paused/busy не равны успеху |
| Игровой объект | Канонический физический SVG/renderer, свой entity/owner | Выбор/доступность/ошибка отличаются от disabled UI; декоративная miniature не становится маленькой кнопкой |

Одинаковая форма контрола означает один тип взаимодействия. Glyph сам по себе — метафора объекта/направления, а не глобальный command ID: допустимые контекстные повторения перечислены в [ревизии иконок](ICON-SEMANTICS-1111.md). Доступное имя называет конкретную операцию. Это явные исключения, а не разрешение менять поведение одинаковой кнопки в одном контексте.

## Компактная карточка параметра

Единственная реализация — `ruleControl`/`syncRuleChoices` в app/app.js и scoped room-rules-021.css. Нативный fieldset сохраняет legend как доступное имя, legend визуально скрыт и не занимает специальный rendered-legend box. Видимый `.rule-choice-heading` находится ВНУТРИ фона карточки; Help44×44 привязан к обычному header, а не к анонимному содержимому fieldset. Никаких отрицательных top-offset или второго фона вокруг выпавшего заголовка.

- Группы «Порядок игры» / «Параметры» / «Завершение» видимы последовательно. Обычные карточки — две колонки с естественным reflow крупного текста. Максимум один hero, только явно объявленный presentation:mode у preset/settings. Разные числа карт сами по себе не делают hero.
- Одна реальная illustration + короткое описание выбранного варианта; кнопки ниже выбирают точный ID. Четыре числовых варианта —2×2. Подписи/описания в нормальном phone-размере до2строк без clamp; крупный текст растит/reflow содержимое, не обрезается.
- Tap по preview/неинтерактивной части карточки циклически выбирает следующий доступный вариант; chip выбирает конкретный, повторный tap не даёт второго изменения. Preview — настоящий button для Enter/Space. Help, ввод, +/- и вертикальная прокрутка не циклят значение.
- Условный параметр остаётся на месте: inactive inputs/preview/stepper disabled+dimmed, Help доступен. `visibleWhen`/`inactiveWhen` читают публичные значения. Недоступные options исключаются из submit; возвращение режима восстанавливает прежний draft. Не скрывать карточку и не перемещать соседей.
- Визуальный output под art убран, исходный aria-live output/accessible selected value сохранён. У text/symbol counter единственное значение видно МЕЖДУ +/- (visual span aria-hidden); количественный art cards/dice/health/lives/fleet/teams не получает дубликат. Пустой preview без art/описания не создаёт пустое место/tab-stop.
- Пояснение закреплено8px над собственным рядом controls. Ряды controls выровнены снизу; backdrop карточки содержит title/art/detail/controls. Опция и +/- имеют36px видимый фон и минимум44px реальную область label/button. Компактный paint не является уменьшением hit target.
- Изменение public варианта не меняет field height, следующий rowY, scroll/draft/focus. Bounded reserve берётся по реальным публичным вариантам без ghost clones/input/authority/live-output мутаций; исходные nodes возвращаются. Summary тоже резервируется. Observer delivery только читает размеры, writes coalesced в rAF; cache/ownership/dispose fencing обязательны. Временное измерение восстанавливает собственный scrollport, не трогает чужую прокрутку.

Это поздний owner override раннего универсального dropdown A08. Прочие dropdown остаются общим openSelectChoice; они не переписываются в игровые карточки автоматически. Новые public preview hints принадлежат SDK/паку, не game-ID ветвям хоста.

## Масштабируемые рисунки и справка

Физические размеры принадлежат `card-deck`/shared family: portrait radius12.5%X/8.928571%Y, square12.5%, die11/60. Канонический SVG уже содержит rim/print clip; второй фиксированный wrapper clip не должен срезать miniature. Mini/UNO/Solitaire используют те же доли, без fixed6pxfloor. Это не замена UI radius токенов у кнопок, чатов и панелей. Skin не меняет entity/приватность/правила.

Brief/full используют одинаковые public игровые компоненты. Semantic diagram grid сохраняет2×2 при доступной ширине; крупный текст допускает одну колонку. Background ограничен реальным art; list rows максимум30rem и центрированы без урезания phone-ширины. Таблицы используют intrinsic/auto columns, normal wordwrap вместо дробления слов фиксированной29% колонкой; текст не clamp/уменьшение шрифта. Rulebook/параметры — panels по последнему запросу владельца, а не старые полноэкранные формы.
