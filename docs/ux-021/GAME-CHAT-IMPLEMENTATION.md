# A21: новая компоновка игрового чата

2 ноября 2026 года. Источник: выбранные `reference-chat-{390,844}.png`, вариант
chat=0 и поздние уточнения владельца о launcher, ручке и composer. Это реализация
настоящего приложения, а не перенос декоративного HTML поверх старой формы.

## Структура

`room-chat-ui.js` теперь имеет отдельный `gamePanelMarkup` для игрового drawer:
ручка размера → заголовок «Чат комнаты» с закрытием справа → фактически доступные
каналы → прокручиваемая история → сообщение ошибки с тихим повтором → composer.
Общий и командный канал не дублируются в разных местах. Канальные вкладки общие
для полного и игрового представлений; в drawer они стоят перед историей.

Из drawer удалены повторные арт/название игры/название комнаты и иконка обновления
в шапке. История больше не использует оформляющий класс `.social-list`: фон панели
общий, оформлены отдельные сообщения. Тонирование команды сохранено на сообщениях,
а старое оформление контейнера применяется только к полноценному `.social-list`.

«Загрузить более ранние сообщения» — тихое действие внутри прокручиваемой истории.
Поэтому его исчезновение после загрузки последней страницы входит в изменение
scrollHeight и не сдвигает видимое сообщение. Навигационные круги приглашений и
перехода вниз используют существующий общий стиль также в body-drawer, вместо
неоформленной нативной кнопки на всю ширину.

В drawer круглые действия composer имеют 44 px, закреплены внутри капсулы снизу:
прозрачные реакции слева, зелёная отправка справа. Общий composer получает один
канонический `reaction` SVG из `core/ui.js` вместо мелкого текстового `☺`.
Полноэкранные DM и группы сохраняют свою шапку и геометрию, а также тот же новый SVG.

Параметры composer выражены существующими CSS-правилами через переменные размера,
внутреннего отступа и расстояния до края. Непрозрачная надстройка из новых offsets
не создавалась. Убран унаследованный margin-bottom:20px старой `.modal-head`.

## Поведение и границы

- Канал команды показывается только при его фактическом наличии в ответе действующего
  сервиса. Для обычного Домино вкладки скрыты; для Ludo teams проверен настоящий blue.
- Non-modal dock, его размеры, вытягивание, роли и закрытие не меняют владельца
  сессии или геометрию поля. Контекст модальной поверхности по-прежнему приостанавливает dock.
- История, ответы, реакции, прочтение, черновики каналов, generation и исходные
  callback/service/authority-контракты сохранены. Замена структуры не перерисовывает
  нативный ввод при каждом обновлении истории.
- Ошибка чтения показывает прежнее сообщение и тихое «Повторить» у задачи;
  штатная успешная синхронизация остаётся автоматической. Состав сообщения не теряется.
- Оранжевая линия на прежних кадрах была настоящим keyboard focus от старого
  глобального button:focus-visible, а не debug overlay. Фокус сохранён: вокруг
  ручки виден индикатор общей палитры `--ui-focus`, а не контур на всю ширину/высоту.
  Другие кнопки drawer также используют этот общий цвет фокуса.

Менялись только presentation markup, его scoped CSS и один общий SVG. ChatState,
RoomChat service, фильтрация приватных сообщений, authority и wire не менялись.

## Адресная проверка

Используется существующий случай:

```
node scripts/codex/test.cjs case/lobby-layout-browser --name 'game overlays 0.21:'
```

Он создаёт настоящие локальные пары RTC для Домино и командной Ludo. Проверяются
новый заголовок и отсутствие внешней рамки, 44px-кнопки со SVG, сохранение сцены,
подгрузка истории, ответы и прикреплённые реакции, черновик при повороте/resize,
ошибка и повтор с сохранением того же form, а также настоящий командный канал.

Для длинной истории 84 старые записи подготовлены через durable Data из одной
валидной записи настоящего RTC-сообщения; вместе с исходной это 85 записей.
Это историческая fixture, не 85 отправок и не обход ограничения частоты сообщений.
Старые сообщения отмечены прочитанными штатной командой; UI-cache охлаждён для
реального постраничного чтения. Ответ и реакция после этого отправляются и читаются
другим настоящим клиентом по RTC.

Контрольная ошибка вводится через существующий provider port только для чтения;
реальное соединение не разрывается. Повтор читает настоящий сервис и сохраняет
тот же нативный form и черновик. Командное сообщение проверяется в blue-канале
напарника и отсутствует в общем канале; общий черновик восстанавливается после смены вкладки.

Артефакты: `tmp_files/ux-021/ui-platform-audit/`, включая filled `*-chat-*`,
`*-chat-error`, `*-chat-retried`, `*-team-chat-{390,844}`, engine reports и исходные хеши.
Финальные результаты после последней коррекции отступа и независимая визуальная
приёмка фиксируются ниже. Полная приёмка A01–A36 и физические телефоны отдельно.

Общий SVG дополнительно проверяется существующим meaningful DM/group случаем
`cloud message UX: DM and group replies, reactions, draft return and cancelled reply`.
Первый повтор выявил устаревший маршрут теста: выбирались «Друзья», затем
искалась группа без перехода. В принятом A18 группы находятся только в «Чатах»;
это подтверждено его отдельным случаем. Open-helper теперь действительно нажимает
вкладку «Чаты» и исходную строку разговора. Все проверки ответов, реакций и черновиков
сохранены; прямой вызов окна группы и изменение runtime ради старой группировки
не применялись. Ранние неуспешные попытки не считаются зелёными.

## Финальный результат этой ревизии

После последней коррекции margin оба адресных случая прошли в **Chromium и WebKit**:

- `game overlays 0.21:` — по **1/1 PASS**, 15 PNG и 15 групп наблюдений в каждом
  движке, errors[] и native Supabase0. Подгрузка истории: сдвиг якоря **0 px**;
  настоящие ответы/реакции доставлены, команда blue приватна относительно room-канала.
- `cloud message UX:` — по **1/1 PASS**. Проверены прикреплённые реакции, ответы,
  профиль/группа поверх разговора, сохранение черновика и отмена ответа, успешная
  отправка без воскрешения старого черновика и отложенное завершение. Native Supabase0;
  WebKit provider intercepted42. Остальные проверки исходного случая сохранены.

Независимый дизайнер просмотрел Chromium chat390, WebKit chat844, WebKit team390,
Chromium team844, Chromium error и WebKit retried. Структурные замечания A21 закрыты;
новых P0/P1 в этих состояниях нет. Приняты короткая шапка, отсутствие outer tile,
реальные командные вкладки, читаемый reaction SVG, закреплённая капсула и понятный
Retry с черновиком. Клавиатурный индикатор resize сохранён в общей палитре.

Это bounded presentation/interaction acceptance. Она не означает проверки всех
ролей/тем, реальных экранных клавиатур, физических жестов или всей матрицы A01–A36.
Отдельная политика speech-bubble поверх поля при уже открытом drawer передана
ведущему для A32: её поведение в этом presentation-переносе не менялось.
