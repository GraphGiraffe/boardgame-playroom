# Откуда оставались задержки — preview.14, 2026-11-05

Проверены реальные путь сетевого подтверждения и публичный раунд с двумя
действиями, человек + 7 ботов. Исправления относятся к общим SDK/UI и хранилищу;
правила игры не менялись.

## Причины и изменения

1. **При обновлении строился весь набор HTML-кадров раунда.** Пак пытался
   кешировать его по `ui.renderOwner`, но этот внутренний host-параметр удалялся
   из контекста renderer. Кроме генерации разметки, повторялись сериализация и
   разбор полного DOM-банка. Вместо восстановления доступа пака к host-owner
   добавлен общий локальный порт `ui.publicFrames`: первый кадр нужен сразу,
   следующий готовится отдельной idle-задачей во время текущей анимации. Кеш
   принадлежит области viewer/пака/поверхности/скина. Хранятся максимум два
   разобранных шаблона, а весь раунд в DOM не передаётся.
2. **Готовность ботов вызывала чтение промежуточной истории.** После накопления
   решений контроллер восстанавливал каждую пропущенную revision, хотя публичный
   план и события не менялись. Это блокировало поток во время показа. Общая
   `planningUpdate` объединяет такие обновления внутри одного окна решений,
   включая смену координирующего игрока. История полностью сохраняется и доступна
   при явном просмотре. Новые публичные события, окна, эффекты и управляющие
   границы сохраняют обычный backfill. Для этих закрытых решений также не
   измеряется геометрия отсутствующего публичного движения.
3. **Чтение высот карточек чередовалось с их изменением.** Высоты всех игроков
   теперь читаются до первого patch, затем выполняются изменения DOM.
4. **Первое подтверждение заметную часть времени ждёт IndexedDB.** Отдельный
   замер без CPU-профайлера показал: правила ~12 мс, транзакция ~385 мс при CPU ×4.
   Запись sessions имеет размер около 17 КБ: это не копирование огромного пакета.
   Запросы и автоматическое завершение образовывали несколько асинхронных циклов.
   После постановки всех записей теперь вызывается поддерживаемый браузером
   `tx.commit()`. В таком же отдельном замере транзакция заняла ~315 мс.
   Ответ всё ещё отправляется только после COMPLETE, а не после put/начала
   коммита. Защита revision/transfer и атомарность состояния с квитанцией сохранены.

Контракт описан в [PRESENTATION-PLAYER.md](../PRESENTATION-PLAYER.md) и в SDK
коллекции. Отложенный callback получает уже авторизованные сцены, сохраняет
контекст ассетов и не вызывает правила, сеть, хранилище или измерение DOM.

## Контрольный прогон

Chromium 156, CPU ×4, seed 17, 384×782, DPR 2.8125, fast, звук включён.
По одному последовательному прогону preview.13 и финального preview.14.

| Метрика | .13 | .14 |
| --- | ---: | ---: |
| Первое нажатие → закрытый план в DOM | 689,3 мс | 579,3 мс |
| Максимальный интервал между публичными кадрами | 1527,2 мс | 694,7 мс |
| Суммарное время вызовов renderer в сценарии | 637,4 мс | 136,4 мс |
| Сумма long tasks | 21145 мс | 17207 мс |
| Сценарий целиком, включая анимации и звук | 29361 мс | 25383 мс |

Все 16 последующих кадров построены во время предыдущего, по 5–8 мс, без
повторной генерации при пассивном обновлении. Все 42 отслеженных конечных
эффекта завершились; отменённых promise и ошибок страницы — 0. Длинного
провала внутри публичного показа в финальном сценарии нет. Эти интервалы
включают заданное время показа фаз, не только вычисления.

**Ожидание после подтверждения не стало нулевым.** В финальном прогоне первая
транзакция заняла ~326 мс из ~579 мс до изменения DOM. Максимальный long task
~1285 мс относится к начальному показу игры. Второй контрольный маркер
Playwright (2102 → 1904 мс) включает polling/IPC; это не точное время от
нажатия до первого нарисованного кадра и не основание объявлять такую задержку
чистым временем вычисления. Старый отчёт preview.13 следует читать с этим
уточнением. Ни один из этих прогонов не заменяет проверку на телефоне и не даёт p95.

## Проверки и публикация

- Regression `public frame ports`: поэтапность, повторное использование и граница viewer.
- GameFlow/GameScreen: 51 проверка; после уточнения одновременной очереди —
  33 проверки GameScreen. Проверки durable authority/integrity — отдельный
  выбранный прогон 47 проверок до последнего уточнения координирующего turn.
- Браузер: все 15 паков, первое действие и повторная доставка ACK; история,
  приватность и сетевые поверхности — 6 сценариев.
- Эффекты Mage: движение/атаки/урон/смерть/падение; отдельный итоговый сценарий
  проверяет поэтапную подготовку, отсутствие повторных показов готовности и
  поворот окна. Снимки экрана отключены.
- IndexedDB: явный коммит, атомарные квитанции, восстановление после reload,
  повтор команды и публичность — 2 браузерных сценария.
