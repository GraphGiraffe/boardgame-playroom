# Решения для полной сборки интерфейса 0.21

## Зафиксировано владельцем

- Сохраняем палитру и стиль иконок старого интерфейса. Ревизия назначений/подписей иконок не означает новый графический стиль. Перед переносом используем реальные токены и ассеты приложения, а не заменяем их условными SVG макета.
- Каталог имеет один интерфейс с переключением вида как в файловом менеджере: строки с компактными артами, 2 столбца, 3 компактных столбца. Это настройка пользователя, не три конкурирующих дизайна.
- Основа по умолчанию — 2 столбца; вид запоминается на устройстве. Фильтры, избранное и сортировка при переключении сохраняются. Во всех режимах остаются название, арт и доступ к игре; мелкие подписи можно уплотнить, но зоны касания не уменьшать.
- Общие поверхности/сценарии и уточнения — DECISIONS-REVIEW-2.md и DECISIONS-REVIEW-3.md. Реакции рядом с сообщением; модальные панели и уведомления поверх экрана, без сдвига игры.

## Что осталось специфицировать перед переносом

1. **Полный маршрут и Back.** Точное дерево Игры / Мои партии / Общение / Профиль по выбранной навигации A. Что сохраняется при возврате, куда ведёт закрытие панели и возврат из партии. Системный Back закрывает верхнюю поверхность прежде перехода назад. Не нужны новые независимые варианты всех экранов — нужен один связный прототип.
2. **Иерархия содержимого карточек.** Какие поля обязательны в каталоге/сохранениях/разговорах и какие скрываются в компактном виде. Основа: название + арт + число игроков; жанр/описание вторичны. Детали игры — по нажатию; не дублировать все действия на каждой карточке.
3. **Набор действий внутри партии.** Единая зона по центру для действий конкретной игры, чат слева, меню справа. Собрать представители: домино, карточная рука, квадратное поле, командная игра, зритель/Стол. Не решать раскладку всех игр по одному макету домино.
4. **Панели, клавиатура и поворот.** Разрешённые высоты/раскрытие, прокрутка содержимого, закрытие снаружи/Escape/Back, несохранённый ввод, safe-area. Черновик чата и контекст партии сохраняются. Это спецификация общего компонента, а не отдельных браузерных исключений.
5. **События и состояния.** Матрица уведомление / inline-ошибка / подтверждение / фоновый индикатор; ожидание, потеря сети, отказ в разрешении, отсутствие прав. Не дублировать события открытого чата/партии системным Push. Независимые события не создают каскад модальных окон.

## Рекомендуемый следующий шаг

Собрать единый согласованный интерактивный прототип без A/B/C: каталог → выбор игры → лобби → приглашение → подключение → партия → чат → результат; затем профиль/настройки/данные. Уложить все выбранные механизмы в общие компоненты. Проверить с владельцем и друзьями без подсказок; после этого переносить в приложение по основным сценариям. Уже согласованные палитру, иконки и поверхности повторно не переоткрывать.

Пока выполнены только изменение макета и фиксация решений. Реальные продуктовые стили и ассеты не переносились.

## Последующие уточнения: обратная связь и чат партии

- Кнопки: мягкое сжатие при нажатии и короткий возврат при отпускании. Размеры раскладки не меняются. Hover не заменяет отклик на телефоне.
- Окна, панели и уведомления: небольшой однократный отскок при появлении, 200–260 мс; без повторного прыжка при каждом обновлении сообщения/содержимого. Reduced motion отключает движение.
- Вместо кнопки чата — область с шевроном и иконкой: снизу в портрете, справа в landscape. Тап открывает чат; вытягивание вверх/влево раскрывает его по направлению жеста. Жест начинается только в этой области, не на игровом поле и не у системного края.
- В открытом чате ручка меняет размер: вверх увеличивает историю в портрете, влево — ширину в landscape. Поле ввода остаётся внизу; история прокручивается внутри. Нажатие ручки — доступная альтернатива раскрытию. Размер сохраняется при отправке сообщения и повторном открытии.
- Меню партии больше не занимает нижнюю быструю строку. Портрет: сверху справа. Landscape: сверху слева, правый край отдан чату/элементам игрока. Последнее расположение — предложенная компоновка для проверки владельцем, не окончательно утверждённое предпочтение.
- Панели не двигают игровую сцену. Для launcher заранее зарезервировано место в каркасе; оно не появляется только в момент открытия чата.

Реализовано в автономном макете, не в приложении. Представители реальных игр и физические устройства остаются необходимой проверкой переноса.

Уточнение области чата: компактная иконка с шевроном без подписи. Портрет — снизу слева, landscape — снизу у правого края. При раскрытой панели launcher скрыт; закрытие возвращает его. Минимальная зона касания 44 px сохраняется.

Область чата прилегает к краю без скругления на этой стороне: портрет — плоский нижний край, landscape — плоский правый. Уменьшенный шеврон расположен справа от иконки в портрете и снизу в landscape; направление открытия остаётся вверх/влево.

## Единое поле ввода чатов

Однострочное поле — капсула с полукруглыми торцами. При переносе растёт вверх до ограничения, далее прокручивается внутри; углы остаются круглыми. Внутри снизу закреплены две круглые кнопки: слева прозрачные реакции, справа зелёная отправка. Набор реакций и арты берутся из прежнего приложения: Привет, Спасибо, Хороший ход, Думаю, Хе-хе, Ого, Жду, Вызов, Цензура. В макет встроены оригинальные WebP и существующий rich-composer: реакция при редактировании вставляется в сообщение, при пустом неактивном поле отправляется отдельно. Это не палитра реакций на конкретное сообщение — она остаётся у сообщения. Одинаковое поле используется в личном, групповом и игровом чате. Физическая клавиатура iOS требует отдельной приёмки.
