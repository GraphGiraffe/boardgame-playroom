На каждой странице лаборатории есть A/B/C, состояния, инструкция для проверки, рекомендация, источники и комментарий. Можно выбрать комбинацию в комментарии. ## Предлагаемая общая система

- Основные назначения: Игры / Мои партии / Общение / Профиль. Альтернатива: три назначения и профиль в шапке. Главный каталог сохраняется по композиции; меняются только неоднозначные точки входа.
- Короткие контекстные действия — нижняя панель; длинное чтение/формы — экран; подтверждение — единый механизм, по вашему выбору B нижняя панель последствий (диалог можно выбрать глобально). Одновременно одна модальная поверхность, без окон внутри окон.
- Общий чат-компонент: на телефоне панель с двумя высотами, на широком экране правая область, полный экран для длинного разговора. Размер выбирается по доступному месту, не по имени браузера.
- Подписанная строка с шевроном означает переход; switch меняет параметр на месте; глагол на основной кнопке выполняет действие; текущая вкладка видима. Иконки: единый stroke, словарь назначений, подписи для неочевидных действий.
- Сетка отступов 4/8/12/16/24; не складывать внешние поля и несколько внутренних контейнеров. Текст и кнопки переносятся; 44–48 CSS px зона касания. Ручного масштаба и ручной рассадки трёх соперников нет.
- Жесты дополняют видимые кнопки. Свайп сообщения — ответ; свайп строки — раскрытие безопасного действия; вкладки — только в отдельной области. Края ОС, скролл, выделение текста и игровые drag/pinch не перехватываются.
- Открытие/смена состояния 140–220 мс, transform/opacity; reduced-motion убирает движение. Нет циклических декоративных анимаций. Ожидание сети не маскируется анимацией успеха.

## Этапы после выбора

1. Свести JSON решений в decision log: выбранные варианты, гибриды, отклонённые варианты, причины. Проверить совместимость навигации, типов поверхностей и действий Back. Незакрытые вопросы не решать молча.
2. Создать общие UI-примитивы: AppShell, PageHeader, Screen, Sheet, ConfirmDialog, SegmentedTabs, ActionRow, SwitchRow, PersonRow, InlineStatus, Toast, Composer. Фокус, safe-area, keyboard и прокрутка принадлежат этим компонентам.
3. Перенести путь P0: каталог → способ игры → лобби → приглашение → подключение → готовность → партия. Сохранить права/ACK/состояние комнаты в application, не копировать их в UI.
4. Перенести общение: список, профиль участника, группы, единый чат, реакции, прочитанность, карточки приглашений. На открытие окна подавать готовый набор действий; после открытия изменять статус в зарезервированной области.
5. Перенести профиль/настройки/данные/паки/помощь. Редкие действия сгруппировать и не дублировать в меню партии. Не расширять сетевые возможности ради прототипа.
6. Унифицировать события: новая информация, локальный успех, ошибка поля, потеря связи, решение пользователя. Обновления с Push — только по отдельному указанию владельца. Ваш ход/старт/конец не отправлять Push при открытом экране партии.
7. Проверить пути без подсказок на людях, затем физические Android/iPhone. Считать завершение задачи, ошибочные нажатия, возвраты, просьбы о помощи и время; не выдавать предложенное число шагов за измеренное.

## Что лаборатория не доказывает

Макет не подключается к Supabase, WebRTC, push или реальным данным. Демонстрационная партия не реализует движки 15 игр; показан общий каркас на примере домино. Нужно отдельно проверить квадратные поля, карточные руки, командные проекции, зрителя и Стол. Симуляция клавиатуры не заменяет iOS Safari. Экспорт/импорт решения проверяется отдельно от продуктовых сохранений.

## Исследовательские заметки

Карточку Apple Maps переносим на чат как гипотезу сохранения контекста: карта и партия решают разные задачи. Spotify полезен для возврата к активному процессу, но не оправдывает плавающие элементы поверх руки. Telegram показывает обнаруживаемые вкладки и быстрые действия; жесты в нём конфликтуют между собой в разных режимах, поэтому в ХОД зоны жестов должны быть разнесены. Discord полезен карточками людей и сведениями группы, но его сложную серверную структуру не копируем. Chess.com и BGA дают сценарий приглашения конкретного человека за стол; в ХОД сохраняем единственную точку отправки в лобби. Signal помогает отделить обслуживание данных от ежедневного взаимодействия.
