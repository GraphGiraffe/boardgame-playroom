# Локальная диагностика партии · 04.11

В превью: меню партии → Настройки → Диагностика партии. Включить перед игрой; после появления задержек нажать «Скачать диагностику» и передать JSON. Кнопка доступна и вне партии через общие Настройки. Сбор не отправляет данные по сети.

Сохраняются:
- Первые64 записи и последние5000; число вытесненных записей указано отдельно. Замеры раз в2секунды, счётчики кадров — через requestAnimationFrame. Время самого sample также записано. По умолчанию выключено; выбор включения сохраняется локально, сам журнал живёт до перезагрузки страницы. Перед перезагрузкой нужно скачать файл.
- Длительность обработки действий, рендера, сохранений, интервалы между действиями. Ревизия, длина истории, создание/возобновление партии, паузы, экран/режим, размеры сохранения и число ожидающих транзакций.
- Фактическая длительность и requested duration/delay/iterations Web Animations, завершение и отмена; завершение/отмена presentation-плана, размер очереди и группа ожидания.
- Подготовка аудио, воспроизведение, длительность/результат аудиогрупп, принудительная остановка, состояние AudioContext, число голосов, групп и ожиданий.
- Запрошенная и фактическая задержка, опоздание и отмена таймеров презентации и локального authority; счётчики планов и таймеров. Обёртка clock сохраняет прежние wall-clock semantics authority и не меняет заданных задержек.
- Длинные задачи, Event Timing, Long Animation Frames и доступная атрибуция скриптов; разрывы кадров и задержка двухсекундного пробника.
- Доступная JS heap memory, общий объём JS heap/лимит, приблизительная deviceMemory, logicalProcessors, версия/UA/viewport. Число DOM-узлов, активных анимаций, отслеживаемых/отсоединённых geometry-регионов и групп панелей.
- Ошибки по типу без приватного текста, уход в фон, pagehide/pageshow, online/offline, resource timings без URL.

Полная CPU load %, RAM процесса/всего телефона, память GPU, события GC и отдельные обращения к адресам памяти недоступны обычному приложению браузера; отсутствующие значения указаны как null/limitations, не как ноль. Frame gaps/long tasks — признаки занятости main thread, а не проценты CPU. performance.memory может быть приближённым. Сам включённый сбор добавляет нагрузку; до/после нужно сравнивать с одинаково включённым сбором.

Источники API: [Long Animation Frames](https://developer.chrome.com/docs/web-platform/long-animation-frames), [поиск медленных взаимодействий](https://web.dev/articles/find-slow-interactions-in-the-field), [ограничения memory API](https://github.com/WICG/performance-memory/blob/master/explainer.md).

При выгрузке один раз создаётся portable-save текущей локальной партии: seed, опции, история, действия, игровые данные/имена, точная версия и digest пака. Закрытые игровые данные включены по прямому поручению владельца; reconnect-credentials, аккаунт, переписка и служебная идентичность комнаты удаляются штатным SaveTransfer. Пак не вкладывается. Во время игры полные снимки для диагностики не создаются. В сетевом экране устаревшая локальная партия не выдаётся за текущую: сохранение недоступно; это не сбор всей сетевой authority-истории.

Отключение останавливает rAF/interval, PerformanceObserver и listeners, восстанавливает Element.animate. Игровые анимации и таймеры не отменяются выключением диагностики. Первые/последние записи сохраняются для скачивания после выключения. Никакой постоянной записи больших логов на каждый ход нет.

Проверки:
- Recorder:1/1 — выключенный режим, ограничение буфера, отсутствие сериализации игры во время сбора, вырезание секретных полей телеметрии, async durations/error и остановка.
- Game-flow18/18, включая диагностические часы: planned/actual/cancelled задержки, отсутствие сохранённых timers после завершения, прежние последовательности/отмены.
- SaveTransfer1/1: полная история/точный dependency, удаление reconnect credentials.
- Готовый HTML в Chromium и WebKit: реальное включение через Настройки, нативный тап фишки/кубика Лудо, движение со звуком, запись источников задержек, реальное скачивание JSON, восстановление вложенной партии, проверка счётчиков и выключения. По1/1.
- На том же HTML боты Лудо после Settings/Appearance и явная Pause: по1/1 в Chromium и WebKit.
- Screenshot настроек просмотрен; физический телефон/Android download UI ещё не проверен.

Первоначальный сценарий не прошёл из-за неоднозначного селектора трёх кнопок закрытия меню; выбран явный заголовок. Затем обнаружено, что SaveTransfer возвращает envelope text/checksum: provider теперь встраивает разобранный portable-save, а не служебную оболочку. Неуспешные логи сохранены и green не считаются. Первый unit таймеров ожидал5 событий вместо фактических4; ожидание исправлено после проверки arm/fire/arm/cancel, runtime из-за этого не менялся.
