# A10: поиск комнаты перед вступлением

02.11.2026. Основа: выбранный вариант входа, связный прототип и GOAL.md.
Реализован самостоятельный экран: поиск → карточка → явное «Войти в комнату».

## Поведение

- Видимая подпись «Номер комнаты или ссылка», проверка четырёх цифр/ссылки до RPC.
  «Найти комнату» вызывает только `room-preview`; никакого fallback через Join.
  Выбор открытой комнаты также сначала показывает карточку. Старые UUID-ссылки
  используют тот же безопасный предпросмотр по roomId.
- Карточка показывает реальные название, игру, хоста и номер. Пароль запрашивается
  при необходимости; для скрытого приглашения можно передать его уже при поиске.
  Состав участников и свободные места не придумываются из демонстрационных данных.
- Неверный пароль возвращает к тому же экрану и вводу. Ошибки недоступности,
  неверного номера и отсутствующего серверного метода имеют понятные пояснения.
  Старый сервер не вызывает автоматического вступления вместо предпросмотра.
- Гость получает подписанный переход в аккаунт и вторичный «Рядом». Настоящий вход
  в аккаунт закрывает только верхний AccountUI, сохраняет исходный экран/ссылку
  и не присоединяет к комнате без отдельного действия.
- Открытая локальная/сетевая комната возвращается пользователю вместо тупика
  с отключённой кнопкой. Discover — вторичный раскрываемый список, не второй
  постоянно конкурирующий способ входа.
- Lookup, discovery и admission привязаны к своему frame, аккаунту и поколению.
  Поздний поиск не восстанавливает закрытый экран. Поздний неверный пароль
  не закрывает новое окно. Успех admission под временным дочерним окном не
  навигирует в комнату: исходный экран подключения получает безопасный повтор.
- Сохранены прежние прямые приглашения из чата и запрос дружбы. Общая тихая строка
  больше не зависит от наличия wrapper `.menu-list`; одинаковые переходы используют
  общий компонент, а не стандартные серые браузерные кнопки.

Серверный контракт, политика доступа, изолированные SQL-проверки и точный артефакт
обновления описаны в [ROOM-PREVIEW-CONTRACT.md](ROOM-PREVIEW-CONTRACT.md).
**Production backend не менялся**: до его отдельного обновления поиск нового
интерфейса показывает состояние недоступного метода. Это не опубликованная функция.

## Проверки

```sh
node scripts/codex/test.cjs case/cloud-room-entry-browser --name 'room entry 0.21'
env PLAYWRIGHT_BROWSERS_PATH=/tmp/playroom-webkit \
  LD_LIBRARY_PATH=/tmp/playroom-webkit/deps/usr/lib/x86_64-linux-gnu \
  LAB_ENGINE=webkit node --test --test-name-pattern='room entry 0.21' tests/cloud-room-entry-browser.test.cjs
node scripts/codex/test.cjs case/cloud-account-browser --name 'optional launch'
```

Итог: **1/1 Chromium + 1/1 WebKit + соседний account case 1/1 Chromium**.
Каждый entry report содержит 10 групп проверок, pageerrors[] и 0 native Supabase
requests. Авторизация проходит настоящие адаптеры через изолированный fetch fixture;
для точного управления порядком admission/lookup транспортные порты управляются
внутри браузерного сценария. Это не доказательство production signaling или ICE.

Проверены реальные действия: вход из guest с сохранением приглашения/DOM,
Find/UUID/discovered preview без membership, ошибка старого backend без Join,
неверный пароль, ошибка подключения и возврат с тем же вводом, отложенный поиск,
смена аккаунта, поздний неверный пароль после Back, paused admission под child,
прежняя заявка дружбы/приглашение из чата и возврат в уже активную комнату.
Портрет 390×844 и альбом 844×390 проверены на переполнение и сняты.
