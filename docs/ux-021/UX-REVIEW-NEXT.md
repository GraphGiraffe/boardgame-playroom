# UX: следующий этап переноса 0.21

01.11.2026. Независимая ревизия текущего runtime и выбранного connected prototype.
Это план реализации и критерии приёмки, не утверждение о завершённом переносе.
Область: профиль, аккаунт, настройки, общение, входы в лобби после снятия shortcuts.
Источники: `ASSEMBLY-DECISIONS.md`, `CONNECTED-PROTOTYPE.md`,
`tmp_files/ux-021/connected-prototype/prototype.js` в корне workspace.
Проверка: чтение реальных обработчиков и разметки; свежие `root-profile.png`,
`root-social.png`, `root-sessions.png` просмотрены после обновления runtime.
Физические устройства здесь не проверялись. Lifecycle аккаунта подтверждён
код-критиком: `case/optional-launch` PASS 1/1 (login/rename/logout/Back focus).

## Что закрыто в текущем узком этапе

- На трёх просмотренных guest root-экранах единый заголовок и четыре подписанных
  назначения; верхние старые shortcuts отсутствуют.
- Профиль получил одну строку личности с аватаром и явным входом в аккаунт.
- В авторизованном AccountUI появились подписанные строки имени/пароля/
  восстановления/выхода; это проверено в исходнике, не новым guest-скриншотом.
- Общение: guest-вход подписан; две вкладки имеют видимые текстовые названия.
- По отчёту код-критика профиль обновляет identity после входа/выхода/rename без
  root remount; Back возвращает focus. Родителем также перенесено сохранение
  вкладки и scroll Общения. Не считать это проверкой всех online-состояний.

Не закрыто: редактирование локального имени гостя из профиля, разделение общих
настроек и контекстных игровых команд, отдельные данные/уведомления, лобби и
структура активных/завершённых партий.

## Главный оставшийся разрыв

Четыре корневые вкладки уже появились, но часть вложенных поверхностей всё ещё
использует старую архитектуру. «Профиль → Настройки приложения» открывает общую
модалку с личностью, облачным аккаунтом, быстрыми действиями и параметрами игры.
Этот разрыв в аккаунте уже сокращён подписанными строками; дублирование identity,
аккаунта и быстрых действий внутри общих настроек остаётся. Главный следующий
видимый разрыв — «Мои партии»: основная задача активной/прошлой игры подменена
фильтрами типа подключения.

В выбранном прототипе профиль — спокойный индекс, настройки/данные/уведомления —
именованные назначения, а действия комнаты доступны в контексте комнаты.
Следующий перенос должен исправить владение функциями и ожидания перед нажатием,
а не ограничиться заменой шапки и CSS.

### Критерии приёмки P0

- Гость находит изменение имени и вход без открытия общих настроек.
- Авторизованный пользователь видит свой никнейм, имя аккаунта и email; изменение
  каждого понятного пользователю поля не зависит от расшифровки иконки.
- После входа/выхода/изменения имени и закрытия дочернего окна профиль сразу актуален,
  без обязательного переключения вкладок; позиция прокрутки сохраняется.
- Изменение пароля и восстановление различаются видимыми подписями и коротким
  объяснением внутри соответствующей формы. Успех/ошибка остаются рядом с действием.
- Email отображается как информация. Не обещаем смену email, которой нет в принятом scope.
- Выход имеет подтверждение с пояснением, что локальные партии остаются.
- В root-профиле нет глобальной справки по всем правилам: правила доступны у игры,
  в лобби и в партии, пояснения параметров — через локальный вопросительный знак.

## Карта доступности после снятия верхних shortcuts

| Функция | Основное место | Контекстный повтор допустим |
|---|---|---|
| Друзья, чаты, создание группы | Общение | Чат/карточка участника в лобби или партии |
| Вход, имя аккаунта, пароль | Строка личности / Аккаунт в профиле | Подписанный вход из Общения или онлайн-подключения |
| Игры, паки, обновления паков | Профиль → Игры и обновления | Понятное восстановление отсутствующего пака в сохранённой партии |
| Обновление приложения | Профиль → Обновление ХОД | Входящее уведомление только по отдельно разрешённому важному анонсу |
| Тема/скины | Профиль → Оформление | Быстрое переключение темы допустимо, если не скрывает настройки оформления |
| Громкость, анимации, быстрый ход, обучение | Профиль → Настройки | Меню партии → Настройки с сохранением текущего контекста |
| Сохранения, импорт/экспорт, облако | Мои партии + Профиль → Данные и облако | Конкретная партия → управление её сохранением |
| Полноэкранный режим | Профиль | Меню партии; подпись отражает включение/выход |
| Вид списка игр | Каталог, рядом с «В комнату» | Не нужен второй переключатель в настройках |
| Порядок и скрытые игры | Управление каталогом, доступное из профиля | Одно явное действие в каталоге; не возвращать старые счётчики ради него |
| Приглашение, передача хоста, исключение | Лобби и карточки участников | Из партии — через переход в лобби; не отдельный менеджер игроков |

Снятие shortcuts проверять по этой карте: функция либо доступна в выбранном месте,
либо явно записана как ещё не перенесённая. Скрытый legacy-контрол не считается доступностью.

## Общение (P1)

- **Guest CTA закрыт:** свежий root-social.png показывает текстовое «Войти или
  создать аккаунт». Возврат после входа к исходной задаче остаётся отдельной приёмкой.
- **Подписи закрыты на свежем root-social.png:** «Друзья» / «Чаты» видны.
  Геометрия обоих browser engines и ориентаций принадлежит UI-проверке.
- Группы сейчас входят в список друзей. Заголовок «Друзья» не должен неожиданно
  означать одновременно людей и групповые чаты: при следующем переносе списка
  группы должны находиться в «Чатах», а люди — в «Друзьях», с сохранением существующих
  действий создания/добавления. Если это расходится с выбранной деталью прототипа,
  решение сверить с владельцем до изменения информационной структуры.
- **В runtime перенесено запоминание вкладки/scroll** по сообщению родителя.
  Приёмка сценария с длинным живым списком и прочитанными счётчиками остаётся нужна;
  перезаход в корневой раздел не должен неожиданно сбрасывать текущую задачу.
- Ошибка обновления списка не заменяет сохранённые элементы пустым экраном;
  показывается короткое сообщение с подписанным повтором.

Приёмка: гость понимает причину входа; зарегистрированный пользователь находит
друга, личный и групповой разговор без расшифровки двух неизвестных пиктограмм;
системный Back закрывает верхнюю поверхность и возвращает к тому же списку.

## Лобби и меню партии (P1)

`lobby-view.js` всё ещё показывает значимую часть команд иконками: правила,
редактор правил, выбор игры, приглашение, готовность/старт. Одних aria-label/title
недостаточно для зрячего пользователя телефона. Переносить по roomBody прототипа:
игра + читаемый режим/код/хост, секция участников, подписанные правила/приглашение,
автостарт с объяснением условий, строка доступа/настроек, ясная готовность.

- «Правила» читает; «Настроить правила» редактирует. Это два разных назначения.
- Карточка участника открывает панель с подписанными действиями «Написать»,
  «Передать хоста», «Исключить». Состав определить до показа; не прыгать при загрузке.
- Передача хоста не блокирует игру; предложение, ответ, ошибка сообщаются сверху.
- При автостарте не показывать два равнозначных первичных старта. Готовность и
  условие старта понятны словами; причина невозможности видна, не только disabled.
- Меню партии — короткие строки «Лобби», «Правила», «Настройки», «Завершить партию».
  Старый глобальный `showSettings` с quickAccess не заменяет это меню.
- Управление комнатой сохраняет текущие transport/authority ограничения;
  UX-перенос не должен заново реализовывать передачу, синхронизацию или запуск.

Приёмка: новый пользователь без подсказки называет результат каждого видимого
основного действия, приглашает друга и становится готовым; гость/хост/зритель
не видят неподходящих команд без пояснения; overlay не сдвигает игровое поле.

## Мои партии (следующий P0, согласовано с дизайн-критиком)

Основное разбиение в прототипе — «Активные» / «История». Сейчас `savedGamesMarkup`
начинает с фильтров типов соединения и сложной карточки архива. Сначала разделить
по пользовательской задаче «продолжить» или «посмотреть сыгранное»; На устройстве /
Онлайн / Рядом оставить вторичным фильтром при необходимости. Пустое состояние:
один заголовок, короткий текст, «Выбрать игру». Импорт/экспорт доступны, но не
соперничают с продолжением партии. Бейдж содержит только активные доступные партии.

## Следующая узкая очередь после свежей ревизии

1. **Root: «Мои партии» → Активные / История.** Не менять модель сохранений и
   облачные операции. Перегруппировать уже известные записи по finished, выбрать
   активные по умолчанию, вторичные фильтры подключения убрать из первого уровня.
   Приёмка: при одной активной и одной завершённой записи каждая находится в своём
   разделе; продолжение и история имеют разные очевидные подписи; пустые оба
   раздела объясняются без технического «проверьте другой раздел»; импорт остаётся
   доступен через подписанное действие, удаление не активно в пустом списке.
2. **Дизайн-критик: сверка двух состояний sessions.** Убрать зрительный шум
   экспорт-иконка → фильтры → счётчик → trash → пустая карточка. Оставить заголовок,
   две вкладки и содержимое. Импорт/управление — одно спокойное вторичное действие.
   Не полировать геометрию старых фильтров перед их заменой.
3. **UI-критик: geometry/focus sessions после перестройки.** 390×844 и landscape,
   Chromium/WebKit; две вкладки с названиями, без лишней пустой полосы и переполнения.
   Стабильный scroll при смене статуса записи и открытии/возврате из карточки.
4. **Следом root: локальная личность и settings.** Дать гостю прямую подписанную
   форму никнейма/аватара из профиля, затем убрать identity/account/quickAccess из
   общих предпочтений. До удаления проверить карту доступности выше. Облачные
   формы не использовать как редактор локального гостя.

Это очередь реализации, а не общий редизайн заново; нет необходимости повторять
выбор вариантов или менять принятую палитру.

## Порядок работы и независимая проверка

1. Root-header и единый вход профиля закрыты для просмотренных guest-состояний;
   online-состояния проверять отдельно (root + дизайн-критик).
2. Перенести аккаунт и отделить общие preferences; проверить актуализацию личности
   после возврата (root + код-критик, lifecycle-замечание отправлено).
3. Подписать guest-вход и вкладки Общения; проверить Back/scroll/unread (UI-критик
   проверяет 390 px и WebKit, UX — сценарий и понятность).
4. Перенести лобби/меню партии, затем Активные/История без потери сохранений.
5. Сверить целые экраны в светлой/тёмной теме и обеих ориентациях с прототипом;
   завершёнными считать только сценарии с проверкой поведения и геометрии.

Документ не меняет согласованный визуальный стиль и не предлагает новый набор
вариантов A/B/C. Новые спорные решения передавать владельцу; повторяемые дефекты
понятности исправлять внутри уже выбранных механизмов.
