# A29: данные устройства и облака

02.11.2026. Реализация выбранной композиции `data1`; область проверки — локальная
сборка с настоящими прикладными сервисами и изолированным облачным провайдером.

## Реализовано

- «Устройство / Облако», сводка количества и состояния; поздний ответ закрытого
  экрана не меняет открытый позже. Экран владеет своим подключённым DOM-слоем.
- Измеренный состав данных приложения: приложение, игры/арты, сохранения.
  Линия показывает доли измеренного объёма, а не вымышленный процент свободного
  места телефона. Частичное измерение и ошибка отмечаются отдельно.
- Облачная квота 10 МБ использует существующий сервис. Список, ожидание, ошибка,
  последнее известное значение и загруженное пустое облако различаются; до ответа
  нет заявления об успешной синхронизации. Доступен повтор.
- Автоматическое сохранение использует общий переключатель с настройками.
  Его визуальный и анимационный контракт вынесен в `design-system.css`.
- «Перенос и обслуживание» первоначально свёрнут. Экспорт — выбор партии
  подписанной строкой; импорт по-прежнему сначала открывает предпросмотр.
  Локальное и облачное удаление разделены и подтверждаются; пустое удаление
  недоступно. Неисправные/несовместимые локальные записи доступны для экспорта.
- Раскрытые разделы сохраняются при обновлении сервиса, смене вкладки и возврате
  из экспорта. Получение облачной копии из данных оставляет исходный экран
  и выбранную вкладку; завершение старой операции не навигирует поверх нового окна.
- Операции после подтверждения, settings→scan, toggle→upload и удаление после
  refresh проверяют исходное поколение аккаунта. Смена аккаунта не переносит
  прежнее намерение в новый аккаунт. Доменный контракт и RPC не менялись.

## Проверки

Финальный Chromium:

```sh
node scripts/codex/test.cjs case/cloud-saves-browser
```

Финальный WebKit:

```sh
env PLAYWRIGHT_BROWSERS_PATH=/tmp/playroom-webkit \
  LD_LIBRARY_PATH=/tmp/playroom-webkit/deps/usr/lib/x86_64-linux-gnu \
  LAB_ENGINE=webkit node --test tests/cloud-saves-browser.test.cjs
```

Оба — **PASS 1/1**. Это существующий сквозной сценарий двух устройств: opt-in,
реальный архив без секретов комнаты, загрузка отдельной копии, офлайн/повтор,
конфликт, автоматическое сохранение при завершении/выходе, сохранение политик после
перезагрузки, раздельное локальное/облачное удаление. Добавлены сценарии позднего
измерения после Back и повторного открытия, сохранения DOM после экспорта,
свёрнутого обслуживания и недоступного пустого удаления, обе ориентации.
Запросы Supabase перехвачены до native fetch; проверено наличие обращений к fixture
и **0 внешних Supabase-запросов** в каждом из двух браузерных контекстов.

Старый тест ожидал всегда видимые кнопки сохранений и пять иконок обслуживания
в паке. Он перенесён на принятую навигацию: меню действий партии, отдельные данные
и раскрываемое обслуживание. Проверки операций и архивов сохранены. Промежуточные
падения на скрытых старых селекторах не объявляются успешными прогонами.

Дополнительно кодер расширил существующий unit-сценарий смены аккаунта во время
успешного refresh перед удалением: удаление не вызывается, привязки нового аккаунта
сохраняются; выбранные account-switch/delete/quota/delete-during-upload — 3/3.
