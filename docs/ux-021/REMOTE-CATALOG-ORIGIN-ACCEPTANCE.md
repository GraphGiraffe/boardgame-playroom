The offline reader owner reproduced a real WebKit file-HTML startup error: the application automatically called the origin-relative `/api/packs/catalog` endpoint from `file://`. This is a transport capability problem, not a WebKit-specific exception or a rules-reader defect.

Pack UI shows the reason beside its disabled refresh action, disables unavailable remote install/update controls and preserves installed games and local file import. No fake empty remote success is returned. The existing local-directory basePath validation, rejection of foreign absolute URLs, manifest URL checks, redirects and SHA checks are unchanged; no new transport configuration API was added.

The existing `remote catalog supports a project subpath without weakening manifest URL validation` unit was extended with a captured file-protocol context.
