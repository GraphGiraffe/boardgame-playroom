# Фоновые обновления: уведомление без перехода на экран

В свободном главном интерфейсе обнаружение новой версии больше не открывает полный экран автоматически. Используется существующий верхний app-notice с явным действием «Открыть»; пункт «Обновление» в Параметрах остаётся доступным. Фоновое событие не перерисовывает весь hub, не меняет фокус и не заменяет карточки. Когда экран обновлений уже открыт, его актуальные данные продолжают обновляться в том же owner/frame.

Согласованный контракт — GOAL.md, «Внешнее событие → неблокирующее верхнее уведомление → явное открытие». [web.dev: обновления PWA](https://web.dev/learn/pwa/update) разделяет проверку, подготовку и применение обновления. Уведомление с действием не выдаётся за пассивный noninteractive toast из [примера web.dev](https://web.dev/articles/building/a-toast-component): здесь это существующая интерактивная поверхность app-notice с семантикой status, без захвата фокуса.

## Поведение и общая реализация

- Общий `toast`/app-notice host получил необязательное действие; прежние сообщения сохраняют свой срок жизни. Уведомление с действием доступно до закрытия или перехода в другой контекст, чтобы его можно было открыть с клавиатуры. Оно не заменяет уже показанное сообщение об ошибке.
- Повтор обнаружения одного кандидата не пересоздаёт действие и не запускает вход заново. Закрытая версия остаётся тихой. Непрочитанность паков не сбрасывается просмотром баннера.
- Перед открытием через баннер возвращается допустимый исходный фокус; Back возвращает к нему, а не к уже удалённой кнопке. Ссылка на origin освобождается при закрытии уведомления.
- Шрифт общего app-notice переведён в rem с прежним базовым размером12px. Действие и закрытие нового баннера имеют область минимум44px. При увеличении текста и нехватке места действия переносятся ниже сообщения, а не сжимают его до нескольких букв.
- Ручная проверка, её busy/deadline/retry, явное важное уведомление и сохранение родительской поверхности остаются. Подписки Push и объявления не отправлялись.

## Идентификатор сборки

Превью с одинаковым номером приложения ранее разделяли `app@version`: новое содержимое могло не получить повторного уведомления. Service worker добавляет `cache:CACHE` к уже существующему `playroom-update-info`. Это публичная идентичность сборки с хешем содержимого, а не отдельный запрос/скачивание. UI использует её для dedup; для старого worker без поля остаётся fallback на version. Download/activation protocol1 и правила проверки файлов не менялись.
