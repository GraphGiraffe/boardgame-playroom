# Stable native scrollbar policy

The existing root-navigation browser case was extended to expose desktop Chromium's real classic scrollbar (Playwright's default `--hide-scrollbars` is omitted). At 1280×620, actual short Profile/Social content and long Games content changed the main width from **1196 to 1181 px**, exactly matching the **15 px** scrollbar. Opening/closing real Settings also changes root overflow ownership.

The shared fix uses `scrollbar-gutter: stable both-edges` on the root and thin visible scrollbars. Classic bars retain a symmetrical layout reserve through scrolling/non-scrolling pages and modal overflow locks; overlay platforms keep their native overlay behavior. Modal reading/list panes retain a visible thin affordance and symmetrical stable gutters instead of the former hidden scrollbar rule. The portrait fixed brand now aligns to the available content viewport rather than treating `100vw` as usable content width.

Twenty obsolete `.game-tile:last-child` selectors were removed from `app/styles.css`. Other selectors in combined lists remain. New catalog rows/densities own their layout; this removal does not add another last-card override.

Selected command: `node scripts/codex/test.cjs case/rc2-hub-browser --name 'root navigation selection'`.

- **Chromium1/1 PASS**: main left94/width1176 remains constant across Profile/Games/Social and real Settings open/Back; the actual thin classic bar consumes10px when visible. Existing eight viewport transitions and navigation/badge/44px/bounds checks remain.
- **WebKit1/1 PASS**: main left84/width1196 remains constant. This runtime reports zero consumed gutter even with GTK overlay scrolling disabled, so it proves the overlay path, not a classic-scrollbar WebKit environment or physical Safari.
- Both runs retain zero native Supabase requests and no page errors. The rail's edge assertion now uses the body's actual stable content edge instead of assuming the physical window coordinate0.

Desktop Profile capture was visually inspected. Evidence: workspace `tmp_files/ux-021/scroll-policy/` red/final logs, measured alignment JSON and removed-selector inventory; screenshots under `tmp_files/ux-021/navigation-021/`. The policy follows [CSS Overflow's gutter rules](https://www.w3.org/TR/css-overflow-3/#scrollbar-gutter-property) and [CSS Scrollbars](https://www.w3.org/TR/css-scrollbars-1/#scrollbar-width). No build, deployment or production operation was performed for this correction.

The final shared header integration uses `--surface-inline-inset:12px` for root/modal chrome and a separate `--game-field-inset:8px` (6px landscape). Existing game field padding values are preserved. UI owns the full-bleed game header and canonical modal surface token references; the shared modal header has zero additional inline padding, so its outer frame owns the inset exactly once. The document uses stable symmetrical gutters **uniformly**, including game/countdown/handoff scenes: switching from a root/lobby to the game must not change the absolute chrome axis. Overlay platforms reserve no gutter. Positions are measured against the actual body/client content viewport, rather than treating classic desktop gutters as artificial phone margins.

The affected root-navigation case was repeated after uniform-gutter/header integration: **Chromium1/1 and WebKit1/1 PASS**. Its actual Settings header is additionally measured12px from the modal content edge (excluding a real1px border on the adaptive desktop window). Modal Back controls use a common44px border-box and8px title gap; old per-surface inline padding/gap overrides were removed by the UI owner. Final logs are `*-uniform-final.log`, measured `*-uniform-alignment.json` and `uniform-source.sha256` in the evidence directory. Game/RTC geometry and all-pack header acceptance are owned by the separate UI integration track and are not claimed from this root-only case.
