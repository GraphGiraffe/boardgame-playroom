## Звуки и разрешённое воспроизведение

Это не отсутствующая функция: существующий app/ui-feedback.js уже содержит12 разных семантических cues и подключён к сообщениям/реакциям/приглашениям/дружбе/передаче хоста/соединению/обновлению. В app.js AudioContext разблокируется из pointerdown/keydown, а общий порт применяет master mute/volume. Нет отдельного автозапуска музыки или запроса права на звук при первом открытии. UIFeedback подавляет hidden/unfocused/quiet/gamebusy, запоминает ограниченные event IDs и не воспроизводит пропущенные muted события задним числом.

Существующая неизменившаяся проверка `semantic UI audio` уже включена в PASS3/3, зафиксированный FINAL-CODE-ACCEPTANCE.md; повторять её без изменения источников не требуется. Матрица событий и серверных Push — PUSH-AND-FEEDBACK.md. Реальное звучание на динамиках телефона и звук системного Push зависят от ОС и этим source review не подтверждены.

## Устаревшие части источников

Учебные главы разных лет содержат уже неверные платформенные ограничения: macOS Safari поддерживает Add to Dock, iOS сторонние браузеры могут предоставлять Add to Home Screen, а Web Push поддерживается Home Screen apps. Сопоставление уточнено по [WebKit16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/) и [WebKit26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/). Не копировать из старой главы утверждение «Push только Chromium» и не добавлять browser-specific layout offsets.

## Порядок завершения

1. Выявленные actual-flow дефекты закрыты: keyed Hub boundaries, retained Social deactivation, вложенные DM/group/Back/BFCache, RTCdrawer↔Group и group membership cache fences. Адресные доказательства сохранены; весь продукт этим не сертифицирован.
2. Зафиксировать независимые contrast/text-scale измерения и исправить подтверждённые проблемы общими текстовыми токенами/scroll contracts, сохранив палитру и игровые арты.
3. После freeze собран локальный app candidate с15исходнымипаками, все8SHA256SUMS корректны; состав в LOCAL-CANDIDATE.md. RoadMap остаётся work. Полный набор/Lighthouse/perf harness автоматически не запускались.
4. Отдельная физическая приёмка: iPhone Safari → Home Screen → запуск/вход → pack download → offline → notifications opt-in; Android native invitation → system install → launch; затем portrait/landscape/keyboard. Это ещё не выполнено.

Performance/Core Web Vitals, скринридер VoiceOver/TalkBack, все браузерные квоты и production installability не получили выдуманный PASS. Их измерение — отдельные адресные задачи, если требуется расширить приёмку; эта сверка не создаёт автоматическую необходимость переписать приложение на Workbox или framework.

Контраст проверяется по [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): для обычного мелкого текста порог4.5:1; правило3:1 для крупного текста не применяется к metadata11/12px. Измеряются computed цвета, а не сглаженные пиксели скриншота.
