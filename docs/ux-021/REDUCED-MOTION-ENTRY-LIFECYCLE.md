# Повторный вход экрана при выключении «Меньше движения»

Локальный фикс заморожен. Сборка/публикация этим агентом не выполнялась.

## Причина и RED

В `mobile-surfaces.css` анимация входа назначалась всем существующим модальным поверхностям через постоянное условие `body:not(.reduced-motion)`. При удалении класса или переключении системного режима старое окно заново получало `ui-screen-in`, несмотря на сохранённые DOM и данные.

Существующий motion case воспроизвёл это без app rerender: тот же frame/editor, та же ширина824px, но x менялся с10 на34px; `ui-screen-in` был running. Chromium: ожидаемые0 анимаций против фактической1, exit1. Видео владельца совместимо с этим эффектом; переход вкладки Доступность→Звук рассматривает parent отдельно в app/settings.

## Общее решение

ModalController выдаёт новому frame одноразовую метку `data-ui-motion="enter"` только при разрешённом движении и видимом документе. CSS входа требует эту метку. Окно, открытое при reduced motion, её не получает, поэтому последующее включение движения не создаёт вход заново.

После подключения DOM контроллер наблюдает собственные CSS-анимации модального корня, исключая дочерние. Метка расходуется при native finish/cancel, системном reduce, body reduced-motion или скрытии документа. Слушатели и короткий observer класса body существуют только во время входа; bounded fallback очищает lifecycle при отсутствующем native completion. Отдельного глобального хранилища не добавлено.

В качестве motion context используется owning document хоста: до подключения узел находится в инертном template.content, чей ownerDocument не имеет defaultView. Это позволяет подготовить состояние до первого показа и сохранить настоящий вход новых окон.

При закрытии сначала сохраняется текущая визуальная поза в существующий exit helper, затем освобождается entry lifecycle. Поэтому Back во время входа не перескакивает к исходной позиции, а старый callback не удаляет exit-состояние или заменившее окно. Reset/invalidate продолжают синхронно освобождать владельца и приватный DOM.

## Проверено

Один существующий case `nearby choice 0.21: shared panels retain the source and reject stale options`, предварительно выбранный через `--list`:

- Chromium1/1 и WebKit1/1, оба exit0, errors=[].
- Старый экран после reduced→normal: x10→10, нет entry-анимаций, native frame/editor сохранены.
- Прерывание нового входа настройкой приложения и системным reduce; последующий normal не повторяет вход. Поле ввода, значение, фокус и выделение остаются теми же.
- Новые normal surfaces всё ещё анимируются; начальный reduced не анимируется. После завершения входа метка расходуется.
- Сохранены прежние проверки Back во время входа, полноценного выхода, reopen во время закрытия, двух быстрых Back, stale controls, жестов/scroll и desktop/touch × normal/reduced.

В root/settings test и app handlers изменений нет. Физический повтор на устройстве и actual settings integration этот компонентный сценарий не подменяет. Неигровые nonmodal banner/drawer/popover producers находятся вне выданного lease; их существующие preference-gated entry selectors этим изменением не переработаны.
