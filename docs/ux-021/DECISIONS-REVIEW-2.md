# ХОД 0.21 · согласование решений, редакция 2

Источник: `tmp_files/ux-021/design-lab/owner-decisions-2026-11-01.json` — неизменённый экспорт владельца. Все 36 выборов и комментарии импортированы в лабораторию. Предыдущий HTML сохранён как `design-lab-v1.html`. Новый: `design-lab-v2.html` (также `design-lab.html`). Это макеты, не обновление приложения.

## Что выбирается один раз

| Решение | Текущая основа | На что влияет |
|---|---|---|
| Короткие действия и подтверждения | Нижние панели, включая панель последствий B | Карточка игры, фильтры, участник, бот, настройки комнаты, меню партии, профиль собеседника, подтверждения |
| Адаптация чата и меню | В портрете снизу, при ширине от 600 CSS px справа | Общий механизм чата поверх партии и меню партии; не определяется именем браузера |
| Быстрые действия списков | Карточка следует за пальцем; действия под ней; ⋯ доступно всегда | Сохранения и разговоры; необратимое действие не выполняется длинным свайпом |

В HTML можно сравнить две альтернативы первого правила: контекстные панели с отдельным центральным подтверждением; короткие действия на отдельных экранах с центральным подтверждением. Второе и третье правила также переключаются глобально. Эти значения сохраняются и экспортируются в поле `system`. Старые локальные варианты остаются в JSON как история выбора содержания; `inherited` указывает области, где тип поверхности теперь наследуется, а A/B/C не предлагаются повторно.

## Обязательная матрица поверхностей

| Задача | Поверхность / обратный путь | Примеры |
|---|---|---|
| Самостоятельный раздел, длинное чтение или форма | Полный экран, Back возвращает контекст | Разговор, профиль, регистрация, настройки, данные, правила, результаты |
| Короткий выбор в текущем контексте | Общая контекстная поверхность | Участник, бот, фильтр, короткие параметры комнаты, редактирование имени |
| Разговор без ухода из партии | Одна адаптивная панель; закрытие возвращает стол | Чат комнаты, меню партии; полный разговор — отдельный экран |
| Последствия опасного действия | Общий тип подтверждения; явные глаголы и отмена | Удаление, выход, закрытие комнаты |
| Ошибка поля или загрузки | Рядом с соответствующим действием; повтор/альтернатива | Сеть, вход, загрузка списка; не отдельное модальное окно |
| Новое внешнее событие | Верхнее уведомление | Сообщение, приглашение, решение о передаче хоста |
| Обратимое локальное действие | Нижнее Undo, без подтверждения заранее | Архивирование разговора/партии |
| Настройка на месте | Switch; не открывает окно | Звук, автозапуск, уведомления |
| Смена подраздела | Вкладка; не новый экран и не окно | Правила, данные, адресаты приглашения |

Контекстный профиль собеседника и собственный полный профиль имеют разные задачи; это обоснованное различие, а не случайная разница компоновок. Системное меню «Поделиться» принадлежит ОС и в HTML только имитируется. Одновременно одна модальная поверхность. Ошибка/успех не создают ещё один уровень окон.

## Найденные противоречия

- A/B/C раньше смешивали выбор содержания и контейнера: полный профиль и короткая карточка, результат на экране/панели, четыре разных варианта контекстных действий. Теперь длинные разделы остаются экранами, короткие действия наследуют правило. Профиль B и разговор C переработаны как компактные экраны.
- Выбор чата A + C в landscape и меню A + C решает одну задачу адаптации. Объединён, независимо переключать их больше не нужно.
- Подтверждение B конфликтовало с прежним текстом плана «всегда dialog». Основа плана исправлена на выбранную панель последствий, центральный диалог — только общая альтернатива.
- Свайпы сохранений и разговоров раньше были разными имитациями. Используется один revealCard; список не прыгает сразу в конечное состояние, кнопки находятся под карточкой.
- Макеты уведомлений смешивали внешний сигнал, ошибку и Undo. Их назначение зафиксировано отдельно от локальных вариантов экрана.

## Применение комментариев владельца

| Область | Изменение / повторная оценка |
|---|---|
| Сохранения, жесты | Иконка ⋯ без подписи «Действия»; реальное движение карточки; явные быстрые действия, архив/Undo. Основание: [Pocket Casts](https://support.pocketcasts.com/knowledge-base/playlists/) |
| Приглашения | A + поиск B + «Поделиться» C во вкладке ссылки; выбор адресатов и фильтрация работают |
| Чат и меню | Одна адаптация нижняя/правая панель; полный разговор отдельно |
| Переписка | Собеседник в шапке; поиск из меню профиля, убрана постоянно занимающая место служебная шапка |
| Сообщения | Работают реакции, ответ с цитатой, повтор отправки; видимые различия ⋯ / удержание / свайп |
| Приглашение истекло | Компактная приглушённая строка без входа |
| Профиль | Изменение имени/аватара, сохранение и переходы; B теперь компактный экран |
| Помощь | Четыре разных шага, полные раскрываемые правила, отдельные варианты контекстной подсказки и обучения |
| Обновление | Загрузка → готово → применение → демонстрационный перезапуск с каталогом; отмена и повтор |
| Состояния | Ошибки и ожидание в контексте; повтор возвращает содержимое |

Непонятные в первой редакции области не считаются окончательно утверждёнными: conversation, message, profile, help, update, gestures, states. В HTML они отмечены для повторного просмотра.

## Порядок переноса после просмотра

1. Согласовать глобальные правила и повторно оценить переработанные области; сохранить новый JSON.
2. Зафиксировать таблицу компонентов/поверхностей и исключений; не принимать каждую схему независимо заново.
3. Реализовать общие Screen/ContextSurface/Confirmation/Toast/InlineStatus/SwipeRow, safe-area, фокус, клавиатуру, прокрутку, reduced-motion.
4. Перенести путь каталог → лобби → приглашение → подключение → партия; затем общение и обслуживание.
5. Проверить возвраты, состояния ошибок, права без скачков кнопок, Android/iPhone и задачи с друзьями без подсказок.

До нового выбора продуктовая переработка не продолжается; текущие продуктовые изменения предыдущего этапа не затрагиваются. Браузерные результаты редакции 2 — в VALIDATION.md рядом с исходниками лаборатории; физический iPhone и игровые/сетевые сервисы этими макетами не проверяются.
