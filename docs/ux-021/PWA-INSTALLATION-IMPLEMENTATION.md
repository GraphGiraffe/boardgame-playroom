# Установка ХОД: iPhone, Android и desktop

02.11.2026. Дополнение к цели0.21 по прямому указанию владельца.

## Основания и принятое решение

[web.dev Installation](https://web.dev/learn/pwa/installation) различает browser invitation и ручное добавление на домашний экран iPhone; рекомендует apple-touch-icon и предупреждает об изоляции данных установленных iOS-копий. [Installation prompt](https://web.dev/learn/pwa/installation-prompt) описывает однократное использование сохранённого события и ручную инструкцию, когда такого события нет. [Patterns for promoting installation](https://web.dev/articles/promote-install) рекомендует не прерывать основной сценарий, ждать интереса пользователя и запоминать отказ.

Часть платформенных подробностей старых web.dev страниц устарела. Проверка по [WebKit Safari26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/) подтверждает современный переключатель Open as Web App и установку через Home Screen; [WebKit16.4](https://webkit.org/blog/13966/webkit-features-in-safari-16-4/) допускает Add to Home Screen и в сторонних iOS-браузерах. Поэтому инструкция не утверждает, что установить можно исключительно из Safari: Safari предлагается как понятный запасной путь, если нужного пункта нет. macOS Safari получает отдельную инструкцию Add to Dock.

## Реализация

- `hub-action.js` — единый presenter установки: постоянная подписанная строка профиля, компактное скрываемое предложение под hero и общая owned panel. Старый icon-only install/update в заголовке удалён; обновления имеют собственную строку профиля с текстовым статусом.
- В разделе «Уведомления» iPhone/iPad без доступного Push получает подписанный пункт «Установить ХОД для уведомлений». Он открывает ту же инструкцию поверх настроек, не запрашивает разрешение и при возврате сохраняет исходное окно.
- Предложение не появляется при первом знакомстве. Локальный признак интереса ставится после открытия игры или другого корневого раздела; показ — при следующем безопасном обновлении Hub. Во время модального окна hint не меняет геометрию фона. Отказ сохраняется локально; постоянный пункт остаётся доступным.
- `pwa.js installState()` различает native invitation, iOS instruction, generic menu guidance, insecure и наблюдённую installation/standalone. UA выбирает только текст инструкции; право native prompt определяется настоящим событием. `canInstall()` не начинает ложно возвращать true на iOS.
- `prompt()` вызывается только явным нажатием, один раз на исходное событие. Dismissed не становится успехом, accepted не объявляется завершённой установкой. Поздний userChoice после закрытия не открывает панель и не меняет другой экран. appinstalled и standalone учитываются отдельно; проверить все ранее установленные копии из обычной вкладки невозможно.
- iPhone: меню браузера → Поделиться → На экран Домой → при наличии оставить «Открывать как веб-приложение» → Добавить. Нет фиктивной системной кнопки установки. Новый запуск может требовать повторного входа; локальные партии предлагается переносить через Данные и облако. Офлайн-работа обещается после загрузки игр в установленной копии.
- Копируемая ссылка строится из каталога приложения, без userinfo, query/hash и токенов комнаты/аккаунта. Ошибка clipboard оставляет выделяемое поле. Добавлена существующая PNG как apple-touch-icon. При расширенной сверке web.dev удалены старые proprietary capability/title meta: конфигурация окна и имени имеет один источник в manifest. Manifest сохраняет стабильный id /playroom, start_url/scope и standalone.

## Проверки и границы

Существующий `case/pwa-install-handoff`:4/4, сохранены проверки password-gate handoff и однократности; добавлены iPhone/iPadOS/Mac/native/observed-installed/insecure состояния.

Существующий `case/rc2-hub-browser --name 'PWA installation 0.21:'`: Chromium1/1 и WebKit1/1. Последний runtime-проход уточняет рекомендации по интересу/отказу; результаты фиксируются рядом с PNG. Проверяются явные входы, manual iOS без beforeinstallprompt, чистая ссылка (включая искусственный username/password локального URL) и реальная clipboard port, own-frame в двух ориентациях, непустой набор измеренных кнопок>=44px, dismissal/reload, native invitation fixture ровно один раз, canceled/accepted-late/appinstalled и отсутствие позднего перехода. Также проверен контекст «Уведомления» → инструкция Home Screen → возврат в точное исходное окно, без запроса разрешения. Safe fetch до goto, native Supabase0, pageerrors[].

Артефакты: workspace tmp_files/ux-021/installation-021/. Свежие Chrome/WebKit PNG и отчёты отделены от самостоятельного визуального review. Нативное invitation в browser case — явно управляемый fixture порта, а не доказательство открытия системного Android install dialog. WebKit с iPhone UA проверяет движок и наш интерфейс; системный iOS Share Sheet, значок Home Screen, новое хранилище и запуск на физическом iPhone требуют отдельной проверки на устройстве. Production, реальная рассылка и установка на телефоне не выполнялись.
