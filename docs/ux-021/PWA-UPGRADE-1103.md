# Переход между точными PWA-сборками при одинаковой версии

Проверены настоящие собранные каталоги предыдущего `text-scale-followup-verified/final/pwa` и текущего `update-notification-followup/final/pwa`. Файлы не изменялись, не добавлялись synthetic CSS build markers и не подменялся worker. Один loopback HTTP origin сначала отдавал старую сборку, затем новую; браузер использовал настоящие ServiceWorker/CacheStorage и штатные команды подготовки/установки.

Обе сборки имеют version`0.21.0-preview.1`. Исходный cache`0a7c55452f871205`, новый`36be9605c0aa4734`; новая таблица стилей подтверждена по точному имени из готового index. Контрольная партия «Крестики-нолики» с одним ходом записана через `saveLibrary.activateAsync`, затем открывалась обычным library API. Профиль создан один раз: init-script не восстанавливает его повторно при reload и не маскирует потерю данных.

## Выборка и результат

В существующий tests/pwa.test.cjs добавлен case `same-version built PWA upgrade retries an interrupted changed asset and preserves a real saved game`. HTTP fixture вынесен в общий serveBuiltPreviewUpgrade и используется также прежним legacy-case, без копирования его серверной реализации. Старые legacy0.20 assertions сохранены; они не выполнялись в этой выборке.

Команда из каталога playroom:

```sh
PATH=/home/ivan/.nvm/versions/node/v22.14.0/bin:$PATH \
PLAYROOM_OLD_PWA=../tmp_files/ux-021/text-scale-followup-verified/final/pwa \
PLAYROOM_NEW_PWA=../tmp_files/ux-021/update-notification-followup/final/pwa \
PLAYROOM_CAPTURE_DIR=../tmp_files/ux-021/same-version-upgrade \
node --test --test-name-pattern='^same-version built PWA upgrade' tests/pwa.test.cjs
```

**1/1PASS, exit0**, Chromium, около6.5s. Подготовка теста исправлена до успешного результата: новое сохранение создаётся через activateAsync (writeAsync обновляет существующее), удерживается реальное хешированное имя изменённого app asset, а не отсутствующий app/app.js. Это ошибки подготовки fixture, не объявленные дефектами продукта.

Проверено:

1. Новый waiting worker обнаружен, metadata содержит настоящий cache ID, а availability ещё не скачивает app payload.
2. HTTP-ответ изменённого JS прерван после16байт. Подготовка переходит в paused; старый документ и его стили остаются активными.
3. Повторное нажатие завершает загрузку. Повторно по сети не запрошен ни один неизменённый installed-packs файл. Использовано220сохранённых файлов/5678362байта; скачано282149байт из5960511байт payload. Это измерение выбранной пары сборок, не обещание одинакового объёма любого будущего обновления.
4. Готовность не активирует обновление сама. Явная установка вызывает ровно один domcontentloaded, загружается точная новая таблица стилей; старый cache удалён, новый остаётся, старый updates-modal исчезает.
5. Экспорт реальной партии и профиль совпадают до/после; сравнивается также сырой snapshot сохранённого ключа настроек и дополнительный marker. Все пользовательские варианты настроек отдельной выборкой не проверялись.
6. После отключения сети новый документ снова загружается, присутствуют все15игр и открывается сохранённая партия. Ошибок pageerror/native Supabase запросов нет.

Это переход уже открытой PWA в Chromium через локальный HTTP, а не только fresh startup. Он не заменяет физический Home Screen, конкретные мобильные ограничения, внешние сети, AT, Push доставку и самостоятельную usability. Старый исполняемый код может показывать прежний automatic update UI; новое поведение баннера проверено отдельным source/artifact-прогоном и начинает действовать после установки новой сборки. Общая цель0.21 остаётся открытой.
