# Отзывчивость движка и SDK — 2026-11-05

Кандидат: приложение `0.21.0-preview.13`, engineApi 4 / viewApi 3 / protocol 3.
Изменения относятся к общему runtime; специфические обходы по ID игр не добавлены.
Контракт автора обновлён в `playroom-paks/docs/COMPONENT-SDK.md`, порядок обработки
действий — в [PRESENTATION-PLAYER.md](../PRESENTATION-PLAYER.md).

## Что исправлено

| Участок | Причина повторной работы | Новый порядок |
| --- | --- | --- |
| ModelRegistration | Позиция копировалась даже для отсутствующей опциональной механики | Нейтральный результат до создания позиции/проекции |
| GameModel | Одна неизменяемая позиция повторно копировалась и проверялась для разных запросов | Проверенная позиция запоминается приватным WeakSet конкретного model; внешние значения проверяются |
| Engine.applyAction | Копировались старые domain data, которые portable reducer затем заменял целиком | Старые data передаются portable adapter как исходное значение; defensive copy legacy-пути сохранена |
| Authority → transport → client | Одна уже авторизованная проекция сериализовалась повторно | Protocol.immutable отделяет внешние данные один раз и переиспользует свои глубоко замороженные значения |
| GameScreenController | Повторное уведомление об ACK повторно ставило тот же кадр в очередь | Дедупликация по идентичности immutable snapshot; новые control/reaction snapshots принимаются |
| SharedViews | Вход в pending и выход из него перестраивали сцену | Дешёвые метаданные блокировки; settlement той же сцены без повторного render |
| NetworkPresence | Полный снимок комнаты создавался для каждой карточки игрока | Один roster на render всех карточек |
| PublicSequence | Внешняя оболочка могла патчить потомков активного публичного кадра | Runtime владеет детьми public-display через DOM.manageChildren |
| PlanPlayer | Повторная установка той же скорости паузила/возобновляла эффекты и таймер | Неизменившаяся скорость — no-op |

Live команды могут быть подготовлены в актуальной сцене до завершения показа;
вызов команды по-прежнему проходит проверки pending/pause/history/прав/очереди.
Независимые реакции используют свои текущие права. Старая сцена не получает
новые команды. Действия authority и durable commit не зависят от проигрывания.

## Область аудита копий и проверок

Статический проход охватил 169 JS-модулей runtime приложения в core/application/
presentation/app/platform и 113 JS-модулей установленных паков (без assets,
vendor и generated runtime). Найдены 71 модуля с clone/snapshot/JSON-copy sites;
инвентарь сохранён в `tmp_files/perf-steps-1105/copy-inventory.json` рабочего корня.
По результатам разбора горячего пути изменены общие границы выше. Поиск сам по
себе не доказывает ненужность копии и не является построчным доказательством
оптимальности всех модулей.

Сохранены обоснованные границы:

- Schema/authorization/legal-command/revision/epoch/audience проверки на входе,
  защита от повтора commandId и порядок durable commit.
- Копии импорта, восстановления, экспорта/сериализации, сетевых сообщений и
  пользовательской конфигурации: вызывающий не может менять сохранённое значение.
- Изменяемые рабочие копии в чистых редукторах паков: предыдущее состояние и
  история должны оставаться неизменными.
- Промежуточные авторизованные сцены движения/добора/сбора: последующие кадры
  не должны переписывать уже показанный checkpoint.
- Проверки сборки, целостности паков и совместимости API; они не входят в
  обработку каждого нажатия. Операционные утилиты не оптимизировались под FPS.

Это целевой аудит runtime и путей взаимодействия; не заявление, что любая копия
во всех инструментах проекта удалена или что остаточных задержек больше нет.

## Измерение

Последовательное сравнение опубликованного preview.12 и кандидата с общими
исправлениями: Chromium, 384×782, DPR 2.8125, CPU throttling ×4, seed 17,
сетевая комната, человек + 7 ботов, два действия, fast, звук включён.
Времена отсчитываются от capture-обработчика настоящего click до наблюдаемого
изменения DOM, без ожидания actionability Playwright перед самим нажатием.

| Метрика | До | После | Снижение |
| --- | ---: | ---: | ---: |
| Первое подтверждение → закрытый план в DOM | 947,2 мс | 699,9 мс | 26,1% |
| Второе подтверждение → начало публичного показа | 3890,2 мс | 2173,3 мс | 44,1% |
| Максимальный long task сценария | 1924 мс | 1256 мс | 34,7% |
| Сумма long tasks | 24968 мс | 21214 мс | 15,0% |
| Полный сценарий, включая анимации/звук | 32255 мс | 29338 мс | 9,0% |

Оба прогона: 42 конечных эффекта завершились, отменённых promise — 0,
ошибок страницы — 0. Поэтому исходное впечатление «обрыва» не приравнивается
к доказанной отмене анимации. Регрессия отдельно проверяет, что пассивный patch
оболочки сохраняет живые элементы эффекта. Задержки основного потока ещё есть;
это один контролируемый прогон на компьютере, не p95 и не измерение телефона.
Метаданные версии и ветка optional undefined reply изменены после профиля;
измерявшийся путь действий от этого не менялся.

## Проверка и артефакты

В `tmp_files/perf-steps-1105` сохранены исходные профили CPU, таймлайн кадров,
comparison.json, логи и матрица all-packs.json. Контрольные проверки:

- Core/model/session/game-flow/game-screen: 118 сценариев.
- Авторизация, WebRTC, MessagePort, presence и UNO reactions: 70 сценариев.
- Pack models и game feedback: 38 сценариев.
- Общая SDK-матрица финального HTML: все 15 игр, максимальное число игроков,
  первое разрешённое действие, revision/history, неизменность прежнего состояния;
  три повторных ACK дают 0 дополнительных render в каждой игре.
- Отдельные браузерные сценарии: история/права поверхностей и Mage эффекты,
  повторная привязка, поворот окна с возвратом.

Матрица не подменяет полный игровой прогон каждого пака, работу через реальные
пары телефонов, потери сети или замер каждого жеста. Новые снимки галереи не
собирались: визуальные правила не менялись. Финальный HTML/PWA и публичные SHA
проверяются отдельно; результат публикации — `publication.json` рядом с логами.
