# A35 — уведомление о старых данных на общей поверхности

02.11.2026. UpgradeUI использует общий ModalController и owned screen вместо отдельного native dialog. Подтверждение остаётся явным; Escape не принимает решение за пользователя. Архивы не удаляются.

Экспорт читает настоящие архивы через действующий сервис, сохраняет их содержимое и удаляет секреты из выгрузки. Ошибка чтения остаётся в своём экране с повтором. После подтверждения возвращаются тот же родительский DOM, draft, focus и selection. Если экран уже заменён, позднее чтение не запускает download и не меняет другой экран.

Существующий case/data-storage-browser, сценарий `upgrade notice 0.21 keeps archives and uses the shared owned surface`: Chromium 1/1, WebKit 1/1. В обеих ориентациях создана настоящая legacy-запись через PlayroomData.put, скачан и разобран JSON, проверены сохранность исходного архива, redaction access_token/password, ошибка/повтор, подтверждение и отменённое право позднего экспорта. Один download на движок, console errors отсутствуют. Workspace-артефакты: tmp_files/ux-021/upgrade-notice-021/.

Это проверка общего слоя и сохранности данных в локальном browser fixture, не production-миграция всех пользовательских архивов.

Независимая UX-сверка убрала техническую формулировку про API: canonical ui-upgrade.json теперь объясняет обновлённый формат, сохранность данных и возможность backup, основное действие — «Продолжить». Это изменение текста, не миграционного контракта; core/messages.js регенерирован штатным генератором.

Общий стандарт `.modal-foot` теперь растягивает элементы по поперечной оси: две кнопки в одной строке имеют одинаковую высоту и при переносе длинной подписи. Последняя адресная проверка upgrade gate по1/1 Chrome/WebKit измеряет обе кнопки >=44px, расхождение высоты <1px, и сохраняет прежние export/redaction/late-operation проверки. Новые PNG содержат человеческий текст.
