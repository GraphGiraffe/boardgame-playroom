# UI-ревизия A13 / A15 / A21: общий стек меню и игровой чат

2 ноября 2026 года. Независимый UI/frontend-проход настоящего приложения.
Результат ограничен перечисленными ниже сценариями. Это не приёмка всех A01–A36,
всех ролей, физических телефонов или опубликованной версии.

## Найденные и исправленные проблемы

1. **A15: Tab застревал на «Остановить партию».** Прежний обработчик перебирал
   все кнопки, включая потомков закрытого «Дополнительно», и исключал `summary`.
   На настоящем Chromium после четырёх действий фокус восемь раз оставался
   на остановке. Теперь используется нативный порядок внутри доступного меню;
   обработчик только замыкает его границы. Учитываются `summary`, disabled,
   hidden/inert и закрытые родительские `details`; проверен обратный Shift+Tab.
2. **A21: общий токен кнопок шапки изменял edge launcher чата.** Поздний
   `game-frame-header .icon-btn` переопределял ширину и скругления. Launcher исключён
   из этого токена; исправлен исходный портретный height/min-height 40→44 px.
   Новый слой CSS-переопределений не добавлен. Реальные размеры: 68×44 px
   в портрете и прежние 44×64 px в альбомной ориентации. Внешний край плоский.
3. **A15: меню имело отдельный body-layer и ручной `app.inert`.** Оно перенесено
   на общий `ModalController` в `#modal-root`, с собственным frame, `meta.dismiss`,
   проверкой текущей сцены/сессии/комнаты/роли и очисткой при утилизации. Общий
   registry владеет блокировкой фона, сохранением контекста и возвратом фокуса.
   Особая компоновка меню снизу / справа сохранена в его scoped CSS.
4. **Старый shortcut dispatcher сбрасывал родителя перед открытием формы.**
   Добавлен узкий общий контракт `data-surface-action="child"`. Оба существующих
   диспетчера пропускают reset только если кнопка с этим атрибутом находится
   в текущем активном frame. Обычные shortcuts сохраняют прежнее поведение.
   Нет нового command router или обхода authority. Настройки, правила и
   подтверждение остановки сохраняют точное меню; навигационные действия уходят из него.
5. Старый независимый z-index меню удалён: последовательность общих поверхностей
   теперь определяет порядок меню, дочерних экранов и подтверждения. Перетягивание
   меню прекращается при его приостановке дочерней поверхностью; ручное inert
   или управление чужим foreground из меню отсутствуют.

Основные файлы: `app/game-menu.js`, `app/game-menu-021.css`, одна строка токена
в `app/game-frame-021.css`, исходный edge rule `app/mobile-surfaces.css` и по одной
ветке shortcut dispatch в `app/app.js` / `app/shared-views.js`. Изменения
не затрагивают правила, authority, wire, хранилища или сервер.

## Настоящий браузерный сценарий

Один адресный случай добавлен в существующий `tests/lobby-layout-browser.test.cjs`:

```
node scripts/codex/test.cjs case/lobby-layout-browser --name 'game overlays 0.21:'
```

Финальный **Chromium: PASS 1/1**. Тот же случай в WebKit:

```
PLAYWRIGHT_BROWSERS_PATH=/tmp/playroom-webkit LD_LIBRARY_PATH=/tmp/playroom-webkit/deps/usr/lib/x86_64-linux-gnu LAB_ENGINE=webkit node --test --test-name-pattern='game overlays 0.21:' tests/lobby-layout-browser.test.cjs
```

Финальный **WebKit: PASS 1/1**. Для каждого движка — 11 PNG, 13 групп наблюдений,
`page errors: []`, `nativeSupabaseRequests: 0`. Обмен выполняется двумя настоящими
локальными RTCPeerConnection через действующий мастер «Рядом». Safe fetch fixture
подключён до навигации. Service Worker разрешён; его управление страницей и
сценарий обновления в этом случае отдельно не утверждаются.

Проверено в 390×844 и 844×390:

- Контекстная панель комнаты использует общий тип panel и доступную прокрутку.
  Это только наблюдение A13: редактор имени и его отмена имеют отдельного владельца.
- Меню не перемонтирует сцену и не меняет её координаты/размеры.
- Tab доходит до «Дополнительно» и «Вернуться к игре»; раскрытие Enter даёт доступ
  к истории; закрытые действия пропускаются вперёд и назад; границы замкнуты.
- Настройки → Escape возвращают тот же connected menu и фокус на исходное действие.
- Правила → Back и Остановить → Отмена возвращают то же меню и ту же сцену.
- Escape в портрете и настоящий `history.back()` в альбомной ориентации закрывают
  меню без orphan frame и без оставшегося `app.inert`.
- Edge launcher стоит у требуемого края, имеет правильную форму и порядок
  иконки/малой стрелки; подпись отсутствует. Вытягивание открывает чат,
  launcher скрывается; повторное открытие нажатием сохраняет черновик.
- Панель меняет высоту/ширину ручкой с клавиатуры. Многострочный черновик
  переживает поворот и уменьшение viewport до 390×430; кнопка отправки доступна.
  Это модель уменьшенной видимой области, а не физическая экранная клавиатура.

## A15: отдельная последующая проверка локального бота

Дизайнер воспроизвёл пропадание меню после одного нажатия в локальной партии.
Причина: `saveLibrary.current()` восстанавливает новый объект Session при каждом
чтении. Сравнение ссылок в `valid()` сразу утилизировало корректное меню. Теперь
проверяется устойчивый `current().id`; точные проверки shell/layout/room/role
сохранены. Подмена активного сохранения другим ID по-прежнему закрывает меню.

Существующий адресный `game overlays 0.21:` дополнен настоящей локальной партией
с ботом: одно нажатие, повторная запись/восстановление той же сессии под тем же ID,
Настройки → Escape, остановка → Отмена, затем смена ID. Все проверки прошли
Chromium **1/1** и WebKit **1/1**, вместе с прежним реальным RTC и A32 no-duplicate.
Ошибок страницы нет; native Supabase requests — 0. Сборка hotseat запускается
штатной «Начать»: auto-start/ready в ней не отображаются. Сценарий проверяет эту
компоновку, а не добавляет отсутствующие контролы ради теста.

Кадры: `tmp_files/ux-021/ui-platform-audit/{chromium,webkit}-local-menu-stable-id.png`.
Логи этого последующего прохода:
`tmp_files/ux-021/conversation-search/rtc-{chromium,webkit}.log`.
Это расширяет локальную область проверки A15, но не доказывает все игровые роли.
