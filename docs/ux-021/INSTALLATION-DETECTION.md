# Установленная PWA в браузере

Повторное посещение браузера больше не зависит от appinstalled только текущей вкладки. Manifest объявляет себя через related_applications/webapp; API getInstalledRelatedApps проверяется при запуске, возвращении фокуса и видимости. Запросы объединяются, постоянного опроса нет. Принимается только точный manifest URL и собственный стабильный id /playroom; userinfo из manifest URL исключается. Стороннее приложение не скрывает установку. Ошибка API сохраняет последнее известное состояние, пустой успешный ответ сбрасывает related-installed. Новый beforeinstallprompt перекрывает поздний старый ответ. Установленность не сохраняется вечным localStorage-флагом.

При точном installed-related подтверждении в браузере вместо «Установить ХОД» показывается «Открыть приложение»: обычная чистая HTTPS-ссылка с target=_blank/rel=noopener, передаваемая браузерному navigation capturing. Она не содержит паролей, query или fragment. В standalone оба предложения скрыты. Существующий launch_handler focus-existing/auto сохранён, чтобы не перезагружать открытую партию. appinstalled без related-подтверждения скрывает предложение, но не обещает готовность Android WebAPK.

Запуск установленного приложения выбирает браузер с учётом пользовательских настроек; запрет перехвата ссылок может оставить обычную вкладку. Наличие ссылки не объявляется доказанной физической передачей в приложение. На iOS/Safari без installed-related API остаётся инструкция и настоящее standalone-определение; придуманная установка по отсутствию beforeinstallprompt не используется.

Официальные источники: [Chrome installed-related](https://developer.chrome.com/docs/capabilities/get-installed-related-apps), [navigation management](https://developer.chrome.com/docs/capabilities/pwa-navigation-management), [web.dev detection](https://web.dev/learn/pwa/detection).

Адресные проверки: pwa-install-handoff.test.cjs 6/6 и manifest case1/1. Existing PWA installation 0.21 browser case проверяет iOS/manual/native, отмену/late choice, точный related manifest, чистую launch-ссылку, скрытие внутри standalone и возврат установки при новой invitation. Отчёты tmp_files/ux-021/install-detection/{chromium,webkit}. Браузерный related API в case подставлен явно; реальная установка/передача на физическом телефоне остаётся отдельной приёмкой.
