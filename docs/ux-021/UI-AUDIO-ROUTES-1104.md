## Разобранный RED

Первые Chrome/WebKit-запуски остановились на ожидании offer cue при работающем AudioContext. Диагностический повтор показал, что UI feedback вообще не получил handoff event; connection success/error уже прошли. Причина — неполный протокол теста: не был передан MessagePort. В production `platform/web/push-worker.js` использует MessageChannel и передаёт port2, а PushUI вычисляет `visible(payload)` в аргументе optional postMessage. Без порта этот вызов не исполняется.

Тест исправлен передачей настоящего MessageChannel и проверкой `{handled}` для каждой входящей ветки. Код приложения и assertions по числу звуков не ослаблялись. Первый RED и диагностика сохранены, не названы дефектом production. Повторная инициализация PushUI в изолированном тесте оставляет прежний listener: dedup предотвращает двойное воспроизведение и в этом случае. Ничего не устанавливается/не регистрируется на реальном устройстве.
