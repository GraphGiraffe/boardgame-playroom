# Shared ordering and quiet pack actions

`app/community-order-ui.js` now exports the generic `PlayroomOrderUI.create` presentation controller; `PlayroomCommunityOrderUI.apply` remains its existing Community adapter. Pack ordering uses a separate owned instance. There is no copied pointer controller or extra order store: Community retains its existing preference port, and Packs writes the existing display-preference order. Native catalog desktop drag remains the root owner's adapter; catalog touch can use the same factory.

The factory accepts an owned `list`, dynamic `rows`, `key`, `handle`, `current` guard, `move` callback, optional `resolveDrop`, scroll pane, preview host/omit/classes and pointer-type/delay/start filters. It returns `cancel()` and `dispose()`. Default list placement uses vertical before/after; a caller can resolve a grid card or an empty category container inside its owned list. Delayed touch gestures preserve normal taps/scrolling until activation; handle-only gestures start immediately. Pointer identity, cancellation, Escape, lost capture, blur, pagehide, hidden/suspended owner and disposal clean up timers, animation frames, capture and the preview. Each instance has its own AbortSignal listeners. A root/document scroll owner uses viewport bounds for edge scrolling.

Previews are inert and inaccessible, fixed without affecting layout, bounded to the viewport and retired if disconnected. Action IDs, form names and interaction data attributes are stripped; only `data-theme`, `data-art-plane` and `data-art-slot` presentation attributes remain. A configured preview host preserves the caller's CSS/theme context. The controller never receives or writes backend/game state.

The pack menu uses one row for **Выше / Ниже**, retains endpoint disabled states and adds a drag handle only for active versions. Hide/show, favourite, deletion and maintenance actions have semantic registry icons and shorter contextual labels. The old filled removal/visibility/favourite rules were removed instead of adding another overriding card-specific patch. Ordinary `.ui-action-danger` entries now use a transparent background and danger text/icon; destructive confirmation buttons retain their explicit accent variants. The lobby's obsolete special red rectangle was removed so its actions use the common widget. The app-owned `refresh` glyph is distinct from undo; Pack catalog checking uses refresh, while restore keeps undo.
