## Проблема и критерий успеха

Новые пользователи не находят действия и не предсказывают результат нажатия даже
после объяснения. Причина по аудиту: смешанные уровни навигации, множество кнопок
без подписей, настройки вместо сценариев, вложенные окна и повторные поля.
Успех — человек без инструктажа создаёт комнату, приглашает друга, начинает партию,
пишет сообщение и возвращается к игре. Считать ошибки, возвраты и обращения за помощью,
а не только число кликов. Проверка с друзьями ещё не выполнена.

## Ограничения

- Телефон — основная поверхность. Основная матрица CSS viewport: 360×800, 390×844,
  412×915, 430×932 и поворот. Это классы размеров, а не обещание конкретных моделей.
  Дополнительно 768×1024 и 1366×768. WebKit и Chromium; реальные телефоны — отдельная приёмка.
- Не оптимизировать заново под 320px, но не блокировать увеличение текста и браузерный zoom.
- Сохранять минималистичные арты и мягкую палитру. Каталог на главной остаётся узнаваемым.
- Онлайн приоритетнее локальной сети. Без аккаунта можно играть на устройстве; вход нужен
  в момент онлайн-действия. Не переводить существующую комнату в другой режим автоматически.
- Удалить ручной масштаб интерфейса и выбор схемы трёх соперников. Адаптация по доступному
  месту, безопасным областям и клавиатуре; старая настройка не должна менять новый экран.
- Свайп — ускорение видимого действия, не единственный способ. Не перехватывать края
  системного Back, вертикальную прокрутку, выделение текста, drag карт и системный pinch.

## Структура и компоновка

Основные назначения: Игры / Мои партии / Общение / Профиль. Названия и иконки вместе.
До изменения нижней навигации проверить прототип: сохранение главного каталога важнее
добавления новой полосы. Активная партия доступна одной постоянной строкой возврата.

Лобби: заголовок комнаты; подписанный способ игры; игра и «Правила»;
список игроков; «Пригласить»; закреплённая нижняя область готовности/старта.
Зрители и общий Стол — раскрываемая вторичная секция. Детальные правила и доступ
к комнате — отдельные экраны, а не стены иконок. Нельзя менять состав кнопок после
показа окна участника: права вычисляются до открытия, загрузка имеет стабильное место.

Общение: вкладки Чаты / Друзья с подписями и счётчиками. Личные и групповые разговоры
в одном списке; фильтры появляются при необходимости. В игре чат открывается поверх
партии, хранит черновик и прокрутку; закрытие возвращает точно туда же. При клавиатуре
sheet расширяется и composer остаётся видимым. Смена команды/общего чата явная.

Настройки: заголовок, 3–4 смысловые секции, вертикальная прокрутка. Не дублировать
друзей, правила комнаты и приглашение. Профиль отделён от игровых предпочтений.

## Ограниченная система компонентов

- Основная кнопка: глагол + объект, одна доминирующая на смысловую область.
- Переход: строка с заголовком, коротким пояснением и шевроном.
- Окно выбора: подписанное действие, текущий выбор виден до открытия.
- Переключатель: подпись + switch + видимое состояние; не использовать кнопку перехода.
- Вкладки: 2–4 соседних раздела, выбранное состояние, клавиатурные стрелки и tap;
  горизонтальная прокрутка для длинных названий. Свайп содержимого только без конфликта с игрой.
- Иконка без подписи только для общеизвестного локального действия: закрыть, назад;
  доступное имя обязательно. Остальные действия подписывать.
- Зоны касания 44–48 CSS px; рисунок может быть 20–24px. Уменьшать пустоты, а не цель касания.
- Шкала отступов 4/8/12/16/24; телефонные поля 12–16, не складывать поля backdrop,
  modal и body. Одна вертикальная прокрутка на поверхность; footer вне неё.
- Короткое окно выбора — sheet; длинные настройки — экран с Back; подтверждение — общий механизм (основа: выбранная панель последствий B; dialog — глобальная альтернатива).
- Анимации 140–220ms для состояния/появления, transform/opacity; reduced motion убирает
  движение. Анимация не задерживает действие, ввод или сетевой ACK.

## Оповещения

| Событие | В приложении | В фоне | Действие |
|---|---|---|---|
| Новое сообщение | Обновить открытый чат; иначе компактный баннер | Push | К конкретному сообщению |
| Приглашение | Карточка с игрой/комнатой | Push | Войти; истёкшее без активной кнопки |
| Ваш ход / старт / конец | Состояние партии; без дубля при открытой партии | Push по правилам | Открыть партию |
| Потеря связи | Неблокирующий статус, повтор при необходимости | Без потока повторов | Переподключиться |
| Ошибка формы | Рядом с полем/действием, сохранить ввод | — | Исправить/повторить |
| Успешное сохранение | Короткий статус без подтверждения | — | Ничего не требуется |
| Важное обновление | Карточка обновления | Только по явному указанию владельца | Обновить с понятным прогрессом |

## План реализации и приёмки

1. Основа: убрать ручной масштаб/рассадку, компактные адаптивные поверхности, стабильные зоны действий.
2. Онлайн-путь: подписанные режимы, онлайн первым, простой вход и приглашение, локальные способы во втором уровне.
3. Лобби: участники и готовность, дополнительные настройки отдельно; убрать повторяющиеся кнопки.
4. Общение и профиль: вкладки, единый чат-sheet, возврат/черновик/клавиатура.
5. Сигналы и анимации: общие состояния, reduced motion, актуальные бейджи и действия.
6. Приёмка: WebKit/Chromium, 4 телефонных размера, landscape, клавиатура, zoom текста,
   Android Back/iOS edge navigation; отдельная проверка с друзьями без подсказок.

Для каждого сценария фиксировать исходные и новые шаги; цель — меньше возвратов и
лишних решений. Не выдавать проектируемое число шагов за измеренное. Физические
испытания с друзьями и системными жестами не заменяются desktop-эмуляцией.
