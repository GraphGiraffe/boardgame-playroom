# Планирование, RAM и сохранение — preview.15, 2026-11-06

Приложение 0.21.0-preview.15, коллекция 0.8.9-preview.23, Стихийная потасовка
0.2.7-preview.13. Старый неизменённый пак 0.2.7-preview.12 из пользовательской
партии проверен отдельно. Публикуется существующее превью, не stable-релиз.

## Что исправлено

Активная партия и загруженный пак используются из памяти. Выбор, поворот и
промежуточное подтверждение первой карты не читают и не записывают IndexedDB.
Полный план игрока сохраняет накопленные шаги и квитанции одной атомарной
транзакцией. Хост читает заголовок внутри этой транзакции только для проверки
revision/transfer fence; история заново не загружается. Ожидание диска остаётся
на полном подтверждении, поскольку его ACK должен пережить сбой процесса.

Черновик получает явный `draft:true`: при аварийном закрытии до полного
подтверждения его можно потерять. Повтор команды использует RAM-квитанцию.
Неудачная запись полного плана не продвигает финальное состояние, ранее
принятый черновик остаётся доступен для повтора. Пауза, смена контроллера и
передача хоста сначала сохраняют накопленные черновики. Явный локальный
save/exit также может сохранить незавершённый план.

Механизм общий: пак задаёт чистый checkpoint, а старые portable-паки используют
описанное ими окно одновременного решения. Новое публичное событие или конец
игры всегда требуют checkpoint. В движке нет проверки ID игры. У обычного
действия без частичного плана сохраняется прежняя атомарная запись.

Источник публичных кадров больше не создаёт поле заранее в оболочке и затем
повторно при prepare. Текущее поле материализуется по требованию; подготовка
следующего кадра по-прежнему идёт в idle-периоды текущей анимации. Сравнение
авторских шаблонов пропускает неизменившиеся поддеревья, сохраняя живые эффекты.
Локальный поворот готовит небольшие карточки игроков вместо второго SVG поля.

Обычное закрытие панели больше не посылает ложное событие изменения настроек,
которое отменяло presentation и запускало повторные render. Неизменившийся
экран остаётся на месте; реальные изменения прав и настроек обрабатываются.
Все 12 схем памятки наследуют цвет стихии, включая сохранённый пак preview.12.

## Почему 11 КБ в файле и около 2,4 МБ в базе

В присланном файле 11 215 байт: gzip-base64-v1. Gzip-поток занимает 8 290 байт,
развёрнутая переносимая оболочка — 75 220 байт. Внутри применяется
interned-json-v1: одинаковые поддеревья записаны один раз. Полностью развёрнутая
Session занимает 2 502 473 байта; это 50 состояний и 49 действий.

Старые сетевые строки шагов занимают 2 464 231 байт JSON, в том числе много
повторных публичных кадров. Новый журнал изменений для той же истории —
310 513 байт до сжатия, примерно в 7,9 раза меньше. Все 50 состояний прошли
точное обратное сравнение. Это размер полезной нагрузки, не размер файла
IndexedDB: служебные индексы, квитанции, заголовок и резервные записи считаются
отдельно. В разделе данных добавлено пояснение различия с экспортом.

Старый журнал восстанавливается в RAM и уплотняется в фоне, уступая управление
после каждых четырёх состояний. Последняя атомарная запись проверяет актуальность
партии и сохраняет более новые метаданные. Полный журнал событий используется
и для исторических состояний с коротким хвостом: пакет из семи событий на ход
восстанавливается без потерь. Исходные сохранения и версии паков не заменяются.

## Проверка и пределы измерений

Chromium 156, 384×782, DPR 2,8125, CPU ×4; сценарий UI восстановлен из присланного
сохранения. Дополнительные скриншоты для измерений не собирались.

| Измерение | preview.14 | preview.15 |
|---|---:|---:|
| Синхронный обработчик поворота после прогрева, с CPU-профайлером | 82–87 мс | 58–61 мс |
| Закрытие памятки, синхронная часть, с CPU-профайлером | 183 мс | 113 мс |
| Render игры при неизменённом закрытии панели | 2 | 0 |
| Цветные схемы памятки | 0 из 12 | 12 из 12 |

Отдельный сетевой профиль: первая карта, от capture обработчика до изменения
DOM, около 219 мс при CPU ×4; в этом интервале нет операций IndexedDB. Маркер
перед Playwright.click включает ожидание автоматизации и не является временем
отклика приложения. Оставшиеся расходы DOM/layout/focus не объявляются нулевыми;
60 FPS на физическом телефоне этим прогоном не доказаны.

Проверки на точном companion и итоговом HTML:

- 88 core-кейсов: authority, durable-authority, network-store-integrity,
  host-recovery, model-contract, session. После последней правки миграции отдельно
  повторены 3 нативных IndexedDB-кейса и 16 checkpoint/integrity-кейсов.
- Нативный IndexedDB: первая карта 0 read/write транзакций, дубль 0 записей,
  полный план 1 write-транзакция, после reload 2 шага и 2 квитанции. Уплотнение
  legacy-журнала, включая 7 событий за ход, сохраняет экспорт без отличий.
- Неизменённый Mage preview.12: тот же результат 0/1 транзакций и восстановленная
  revision 2. Партия пользователя не переводится на другую версию правил.
- 3 Mage browser-кейса: elemental effects, viewport geometry, local RAM draft +
  закрытие реальной памятки. В последнем исправлена тестовая разблокировка
  hotseat после resume; повтор этого кейса зелёный.
- 6 общих browser-кейсов: history input, projected network, personal network,
  SDK interaction audit. Матрица покрыла первое действие всех 15 паков и повтор
  ACK без render; это не полный прогон каждой партии.
- Lazy publicFrames: первый renderer вызывается при материализации кадра,
  а не при генерации оболочки.

Рабочие логи и профили: `tmp_files/perf-input-1105/`. Исходное личное сохранение
и видео не включаются в публикуемые материалы. Галерея остаётся прежней:
изменения этой итерации относятся к производительности, хранению и памятке.
