## Найденные при интеграции ошибки

- Владелец-зритель или Стол не мог занять свободное место через новый список.
  В панели свободного места добавлено явное «Занять место / Пересесть сюда» с
  действующей доменной проверкой. Собственные роли перенесены в окно участника.
- Возврат после изменения имени восстанавливал устаревшую строку участника.
  Восстановленное лобби перечитывает текущую модель комнаты; окно участника получает
  актуальные имя и аватар. Несохранённые редакторы не заменяются этой синхронизацией.
- Ответ в личном чате терялся при закрытии окна. Сохранение текста и цитаты перенесено
  до удаления DOM и защищено ключом владельца. Позднее подтверждение отправки очищает
  только отправленный черновик; подробности и финальные проверки ведёт UX/код-ревью.

Адресные регрессии лобби ещё согласуются с последними исправлениями. Chromium account/social — полный файл 16/16 и два успешных адресных повтора после исправления предпосылок. WebKit — полный файл 14/16, затем оба упавших случая успешно проверены адресно. Причина последних двух сбоев — не пройденное фикстурой начальное окно имени; проверки прокрутки не ослаблены. Это составное доказательство, а не новый полный прогон 16/16. Финальная расширенная проверка ответов/реакций/черновиков и задержанного ACK также прошла в обоих движках. Эти числа не объявляют готовыми весь интерфейс или физические устройства.

## Ограничения доказательств

WebKit с активным service worker может обходить Playwright HTTP route fixture.
Сетевые фикстуры аккаунта переведены на общий перехват Supabase fetch до native
networking; проверяются ненулевые перехваты и ноль внешних Supabase-запросов.
Настоящий service worker остаётся включённым. Это изолированные локальные проверки,
а не доказательство работы production Auth или фактической доставки Push.

Публикация, production-миграции, рассылки, реальные мобильные клавиатуры и приёмка
новыми пользователями в этот этап не входят как выполненные действия. Оставшиеся
структурные расхождения перечислены в [PROTOTYPE-FIDELITY.md](PROTOTYPE-FIDELITY.md).

Категориальные параметры правил больше не используют ползунки: имена режимов и способы завершения доступны через подписанные списки. Числовые параметры сохраняют подходящий числовой регулятор. После изменения проверены по девять состояний в Chromium и WebKit. Удалено прежнее правило, уменьшавшее кнопки заголовков до 32 px на поддерживаемой ширине 360 px; применяется общий сенсорный размер.


Финальные адресные проверки лобби этой итерации: шесть выборок, десять TAP-узлов
прошли в Chromium; исходные артефакты и ограничения —
`tmp_files/ux-021/lobby-migrated/VALIDATION.md`. Дополнительно исправлен конфликт
между выбором первого игрока и открытием профиля: при вооружённом выборе нажатие
получает контроллер назначения, затем обычное нажатие снова открывает профиль.
Проверка назначает конкретного другого участника, а не только проверяет наличие ID.

Обнаруженный при независимой проверке UX-05 остаётся открытым: панель друга из
разговора теряет видимую подложку разговора. Для исправления начата общая задача
`ux-021-surface-stack` с owner-scoped registry, capture/restore и переносом
контроллеров на активный слой. Обычная панель остаётся нижней в обеих ориентациях;
правый вариант используется только игровым чатом и игровым меню. Новая задача
добавлена в облачный RoadMap, прочитанная обратно ревизия — 327.
