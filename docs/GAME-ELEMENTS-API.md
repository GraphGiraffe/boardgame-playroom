# API 2: игровые элементы и компоновка приложения

Решение от 10.10.2026: все пять исходных паков переходят на `viewApi: 2`. Старый API, возвращавший готовую HTML-сцену, не поддерживается. UNO — 0.3.0; домино, дурак, шашки, змеи и лестницы — 0.2.0. Правила и stateVersion сохраняют прежнюю семантику. Старые опубликованные файлы не перезаписываются, старые сохранения не получают другую версию пака автоматически.

## Разделение ответственности

Пак создаёт рисунок поля и фигур, тексты, разрешённые действия, приватные и публичные компоненты из переданной проекции состояния. Он не выбирает места руки, участников, действий, настроек или истории. Приложение создаёт контейнеры, выбирает компоновку, размеры веера и доступную область поля, подгоняет поле, обслуживает ввод и повтор.

`core/ui.js: composeScene` — один компоновщик для local, combined, table, player и истории. `GameScreen.layoutScene` наблюдает размеры сцены через ResizeObserver, выбирает режим и подгоняет поле. Имя игры не используется для выбора компоновки.

```js
const V = globalThis.PlayroomViews, H = V.helpers;
V.register('my-game', (state, viewer, actions, ui) => ({
  api: 2,
  family: 'cards', // 'board' для поля без руки
  className: 'my-game-scene', // оформление пака
  elements: {
    participants: H.opponents(state, viewer, drawCard),
    status: '<span>Состояние игрового поля</span>',
    field: drawField(state, actions, ui),
    actions: H.actionBar(actions),
    hand: H.hand(drawOwnCards(state, viewer, actions, ui), count, '', '', {layout:'fan'}),
    auxiliary: '<span>Короткая дополнительная информация</span>'
  }
}), drawCover);
```

`field` обязателен и непустой. Остальные элементы опциональны; пустая строка означает отсутствие. Значения элементов — доверенный HTML пака. Неизвестные элементы, неподдерживаемая family, неверный api и старые строки-сцены отклоняются. Пользовательские строки экранируются через `H.esc`; действия — через `H.actionAttr`, `H.source` и `H.target`.

Для квадратной доски указывается `fieldAspect: 1`; для другой формы — отношение ширины к высоте. Внутренняя геометрия доски, клеток, цепочки и фигур принадлежит полю. Приложение выделяет ему прямоугольник и сохраняет пропорции.

## Общие позиции и режимы

| Режим | Выбор | Компоновка |
| --- | --- | --- |
| phone-portrait | ширина до 760 px | Участники и статус сверху, поле в центре, действия перед рукой, дополнительная информация снизу. |
| phone-landscape | ширина больше высоты, высота до 550 px | Карточное поле слева, рука справа; действия под полем. Для доски поле слева, статус и действия справа. |
| tablet | остальные размеры до 1100 px по ширине | Более свободная компоновка; доска получает отдельную область статуса, карточная рука ограничивается доступной шириной. |
| desktop | ширина от 1100 px | Поле получает основное пространство, рука ограничена комфортной шириной; панели не растягивают игровую графику. |

`TabletopUI.selectLayout(width, height)` задаёт режим; приложение выставляет `data-layout-mode`. Навигация приложения остаётся в верхней шапке: возврат слева, справка и настройки справа. Режим не выбирается внутри пака.

Для сложной группы действий используется `H.actionGroups({start, primary, end})`. Пак предоставляет содержимое; общий компонент размещает крайние действия и центральную группу. Все прикладные иконки доступны через `H.icon(name)`; `GameScreen.icon` является тем же источником.

## CSS и взаимодействие

CSS пака описывает фигуры, графику и внутреннее содержимое поля. Он не управляет `.table-shell`, `.table-header`, `.player-strip`, `.game-layout-slot`, `.own-hand`, `.hand-track`, `.opponent-hands` или общими панелями действий. Поле не меняет состояние и не выполняет действие по изменению размера.

Размер доступной области определяет приложение. Подгонка поля не масштабирует шапку, руку и панель действий. Приложение сохраняет размер hit target для действий; рисунок фигур может уменьшаться пропорционально. Карточная рука использует `H.hand` с `layout: "fan"`, плитки — с `layout: "tiles"`; размеры и размещение обоих компонентов задаёт приложение. Длинная рука и большая публичная рука прокручиваются внутри своих компонентов. Клетки доски отмечаются `data-grid-cell`, отдельные пустые цели — `data-hit-target`. Обработка click, touch, drag, swipe, preview и клавиатуры сохраняет прежние атрибуты и проверку разрешённых действий.

`surfaces.table/player` возвращают тот же объект API 2, с разрешёнными элементами. `table` получает пустые actions; закрытые руки не передаются публичному viewer. Отсутствие surface по-прежнему запрещает его использование. История получает разрешённую проекцию и пустые действия.

## Проверки и доставка

Геометрия общих областей проверяется на синтетических элементах в `game-layout-browser.test.cjs`. Паковые проверки сохраняют правила, приватность, покрытие legal actions, рисунок и игровые drag/drop цели. Проверка компонента не заменяет проверку состояния конкретной игры.

Новый app и новая коллекция паков должны поставляться совместно. CI использует конкретный SHA новых исходников паков. Приватный companion checkout читает через репозиторный deploy key только для чтения (`PLAYROOM_PAKS_READ_KEY` в Actions приложения); ключ не входит в Git или сборки. Пак с viewApi 1 отклоняется с сообщением об обновлении, а не подключается через legacy-адаптер. Старые записи в библиотеке не удаляются и не переназначаются другой версии.

PWA использует отдельное имя кэша оболочки API 2, чтобы не смешивать ресурсы с установленной RC9. IndexedDB, журналы и локальная история при смене кэша не удаляются. Это изменение исходников; опубликованный RC9 не заменяется.
