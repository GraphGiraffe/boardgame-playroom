# Игровые элементы: viewApi 2

Пак предоставляет правила, графику и содержимое элементов. Приложение владеет компоновкой, карточками игроков, руками, панелями действий, историей и навигацией. API 1 не исполняется. Актуальные паки: UNO 0.4.1, домино/дурак 0.3.2, шашки/змеи 0.3.1; пример private-counter 0.3.0.

## Контракт

```js
const V = globalThis.PlayroomViews, H = V.helpers;
function render(state, viewer, actions, ui = {}) {
  return {
    api: 2, family: 'cards', className: 'my-game',
    playerContent: H.playerContent(state, viewer, cardHTML, {
      scoreLabel: 'очки', badges: index => [],
      color: index => null, colorLabel: index => ''
    }),
    elements: {
      field: fieldHTML(state),
      hand: viewer >= 0 ? H.hand(state.data.hands[viewer].map(cardHTML),
        state.data.hands[viewer].length, '', '', {layout: 'fan'}) : '',
      actions: H.actionBar(actions), status: '', auxiliary: ''
    }
  };
}
V.register('my-game', render, null, {surfaces: {
  table: (s, v, a, ui) => render(s, v, [], {...ui, surface: 'table'}),
  player: (s, v, a, ui) => render(s, v, a, {...ui, surface: 'player'})
}});
```

`elements.field` обязателен и содержит HTML поля. `family` — `cards` или `board`. Для доски задаётся `fieldAspect` (ширина/высота, обычно 1). Неизвестные слоты, неверные типы и старые строки-сцены отклоняются. Экраны участников используют одну комбинированную сцену; публичный стол не получает приватную руку или игровые действия.

`playerContent` — массив по индексам игроков. Дескриптор содержит `handHTML`, `handCount`, `open`, `scoreLabel`, `countLabel`, `badges`, `color`, `colorLabel`. Имя, тип игрока, счёт и очередность приложение берёт из **проекции**, переданной рендереру. `H.playerContent` передаёт каждую закрытую карту рубашкой, без ограничения количества, и не дублирует собственную руку. Длина массива совпадает с числом игроков; подписи — строки, `open` — boolean, `handCount` — неотрицательное целое, badges — строки или объекты с label. Единицы счёта должны совпадать с `rules.scoreLabel`. Пак может показать публичную информацию (например, число шашек, позицию или роль атакующего) через badges. Публиковать секреты в строках HTML запрещено; проекция rules-пака должна скрывать их до вызова view.

Для поля с отдельной колодой используется дополнительный `fieldGroups: {stock: stockHTML, play: playHTML}`. Приложение располагает stock слева, play справа. Эту схему использует Дурак. Содержимое игрового поля и внутреннюю геометрию пар карт определяет пак.

## Компоновка

| Режим | Условие по доступной сцене | Размещение |
| --- | --- | --- |
| phone-landscape | ширина больше высоты, высота ≤550 px | Оппоненты и статус слева, поле в центре, собственные сведения, действия и рука справа. |
| phone-portrait | ширина ≤760 px | Оппоненты сверху, поле в центре, собственные сведения, действия и рука снизу. |
| tablet | оставшаяся ширина <1100 px | Вертикальная компоновка с дополнительным пространством поля. |
| desktop | ширина ≥1100 px | Оппоненты слева, поле в центре, собственная область справа. |

`TabletopUI.selectLayout` и `GameScreen.layoutScene` реагируют на ResizeObserver, поворот и историю. Доска остаётся пропорциональной; карты и кости сохраняют размеры и пропорции. Длинная рука прокручивается внутри компонента, длинное поле — внутри своей области. Навигация и сведения игроков не масштабируются вместе с полем. Поле, которое нельзя поместить без уменьшения, масштабируется целиком; это не меняет состояние партии.

CSS пака оформляет игровые объекты и внутренние группы поля. Он не задаёт положения `.layout-*`, шапки, карточек игроков, рук или общей панели действий. `H.actionGroups({start, primary, end})` предоставляет содержимое общей панели; `H.icon` — общий источник SVG-иконок.

## Действия и начало партии

Обычные действия используют `H.actionAttr`, `H.source`, `H.target`. Приложение перед выполнением проверяет актуальную законность. Доступный объект получает `.is-playable` с тонкой зелёной обводкой; выбранный — `.is-selected` с золотой обводкой. Это общий контракт карт, костей, шашек и кубика. Пак отмечает возможность броска на самом кубике, без отдельной кнопки.

Действие над игроком объявляет `target: playerIndex, targetKind: 'player'`. Нажатие карточки оппонента открывает меню **всех** доступных действий; действие выполняется только отдельной кнопкой. Повторное нажатие закрывает меню. Escape возвращает фокус, стрелки/Home/End перемещают его между кнопками, внешний клик закрывает меню. Обновление состояния отменяет устаревший выбор; клик повторно сверяется с legal actions. Собственная карточка не открывает это меню.

Приложение передаёт `firstPlayerMode: 'random' | 'assigned' | 'rules'`. Для random/assigned движок вычисляет `resolvedFirstPlayer` до `pack.create(state, options)`. Пак применяет этот индекс в собственной инициализации, включая связанные роли. Для rules поле отсутствует и пак использует своё правило. Шашки назначают первому игроку светлые фигуры; Дурак согласованно назначает атакующего и защитника. Сохранённое состояние содержит уже выбранного первого игрока; восстановление не бросает жребий повторно.

См. [UI-DESIGN-SYSTEM](UI-DESIGN-SYSTEM.md), [общую комнату и миграцию](UNIFIED-TABLE-RC11.md), [TESTING](TESTING.md).

Для номинала в верхней части карты используйте `.card-corner` (нижняя копия дополнительно имеет `.bottom`). Приложение измеряет его реальную ширину и сохраняет читаемую часть веера при различающихся системных шрифтах. Для длинной руки разрешена прокрутка вместо растягивания карт или уменьшения текста.

### Контраст взаимодействия

Общее выделение `.is-playable` использует двухпиксельную обводку. Компонент пака может задать `--ui-action-outline` для контраста с собственной графикой, не меняя размещение и поведение: светлая обводка на тёмной фигуре, тёмная на светлой. Выбранный объект сохраняет отдельное выделение `.is-selected`.

Карточка соперника является общей целью взаимодействия: нажатие на информацию или руку открывает одно меню внутри карточки; действия заново проверяются по легальным действиям перед отправкой. Приложение размещает собственную информацию под рукой и кнопками. Геометрия карты/костяшки принадлежит паку и сохраняет пропорции.

В `surface: table` приложение исключает `hand` и `actions`: личных элементов на публичном экране нет. Публичную информацию и пассивные компоненты пак размещает в `status` / `auxiliary`. Общая компоновка расширяет поле вместо резервирования пустой личной колонки.


## Ресурсы и граница оформления

`PlayroomPack.asset('assets/file.svg')` разрешает путь только внутри установленного пака. Сборщик включает ресурсы в переносимый JSON, загрузчик преобразует CSS `url(...)` в локальные data URL. Представление сетевого клиента получает те же разрешённые ресурсы через `exportView`, без исполняемого кода правил. Повторная установка сетевого представления заменяет таблицу стилей того же пака. Отсутствующий ресурс отклоняется до установки пака; внешние CSS-импорты запрещены.

Пак оформляет свою карту/кость/доску, включая компактный вариант объекта. Он не переопределяет `.mini-hand`, `.player-info`, `.player-panel`, `.hand-heading`, `.hand-tools`, `.opponent-hand` и другие общие контейнеры. Эти селекторы отклоняются загрузчиком. Компактный вариант передаётся в `cardHTML(card, attrs, {variant:'compact', surface:'opponent', interactive:false})`; он должен помещаться в рамку приложения, сохранять содержимое и не создавать собственный скроллбар. Скрытая карта всегда оформляется общим `H.back(kind)`.

На публичной поверхности `table` приложение обнуляет действия и при вызове view, и при построении карточек игроков. Переносить управление личной рукой в HTML поля запрещено. Приватность обеспечивается предварительной проекцией состояния; пустой список действий её не заменяет.
