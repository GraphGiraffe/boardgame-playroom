# UI API 3 · ХОД 0.21.0

Область применения: приложение **0.21.0** и коллекция **0.8.9**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; текущая приёмка хранится в [utils](https://github.com/GraphGiraffe/boardgame-playroom-utils/blob/main/docs/project/app/reports/ACCEPTANCE-0.21.0.md).

Пак регистрирует `PlayroomViews.register(id, render, cover, options)`. render получает разрешённые state/viewer/actions/ui и возвращает **элементы сцены**, не собственную оболочку. Эталоны: tictactoe/view.js (поле), gofish/view.js (руки/таблица), yatzy/view.js (таблица), ludo/view.js (маршруты).

Приложение владеет header/status, игроками, рукой, actions, history, modal root. Пак возвращает field/hand/actions и policy компоновки: family, fieldSizing, fieldAspect, layout.focus, anchors. `family:board, fieldSizing:fit` сохраняет полноценное поле заданных пропорций; default aspect — квадрат. Маленький стол/карточные элементы могут занимать меньше места. Паки не переопределяют `.layout-*` глобальным CSS и не добавляют подписи, меняющие размер сцены.

## Ввод

В рабочей версии 0.19.3 добавлены общие зоны сброса. `data-drop-zone` на контейнере позволяет выбрать ближайший видимый разрешённый `H.target` внутри него. Для поля с `display:contents` у вложенных групп используйте `fieldDropZone:true` в recipe: зону создаёт оболочка приложения. Единственная цель принимает сброс в любой точке зоны; несколько целей выбираются по расстоянию до центра. Прямое попадание в запрещённую цель не перенаправляется на другую.

`data-drop-snap` на цели центрирует переносимый объект над ней. `data-drag-view-key="pawn"` на источнике передаёт физический ID в `ui.viewState.pawn` вместо `ui.selected`; это позволяет сохранять обычный выбор маршрута фишки. Состояние правил не меняется до отпускания над разрешённой целью. Отмена, история, модальные окна и ограничения authority сохраняются. Идентичность — конкретный экземпляр, не тип карты. Перевод в Дураке и цвет джокера UNO не выбираются эвристикой.

```js
const H = TabletopUI.helpers;
const source = H.source(card.id, actions, ui.selected, {
  key:'card', mode:ui.quickPlay ? 'immediate' : 'select',
  preview:true, inspect:true, drag:true, swipe:true
});
const attrs = H.actionAttr(command); // fixed layout remains the default
const target = H.boardTarget(command, {kind:'move', color:'#3e9168'});
```

Используйте H.target, H.hand, H.actionGroups, H.icon и стабильные data-entity для общей обработки. data-view-key/data-view-preference меняют только представление. DOM атрибут не выдаёт право хода: после ввода authority сверяет разрешённую команду.

Фиксация внешних областей не заменяет резервирование внутри пака. Колода, позиции выкладки и резервные ячейки имеют стабильные координаты независимо от числа карт и выбора. Сетка не должна растягивать занятые колонки или перераспределять строки после каждого хода: резервируйте полную вместимость, пустые ячейки скрывайте без удаления геометрии. Выбор, drag/drop, добор, очистка стола и исчерпание колоды сами по себе не разрешают перекомпоновку. Для исключений используйте существующий `allowLayoutChange`; изменение viewport/ориентации/масштаба штатно пересчитывает геометрию.

В коде host фиксирует также вычисленные треки, зазоры и выравнивание `.game-field-groups`. Собственные структурные сетки обозначайте стабильным уникальным `data-layout-grid="table"`; они используют тот же замок, без отдельного разрешения на уровне пака. На изменение счётчиков/жетонов замок не сбрасывается. Резервирование полной вместимости остаётся обязанностью компонента: замок не создаёт отсутствующие ячейки.

Внешняя геометрия фиксируется на партию/viewer/surface/размер окна. Единственное разрешение динамической геометрии на действии — `H.actionAttr(command,{allowLayoutChange:true})`. Input передаёт context; после успешного commit вызывается `GameScreen.allowLayoutChange(host,context)`. Флаг не входит в domain/сохранение/сетевой protocol, не задаётся для всего пака. По умолчанию игровые действия не используют его. Изменение масштаба — явное изменение предпочтения, создающее новую геометрию.

## Компоненты и слои

- Avatar: квадратный artboard, единые пропорции скругления, цвета участников не повторяются. Уменьшается весь компонент; hit area может быть больше изображения.
- Participant: роль/имя, смысловые метрики, first-player/team badge. Отложенные значки — одна строка со scroll, без роста высоты.
- Hand: overlap с ограниченным шагом, скролл даже с недоступной карты. Мини-руки выровнены влево и обрезаны по высоте во всех рассадках.
- BoardTarget: обычная цель золотая, благоприятная зелёная, опасная красная, специальная сохраняет свой усиленный цвет. Иконку клетки цель не перекрывает.
- Board: клетки → интерактивные цели/иконки → маршруты змей/лестниц → фишки. Важное поле не сжимается от появления текста/кнопки.
- ActionReveal: card/cards/dice, копия не содержит действий; слой ниже dialog/popover. Карточные наборы используют лица без двойных белых подложек.
- CardChoiceDialog: выбор закрытой карты относительно viewport, крупные карты, доступное закрытие.
- FieldHelp: единый popover поверх формы, не занимает место внутри строки.
- MiniCard: asset-pack mini-cards; ранг сверху слева, одинаковое перекрытие включая 10, соразмерные толщина/тень.

Рассадка anchors/row — preference устройства, не команда игры. На тесном экране возможен row fallback без перезаписи предпочтения. Порядок по углам читается по периметру; смена направления UNO не переставляет панели. Рыба/Ятзи используют ряд. `layoutRect` переводит экранные размеры в локальные px при масштабе; жесты остаются в координатах viewport.

Проверка: портрет 320/390, короткий landscape, оба режима руки, максимальный roster/счётчики, длинная рука, сеть/Стол/history. Сравнивать геометрию до/после действия; отсутствие ошибок console не подтверждает устойчивость сцены.

Для игры без выбора первого игрока manifest задаёт `capabilities.firstPlayer: false`: скрываются соответствующее правило и жетон в лобби/результате. Порядок рассадки сохраняется.

## Одновременная подготовка

`showTurn: false` убирает выделение текущего игрока, подпись/номер хода и сигнал передачи хода. Общая подсветка `playerContent[].ready` использует тот же зелёный цвет, что активный игрок, но не ставит `aria-current`. Служебный указатель authority, выбор получателя награды и защита скрытой руки не меняются. По умолчанию `showTurn: true`.

## Соло-поле

`hidePlayers: true` разрешён только сцене с одним игроком: не создаёт панели участников/self, сохраняя field и actions. Не меняет правила и проекции. Пасьянсы используют этот режим вместе с `fieldSizing: "scroll"`.

Соло-сцена с `hidePlayers` маркируется `data-solo-field`, занимает полную ширину в обоих положениях и может использовать общий нижний `elements.actions`. Для источника с немедленным drag: `data-drag-start="immediate"`; группа размечается контейнером `data-drag-stack` и обёртками `data-drag-stack-member="индекс"`. Input клонирует только уже разрешённые renderer источники, без вычисления правил.

Opt-in `actionPlacement: "header-landscape"` переносит общий action slot в центр заголовка только в landscape; portrait возвращает его в исходный слот. `data-double-action` задаёт авторизованную команду двойного нажатия на пустую часть поля; интерактивные дочерние элементы исключены. `data-motion-layout="cards"` включает публичные перемещения по entity ID, `data-motion-anchor` — стабильные точки для открытия/истории. Публичные упорядоченные переносы описываются `data-motion-transfers`/`data-motion-trigger` и каноническими лицами `data-motion-template`. Скрытые идентичности не используются; ordinary drag не ждёт анимационного удержания. Отключённая анимация не задерживает команду.

`layout.wideHand: true` запрашивает более широкую область локальной руки в горизонтальной компоновке. Размеры колонок и отступы определяет приложение; стандартная компоновка остальных игр сохраняется.
