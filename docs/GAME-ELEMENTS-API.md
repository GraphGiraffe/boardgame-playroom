# Игровые элементы: viewApi 2

Пак предоставляет правила, графику и содержимое элементов. Приложение владеет компоновкой, карточками игроков, руками, панелями действий, историей и навигацией. API представления 1 не исполняется (поддерживаются API правил 1 и 2). Стабильная коллекция 0.4.0: UNO 0.4.6, домино 0.3.4, дурак 0.3.5, шашки 0.3.2 и змеи 0.3.5.

Необязательный `actionReserve: true` резервирует строку действий личного живого экрана даже при пустом `elements.actions`. История/публичный Стол исключают этот резерв. `motionSequence` описывает маршрут через `{trigger, entity, player, counter, origin:{anchor,label}, steps:[{anchor,label}], jump?:{anchor,label}}`; якоря находятся по `data-motion-anchor`. Для предварительного броска используется `data-motion-lead="roll"`, для временного значения счётчика — badge `{label, motion:'position'}`. Рендерер не запускает таймеры: очередь, клонирование и ожидание движения принадлежат приложению. [Возможности 0.15](RELEASE-0.15.md).

## Контракт

`H.actionGroups({start, primary, end, exclusive:false})` размещает общую строку действий. При `exclusive:true` основной выбор занимает всю ширину той же строки; боковые области сохраняют геометрию, становятся `inert` и `aria-hidden`. Это позволяет показать, например, четыре варианта цвета без увеличения панели.

```js
const V = globalThis.PlayroomViews, H = V.helpers;
function render(state, viewer, actions, ui = {}) {
  return {
    api: 2, family: 'cards', className: 'my-game',
    playerContent: H.playerContent(state, viewer, cardHTML, {
      scoreLabel: 'очки', badges: index => [],
      color: index => null, colorLabel: index => ''
    }),
    elements: {
      field: fieldHTML(state),
      hand: viewer >= 0 ? H.hand(state.data.hands[viewer].map(cardHTML),
        state.data.hands[viewer].length, '', '', {layout: 'fan'}) : '',
      actions: H.actionBar(actions), status: '', auxiliary: ''
    }
  };
}
V.register('my-game', render, null, {surfaces: {
  table: (s, v, a, ui) => render(s, v, [], {...ui, surface: 'table'}),
  player: (s, v, a, ui) => render(s, v, a, {...ui, surface: 'player'})
}});
```

`elements.field` обязателен и содержит HTML поля. `family` — `cards` или `board`. Для доски задаётся `fieldAspect` (ширина/высота, обычно 1). Неизвестные слоты, неверные типы и старые строки-сцены отклоняются. Экраны участников используют одну комбинированную сцену; публичный стол не получает приватную руку или игровые действия.

`playerContent` — массив по индексам игроков. Дескриптор содержит `handHTML`, `handCount`, `open`, `scoreLabel`, `countLabel`, `badges`, `color`, `colorLabel`, необязательный `counters`. Имя, тип игрока, счёт и очередность приложение берёт из **проекции**, переданной рендереру. `H.playerContent` передаёт каждую закрытую карту рубашкой, без ограничения количества, и не дублирует собственную руку. Длина массива совпадает с числом игроков; подписи — строки, `open` — boolean, `handCount` — неотрицательное целое, badges — строки или объекты с label. Единицы счёта должны совпадать с `rules.scoreLabel`. Пак может показать публичную информацию (например, число шашек, позицию или роль атакующего) через badges. Публиковать секреты в строках HTML запрещено; проекция rules-пака должна скрывать их до вызова view.

`H.countBadge(count, label, {corner: true})` создаёт общий числовой индикатор: светлая подложка, зелёная цифра и мягкая тень в стиле UNO. Принимает неотрицательное целое; label задаёт доступную подпись. `corner: true` закрепляет его в левом верхнем углу относительно позиционированного контейнера колоды. Руки оформляет приложение: `hand: true` создаёт наклонённую подложку в пропорциях карты UNO (13×18px, цифра наклонена вместе с подложкой; вертикальные поля не увеличивают высоту ряда счётчиков) с цифрой внутри. Индикатор находится во втором ряду сведений игрока, перед очками/победами, и не дублируется над рукой. Стиль `.piece-count` и обёртка `.player-hand` принадлежат приложению и не переопределяются паком.

Для поля с отдельной колодой используется дополнительный `fieldGroups: {stock: stockHTML, play: playHTML}`. Приложение располагает stock слева, play справа. Эту схему использует Дурак. Содержимое игрового поля и внутреннюю геометрию пар карт определяет пак.

## Компоновка

| Режим | Условие по доступной сцене | Размещение |
| --- | --- | --- |
| phone-landscape | ширина больше высоты, высота ≤550 px | Оппоненты и статус слева, поле в центре, собственные сведения, действия и рука справа. |
| phone-portrait | ширина ≤760 px | Оппоненты сверху, поле в центре, собственные сведения, действия и рука снизу. |
| tablet | оставшаяся ширина <1100 px | Вертикальная компоновка с дополнительным пространством поля. |
| desktop | ширина ≥1100 px | Оппоненты слева, поле в центре, собственная область справа. |

`TabletopUI.selectLayout` и `GameScreen.layoutScene` реагируют на ResizeObserver, поворот и историю. Доска остаётся пропорциональной; карты и кости сохраняют размеры и пропорции. Длинная рука прокручивается внутри компонента, длинное поле — внутри своей области. Навигация и сведения игроков не масштабируются вместе с полем. Поле, которое нельзя поместить без уменьшения, масштабируется целиком; это не меняет состояние партии.

CSS пака оформляет игровые объекты и внутренние группы поля. Он не задаёт положения `.layout-*`, шапки, карточек игроков, рук или общей панели действий. `H.actionGroups({start, primary, end})` предоставляет содержимое общей панели; `H.icon` — общий источник SVG-иконок.

## Действия и начало партии

Обычные действия используют `H.actionAttr`, `H.source`, `H.target`. Приложение перед выполнением проверяет актуальную законность. Доступный объект получает `.is-playable` с тонкой зелёной обводкой; выбранный — `.is-selected` с золотой обводкой. Это общий контракт карт, костей, шашек и кубика. Пак отмечает возможность броска на самом кубике, без отдельной кнопки.

Действие над игроком объявляет `target: playerIndex, targetKind: 'player'`. Нажатие карточки оппонента открывает меню **всех** доступных действий; действие выполняется только отдельной кнопкой. Повторное нажатие закрывает меню. Escape возвращает фокус, стрелки/Home/End перемещают его между кнопками, внешний клик закрывает меню. Обновление состояния отменяет устаревший выбор; клик повторно сверяется с legal actions. Собственная карточка не открывает это меню.

Приложение передаёт `firstPlayerMode: 'random' | 'assigned' | 'rules'`. Для random/assigned движок вычисляет `resolvedFirstPlayer` до `pack.create(state, options)`. Пак применяет этот индекс в собственной инициализации, включая связанные роли. Для rules поле отсутствует и пак использует своё правило. Шашки назначают первому игроку светлые фигуры; Дурак согласованно назначает атакующего и защитника. Сохранённое состояние содержит уже выбранного первого игрока; восстановление не бросает жребий повторно.

См. [UI-DESIGN-SYSTEM](UI-DESIGN-SYSTEM.md), [общую комнату](DEVELOPER-UI.md), [TESTING](TESTING.md).

Для номинала в верхней части карты используйте `.card-corner` (нижняя копия дополнительно имеет `.bottom`). Приложение измеряет его реальную ширину и сохраняет читаемую часть веера при различающихся системных шрифтах. Для длинной руки разрешена прокрутка вместо растягивания карт или уменьшения текста.

### Контраст взаимодействия

Общее выделение `.is-playable` использует двухпиксельную обводку. Компонент пака может задать `--ui-action-outline` для контраста с собственной графикой, не меняя размещение и поведение: светлая обводка на тёмной фигуре, тёмная на светлой. Выбранный объект сохраняет отдельное выделение `.is-selected`.

Карточка соперника является общей целью взаимодействия: нажатие на информацию или руку открывает одно меню внутри карточки; действия заново проверяются по легальным действиям перед отправкой. Приложение размещает собственную информацию под рукой и кнопками. Геометрия карты/костяшки принадлежит паку и сохраняет пропорции.

В `surface: table` приложение исключает `hand` и `actions`: личных элементов на публичном экране нет. Публичную информацию и пассивные компоненты пак размещает в `status` / `auxiliary`. Общая компоновка расширяет поле вместо резервирования пустой личной колонки.


## Ресурсы и граница оформления

`PlayroomPack.asset('assets/file.svg')` разрешает путь только внутри установленного пака. Сборщик включает ресурсы в переносимый JSON, загрузчик преобразует CSS `url(...)` в локальные data URL. Представление сетевого клиента получает те же разрешённые ресурсы через `exportView`, без исполняемого кода правил. Повторная установка сетевого представления заменяет таблицу стилей того же пака. Отсутствующий ресурс отклоняется до установки пака; внешние CSS-импорты запрещены.

Пак оформляет свою карту/кость/доску, включая компактный вариант объекта. Он не переопределяет `.mini-hand`, `.player-info`, `.player-panel`, `.hand-heading`, `.hand-tools`, `.opponent-hand` и другие общие контейнеры. Эти селекторы отклоняются загрузчиком. Компактный вариант передаётся в `cardHTML(card, attrs, {variant:'compact', surface:'opponent', interactive:false})`; он должен помещаться в рамку приложения, сохранять содержимое и не создавать собственный скроллбар. Скрытая карта всегда оформляется общим `H.back(kind)`.

На публичной поверхности `table` приложение обнуляет действия и при вызове view, и при построении карточек игроков. Переносить управление личной рукой в HTML поля запрещено. Приватность обеспечивается предварительной проекцией состояния; пустой список действий её не заменяет.

Слева в карточке сохраняется цветная аватарка с буквой имени. Сведения имеют два ряда: иконка роли с именем, затем числовые счётчики и публичные игровые показатели. По умолчанию `scoreLabel: 'очки'` даёт светлый индикатор, `scoreLabel: 'победы'` — тёмный. Видимые подписи «Игрок», «Бот», «очки» и «победы» заменены доступными названиями и подсказками. Для двух независимых значений пак может передать `counters: (index, person) => [{kind: 'points', value: person.score}, {kind: 'wins', value: publicWins[index]}]` в `H.playerContent`. `publicWins` здесь означает собственные публичные данные правил, а не вычисляемую приложением статистику. Допускаются до трёх уникальных типов `points`/`wins`/`pieces`, неотрицательные безопасные целые и необязательный `label`; победы стоят последними. `pieces` — число фигур или фишек в круглом индикаторе без видимой подписи. Его `label` сохраняется в aria-label/title (по умолчанию «Фишки»). Например: `{kind: 'pieces', value: 12, label: 'Светлые шашки'}`. Пустой массив скрывает счётчики. Секретные данные в counters запрещены.

`H.participantIcon(person, {network})` принадлежит приложению: игрок, бот, хост, зритель и Стол имеют единые значки. В сетевой игре подключённый участник зелёный, ранее подключавшийся отключённый — коралловый; бот, локальный и ещё не подключавшийся участник используют цвет текста. Присутствие обновляется отдельным публичным сообщением по игровому индексу, вычисленному из занятых мест, без сопоставления по никнейму и без передачи рук.

## относительные места и компактные статусы

Общий renderer применяет `H.seatOrder(count, viewer)` только к DOM-порядку противников. `playerContent` остаётся индексирован игровыми индексами. Зритель/Стол получает исходный порядок; смена Hotseat viewer или viewer истории поворачивает последовательность без изменения партии.

`badges` поддерживает строки и `{label, icon?, motion?}`. Иконки: `sword`, `shield`, `takeCards`. Подпись label обязательна для доступности, подсказки и текстового fallback прежних приложений. Размер значков задаёт движок, статус выбирает пак.

## Общие объекты, история и ввод

Пак не создаёт отдельный кубик для каждого игрока: общий объект размещается через `elements.shared`; приложение располагает его под полем в портрете и в собственной колонке справа в landscape. Используйте действующий пак snakes как пример. История сохраняет компактные разрешённые руки и видимые цели анимаций.

Общая область руки допускает прокрутку по обеим осям до контейнера .layout-self. Нельзя отключать pointer-события всех неходовых элементов способом, лишающим пользователя прокрутки. H.source и общий Input разделяют выбор, перенос и листание; после скролла commit не вызывается.

## Дополнения rc3

`fieldSizing: 'content'` отключает масштабирование содержимого в `fitField`: его ширина следует слоту, высота определяется содержимым, прокручивается только поле. Используйте для таблиц и карточных сеток. Значение `'fit'` по умолчанию сохраняет прежний режим. `fieldSizing: 'content'` несовместим с `fieldAspect`; валидатор отклоняет такую комбинацию.

`ui.viewState` — локальные строки представления, не состояние правил и не сетевые данные. Кнопка `data-view-key="fleet" data-view-value="own"` переключает локальное представление. Ключ — 1–40 латинских букв/цифр с первой буквой; значение до 80 символов. Состояние сбрасывается при смене партии, зрителя или очереди; выбор доски/колонки доступен также в истории и на публичном столе. Личные игровые действия на столе по-прежнему отсутствуют.

Действие с `targetKind: 'player', targetSource: true, card: <ID>` становится доступно после выбора своей карты через H.source. Нажатие карточки соперника выполняет единственное подходящее действие. Для выбора скрытой карты задайте `targetKind: 'player', targetChoice: 'card', cardIndex: <индекс>`: штатное меню рисует ряд доступных рубашек. Индекс публичен, идентификатор и значение чужой карты в action запрещены. Команда всегда повторно проверяется правилами перед применением.

Для нескольких кубиков `data-motion-lead="roll"` ставится на каждый перебрасываемый кубик. Удерживаемые кубики не маркируются. `data-motion-effect="flip|pulse"` с `data-motion-trigger="<тип действия>"` задаёт эффект после подтверждения; `data-motion-key="index" data-motion-value="3"` ограничивает его выбранным объектом. Поля содержат только публичную информацию. Таймеры и завершение эффектов принадлежат движку; reduced motion и instant сокращают их штатно.
