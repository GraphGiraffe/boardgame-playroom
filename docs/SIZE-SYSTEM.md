# Стандартные размеры ХОД

Область применения: приложение **0.21.0** и коллекция **0.9.0**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; актуальное приложение доступно на [сайте](https://graphgiraffe.github.io/playroom-hod-test/).

Контракт приложения 0.18.4. Канонический каталог: `core/size-tokens.json`, сгенерированная браузерная копия `core/size-tokens.js`, выбор/применение: `platform/web/element-sizes.js`. Сборка обновляет копию из JSON. Паки используют `--size-*` с автономными fallback, не собственный store масштаба.

| Семейство | Стандартные значения, px |
|---|---|
| Отступы | 0, 2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 128 |
| Текст | 10, 12, 14, 16, 18, 20, 24, 28, 32, 40, 48, 64 |
| Скругления | 0, 2, 4, 8, 12, 16, 20, 24, 32, 48; круг — 50% |
| Карты, ширина | 20–120 с шагом 10; высота 7/5 ширины |
| Кубики | 20, 24, 28, 32, 36, 40, 48, 56, 64, 80 |
| Костяшки, ширина | 16, 20, 24, 28, 32, 36, 40, 48, 56, 64; высота 7/4 ширины |
| Шашки/фишки | 8, 12, 16, 20, 24, 28, 32, 40, 48, 56, 64 |
| Аватары | 20, 24, 28, 32, 40, 48, 56, 64, 80, 96 |
| Органы управления | роли 32/36/40/44/48/56/64; обычный базовый 44 |
| Предпочтительные окна | роли 320/360/480/560/640/800; ограничены viewport |

Почему не только кратность 8: для текста, мелких значков и промежуточных органов управления она слишком груба. Основной layout использует шаг 4 и крупный 8, текст — 2, рамки — 1–2. Карты имеют отдельный ряд с целой геометрией 5:7. Каталог length содержит промежуточные кратные 4 для существующих UI-ролей. Это согласованные семейства, а не требование делать все объекты квадратами 32/64.

`componentRoles` описывает основные, миниатюрные и grid карты, кубики, костяшки, шашки, фишки, аватары, кнопки, слайдеры, иконки, бейджи, счётчики, панели игроков, окна, зоны, поля ввода, speech и reveal. `bindings` — явная карта прежних CSS-значений к стандартам. Новые компоненты должны выбирать существующую роль/семейство; новый размер требует причины.

Горизонтальная игровая компоновка сначала резервирует читаемые боковые зоны: минимум144px на карточку соперника (либо больше по измеренным показателям) и240px на локальную руку с управлением. Две колонки соперников допустимы, когда после этих резервов полю остаётся200px по ширине; иначе остаётся одна прокручиваемая колонка. Поле получает оставшуюся ширину, даже если она меньше высоты экрана. Эти пределы принадлежат `composition.geometry`, не конкретному паку. Обычный ход не пересчитывает бюджет; смена viewport/явное разрешение геометрии сохраняют прежний контракт блокировки.

Одна ступень/viewport дают один размер основной карты независимо от пака. Адаптивная вёрстка размещает эти карты, а не увеличивает их под контейнер. Длинная рука/столбец прокручивается; новая карта не меняет масштаб соседних. Размеры основного арта и пустых карточных целей совпадают. Стопка drag использует размеры исходных элементов, экранные координаты не делятся на пользовательский процент.

Доска берёт наибольший стандарт, помещающийся в слот. Клетка определяется правилами и внутренними отступами; размер шашки/фишки округляется вниз к стандарту. Положение фигур, проценты, aspect ratio, геометрия SVG, исключающие зоны скина, media breakpoints и оптические смещения — явные производные/исключения, не произвольные новые базовые размеры. Ниже 160px доска сохраняет аварийный proportional fit вместо выхода за экран.

Проверки: адресный `case/interface-scale`, `case/solitaire-input`, `case/domino-layout`, `case/checkers-drag`. Не заменять их полным gate по умолчанию. Размеры DOM не доказывают все длинные игровые состояния; физическая приёмка телефона остаётся отдельной.

## Сетки и направляющие

`layoutGrids` выбирается по фактической ширине и ориентации, без деления на масштаб: на телефоне в портрете2 карточки/8 колонок, в landscape3 карточки/12 колонок и боковое меню. Featured занимает одну карточку. Масштаб меняет размеры отступов и компонентов, но не число игр в ряду. Поля12/16/24px и интервалы8/16/24px выбирают стандартные значения; максимальный контент1280px. Sidebar находится вне контентной сетки; в portrait-phone остаётся нижняя навигация. Поля игр используют собственные клетки/столбцы.

`PlayroomLayoutGuides.show({baseline:4,columns:true,centers:true,zones:true})` включает read-only overlay. `baseline:8` показывает укрупнённый шаг; `hide()` убирает overlay. По умолчанию выключен. Колонки строятся по реальным padding контентного контейнера, зоны — по DOM-прямоугольникам; поправки safe-area уже входят в реальные поля контейнера. Overlay fixed/inert/aria-hidden/pointer-events:none, не меняет hit area, сохранение или выбранный масштаб. Он обновляется при изменении DOM, viewport и прокрутке.

Направляющие показывают фактическую геометрию. Совпадение линии и границы не доказывает правильность всех состояний; оптические поправки арта, перенос действий в header-landscape и прокручиваемые длинные области проверяются по своему контракту.

## Время, визуальные параметры и компоновки

Каталог также содержит `presentation`: неизменяемые при смене масштаба задержки tooltip/drag/toast, коэффициенты перелёта и семантические CSS-параметры времени, прозрачности и обводок. `GameFlow.presets/effectTimes` остаются канонической политикой игровых режимов, без второй независимой настройки скорости. Литеральные fallback сохраняют автономные компоненты; в приложении значения берутся из каталога. Геометрия UI, время и intrinsic art не округляются одним алгоритмом.

`composition` называет текущие профили `solo-field`, `hand-table`, `card-table`, `board-table`, `player-surface`, `public-table`, их зоны/приоритеты и действующие геометрические пороги. Профиль определяется метаданными viewApi2, не ID игры; `data-composition` доступен для диагностики. Это описание существующей раскладки с вынесенными параметрами, а не новый универсальный layout engine. Fixed scene и авторизованные действия сохраняются.

Контекстные действия игрока, подтверждение цели, передача устройства и бейджи имеют отдельные места. `actionReserve` резервирует постоянные действия; popup привязан к участнику. Появление кнопки само по себе не разрешает перерасчёт поля. При нехватке места переносить/прокручивать содержимое своей зоны, не скрывать обязательное подтверждение и не масштабировать карты произвольно.

`hands` фиксирует геометрию ряда, дуги, костяшек и мини-рук. Раскрытие карт зависит от `stacking` активного скина, измеренных ранга/масти и доступной ширины; у пасьянсов закрытое/открытое перекрытие и ось сброса отдельные. `protectedZones` заданы в нормализованных координатах арта; не округлять их к4px. Независимые rotate/translate руки сохраняются при выборе и drag.

`extensibleZones` — проект контракта и прототип для просмотра: смешанные группы карт/мэплов/жетонов/счётчиков, открытый tableau, read-only inspection, тайловые поля с поворотами и раскрытие тайла при движении. Он не подключён к правилам или новому viewApi. Будущий просмотр использует только текущую разрешённую проекцию; unknown не содержит лица/URL в DOM. Жетоны привязываются к локальным координатам карты/тайла; pan/zoom viewport и поворот тайла независимы. До принятия команды preview не меняет состояние; reveal следует принятому событию. Новые игры этим не добавлены.

Полный локальный аудит, таблицы и автономная лаборатория: `../tmp_files/standard-sizes-2026-10-20/`. Статические числовые кандидаты в тенях, слоях, арт-координатах и адаптивных формулах требуют семантического review; их наличие не является само по себе дефектом. Полное покрытие всех игровых состояний и устройств не заявляется.

## Эталон100%: опубликованная0.18.3

`uiBaseline` закрепляет release0e930347b439e29f0d8e1294b00de3491faaffbe. Прежняя попытка `uiDensity` отменена: меню, окна, библиотека, отступы и типографика используют исходные app CSS. При100% это исходная компоновка, а не новый увеличенный preset. Отдельный `--ui-interface-scale` повторяет прежнее масштабирование оболочки и порталов; игровая сцена не получает компенсирующий zoom, размеры игровых компонентов по-прежнему дискретные. Центровка и две колонки телефонной библиотеки сохраняются без общей подмены шрифтов/кнопок. На широком экране библиотека добавляет колонки по доступной ширине контейнера (минимум 200px на карточку), а не растягивает три карточки на весь экран.

Рабочие режимы владельца при100% браузера:384×725 (портрет с адресной строкой),384×797 (полный портрет),797×354 (полный альбом); safe-area-bottom15px в полных режимах. ClientHeight может сохранять прежнюю высоту после скрытия адресной строки, поэтому при scale1 для доступной высоты используется visualViewport.height; это не причина заново увеличивать интерфейс. Старые замеры при80% не используются как baseline.


### Приёмка телефона, 21 октября

Базовый масштаб меню остаётся близким к опубликованной 0.18.3. Заголовок главного экрана — две строки без точек. В «Мои партии» статус обозначается паузой/кубком размером `1em` рядом с типом партии; прогресс в той же верхней строке: раунд → ход → действия. Режим обычным шрифтом рядом с жирным названием; версия/дата и действия образуют компактный нижний ряд.

Кубики роли `board-dice` (Лудо и Змеи) используют 64 px, на коротком горизонтальном экране — 48 px; обычные группы кубиков сохраняют свою роль. Поправка броска не сдвигает центр ряда. История не резервирует место под игровые кубики/поправку. Собираемое поле подбирается по доступной области с шагом 4 px; отдельные игровые компоненты сохраняют стандартные размеры. Карта 48 px добавлена как компактный стандарт для семи колонок; Косынка сохраняет его при повороте телефона.

В Змеях позиция 0 не отображается фишкой на первой клетке. Вход анимации использует скрытый центр первой клетки, а не угол. Змеи и лестницы рисуются целиком по верхней клетке от верхних рядов к нижним. Анимация позиции меняет только SVG-текст счётчика, сохраняя медальон.

Тип сетевой партии использует `surface.tile-blue` (#dbe9e8 в светлой теме); локальная подложка прежняя. В лобби локальный цвет остаётся `action.primary`, сетевой — смесь 70% `side.blue` и 30% `text.primary`. Фон, надписи и ползунок используют общий `--ui-duration-transport:150ms`; reduced/instant motion отключает переход согласно общей политике. Переключатель сохраняет свой DOM-узел.


Лобби с несколькими игровыми местами использует доступную высоту viewport с внешними полями 20 px. Высота не фиксируется в пикселях при смене транспорта и меняется вместе с адресной строкой/ориентацией; лобби одного игрока использует тот же большой профиль и один слот. Резерв кнопки добавления сохраняется. Проверка: `tmp_files/phone-polish-2026-10-21/lobby-height/report.json` в рабочем контейнере BoardGames.

### Общие кнопки, окна и длинные названия

Канонический генератор кнопок — `shared/components/game-components.js` в репозитории паков; приложение получает его при сборке. Приложение использует `TabletopUI.button(options)`, renderer пака — `H.button(options)`. `icon` и `label` задаются независимо, хотя бы одно обязательно. Для кнопки только с иконкой нужен `ariaLabel`. Иконка всегда перед подписью. Пример: `button({icon:'play',label:'Новая партия',attrs:'data-command="home"'})`. `attrs` — только доверенная разметка разработчика; подписи экранируются. Варианты `primary`, `secondary`, `danger`, `plain`, `outline`, `game` задают классы оформления; `disabled`, `active`, `type` сохраняют семантику кнопки. Размеры и оформление находятся в каноническом `game-components.css`, параметры — в `size-tokens.json`; индивидуальные экраны не дублируют оформление. Старые `.btn` остаются совместимыми алиасами. Игровые карты, кубики и счётчики сохраняют собственные общие компоненты.

Большие окна используют единый профиль `data-dialog-size="large"`: внешние поля 20 px, одинаковые ширина, доступная высота и внутренние поля. `openModal` выбирает профиль по содержимому или явному `size:'large'`; подтверждения остаются компактными. В лобби заголовок комнаты, конфигурация игры и нижние действия закреплены; прокручивается только `.lobby-roster-scroll`. Добавление игрока находится в нижнем блоке, его место сохраняется при переключении транспорта. Карточки партий и лобби используют поверхности палитры без отдельной белой подложки.

Приложение и просмотрщик SDK используют общие пределы ширины поверхностей. Выдвижные панели центрируются у нижнего края и занимают до 36 rem, экраны центрируются по горизонтали и занимают до 48 rem. Окно приветствия занимает до 32 rem, экран аккаунта — до 36 rem. Правила с иллюстрациями используют панель до 48 rem. Итоги занимают до 42 rem, а на экранах от 600 × 601 px центрируются по обеим осям и подстраивают высоту под содержимое. На телефоне поверхности сужаются до ширины окна и учитывают безопасные области.

Игровой заголовок занимает одну строку и не расширяет панель инструментов. `GameScreen.gameTitle` / `fitGameTitles` подбирают стандартный размер шрифта до 14 px, затем пробуют необязательный `manifest.shortName`; при дальнейшей нехватке места показывается многоточие. Полное `name` сохраняется в tooltip. `shortName` — непустая строка до 60 UTF-16 единиц; одинаковая проверка действует при сборке и импорте пака. Сокращение относится к тесной игровой шапке и лобби; полное имя в каталоге сохраняется.

Лобби всех игр используют общий большой профиль, включая пасьянсы. Для игр с `constraints.max === 1` транспорт виден, зафиксирован в локальном положении и неактивен с серым оформлением; сетевой режим дополнительно запрещён сервисом комнат.

### Колода и сброс на игровом поле

Профиль `stock-discard` в ХОД и SDK масштабирует центральные карты по выделенной области поля. Ширина ограничена меньшим из 16% ширины и 21% высоты поля, базовым размером карты в руке снизу и 9 rem сверху. Пропорция карты 5:7, обе стопки и пустой слот используют одинаковый расчёт. Рука и карточки игроков используют свои размеры. Выбор карты, изменение счётчика и история сохраняют геометрию для текущего viewport.

### Примагничивание при переносе

Общий `core/input.js` выбирает разрешённую цель по указателю, затем по пересечению ведущего элемента призрака и небольшому зазору `presentation.interaction.dragMagnetPx` (8 CSS px, ограничен четвертью меньшей стороны элемента). Соседние области разделяются сравнением нормированных расстояний между центрами; подсвечивается только выбранная цель. Стопка использует геометрию первой карты. Отпускание пересчитывает ту же цель и выполняет только её разрешённое действие. Скрытые, перекрытые, обрезанные и недоступные цели не притягивают элемент. Точные составные размещения в клетках сохраняют привязку исходной клетки/сегмента; недопустимая клетка не перенаправляет ход на соседнюю. Отмена, жест прокрутки и проверка доступности действия сохраняются.

## Выделение текста

Общее правило `app/styles.css`: интерфейс не выделяется. Исключения — input, textarea и contenteditable (включая вложенный текст); contenteditable=false снова запрещает выделение. Не блокировать selection/copy/paste глобальными JS-обработчиками: поля должны сохранять штатное редактирование и копирование.


## Компактные действия при масштабе

`PlayroomInterfaceScale.sync` вычисляет `data-ui-compact` по доступной ширине оболочки: ширина viewport / применённый масштаб, порог 360px. Узкие правила оболочки используют этот признак, поэтому увеличение до 110–120% на телефоне включает те же компактные действия, что узкий экран при 100%. Возврат масштаба или расширение окна восстанавливает обычные квадратные кнопки. Брейкпоинты игровых сцен и число карточек библиотеки остаются отдельными контрактами.

Быстрые действия в заголовках, правилах, настройках и лобби — 32px в компактном режиме. Слоты лобби резервируют место под две такие кнопки; min-width:0 разрешает колонкам сжиматься без обрезания правого края. Форма никнейма содержит только аватар и поле, без пустой колонки прежней кнопки сохранения. Позиции и центры измеряются в экранных координатах после zoom.


Физические карты/слоты/кубики используют пропорциональное скругление собственного SVG, а не фиксированный token радиуса панели. Для колоды5:7:12.5% поX /8.928571% поY; квадратная карта12.5%; кубик11/60 стороны. Внешняя обёртка не должна повторно обрезать уже оформленную каноническую карту. Mini/UNO/solitaire согласованы с тем же физическим кадром; контролы/панели сохраняют свои UIтокены.

## Карточки параметров

При обычном масштабе телефонная сетка сохраняет два столбца, включая viewport320px; минимальная ширина карточки8rem. Сильно увеличенный текст или более узкая область могут перевести сетку в один столбец. Явно объявленная автором широкая карточка режима сохраняет свой профиль.

Карточка использует собственную высоту, не растягивается под соседа; заголовок резервирует32px или фактическую высоту текста, кнопки сохраняют44px hit-area. Варианты получают ширину по подписи и естественно помещаются в одну строку только когда полностью вмещаются подписи; четыре числовых —2×2. Подпись остаётся над опциями, envelope заранее учитывает все варианты.

Публичные SVG с `data-art-role="parameter-diagram"` сохраняют авторскую единицу как CSSpx и исходный размер плоскости. `getBBox()` используется только для центровки видимого изображения, без увеличения до границ контейнера. Область арта96px высотой у обычной карточки и160px у явно объявленного широкого режима со сложным рисунком. Широкие схемы команд и флота используют естественную высоту с минимумом96px; содержимое центрировано по обеим осям. При недостатке ширины допустимо только уменьшение всей плоскости. Общий стол в стандартном поле и авторском арте использует одну плоскость120×72 и одинаковый физический размер.

Карты в обычных параметрах36×50.4px; кубики40×40px; одиночный служебный значок44px. Число карт меняет перекрытие и состав, а не размер карты. Масштаб авторских элементов и их центр проверяются при переключении всех вариантов, одинаковые примитивы сравниваются между связанными параметрами. Исключений по ID игры в компоновке хоста нет.

## Пункты параметров

Три роли используют общую геометрию `.preference-row`: строка от 56 px, симметричные вертикальные отступы 12 px, подпись стандартного размера label, значок 24 px справа и нижняя линия. Длинный текст увеличивает высоту без смещения центра.

- `--navigation`: переход к самостоятельному экрану из раздела «Параметры», заголовок выделен.
- `--control`: непосредственное изменение параметра (переключатель, уведомления, ползунок), обычное начертание. Ползунок занимает отдельную компактную строку под подписью.
- `--action`: панель выбора или подтверждения в аккаунте и менеджере игр, обычное начертание; опасные действия используют общий цвет ошибки.

Уведомления включаются непосредственно в аккаунте и на вкладке «Поведение» настроек; отдельного экрана нет. Состояние отображается стандартным тумблером (native checkbox с ролью switch) и его accessible label, отдельная подпись не резервируется.

У каждого переключателя параметров есть кнопка всплывающей справки рядом с названием. Она доступна и при выключенном или недоступном переключателе; её нажатие и закрытие не меняют значение. Справка общих параметров находится в каталоге сообщений приложения.

В аккаунте никнейм и аватар редактируются отдельно от учётных данных. Пункт «Онлайн аккаунт» открывает вложенную панель с @именем, e-mail и действиями аккаунта; каждый редактор возвращается в неё на один уровень. Вход и регистрация имеют две вкладки, восстановление открывается отдельным пунктом входа.

Карточка профиля читает метаданные текущего аккаунта сразу из отдельного кэша и обновляется при завершении фоновой синхронизации. Кэш хранит только публичные username/nickname, разделён по authenticated user ID и не используется для авторизации. При проверке сохранённой сессии пункт «Онлайн аккаунт» остаётся доступен для просмотра; действия изменения данных сохраняют обычные проверки готовности сессии.
