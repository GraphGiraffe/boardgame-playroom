# Пасьянсы: рамки только для запрошенной подсказки

Область применения: приложение **0.21.0** и коллекция **0.9.0**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; актуальное приложение доступно на [сайте](https://graphgiraffe.github.io/playroom-hod-test/).

Решение пользователя от 19.10.2026 для будущих Паука и Косынки. **Спецификация, не выполненное изменение shared UI.** Поведение других игр сохраняется.

## Принятое поведение

| Состояние | Рамки доступных действий |
| --- | --- |
| Старт, обычная игра, hover | Нет |
| Выбран источник вручную | Не включаются все возможные цели; выбор можно показать заливкой/небольшим подъёмом |
| Drag над целью | Не включается обзор всех legal targets; локальная обратная связь без рамки доступности |
| Вызвана «Подсказка» переноса | Только рекомендованная карта/подгруппа и конкретная цель |
| Подсказка добора | Только источник добора; не все десять колонок Паука |
| Нет кандидата | Нет рамок, короткое неблокирующее пояснение |
| Replay, pause, handoff, чужая аудитория | Нет активной игровой подсказки |

Это правило о **доступности действий**. Рамка клавиатурного focus-visible остаётся у фактически сфокусированного элемента для доступности; она не обозначает рекомендацию. Тема/границы самой карты также не являются рамками доступности.

## Одна рекомендация, а не все ходы

Подсказка содержит один exact legal command и отдельные ссылки на видимые объекты источника/цели. Для подгруппы выделяется только переносимая часть, без закрытых и неучаствующих карт этого же столбца. Одна общая обводка группы предпочтительнее 13 наложенных колец. Пустая цель имеет форму карточного слота; рамка не выходит на всю строку поля.

Повторный вызов может показать следующий кандидат из текущей позиции, но предыдущие рамки сначала удаляются. Никаких накопленных рамок «всего, что когда-либо предлагали». Текст, цвет/рамка и доступные имена относятся к одной рекомендации.

В узком поле source и target могут находиться в разных частях горизонтального scroll. Подсказка сообщает номера столбцов и позволяет показать нужную область; не уменьшает всё поле автоматически и не перетасовывает столбцы. При необходимости «Показать цель» меняет только положение viewport, не выполняет команду и не блокирует ручную игру.

## Жизненный цикл и безопасность

- Состояние hint привязано к audience/session/pack/revision и конкретной команде. После изменения позиции старый hint не воспроизводится.
- Успешное действие, Undo, restart, смена игры, уход в историю/паузу и явная отмена очищают подсказку. Другой ручной выбор также убирает прежнюю рекомендацию.
- Изменение масштаба/ориентации только пересчитывает геометрию актуального hint; оно не даёт право восстановить подсказку старой позиции.
- Простой render/resize не вызывает поиск всех ходов и не включает рамки по умолчанию. Восстановление игры не восстанавливает старую UI-подсказку.
- Hint — viewState/рекомендация, не действие бота: не расходует RNG, не повышает revision, не выполняет перемещение. Возможный штраф счёта допустим только как отдельное утверждённое правило, не отрисовочный эффект.
- Поиск использует только разрешённую projection и legal commands без скрытых параметров. Он не подглядывает будущую карту stock и не выдаёт её ID через DOM.
- Простой детерминированный порядок кандидатов допустим: открытие новой карты, полезная одномастная сборка/дом, освобождение столбца, затем законный добор. Это наша эвристика, не воспроизведённый алгоритм XP и не solver.
- Hint не гарантирует победу. «Не найден полезный совет» не равно «нет легальных ходов» или «расклад неразрешим».

## Что менять в существующем UI при реализации

`core/ui.js:186` сейчас добавляет `.is-playable` каждому доступному source. В каноническом `playroom-paks/shared/components/game-components.css:30` общий selector обводит `.is-playable` и `.is-selected` с `!important`. `boardTarget` тоже имеет оформление цели. Поэтому недостаточно только перестать передавать какой-то CSS-класс в одном renderer: нужно проверить все пути source/target, selection, drag, empty-cell и shared component styles.

Предлагается общий opt-in режим визуальной обратной связи для пасьянсов. Название поля/атрибута определяется при реализации, не объявляется уже существующим API. Legality, кликабельность, data-action/data-select, drag/swipe и accessible labels остаются полноценными; визуальное множество hint-объектов отделено от множества разрешённых действий. Не фильтровать actions до одного совета ради нужной картинки — это сломает ручную игру.

Изменения канонических shared styles делаются в коллекции и синхронизируются builder, не правкой generated host copies. Другие паки не теряют привычные рамки. В opt-in пасьянсе не наследуется рамка `.is-selected` как скрытый способ снова показать все доступные действия.

## Точечная приёмка после реализации

Оба пасьянса: 0 action outlines до запроса; source+конкретный target после Hint; остальные legal actions доступны, но без рамок; одна рамка при рекомендации draw; корректный перенос подгруппы; нет старых рамок после следующего hint/команды/Undo/reload. Проверить keyboard focus отдельно, формы рамок, масштаб/поворот, offscreen target и reduced motion. Один regression существующей карточной игры должен подтвердить, что её обычная подсветка не изменилась.
