# Адаптивная компоновка: ПК и планшеты

Локальная проверка 22 октября 2026; изменения ещё не опубликованы.

## Применённые принципы

[web.dev: Responsive web design basics](https://web.dev/articles/responsive-web-design-basics) рекомендует выбирать переходы по содержимому и доступному месту, начиная с малого экрана; длинные текстовые строки ограничивать, а промежуточные размеры проверять в браузере.

Для ХОД это означает:
- Библиотека использует `auto-fill/minmax` с минимумом 200px на карточку. `auto-fill` сохраняет размер карточек даже в коротком списке избранного. При 100% UI: 820px — 3 колонки, 1024px — 4, 1440px — 5, 1920px — 6. Прежний максимум ширины содержимого сохраняется.
- Телефон сохраняет две портретные и три компактные альбомные колонки, включая изменение масштаба UI. Масштабировать весь интерфейс ради заполнения монитора не нужно.
- Формы и окна остаются ограниченной ширины; основные действия закреплены снизу, действия отдельных полей остаются возле полей. Панель быстрых действий сохраняет расположение.
- Игровые размеры задаются семантическими стандартами отдельно от библиотеки. Поля остаются квадратными; увеличение карточек каталога не влияет на карты в руках. Свободное место за столом само по себе не требует увеличения всех компонентов.

## Проверенный объём

Снимки библиотеки: 390×844, 820×1180, 1024×768, 1440×900, 1920×1080; горизонтального переполнения нет. Начальные сцены UNO, Морского боя и Лудо, лобби и темы проверены при 820×1180 и 1440×900; настройки — 1024×768. Это проверка настольного Chromium, не физического планшета и не всех стадий партии.

Дополнительно: изменение правил сетевой комнаты вызывает общий toast один раз на ревизию, без встроенного сообщения и повторов при перерисовке. Готовность по-прежнему сбрасывается правилами комнаты. Игровые кнопки получают обычный второстепенный цвет темы вместо отдельной светло-зелёной заливки.
