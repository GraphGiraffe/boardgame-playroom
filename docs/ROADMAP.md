# Roadmap · подготовка 0.16

Единственный актуальный список работ. База — стабильное приложение 0.15.0 и коллекция 0.4.0. Выполненное описано в [релизе](RELEASE-0.15.md); исходные номера LAN сохранены для связи с историей Git. Статус «частично» означает конкретный остаток, а не отсутствие работающей функции.

## Объём 0.16

Кандидат реализует монитор связи/фона без внешнего signalling, безопасный pending retry, инкрементальную историю с тремя курсорами, диагностику клиента и ручной Pages pipeline. См. [состав и ворота приёмки](RELEASE-0.16.md). Приведённая ниже таблица фиксирует стабильную 0.15; физическая сеть и живой deploy не считаются проверенными только по коду кандидата.

## Следующие задачи по приоритету

1. **P1 · ICE-01 + остаток LAN-03/02:** диагностика разрывов/сна/VPN, чёткие состояния подключения, инкрементальная история. Критерий: повтор команды не делает второй ход; смена канала не раскрывает руку и не откатывает ревизию.
2. **P1 · DEPLOY-01:** публиковать точный проверенный release ZIP на прежний Pages origin, с fail-closed Worker и rollback; подробности в [плане деплоя](CLOUDFLARE-PAGES-DEPLOY-PLAN.md).
3. **P1 · AUTHOR-01 / ASSETS-01:** расширить эталоны и диагностику авторских паков, проверять установку/сохранение/replay и ресурсы без CDN.
4. **P1 · LAN-05 → LAN-06:** согласовать права на паузу, лимиты и истечение времени; реализовать authority-время с durable событиями и обратным отсчётом 3–2–1 для таймерных игр. Ни один клиент не назначает штраф сам.
5. **P2 · BOTS-02 / LAN-09 / LAN-10:** сложность ботов по capability пака, временная замена, затем 6–8 участников с мобильной приёмкой.
6. **P2 · LAN-11 / HUB-01:** командный контракт; фильтры, сортировка, избранное и скрытие игр в хабе. Развитие доступности, клавиатуры и compact/main остаётся сквозным требованием.
7. **Future · GAMES-01…13 / SERVICE-01:** новые паки и отдельный онлайн-сервис; порядок игр уточняется при выборе следующей задачи.

## Сохранённые требования к будущим функциям

- Паузы: квота 0–10, по умолчанию 2; хосту опция «Неограниченно». Для таймерной игры возобновление 3–2–1 с замороженными часами. Права вне очереди, снятие чужой паузы и длительность требуют продуктового решения.
- UNO по времени: опциональный расход паузы либо +2 карты; поведение при исчерпанной квоте и момент предупреждения ещё согласовать. Повтор сети/восстановление не назначает штраф дважды.
- Будущие модели часов: per-turn/per-game/team, прибавления и контроли для шахмат; это не текущие поля manifest/API.
- Разрыв не означает выход, автоматический штраф или включение бота. Передача управления должна исключать двух активных владельцев места.
- Авторские инструменты: каталог, доверие/подписи, изоляция недоверенного JS, миграции и автообновления — отдельные задачи. Сейчас установленный пак является доверенным кодом.
- SERVICE-01: self-hosted/cloud сервис, discovery/signalling, STUN/TURN, друзья/приглашения, приватные комнаты, согласованная облачная синхронизация и позже host migration. Архитектуру authority, аккаунты и стоимость relay выбирать отдельно; базовая LAN-игра не требует сервиса.
