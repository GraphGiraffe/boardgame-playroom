# Контракт движка и пакетов игр

[Общий индекс 0.15](DEVELOPER-INDEX.md) · [Реестр правил и боты](DEVELOPER-GAMEPLAY.md) · [Установка и форматы хранения](DEVELOPER-DATA.md) · [Интерфейс GameScreen](DEVELOPER-UI.md)


API движка: **1**; API представления: **2**. Пак содержит правила, конфигурацию и оформление одной игры. Ядро не импортирует готовые игры. Установка и обновление выполняются менеджером паков, в том числе в автономном HTML.

## Структура и установка

Канонический исходный каталог пака находится в отдельном репозитории `boardgame-playroom-paks`:

```text
packs/my-game/
  manifest.json
  rules.js
  view.js
  styles.css
  sounds.js       необязательная звуковая библиотека
  assets/         необязательные локальные ресурсы
```

`manifest.json` содержит идентификатор, версию, совместимость `engineApi: 1` или `2`, обязательный `viewApi: 2`, `stateVersion`, описание для хаба и пути к компонентам. Полный переносимый формат и ограничения описаны в [PACK-FORMAT.md](PACK-FORMAT.md). Сборщик создаёт `.playroom-pack.json`; пользователь устанавливает его через «Паки игр». Изменять подключения в `index.html` не требуется. `manifest.js` в исходных паках — генерируемый мост для прежних модульных проверок; источником метаданных является JSON.

Категории хаба: `cards`, `board` и `dice`. `capabilities.hands: true` включает настройку открытых рук. При `false` или отсутствии признака она не показывается. Параметры формы запуска задаются массивом `settings` в манифесте.

Практический цикл и эталон private-counter описаны в [руководстве автора](https://github.com/GraphGiraffe/boardgame-playroom-paks/blob/v0.4.0/docs/AUTHORING.md); дальнейшие SDK-инструменты перечислены в [Roadmap](ROADMAP.md). Ниже приведены механизмы паков; текущий сетевой транспорт описан в [DEVELOPER-MULTIPLAYER](DEVELOPER-MULTIPLAYER.md).

## Правила

`rules.js` вызывает `TabletopCore.register(pack)`. `id` должен быть уникальным. Функции пакета:

| Поле | Контракт |
| --- | --- |
| `id`, `name` | Машинный идентификатор и название |
| `min`, `max` | Допустимое количество игроков |
| `description`, `rules` | Описание и массив текстовых правил для интерфейса |
| `presets` | Массив `{id, label}` доступных наборов; первый используется по умолчанию |
| `scoreLabel` | Название игрового показателя |
| `create(state, options)` | Заполняет `state.data` и начальную очередь |
| `legal(state, actor)` | Возвращает обычные действия текущего игрока |
| `reactions(state, actor)` | Необязательные реакции участника, в том числе вне очереди |
| `botReaction(state, actor, actions)` | Необязательный выбор реакции бота из переданного списка или `null` |
| `apply(state, actor, action)` | Изменяет выделенную копию состояния; определяет следующий ход и исход |
| `project(out, viewer, fullState)` | Необязательный фильтр игровой информации перед выдачей зрителю |
| `bot(state, actor, actions)` | Необязательный выбор одного допустимого действия; по умолчанию берётся первое |
| `validateState(state)` | Необязательная проверка схемы и инвариантов пакета; выбрасывает исключение при повреждённых данных |

Данные состояния и действия должны сериализоваться в JSON: обычные объекты, массивы, числа, строки и булевы значения. Методы, DOM-узлы, `Map`, `Set`, `Date` и циклические ссылки не являются состоянием игры.

Пакет отвечает за механику: очерёдность, ограничения хода, подсчёт результатов, победу, ничью и тексты событий. Общие функции ядра доступны как `TabletopCore`:

| API | Результат |
| --- | --- |
| `GAMES` | Метаданные зарегистрированных игр |
| `get(id, version?)` | Полный объект выбранной версии пака |
| `createGame(id, options)` | Новое полное состояние |
| `legalActions(state, actor = state.turn)` | Обычные действия текущего игрока плюс его реакции; вне очереди — только реакции; после окончания — пустой массив |
| `applyAction(state, actor, action)` | Новая копия состояния после допустимого действия; иначе исключение |
| `project(state, viewer)` | Новая проекция состояния с учётом видимости |
| `botAction(state, actor = state.turn)` | Обычный ход бота из `pack.legal` или `null` |
| `reactions(state, actor)` | Допустимые реакции участника; без хука пакета — пустой массив |
| `botReaction(state, actor)` | Выбранная реакция бота или `null` |
| `validateState(state)` | Проверяет общую форму состояния и `pack.validateState`; возвращает `true` или выбрасывает исключение |
| `random(state)`, `shuffle(items, state)` | Случайность из состояния; `shuffle` возвращает новый массив |
| `rollDie(sides, state)` | Результат броска кубика с 2–1000 гранями |
| `event(state, text, player, kind, extra)` | Добавляет событие в журнал |
| `finish(state, winner, text, points = 1)` | Завершает партию и начисляет очки. `winner: null` означает ничью; массив индексов победителей доступен в engineApi 2 и записывается как `state.winners` |
| `clone(value)`, `hidden(cards)` | JSON-копия и массив рубашек `{hidden: true}` |

Основные опции: `players: [{name, bot}]`, `preset`, `seed`, `openHands`. Пакет может читать дополнительные опции. `mode: 'solo' | 'pass'` используется оболочкой и сессией; ядро не зависит от способа ввода.

Ядро создаёт состояние `{version, game, preset, players, turn, status, winner, move, rng, openHands, data, events}`. `players` содержат имя, признак бота и счёт. `turn` — индекс текущего игрока; `status` принимает `playing` или `finished`. Для нескольких победителей итог также хранит `winners`; `winner` остаётся первым индексом для совместимости. `applyAction` проверяет действие по списку допустимых, клонирует исходное состояние, увеличивает `move` и передаёт копию в `apply` пакета. Текст `label` не участвует в сопоставлении действий. При одинаковом seed и последовательности действий генератор ядра воспроизводит одинаковые броски и перемешивания.

Не изменяйте состояние в `legal`, `reactions`, `bot`, `botReaction` и `project`; изменения выполняются в `create` и `apply`. Используйте `random(state)` внутри применения действий вместо `Math.random()`, чтобы сохранять воспроизводимость. Действия бота должны выбираться из переданного массива `actions`.

## Звуковые события

Правила описывают смысл звука через необязательное поле `extra.sound`; они не воспроизводят звук и не зависят от браузера или Web Audio:

```js
Core.event(state, 'Игрок берёт две карты и пропускает ход', target, 'draw', {
  sound: { id: 'attack.light', target }
});
```

`sound` — JSON-объект `{id, target?}` с одним основным сигналом. `id` — ключ библиотеки звуков, `target` — необязательный публичный индекс участника, на которого направлено действие. Например, у взятия шашки это владелец сбитой фигуры, а у `+4` — получатель штрафных карт. Не записывайте сюда закрытые номиналы, масти, идентификаторы карт или содержимое колоды. Для источника действия уже существует `event.player`.

Общие ключи библиотеки: `move`, `draw`, `victory`, `defeat`, `draw-game`, `attack.light`, `attack.heavy`, `attack.skip`, `attack.capture`, `attack`, `defend`, `reverse`, `dice`, `climb`, `fall`, `penalty`, `notify`. Они пишутся без префикса `standard.`. Пакет может определять собственные ключи в своём пространстве имён, например `uno.call`, и хранить их звуковые ресурсы внутри пакета. Ключ выбирает эффект, а не является URL или исполняемым кодом.

Библиотека общих звуков и регистрация звуков пакета отделены от правил. Настройка громкости, разрешение воспроизведения после пользовательского жеста, очередь сигналов и отключение звука принадлежат оболочке. Для конечного события `finish` оболочка выбирает `victory`, `defeat` или `draw-game` с позиции текущего зрителя; пакет не должен угадывать эту позицию или добавлять второй сигнал победы.

Метаданные имеют приоритет над общим соответствием `event.kind`. Старые сохранения без `sound` остаются совместимыми: оболочка применяет резервное соответствие по типу события, не анализируя текст на русском или другом языке. При добавлении метки не меняйте число событий, их текст или механику хода. Штрафной добор может оставаться событием `draw`, но иметь `sound.id: 'penalty'`; не дублируйте его обычным сигналом добора. Совмещённое событие «Змей и лестниц» использует `climb`/`fall` при переходе и `dice` при обычном броске. Тихий добор в конце захода дурака не требует нового события только ради звука.

## Скрытая информация и несколько зон

Проекция удаляет генератор `rng`, закрывает чужие `data.hands`, а также `data.drawPile` и `data.stock`. При `openHands` руки открыты участникам, но не анонимному зрителю. Индекс зрителя `-1` подходит для публичной проекции.

Событие с `extra.privateTo` отображается полностью только указанному игроку или участникам из непустого массива уникальных индексов. Остальным выдаётся `extra.publicText` или нейтральный текст, без `transfer`; `publicSound` определяет допустимый звук для остальных. Не помещайте закрытые значения в общий текст события. Для закрытой передачи карты в Акулине адресаты — берущий карту и владелец руки; публичный сброс пары остаётся отдельным событием. Уменьшение/увеличение публичного счётчика руки при этом наблюдаемо.

Для произвольных колод, сбросов, полей, фишек и показателей можно использовать зоны:

```js
state.data.zones = {
  deck: Core.createZone('deck', {items: cards, visibility: 'hidden'}),
  hand: Core.createZone('hand', {type: 'hand', owner: 0, visibility: 'owner'}),
  discard: Core.createZone('discard', {visibility: 'public'})
};
Core.moveComponent(state.data.zones, 'deck', 'hand', cards[0].id);
Core.reveal(state.data.zones, 'hand', cards[0].id, true);
```

`Core` здесь обозначает `TabletopCore`. У компонента нужен уникальный `id` внутри зоны. `moveComponent` переносит компонент в конец целевой зоны или на переданный пятый аргумент `index`. `reveal(..., false)` снова закрывает компонент. Флаг `revealed` следует за компонентом при перемещении — при необходимости пакет должен сбросить его явно.

Произвольные зоны фильтруются в обработчике пакета:

```js
project(out, viewer, fullState) {
  out.data.zones = Core.projectZones(fullState.data.zones, viewer);
}
```

Ядро не может угадать конфиденциальность произвольных полей `data`. Пакет обязан закрыть свою дополнительную информацию в `project`. Экспорт сессии содержит полное состояние; его нельзя раздавать соперникам как публичный сетевой пакет.

## Представление

`view.js` регистрируется отдельно от правил:

```js
PlayroomViews.register('my-game', render, cover);
```

`render(projectedState, viewer, actions, ui)` возвращает объект игровых элементов API 2, а не HTML сцены; см. [GAME-ELEMENTS-API](GAME-ELEMENTS-API.md). В manifest обязательно `viewApi: 2`; старый API не поддерживается. Он получает уже отфильтрованное состояние; `actions` содержит только доступные текущему зрителю действия. `ui.selected` — выбранный компонент, `ui.flipped` — предпочтение ориентации стола. `cover()` возвращает обложку в виде inline SVG с `viewBox="0 0 300 180"`.

Общие компоненты определены в `core/ui.js` и доступны через `TabletopUI.helpers` или совместимое `PlayroomViews.helpers`. Имена, тексты и сериализованные действия экранируются перед вставкой в HTML. Используйте действующие пакеты как примеры визуальных компонентов.

Метод `handleClick` контроллера `TabletopInput.attach()` обрабатывает кнопки с `data-action` — JSON допустимого действия. `data-select` и `data-cell` меняют `ui.selected`. Выбор компонента не является ходом до отправки действия. Оболочка управляет таймером ботов, передачей телефона и повтором истории.

Стили игры ограничиваются её корневым классом, например `.my-game-scene`; общие игровые компоненты лежат в `core/ui.css`. Ресурсы помещаются внутрь `assets/` своего пакета. Локальные CSS `url(...)` включаются в автономный HTML при сборке. Изображения в строках JS должны быть inline SVG или data URL: сборщик не переписывает динамические строки JavaScript. Не используйте внешние шрифты, CDN и сетевые зависимости для обязательного интерфейса.

## Выбор компонента и перетаскивание

Общий браузерный модуль `core/input.js` и его `core/input.css` отвечают за указатель и визуальную копию перемещаемого компонента. Они не импортируют правила игры и не выбирают ход самостоятельно; исполнение правил и сессии остаются независимыми от DOM. Ввод и UI входят в самостоятельный архив движка как подключаемые модули.

Обычно пак использует общие конструкторы, а не собирает поведение вручную:

```js
const H = TabletopUI.helpers;
const component = H.source(card.id, actions, ui.selected, {
  key: 'card', mode: ui.quickPlay ? 'immediate' : 'select',
  preview: true, inspect: true, drag: true, swipe: true
});
const cardHTML = renderCard(card, component.attr, component.className);
const targetAttrs = H.target(card.id, chosenAction);
const handHTML = H.hand(cards.map(renderHandCard), cards.length, '', '', {layout: 'fan'});
```

`chosenAction` берётся из доступных действий. `H.target(id)` без действия оставляет компонент выбранным для дополнительного выбора. Для шашек `key: 'from'` связывает действия с исходной клеткой; геометрия поля и правила взятия остаются в паке. Режим `immediate` выполняет только единственный доступный вариант. `inspect: true` позволяет рассмотреть даже неходовую карту без создания хода. Общая раскладка руки, открытые руки соперников, фокус, preview и обработка жестов находятся в движке. Параметры `source`, собственная разметка цели и стили в корневом классе пака позволяют изменить поведение без копирования общей реализации.

При необходимости пак может описать тот же контракт атрибутами:

- `data-select="piece-id"` на кнопке компонента выбирает его обычным кликом или тапом;
- `data-drag-piece="piece-id"` на той же кнопке разрешает начало перетаскивания;
- `data-drop-piece="piece-id"` и `data-action="..."` на кнопке цели связывают её с выбранным компонентом и конкретным допустимым действием.

`data-action` содержит экранированный JSON действия из `actions`. На самой выбираемой костяшке домино его нет: выбор показывает варианты постановки и не меняет состояние игры. Пакет отображает только разрешённые цели и сохраняет обычный клик по цели как альтернативу перетаскиванию. Заблокированные кнопки и цели другого компонента не принимают сброс.

Оболочка подключает ввод один раз:

```js
const input = TabletopInput.attach({
  getSelected() { return selectedPieceId; },
  canSelect(element) { return hostCanInteract(element); },
  canCommit(element) { return hostCanInteract(element); },
  canStart(element) { return hostCanInteract(element); },
  select(pieceId) { selectPieceAndRender(pieceId); },
  commit(action) { applyValidatedAction(action); }
});
// После обработки собственной навигации оболочки:
scene.addEventListener('click', event => input.handleClick(event));
// При смене режима можно отменить незавершённый жест:
input.cancel();
// При удалении оболочки — снять все обработчики:
input.destroy();
```

Имена `selectedPieceId`, `scene`, `hostCanInteract`, `selectPieceAndRender` и `applyValidatedAction` в примере обозначают функции приложения. `canStart` учитывает очередь игрока, паузу, повтор и экран передачи устройства. `select` может синхронно перерисовать сцену. `commit` получает действие после завершения жеста и удаления визуальной копии; оболочка снова проверяет его через ядро. Движение указателя само по себе не является игровым действием.

Вертикальный жест прокручивает ближайший переполненный контейнер от руки до `.layout-self`; горизонтальный контейнер определяется отдельно. Жест можно начать за любой элемент руки, включая недоступный для хода; быстрый свайп в таком случае не играет карту. Удержание до начала движения сохраняет drag-and-drop. Это позволяет использовать общую руку с перекрытием в несколько рядов на горизонтальном телефоне, не копируя обработчики в пак.

Горизонтальный жест в `.hand-track` или элементе с `data-hand-scroll` прокручивает руку, только если её содержимое не помещается по ширине; удержание или распознанное перемещение позволяет перенести компонент на цель. `Escape`, отмена указателя, потеря окна и скрытие страницы завершают незаконченный жест без хода. Копия `.playroom-drag-ghost` не содержит рабочих игровых атрибутов и не расширяет область документа. Для подсветки используются `.playroom-drag-source` и `.playroom-drop-hover`.

В пакете домино цели имеют класс `.domino-drop-target`; атрибуты `data-preview-a` и `data-preview-b` описывают видимую ориентацию предлагаемой костяшки. Левая цель показывает `preview.b === chain[0].a`, правая — `preview.a === chain.at(-1).b`. На пустом поле предлагается начальная постановка. Эти атрибуты ориентации относятся к домино и не являются требованием общего движка.

Если после переноса нужен дополнительный выбор, цель вместо `data-action` задаёт `data-drop-select="pieceId"` вместе с совпадающим `data-drop-piece`. После отпускания вызывается `select(pieceId)`, игровой ход пока не выполняется. Так UNO предлагает выбрать цвет универсальной карты после переноса на сброс; цветные цели уже содержат полные допустимые действия. Обычный клик по такой цели также сохраняет выбор компонента.

Пак может сохранить быстрый свайп пальцем вверх, добавив источнику `data-swipe-action` с экранированным JSON допустимого действия или `data-swipe-select="pieceId"` для дополнительного выбора. Этот жест требует подъёма более чем на 38 px, горизонтального отклонения менее 65 px и завершения за 300 мс; отпускание над допустимой целью имеет приоритет. Удерживаемый перенос и перенос мышью требуют попадания в цель. Без этих атрибутов, как в домино, отпускание вне цели всегда отменяет перенос.

## Сессии и история

```js
const session = new TabletopSession(Core, 'my-game', options);
session.act(actor, action);
const currentView = session.view(actor);
const earlierView = session.view(actor, 0);
const saved = session.serialize();
const restored = TabletopSession.restore(Core, JSON.parse(saved));
```

`options` в конструкторе можно опустить. `session.current` — последнее полное состояние, `session.states` — начальное состояние и снимок после каждого действия. `current`, `states`, их вложенные данные и `options` доступны только для чтения и глубоко заморожены. Изменения выполняются через `act`; успешный вызов возвращает новый замороженный снимок. Отклонённое действие не изменяет состояние, историю или время обновления.

`view(player, index)` возвращает независимую проекцию выбранного снимка с правами зрителя. Изменение полученного объекта не влияет на игру. Целые индексы за пределами истории ограничиваются первым или последним снимком; дробный индекс, `NaN` и бесконечность отклоняются.

`export()` возвращает независимую изменяемую JSON-совместимую копию сохранения в читаемом формате версии 1. `serialize({compact: false})` возвращает JSON-строку того же формата без промежуточного копирования истории.

Для регулярного сохранения используйте `serialize()` без аргументов. Он выдаёт компактный формат версии 2: повторяющиеся карты, массивы и объекты хранятся один раз в общем пуле. Закодированные снимки кэшируются, новый ход добавляет только новый снимок; при каждом сохранении не нужно заново обходить всю историю полей. Полный журнал хранится отдельно от ссылок на снимки. После восстановления доступны все исходные позиции и произвольный переход по истории.

Читаемый формат: `{format: 'playroom-session', version: 1, game, options, createdAt, updatedAt, states}`. Компактный формат: `{format: 'playroom-session', version: 2, encoding: 'interned-json-v1', game, options, createdAt, updatedAt, states, journal, nodes}`. В версии 2 `states`, `journal` и `options` ссылаются на пул узлов через массивы `[id]`. Узел массива имеет вид `['a', [value, ...]]`, объекта — `['o', [key, value, ...]]`; значения являются JSON-примитивами или ссылками на более ранние узлы. Ссылки вперёд, циклы, неизвестные теги и повторяющиеся ключи объекта отклоняются. Произвольные пути к свойствам не исполняются.

`restore` автоматически определяет версии 1 и 2. Декодер компактного формата ограничивает число узлов (200 000), глубину (128), число значений (2 000 000) и расчётный развёрнутый объём (32 млн символов JSON). После декодирования проверяются оболочка, параметры, временные метки, наличие пакета, общая схема и игровые инварианты каждого снимка, непрерывная нумерация ходов и неизменность участников/набора правил. Произвольные дополнительные ключи не переносятся в объект сессии и не могут заменить её методы. Восстановление не запускает новую партию через `pack.create`.

Все пять встроенных пакетов предоставляют собственный `validateState`. Для нового пакета реализуйте эту функцию: общий валидатор не знает допустимый состав его колод, размеры поля и ограничения показателей. Проверка сохранения не доказывает, что все позиции получены легальными ходами, и не заменяет серверную авторизацию. Изменения схемы правил конкретного пакета потребуют собственной миграции; упаковка версии 2 сохраняет прежние игровые состояния версии 1.

Сессия сохраняет каждую позицию. В `current.events` остаётся полный журнал, а в предыдущих снимках — до четырёх последних событий; это убирает квадратичное дублирование журнала. Компактная упаковка дополнительно устраняет повторяющиеся компоненты и не обрезает историю. В проверке 1200 ходов с 108 картами размер сохранения снизился с 11,27 до 0,78 MiB в UTF-16; медиана сериализации после каждого хода составила 1,70 мс на тестовом компьютере. Это измерение синтетического набора, а не гарантия для любого будущего пакета или телефона. Размер растёт с количеством уникальных данных; приложение по-прежнему сообщает об ошибке квоты `localStorage`, а более крупные проекты могут использовать IndexedDB или файловое хранилище через тот же API сессии.

Сетевой режим должен хранить полное состояние на стороне сервера, проверять принадлежность игрока соединению и отправлять каждому только его проекции. Транспорт, комнаты и повторная доставка после переподключения в этой версии отсутствуют; локальная история уже пригодна для восстановления и просмотра пропущенных действий на устройстве.

## Настройки пакета и реакции

Манифест может задать `settings: [{key, label, default, options: [{value, label}]}]`. Оболочка строит поля запуска и передаёт выбранные значения в `create(state, options)`. Например, UNO объявляет `unoMode` с вариантами `manual` и `auto`; новая партия из хаба по умолчанию ручная, старые сохранения и вызов ядра без этой опции сохраняют автоматический режим.

Реакция — обычное проверяемое `applyAction`, записываемое в сессию и повтор. Пакет сам сохраняет или меняет очередь. Ручной UNO разрешает `declare-uno` и `accuse-uno` всем участникам независимо от размера руки. Достоверное обвинение требует открытого окна после предпоследней карты, отсутствия объявления и ровно одной карты у цели; следующий обычный ход закрывает окно. Ошибочное обвинение даёт две карты обвинителю, верное — забывшему игроку. Раннее объявление лишь записывается. Боты вызывают `botReaction` перед обычным ходом. При передаче телефона прежний участник может объявить UNO или обвинить, затем нажимает «Передать устройство».

## Анимация и просмотр карт

Оболочка использует `PlayroomMotion.capture()` до перехода состояния и `play(snapshot, {duration, draws})` после отрисовки. `draws` содержит только `{player, count, from, fromPlayer?}`, без закрытых карт. Пакет размечает публичные компоненты стабильным `data-entity`, руки — `data-player-index`/`data-hand-count`, колоду — `.stock-button`. Полёт сыгранной карты заканчивается перед добором; ход следующего игрока и передача устройства ждут окончания последовательности. `cancel()` удаляет эффекты и завершает ожидание. Скорости задаются четырьмя пресетами оболочки.

`data-hand-preview` позволяет поднять карту при касании без изменения состояния. `data-tooltip` задаёт текст подсказки при наведении и клавиатурном фокусе. `data-swipe-action` разрешает быстрый вертикальный свайп с точным действием; `data-swipe-select` оставляет выбор цвета игроку. `data-drop-select` на цели выбирает компонент без применения действия. Атрибуты не заменяют проверку правил ядром.

Для компактной руки передайте массив HTML-компонентов в `helpers.hand(cards, count, hint, controls, {layout: "fan"})`. Карты образуют один ряд постоянной высоты; свободная ширина задаёт перекрытие. Когда минимальная читаемая ширина углов уже не помещается, прокручивается только рука. Выбранная карта поднимается над соседями без изменения раскладки. Строковый вызов без `layout` сохраняет обычное расположение компонентов.

`ui.quickPlay` передаёт пользовательскую настройку быстрого розыгрыша. UNO добавляет `data-action` карте только при включённой опции и ровно одном допустимом действии; выбор цвета остаётся явным. Предпочтение хранится в оболочке, не меняет правила или сохранение партии.


Для рук соперников используйте `helpers.opponents(state, viewer, cardRender, options)`. Открытые карты размещаются в `.public-card` внутри многорядной `.mini-hand.is-open`; закрытые руки не раскрывают сущности. Компонент не выдаёт сопернику игровые действия. `options.cardLabel(card)` позволяет добавить короткую экранированную подпись для перекрываемых компонентов (пример домино: `c => c.a + '·' + c.b`). `playerAttrs` и `playerBadge` сохраняются.

Пак может настроить `--public-card-width`, `--public-card-height`, `--public-peek` (видимый угол), `--public-row-step` и `--public-reserve` (минимальная высота). Не применяйте фиксированную высоту закрытых рубашек к `.mini-hand.is-open` или её обёрткам: число открытых рядов зависит от руки и ширины экрана. Углы с номиналом/мастью или подписью должны оставаться читаемыми при горизонтальном и вертикальном перекрытии.
