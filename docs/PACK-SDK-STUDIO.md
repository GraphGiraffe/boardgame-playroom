# Локальная SDK-студия

Обязательный контракт переноса существующих игр: [совместимость с 0.21](SDK-COMPATIBILITY.md). Наличие общей сцены не означает завершённую визуальную приёмку.

SDK исполняет правила и декларативное представление в отдельных QuickJS/WASM-средах. Node-студия и browser player используют одну реализацию VM и GameModel. Каждый рендер получает свежую среду представления с проекцией одного наблюдателя. Решение бота, реакция, задержка и выбор ошибок выполняются в отдельной свежей VM: private cache из create/reduce туда не попадает. Боту передаются только его проекция, разрешённые действия, observe-память и явно объявленный контекст; механика RNG остаётся внутри доверенного порта. Гостевой код не исполняется через host eval или DOM. Ранее опубликованная сборка 0.21.0 этого SDK не содержит; наличие кода и локальная проверка не означают deployment.

Студия использует общие сцены и компоненты карт, костей, фигур, поля, рук, стопок, таблиц, холста, правил и обучения. Семантика взаимодействий задаётся паком через разрешённые команды и source/target; host-компоненты не выбирают правила по ID игры.

Игровой viewport теперь отделён от панели инструментов студии в same-origin iframe. Его ширина и высота участвуют в настоящих CSS media queries. В нём загружаются те же checked-in стили приложения, `TabletopPacks.sceneRecipe`, `TabletopUI`, `PlayroomGameScreen` и `PlayroomSDKSceneRenderer`: отдельной упрощённой разметки участников у просмотрщика нет. Это не редактор файлов и не новая IDE.

`serve` выводит два локальных адреса. `url` открывает игру с выбором зрителя, историей и настройками просмотра. `studioUrl` открывает веб-студию с параметрами партии, событиями, проверкой пака, checkpoint и просмотром ассетов. Все эти инструменты находятся за пределами игрового iframe.

В веб-студии выберите телефон, планшет или ПК в одной из двух ориентаций. Выбранные размеры передаются iframe в CSS-пикселях. Инструменты открываются сбоку, если остаётся достаточно ширины, или отдельной прокручиваемой областью. Если окно меньше выбранного экрана, его можно прокрутить без изменения масштаба и ширины. «Только игра» разворачивает тот же iframe. Выход из полноэкранного режима возвращает его в студию с той же партией и позицией в истории.

Исходники редактируются в VS Code или другом редакторе. `check`, `verify`, `inspect` и `compile` доступны в терминале, а программные сценарии могут использовать `StudioSession` из `sdk/runtime.cjs`. Для управления партией уже запущенной студии используется тот же локальный `/api`, к которому обращаются панели.

Для другого локального host доступен браузерный адаптер `sdk/native-view.js` (`PlayroomSDKGameView`), типы — `sdk/native-view.d.ts`. Один viewport использует канонические контейнеры `#app` и `#modal-root` в своём документе; независимые экраны размещают в отдельных iframe/контекстах. Конструктор принимает `#app` и порты `command`, `preview`, `text`, `error`; `update(frame)` получает только авторизованную проекцию, семантическую сцену, разрешённые действия и публичные ресурсы. Authority/checkpoint/debug передавать renderer нельзя: адаптер отклоняет такой конверт с `SDK_PRIVATE_FRAME_DENIED`, а клиент студии отделяет приватный результат save/debug от отображаемого кадра. Порт команд сохраняет серверную проверку; адаптер не определяет законность хода. История передаётся тем же `update`, с `history.reviewing:true`, без другого renderer. `destroy()` закрывает принадлежащие host меню/эффекты и отключает ввод; освобождённый экземпляр не возобновляют повторным update.

SDK-сервер отдаёт только явный список доверенных UI-зависимостей и стили, перечисленные в index приложения. Произвольные исходники проекта через static routes недоступны. Основная страница сохраняет `frame-ancestors 'none'`; только фиксированный `/viewer.html` разрешает same-origin embedding. Защита Host/Origin/token у API и ассетов сохраняется.

Атомарные события в native host используют очередь приложения `GameFeedback`/`EventPlan`: реплики, показ карт/кубиков, переносы, промежуточные сцены и звук имеют общий жизненный цикл. Не запускайте отдельный звуковой план параллельно ему. Необязательный доверенный порт `audio` принимает `registerPack(id, sounds)`, `prepare(signal)`, `batch(ids, pack, signal)` и `stop()`. Semantic asset-ссылки звука разрешаются общим с установленными паками `TabletopPacks.resolveSoundAssets` только через объявленные ресурсы; посторонний путь отклоняется с `SDK_SOUND_ASSET_INVALID`. Студия подключает к нему стандартный `TabletopAudio`, регистрирует `metadata.sounds` и соблюдает mute/first gesture. Выбор явных и резервных звуков общий с local/network через `NetworkProjection.soundCues`. Непрерывные ink-команды остаются в очереди холста.

`whenIdle()` ждёт отправленную через host команду и её представление. Транспорт, который обрабатывает эту же команду, вызывает `whenIdle({commands:false})`, чтобы не ждать собственный ответ. Навигация может прервать представление и его аудио. `sessionId` стабилен внутри партии и её истории; новый start/restore/reload меняет его и освобождает прежнюю геометрию. Это позволяет начать партию с другим размером поля, сохраняя фиксированную раскладку во время ходов. Студия дополнительно использует монотонный `sessionEpoch`, чтобы отвергать запоздавший stream-кадр прежней партии.

Studio принимает метаданные, локали и медиа один раз для точного хэша пака.
Запросы и поток кадров с совпавшим `knownPackHash` передают только меняющиеся
данные. Первый кадр, новый хэш после обновления и запросы без подтверждённого
хэша получают полную запись. Studio разбирает публичный JSON в окне игры
и передаёт сцену, проекцию, события и паковые данные по ссылке. Эти ветки
неизменяемы. Метаданные, локали и ресурсы переиспользуются при смене
зрителя и в истории. Внешние объекты без подтверждённого владения по-прежнему
копируются перед показом. Закрытые результаты авторских операций разбирает
управляющее окно.
Ответы запросов и поток обновлений проходят одну проверку свежести.
В живой партии оболочка сравнивает эпоху и ревизию для того же зрителя.
История по-прежнему позволяет явно открыть более ранний кадр. При возврате
к партии поток может опередить ответ на навигацию. Studio удерживает
последний живой кадр и применяет его после завершения навигации. Новая
эпоха имеет приоритет над незавершённым переходом по старой истории.
Сервер Studio переиспользует подготовленную проекцию по кадру журнала,
зрителю и варианту каталога. Живой стол и история могут ссылаться на один
расчёт. Статус истории и часы добавляются при отправке. Запуск, восстановление
и перезагрузка партии освобождают прежний кэш.
Компактный игровой кадр берёт каталог правил и иллюстраций из этого снимка.
Подсказки собираются для разрешённых действий текущего зрителя. Если пак
предоставляет `PlayroomPackRuleIllustrations.graphics()`, Studio готовит
его графику внутри свежего гостевого кадра, поскольку она может зависеть
от сцены. Запрос без `knownPackHash` сохраняет полный `support.catalog`.

## Запуск

Нужны Node 22+, Python 3.11+ и checkouts app/packs/utils. В app установить закреплённые зависимости: `npm ci --ignore-scripts`. Из utils:

```sh
python3 sdk.py --app ../playroom new /tmp/my-game --id my-game --packs ../playroom-paks
python3 sdk.py --app ../playroom doctor /tmp/my-game --shared ../playroom-paks/shared
python3 sdk.py --app ../playroom check /tmp/my-game
python3 sdk.py --app ../playroom verify /tmp/my-game --steps 20
python3 sdk.py --app ../playroom serve /tmp/my-game
```

Существующую игру переводят тем же инструментом; старое происхождение сохраняется честно:

```sh
python3 sdk.py --app ../playroom adopt ../playroom-paks/packs/gofish --packs ../playroom-paks
python3 sdk.py --app ../playroom compile ../playroom-paks/packs/gofish --packs ../playroom-paks --shared ../playroom-paks/shared --output /tmp/gofish.playroom-pack.json
```

Изменение уже опубликованного пака требует новой версии; immutable bytes не перезаписываются. `new` и `adopt` не публикуют. Внешняя установка принимает `execution:'isolated-v1'`; пакет не может включить доверенное исполнение своим manifest. Старый host execution доступен лишь проверенному bundled bootstrap либо явному операторскому режиму для fixtures.

Для текущей игры указать `../playroom-paks/packs/gofish --shared ../playroom-paks/shared`. Открыть напечатанный loopback URL. Сервер слушает только 127.0.0.1, проверяет Host/Origin и токен страницы. Код редактируется внешним редактором; watcher сообщает об изменениях, «Перечитать код» создаёт новые среды и партию. Установка проекта не исполняет lifecycle hooks.

Кадр Studio передаёт разрешённые события и триггер движения. Общий экран игры
строит исполняемый план по геометрии своего поля. Это относится и к шагу
вперёд в истории. Авторский публичный план внутри сцены передаётся вместе
со сценой и управляет промежуточными кадрами.

## Как сверить результаты проверки и сборки

`authorSourceHash` в отчёте `compile` совпадает с `hash` из `check`
и `verify` на одной редакции исходников. При расхождении `compile`
возвращает `SDK_COMPILE_SOURCE_MISMATCH` до записи файла. Проверка медиа
использует тот же валидатор, что и импорт в приложении.

`sourceHash` в отчёте совпадает с `sdk.sourceHash` в готовом паке.
Он учитывает преобразованные каталоги и состав модулей для установки.
`sha256` проверяет байты всего файла, выбранного для импорта. Для проверки
поведения запустите Studio и установленный пак с одинаковыми настройками,
выполните те же команды и сравните состояние в истории на одной ревизии.

## Авторский контракт

`Presentation.event` получает типизированный `EventFact` с `type`, `actor`
и `params`. При `metadata.eventInputs: 'facts'` поля `id` и `revision`
отсутствуют. Результат `DieAsset.reveal` можно вернуть в описании события
как JSON без ручного приведения типов.

`manifest.json` задаёт ID/версию. `sdk/project.json` — source-only descriptor: `contractVersion:1`, списки `rules`, `presentation`, чистые `helpers`, начальные `options`, необязательное `checkTypes:true`. Компилятор формирует `playroom-pack` formatVersion 2: один объект `manifest` и структурированный объект `sdk` с выбранными модулями, каталогами, support-кодом и resource closure; произвольные файлы проекта не исполняются. `types` перечисляет локальные .d.ts, `support` — чистые модули правил/обучения, `origin` фиксирует создание или миграцию. Definition использует действующий GameModel contractVersion 1; объявления API находятся в `sdk/contracts.d.ts`. Шаблон копирует объявления, проверка использует канонические типы выбранного app checkout.

Правила получают состояние конкретной партии и явный RNG. Для каждого рендера создаётся свежая VM представления: глобальные переменные модуля не сохраняют проекции других игроков или предыдущих кадров. Отдельная VM представления получает только проекцию наблюдателя; в ней нет определения правил или полного состояния. Модули пака не импортируются в Node/Python хоста. UMD-проверки переключаются на браузерную ветку с сохранением координат исходника; Node require не предоставляется. Произвольные HTML/CSS/JS сцены не вставляются в документ.

Модули выполняются в strict mode. Экспортированные классы ядра, их собственные прототипы и используемые встроенные операции защищены от изменения: пак не может подменить валидацию GameModel. ID модели должен совпадать с manifest.json.

Нет доступа к DOM, сети, Auth, файлам, хранилищам, таймерам, Date и ambient Math.random. Запрещённое обращение фиксируется вне VM и проваливает вызов даже при catch внутри пака. Для обязательных полей использовать `SDK.read(object,key)`; ошибка показывает роль, этап, ресурс и исходную строку. Обычный optional JS-access не позволяет обнаружить всякое чтение отсутствующего поля: помогают типы и сценарии. Необязательные undefined-поля существующих сцен пропускаются с предупреждением; функции/NaN/Infinity запрещены. Произвольные сообщения, code/resource и поддельные stack-пути гостевых исключений не выводятся. Сохраняются известные коды SDK/core и координаты реально загруженных модулей; динамический ключ отсутствующего поля заменяется общим field:required. Закрытые значения не включаются в отчёт.

Ограничения на роль: WASM linear memory 64 MiB, QuickJS allocations 48 MiB, стек 512 KiB, вызов 2 секунды и внешний watchdog 5 секунд. RPC-сообщение и читаемый source-файл до 4 MiB, исходники суммарно до 12 MiB. Это защитные пределы загрузчика; бюджет сериализованного source-export отдельно ограничен 4 MB. Worker используется для остановки зависания, а не как самостоятельная защита доступа.

Подготовленный текст модуля и проверенный размер хранятся в доверенном
QuickJS-хосте до изменения имени или исходника. Гостевой контекст
по-прежнему создаётся заново. В Studio рабочий поток представления получает
каталоги, язык и книги правил. Состав и медиа ассетов остаются у Studio
и доступны её веб-интерфейсу.

Кадр установленной игры содержит сцену, описания действий, обучение и
кадры событий. Он получает разрешённые события как вход для построения
сцены. Приложение и Studio используют один обработчик для текста, звуковых
меток и других эффектов журнала. При первом запросе он получает только
разрешённые данные одного события в отдельном контексте QuickJS. Повторный
запрос переиспользует разобранное неизменяемое описание. Имена игроков и
индексы событий добавляет вызывающий экран. Studio включает оформленные
события в кадр предпросмотра в порядке проекции.

## Ввод, время и уведомления

`Definition.inputs(position, actor)` задаёт ограниченные text/integer/boolean/enum/ink поля. Actor, неизменные параметры (например roundId) и все значения проверяются до reduce; лишние поля отклоняются. `advance(position, now)` получает явное время хоста. Его переходы проходят те же события, durable commit, ACK и историю, что пользовательские действия. Пауза замораживает игровые часы. Отсутствие перехода не добавляет ход на каждый tick.

Общий canvas показывает незавершённые штрихи через авторизованный preview-порт, окончательные операции — через обычный журнал команд. Zoom/pan 100..400% локальны. `scene.vote` задаёт неблокирующее уведомление с голосами, порогом, deadline и разрешённой командой. Оно не ставит игру на паузу и не перехватывает фокус. По окончании неудачного голосования пак удаляет scene.vote; принятое решение ждёт установленной правилами границы. История отключает любые команды и фиксирует таймер по времени кадра. Подробности: [контракт ввода, часов и холста](SDK-DRAWING-CONTRACT.md).

## Правила, история и проверки

`check` проверяет структуру, пути/симлинки, синтаксис, известные запрещённые обращения, типы новых проектов и ассеты. `verify` реально исполняет ограниченные сценарии с seed 1/17: детерминизм, сцены наблюдателей, независимость результата от порядка просмотра игроков, допустимые бот-команды, checkpoint. Это не доказательство правильности всех правил.

Авторские проверки задаются данными в `sdk/scenarios.json`. Если проверка зависит от настроек партии, задайте их явно в `options.options` сценария. При неожиданном отказе команды `verify` выводит ID сценария и индекс шага с нуля.

```json
{"contractVersion":1,"scenarios":[{"id":"first","steps":[{"actor":0,"command":{"type":"increment"},"expect":{"data.count":1}}],"expect":{"status":"playing"}}]}
```

`expect` сравнивает JSON-значение по пути. Шаблон содержит сценарий завершения партии. Для приватности подготовить закрытый JSON с `left`, `right`, `viewer`: валидные положения, отличающиеся только скрытой информацией. Запуск: `python3 sdk.py --app ../playroom privacy /tmp/my-game --fixture /tmp/private-pair.json`. Сравниваются проекция, подписи действий, сцены и события, включая описания звука/движения, публичный score hook и разрешённая память/контекст бота. Различие может означать ошибочную пару; отчёт не раскрывает сравниваемые значения. Это не исчерпывающее доказательство отсутствия утечек.

История выбирает сохранённый checkpoint и вызывает те же правила проекции и presentation.scene/event/action, что и игра. Правила повторно для просмотра не выполняются; менять партию в истории нельзя. Возврат сохраняет live-положение. Студия и приложение используют общие `presentation/transition.js`, EventPlan, PlanPlayer и Scheduler. Нет отдельного проигрывателя с логикой конкретной игры. История студии хранит контрольные состояния в сжатом закрытом временном журнале (каталог 0700, файл 0600), а в памяти держит до восьми прочитанных кадров. Она удаляется при закрытии студии; ограничение в 1000 действий не прерывает длинную партию. Обычное приложение использует свою общую сохраняемую историю.

Checkpoint привязан к hash исходников и содержит закрытые данные. Его экспорт и показ полного состояния доступны только явным действием автора. Экспорт создаётся только по запросу автора; рабочие контрольные состояния временно хранятся в закрытом журнале студии. Изменение исходников делает checkpoint несовместимым.

## Правила в Markdown

Правила можно хранить в Markdown. Укажите файл для объявленной локали в
`sourceModules.rulebooks`, например `{"ru":"rules/ru.md"}`. Понадобится
Mistune 3 в Python. `check`, «Перечитать код» в студии и `compile` обрабатывают
актуальный Markdown одним компилятором. Документ открывается через «Правила»
в игровом меню. Поддерживаются заголовки, абзацы, списки, таблицы и ссылки на
зарегистрированные иллюстрации с записью `![Подпись](illustration-id)`.

## Ресурсы

```sh
python3 sdk.py --app ../playroom import-asset /tmp/my-game /path/to/piece.svg --name piece.svg --license CC0-1.0 --provenance 'Original drawing'
python3 sdk.py --app ../playroom convert-asset /tmp/my-game /path/to/piece.png --name piece.webp --max-edge 512 --license CC0-1.0 --provenance 'Original drawing'
python3 sdk.py --app ../playroom convert-asset /tmp/my-game /path/to/move.wav --name move.ogg --license CC0-1.0 --provenance 'Original recording'
python3 sdk.py --app ../playroom link-shared /tmp/my-game --packs ../playroom-paks --asset counter-card.svg
python3 sdk.py --app ../playroom link-shared /tmp/my-game --packs ../playroom-paks --asset-pack cartoon-deck
```

`convert-asset` использует локальные FFmpeg и ffprobe. PNG, JPEG и BMP
преобразуются в WebP без потерь с сохранением прозрачности. `--max-edge`
уменьшает изображение с сохранением пропорций. WAV, FLAC, AIFF, MP3 и Ogg с
одной дорожкой конвертируются в Ogg Vorbis или MP3. SDK измеряет длительность контейнера и
отклоняет файлы длиннее 10 секунд. Команда сохраняет оригиналы, записывает
SHA исходника и результата и проверяет бюджеты через обычный импорт.

Команда `link-shared` записывает имя в `sharedAssets` или `sharedAssetPacks`
манифеста. Сами ассеты остаются в общей коллекции. Сборщик включает выбранный
ресурс и его зависимости в устанавливаемый пак. До записи команда измеряет
оба артефакта, включая локальные ассеты, общие ресурсы и зависимости. Повторный
вызов с тем же ресурсом сохраняет манифест без изменений.

Для проекта с shared-ресурсами добавьте `--shared ../playroom-paks/shared`. До записи импорт проверяет полный local/shared closure и размер source-export с новым ресурсом, base64 и provenance. Отсутствующий shared root или превышение бюджета не оставляет файл или metadata; импорт также измеряет полный устанавливаемый pack тем же Python-компилятором, включая повторное JSON escaping. Отчёт разделяет `sourceBudget` и `installableBudget`; `compile` остаётся окончательной проверкой готового файла.

Импорт копирует оригинал без перезаписи; лицензия, источник и SHA записываются в `sdk/assets.json`. Допустимы SVG/PNG/JPEG/WebP, WAV/OGG/MP3, JSON-анимации. SVG разбирается XML-парсером: ограниченный словарь, без DTD, скриптов, событий, встроенных стилей и внешних ссылок. Растр: максимум 2048 по стороне/4 000 000 пикселей. Анимация: `contractVersion:1`, `frames:[{time:0,values:{opacity:0}}]`; x/y/rotation/scale/opacity, до 10 секунд/1000 кадров. Галерея позволяет проиграть её с учётом reduced motion. Пользовательский звук прослушивается отдельно; события используют общую TabletopAudio с выключенным по умолчанию звуком.

До 512 файлов в каждом списке SDK-модулей, включая типы. До 512 runtime-ресурсов/2 000 000 байт суммарно. Изображение — до 512 kB (цель 128 kB); SVG и JSON-анимация — до 64 kB; аудио — до 128 kB. SVG ограничен 2000 узлами. Известная сумма decoded-растров — до 32 MiB. Markdown/text-заметки внутри assets перечисляются отдельно и в runtime/source-export resources не включаются; остальные исходные мастера держать вне assets. Импорт сначала проверяет кандидата вместе с текущим inventory и лишь затем пишет ресурс/метаданные. Encoded bytes и известные decoded image bytes считаются отдельно; память SVG/audio не выдаётся за измеренную. WAV PCM/float проверяется по RIFF/fmt/data и ограничен 10 секундами. Для OGG/MP3 длительность на source-check неизвестна и отмечена предупреждением SDK_AUDIO_DURATION_UNVERIFIED; галерея проверяет browser metadata и не проигрывает аудио дольше 10 секунд. Это не доказательство работы декодеров или производительности на телефоне. Исходные мастера и допустимые копии между автономными паками сохраняются.

Для проверки состава используйте `inspect` и поле `resourceUsage`. В сводке
видно, указан ли общий набор прямо в манифесте игры, какие наборы зависят от
него и какое поле манифеста подключает каждый файл. `compile` возвращает
отчёт того же формата в `resources.usage` для готового JSON. Для медиа
доступны размер и SHA-256, для скриптов и стилей — размер исходника. Записи
`documentation` указывают на заметки автора, содержимое которых не
упаковывается. У записей `delivery: "source-only"` код входит в экспорт
исходников. Устанавливаемый пак оставляет медиа и данные, а стандартные
рендереры и стили получает из приложения. Код авторских правил, сцены и
поддержки выполняется через объявленные SDK-точки входа. Отчёт отражает
включение по декларациям. Использование функций и ресурсов из динамических
веток требует отдельного анализа.

Массив `resourceUsage.sdkModules` в `inspect` и `resources.usage.sdkModules`
в `compile` показывает исходники по ролям SDK. Для каждой записи указаны
путь, роль, объём UTF-8 и владелец `shared` или `pack`. В `compile` список
снят с собираемого JSON, поэтому с ним можно сверить исключение модуля из пака.

В `sdk/project.json` поле `assetItems` сужает перечень позиций общих
наборов по их ID. Например, после добавления `characters-minimal` в
`sharedAssetPacks` можно оставить два изображения:

```json
{
  "assetItems": {
    "characters-minimal": ["circle-red", "diamond-blue"]
  }
}
```

Отбор применяется ко всему графу зависимостей пака. Поле относится к
`items` каждого указанного набора, а явные `files` и другие декларации
сохраняют свои правила включения. Пустой список исключает все позиции
из `items`. При отсутствии ключа сохраняется полный набор. SDK проверяет
опечатки и дубли, а отчёт показывает исходное количество и выбранные ID.

Для парных карточек можно оставить один набор рисунков. Например,
`"assetItems": {"characters-minimal": []}` исключает изображения этого
набора из зависимостей `characters-simple`. Если выбранное оформление
отсутствует, открытая карточка использует доступный рисунок того же
персонажа. `verify` показывает эти файлы в `resourceReferences.runs[].skinAssets`.

`verify` записывает явные ссылки в `resourceReferences`. Поле `observed`
сохраняет общий список, а `sources` показывает источник ссылки. Поле
`scenarioAssets` включает ссылки из сцен, действий, событий и выбранных
звуков. `graphics` показывает обращения к рисункам каталога. Для
неразрешённых и динамических ссылок отчёт содержит количество обращений.
`sounds.selected` использует тот же выбор звуков событий, что и проигрыватель.
`sounds.phases` показывает сигналы из групп публичного плана.
`sounds.host` перечисляет те же два вида сигналов, если их предоставляет
стандартная библиотека приложения. Одноимённый звук пака имеет приоритет.
`sounds.unresolved` считает уникальные неразрешённые ссылки по видам сигнала.
`verify` скрывает их значения, поскольку ID может зависеть от данных игрока.
`presentation` перечисляет предложенные взаимодействия, источники передач,
крупные показы и наличие маршрута.

`resourceReferences.assetMethods.profiles` показывает, какие методы общих
классов ассетов вызывались в изолированных прогонах. В каждой записи есть
файл реализации, имя класса и списки `observed` и `notObserved`.
Вызов через `super` учитывается у класса, который реализует метод.
Отдельно видны вызовы при загрузке метаданных и в каждом `runs[].assetMethods`.
`assetMethods.printOverrides` показывает авторские `print`, вызванные
через стандартный `describe`. Переопределение без `super` попадает в
этот список, а вызов `super.print` дополнительно фиксирует стандартную
реализацию. В прогоне с авторским выводом отчёт добавляет
`runs[].assetPrintOverrides`.
Когда несколько сценариев используют одно оформление события, отчёт
учитывает стандартные методы и авторские `print` в каждом из этих
сценариев. SDK берёт их из сохранённого результата без повторного
вызова гостевого кода.
Отчёт описывает работу перечисленных сценариев. Перед удалением профиля или
модуля проверьте редкие настройки, историю, обучение и зависимости наследников.

`resourceReferences.runs` показывает явные ссылки отдельно для каждого
проверенного seed и авторского сценария. В строке прогона есть число кадров,
роли зрителей, файлы, рисунки и сигналы пака и приложения. Поле `assetSets`
показывает объявленные наборы, которые назвала сцена. Конкретные файлы,
выбранные через настройки оформления приложения, проверяются в браузере.
`skinAssets` перечисляет доступные файлы вариантов для открытых персонажей
на поле парных карточек. SDK и движок используют один поиск в каталоге.
Авторский прогон включает начальную сцену при любых заданных параметрах,
даже при пустом
списке шагов. Индекс `-1` соответствует зрителю.

Используйте `notObservedInScenarios` как список для проверки. В него могут
попасть обложки, иллюстрации правил, рубашки и материалы, которые выбирает
скин. Для таких ресурсов и редких вариантов игры нужны отдельные сценарии.
Фактическая работа Web Audio проверяется в браузере. Отсутствие обязательного
ресурса SDK отмечает контекстом кадра.

## Фоновая подготовка ресурсов игры

Web-рендерер готовит изображения выбранного пака по одному в паузах между
работой интерфейса. В локальной и сетевой комнате это начинается до старта
матча, в том числе на устройстве гостя. Поле получает тот же кэш для точной
установленной версии пака, в том числе уже начатое декодирование.
При прямом открытии поля и в Studio подготовка начинается
на первом кадре. Для набора из 32 изображений или меньше она включена
по умолчанию. Для большого набора задайте до
32 приоритетных ссылок в `metadata.preloadImages`, например
`[SDK.resource('assets/die-special.svg')]`. Пустой список отключает
автоматический прогрев. Поле и крупный показ используют один object URL для
той же неизменяемой записи ресурса. URL живёт, пока его удерживает хотя бы
один кэш отображения. Ресурс с новыми байтами получает отдельный URL.
Фоновая подготовка удерживает до 8 МиБ декодированных изображений.
Выход из комнаты без старта освобождает её кэш.

Аудиоадаптер декодирует до восьми уникальных сэмплов выбранного пака после
обычного открытия Web Audio пользователем. Первый игровой сигнал берёт
тот же буфер. Сетевое поле использует зарегистрированный в лобби каталог
звуков той же установленной версии. При смене каталога адаптер принимает
новые определения. Подготовка идёт без звука и без ожидания со стороны правил,
рендерера и очереди событий. Траектория и длительность движения по-прежнему
определяются при принятом ходе и зависят от текущей геометрии поля.

### JSON-анимации событий

Локальный файл в `assets/` содержит `contractVersion: 1` и последовательность
`frames` в порядке времени. `time` задаётся в миллисекундах, `x` и `y` — в
пикселях, `rotation` — в градусах, `scale` и `opacity` — числа. SDK проверяет
файл и готовит ключевые кадры при загрузке пака. В форматтере разрешённого
события передайте ссылку на файл и семантическую цель.

```js
animation: {
  asset: SDK.resource('assets/pulse.json'),
  target: { entity: { namespace: 'die', id: '0' } }
}
```

`target: { zone: 'field' }` адресует поле игры. Анимация вступает в той же
фазе, что звук события, и следует за настройками скорости, паузы и отмены.
Пошаговое воспроизведение истории использует те же ключевые кадры.

## Бюджет полного артефакта

Цель — **500 kB**, жёсткий максимум — **4 MB = 4 000 000 байт UTF-8 до HTTP-сжатия**, без минимального размера. `check` и `build` используют один encoder и возвращают `budget`/`warnings`: подсчёт включает manifest, descriptor, locales, все выбранные модули, JSON escaping и base64 ресурсов. `SDK_PACK_TARGET_EXCEEDED` — предупреждение, а не ошибка. `SDK_PACK_SIZE_LIMIT` отклоняет экспорт до создания файла; существующий output не перезаписывается. Изменившийся после аудита ресурс отклоняется по SHA.

Тот же hard limit применяется к полному устанавливаемому `playroom-pack` в compiler, player parser и проверке импортируемых файлов сайта. Обычный player до создания VM и Blob повторно проверяет count/bytes/SHA, форматы и ограничения медиа тем же переносимым валидатором, что и SDK. Межъязыковой контракт проверяется на точной границе, включая многобайтовый UTF-8. SDK source-export и player-pack остаются разными форматами: размеры одного не доказывают размер другого. Source-мастера и расход памяти VM считаются отдельно.

`build --output FILE` экспортирует новый `playroom-sdk-source` для передачи/ревью. Это не устанавливаемый player-pack, не gameplay-проверка и не deployment. Устанавливаемый pack создаёт `compile`, а проверку обычного player, сети и offline выполняют отдельно от source-проверок. Публикация — отдельная операция.

### Поле рисования и элементы ХОД

Холст занимает доступную область штатного поля. Нативные карточки игроков
остаются единственными карточками; ввод `scene.chat.command` помещается в карточку
текущего отгадывающего с сохранением DOM, фокуса и черновика. Публичные варианты
берутся только из проекции и видны всем её адресатам; анонимность скрывает автора.
Догадки всплывают поверх белого квадрата на пять секунд. Проверка ответов и итог
раунда также остаются поверх рисунка и не меняют компоновку. В фазе `prepare` слово
крупно видно рисующему на холсте, а при рисовании оно находится над инструментами.
`scene.controls` передаёт подписи и команды обычных кнопок в зоне действий.
Студия и установленное приложение выводят их только для разрешённых действий
текущего игрока. Например, в устном раунде рисующий может отметить угадавшего.
`scene.menuActions` (не более 12 `{label, command}`) проходит общую проверку
разрешённых команд и выводится в меню партии. Предложение завершить игру не
занимает строку действий поля, а начатое `scene.vote` остаётся неблокирующим.

Карандаш, ластик, заливка и очистка — круглые кнопки; размер, цвет и масштаб —
квадратные кнопки меню. Цвет/толщина видны на самой кнопке. Стандартная палитра —
чёрный/белый и 12 цветов игроков из `core/player-palette.js`: сетка 4×4, две
капсулы по две ячейки сверху, затем три строки круглых цветов. Перемещение —
правой кнопкой мыши или двумя пальцами, щипок меняет масштаб. Ограниченные
128 точками части штриха отправляются последовательно; ожидание ACK не
переводит непрерывный ввод в историю. История, пауза и отсутствие прав блокируют
запись. Координаты холста измеряются на начало жеста, overlay рисуется по rAF.

`scene.clock` принимает `startedAt`, `deadline`, необязательный `player` (по
умолчанию `projection.turn`) и подпись. Фаза/начало задаются правилами, без
вычисления игровых переходов в UI. Время показывается в статусбаре; фон штатной
карточки активного игрока заполняется слева направо по истёкшей доле. Больше 15 секунд
сохраняется исходный цвет поверхности; 15–10 — исходный→жёлтый, 10–5 —
жёлтый→красный, ≤5 — красный. Истёкшая часть темнее оставшейся.
В истории используется время кадра, а не живые часы.


### Общие уведомления

`PlayroomNotices.ExpandableNotice` и `PlayroomProgressSurface` используются
приложением и SDK-рендерером. `scene.vote` передаёт начало, deadline, голоса
`votes`/`against` и разрешённые команды `command`/`againstCommand`; уведомление
показывает зелёную/красную линию распределения. Нажатие раскрывает подробности,
количества и кнопки. Голосование нельзя закрыть крестиком или жестом.

`scene.notices` принимает до четырёх уведомлений с устойчивыми ID, текстом,
разрешёнными actions и необязательными progress/distribution. Поле `dismissible`
управляет локальным закрытием; по умолчанию закрытие разрешено. Новый ID означает
новое уведомление. Данные и команды проверяет scene-contract до вывода.

Приглашения, сообщения и обновления приложения используют тот же компонент.
При раскрытии приглашения доступны подключение, отказ и переход в чат;
сообщения — полный текст, открытие чата и штатный composer с реакциями и отправкой.
Компактное уведомление об обновлении не содержит кнопку действия: версия,
изменения и переход на экран обновлений доступны после раскрытия. Эти три вида
можно закрыть крестиком или горизонтальным жестом. Короткий жест, возврат назад
и pointercancel сохраняют уведомление. Достаточный конечный сдвиг запускает
короткий уход с прозрачностью; reduced motion убирает анимацию. Вертикальная
прокрутка, ввод и фокус сохраняются. Закрытие голосования по времени принадлежит
правилам, а не UI.

### Разработка в редакторе

SDK остаётся независимым от редактора. Веб-студия предназначена для просмотра
сцен, ресурсов и локальных партий; VSCode используется для файлов и исходников.
`new` и `adopt` utils создают `playroom.code-workspace`, если файла ещё нет:
явные process-задачи new/inspect/doctor/check/verify/privacy/serve/compile. Пути связывают проект
с выбранными app/shared checkout. Задачи запускаются вручную. `check --format
vscode` передаёт сообщения с координатами в Problems. Обычный `check` сохраняет
вывод JSON для CLI и других инструментов. `doctor` проверяет Node, зависимости,
инициализацию QuickJS и статическую проверку пака. Запуск правил выполняет
отдельная команда `verify`. Уже созданный workspace сохраняется при `new/adopt`.


### Игровой интерфейс и обложки

Текущий SDK — функции, библиотеки, контракты, компилятор, проверки и ассеты.
Разработка интерфейсов веб-студии и интеграции с IDE — отдельный этап ROADMAPler.
Превью собирается как обычное приложение ХОД, без панели исполнения команд,
переключателя оформления SDK, второй ленты обучения и дублирующих игроков.

`metadata.cover` может ссылаться на `{kind:'asset',id:'assets/cover.webp'}`.
Загрузчик принимает только объявленный и проверенный локальный image-ресурс.
Отображается обычная обложка; исполняемый код/HTML или внешний URL из метаданных
не используется. Существующие арты текущих игр сохраняются.

Руки и метрики из разрешённой сцены выводятся в штатных зонах приложения через
`data-sdk-hand-owner`, с сохранением DOM и общим портом команд. История использует
те же компоненты и отключает ввод. Рендерер не создаёт формы из полей команд:
игровые развилки используют подписи/арты `scene.commandParameters` и обычные
кнопки выбора; внутренние имена полей в интерфейс не выводятся.


## Устанавливаемый JSON: общая форма

`formatVersion: 2` содержит `format`, `formatVersion`, `manifest`, `lang`, `sdk`, `files`.
Метаданные SDK — обычный JSON-объект, не строка `files["sdk/source.json"]`.
Второй копии manifest внутри SDK нет. Строки исходного JavaScript в `sdk.sources`
остаются строками: это содержимое файлов, а не сериализованный JSON.

`manifest.settings` всегда объект с `fields` и `groups`. В каждом поле есть
`key`, `kind` (`preset`, `option`, `standard`), `valueType`, `default`, `options`
и `control`. Пресет — поле `key: "preset"`, `kind: "preset"` в этом же списке.
`groups` ссылается на поля по key; `placement: "end"` помещает группу в конец
формы и само по себе не завершает партию. Root-поля `presetSetting` и
`ruleGroups` в новом файле не используются. Авторские исходники со старой
структурой нормализует общий compiler. Runtime декодирует общий блок для
существующих внутренних портов. Числовые идентификаторы старых строковых enum
не преобразуются в числа: тип значения является частью контракта игры.
В студии и в установленном паке `Definition.create` получает настройки поля
в `options.options`. Для полей `boolean`, `integer` и `number` приложение передаёт
значение объявленного типа, даже если форма лобби хранит выбор строкой.
При отсутствии выбора для такого поля берётся его `default`.

`releases` в устанавливаемом паке содержит только текущую версию: до трёх
кратких пунктов, до 160 символов на пункт и до 320 суммарно. Preview-история
не попадает в stable-метаданные; полная авторская история остаётся в исходниках.
Параметры выбранной партии, seed, игроки, приватные проекции и сохранения
не записываются в распространяемый пак. `sdk.descriptor.options` — параметры
авторского начального сценария, а не сохранённая пользовательская партия.
После изменения исходников нужно пересобрать JSON: sourceHash и SHA ассетов
вычисляет compiler; ручное редактирование готового артефакта нарушает целостность.


## Отдельные исходники и общий блок языков

Разработчик хранит файлы отдельно: `manifest.json`, `sdk/project.json`,
`domain/*.js`, `presentation/*.js`, `lang/ru.json`, `lang/en.json`, `assets/*`.
`sourceModules.locales` указывает эти языковые файлы. Только `compile` собирает
выбранные модули и замкнутые ресурсы в один устанавливаемый JSON; он не заменяет
исходную структуру проекта. В готовом файле `lang: {"ru": {...}, "en": {...}}`
содержит все словари; отдельной копии `sdk.catalogs` нет. Внутренний SDK-source
и VM по-прежнему называют переданный словарь `catalogs` — это внутренний порт,
а не второй блок устанавливаемого файла.

Отображаемые поля manifest (`name`, `label`, `help`, `description`, `shortLabel`,
заметки версии и др.) используют `{ "key": "manifest.name" }` либо ссылку
с `params`. Preset/options `value`, ID, пути, версии, типы и исходники кода
не переводятся. `SDK.text(key, params)` возвращает строку для текущего языка
в presentation/support; для декларативных полей достаточно ссылки `{key,params}`.
Поле `manifest.defaultLanguage` задаёт резервный язык. Выбор другого языка
не меняет ID команд, options.value, параметры или сохранение партии.

В app при загрузке используется выбранная locale; для явного SDK-просмотра
`loadProject(folder,{shared,locale:'en'})` передаёт тот же выбор в изолированную
VM. Чтение ключа: выбранный язык → defaultLanguage; если ключа нет и там,
compiler/check отклоняет ссылку с указанием ключа. Незавершённые дополнительные
переводы допустимы. Общий starter содержит ru/en и отдельные языковые файлы.
UI выбора нового языка приложения этой миграцией не добавляется.


## Компактные данные и общая локализация

Все исходные manifest теперь используют тот же блок `settings.fields/groups`,
что и устанавливаемый JSON. Отдельных presetSetting/ruleGroups в исходниках нет;
они существуют только как внутренние совместимые порты runtime.

`estimatedDurationMin` — число либо пара чисел `[20,40]`. Числа и единицы
форматирует приложение: «20–40 мин» / «20–40 min». В lang не нужен ключ длительности.
Общие слова задаются ссылкой `{ "common": "yes" }` / `no` / `infinity` / `auto`
и другими зарегистрированными ID. Канонический словарь — `locales/common.json`
приложения, форматирование — `presentation/common-format.js`. Пак его не копирует.
`SDK.common(id)` возвращает общую строку в presentation/support; в rules этот
языковой порт недоступен. `{key,params}` остаётся ссылкой на индивидуальный текст.

Подпись числового варианта можно опустить: runtime форматирует value, сохраняя
его исходный тип. `unit: "s" | "min" | "h"` на поле добавляет общую единицу.
Строковые ID "0"/"1"/"on"/"off" не превращаются в boolean или числа.
Для value="0", означающего бесконечность, нужна явная label common=infinity.

`range: {min:30,max:180,step:1}` заменяет длинный список целочисленных options.
Максимум 256 значений; range и options взаимоисключающие. Раскрытие происходит
только на границе runtime/проверки. Короткие и неравномерные наборы остаются options.

`optionDefaults: {description:{key:"settings.maxRounds.optionDefaults.description"}}`
задаёт общую подсказку вариантов. Локальный description переопределяет её,
`description:null` убирает у конкретного варианта. На диске общая строка и ссылка
записаны один раз. Runtime раскрывает наследование для существующих UI-портов.
Одинаковые индивидуальные переводы используют один ключ, если совпадает весь
набор языков; различающиеся переводы не объединяются. Ключи настроек используют
имя поля и value варианта, а не его позицию в массиве.

Для нескольких паков с одним способом представления можно включить файл
`shared/presentation/<name>.js` в упорядоченный список `presentation` в
`sdk/project.json`. Студия и компилятор читают его из выбранного каталога
`--shared`. В установленном паке хранится собственная копия. Такой модуль
получает только входы presentation и загружается перед использующим его
файлом сцены, если так задан порядок в списке. Пример — представление стопок
«Косынки» и «Паука» в `shared/presentation/solitaire.js`.

При `checkTypes: true` исходники пака проверяются по каноническим декларациям SDK, включая вызовы импортированных профилей. Реализации профилей из коллекции проходят проверку исходника и выполняются внутри изолированной среды. Для размещения в слоте `Asset.place(id, zone, index)` принимает числовой индекс и возвращает запись с обязательным `index`.

Для фишек подключите `shared/presentation/asset.js`, затем
`shared/presentation/token-asset.js`. `PlayroomTokenAsset` строит записи
размещения в клетке или точке и привязывает разрешённую команду к фишке.
Для маршрутов добавьте `shared/presentation/route-token-asset.js`.
`PlayroomRouteTokenAsset` наследует эти операции и принимает готовые
шаги, прыжок и ID уходящих фишек. Пак строит путь по разрешённым данным, а штатный
проигрыватель использует его якоря, фазы, задержки и звуки. «Шашки»
показывают базовый вариант, Ludo и «Змеи и лестницы» используют маршрутный.

Для двустороннего тайла начните с `asset.js` и `tile-asset.js` из
`shared/presentation`. `PlayroomTileAsset` передаёт закрытую сторону как
`{hidden:true}` и сохраняет независимый адрес ячейки. Пак формирует
разрешённые лица до представления. `sharedDomain: ["tile-visibility"]`
даёт общий способ заполнять закрытые ячейки и раскрывать выбранные индексы.
Цепочка дополнительно подключает `tile-connection` в `sharedDomain` и
`shared/presentation/chain-tile-asset.js` после `tile-asset.js`. Предпросмотр
размещения использует тот же стык и поворот, что и применение команды.

Для поля подключите `asset.js` и `board-asset.js` из `shared/presentation`.
`PlayroomBoardAsset.target` задаёт адрес по ID зоны и индексу ячейки.
`activateCell` связывает этот адрес с уже разрешённой командой, а `layout`
собирает основную зону и дополнительные зоны пака. Одно поле достаточно
для «Крестиков-ноликов». «Морской бой» добавляет свои поля и инвентарь.

Для листа категорий добавьте `score-table-asset.js`. Его
`categoryRows` берёт готовые значения, предпросмотр и разрешённые команды,
создавая ячейки с теми же ID категорий. «Покер на костях» оставляет расчёт
очков в правилах. Общий экран отвечает за прокрутку и выбор колонки.
