# Локальная SDK-студия

SDK исполняет правила и декларативное представление в отдельных QuickJS/WASM-средах. Node-студия и browser player используют одну реализацию VM и GameModel. Каждый рендер получает свежую среду представления с проекцией одного наблюдателя. Решение бота, реакция, задержка и выбор ошибок выполняются в отдельной свежей VM: private cache из create/reduce туда не попадает. Боту передаются только его проекция, разрешённые действия, observe-память и явно объявленный контекст; механика RNG остаётся внутри доверенного порта. Гостевой код не исполняется через host eval или DOM. Ранее опубликованная сборка 0.21.0 этого SDK не содержит; наличие кода и локальная проверка не означают deployment.

Студия использует общие сцены и компоненты карт, костей, фигур, поля, рук, стопок, таблиц, холста, правил и обучения. Семантика взаимодействий задаётся паком через разрешённые команды и source/target; host-компоненты не выбирают правила по ID игры.

## Запуск

Нужны Node 22+, Python 3.11+ и checkouts app/packs/utils. В app установить закреплённые зависимости: `npm ci --ignore-scripts`. Из utils:

```sh
python3 sdk.py --app ../playroom new /tmp/my-game --id my-game --packs ../playroom-paks
python3 sdk.py --app ../playroom check /tmp/my-game
python3 sdk.py --app ../playroom verify /tmp/my-game --steps 20
python3 sdk.py --app ../playroom serve /tmp/my-game
```

Существующую игру переводят тем же инструментом; старое происхождение сохраняется честно:

```sh
python3 sdk.py --app ../playroom adopt ../playroom-paks/packs/gofish --packs ../playroom-paks
python3 sdk.py --app ../playroom compile ../playroom-paks/packs/gofish --packs ../playroom-paks --shared ../playroom-paks/shared --output /tmp/gofish.playroom-pack.json
```

Изменение уже опубликованного пака требует новой версии; immutable bytes не перезаписываются. `new` и `adopt` не публикуют. Внешняя установка принимает `execution:'isolated-v1'`; пакет не может включить доверенное исполнение своим manifest. Старый host execution доступен лишь проверенному bundled bootstrap либо явному операторскому режиму для fixtures.

Для текущей игры указать `../playroom-paks/packs/gofish --shared ../playroom-paks/shared`. Открыть напечатанный loopback URL. Сервер слушает только 127.0.0.1, проверяет Host/Origin и токен страницы. Код редактируется внешним редактором; watcher сообщает об изменениях, «Перечитать код» создаёт новые среды и партию. Установка проекта не исполняет lifecycle hooks.

## Авторский контракт

`manifest.json` задаёт ID/версию. `sdk/project.json` — source-only descriptor: `contractVersion:1`, списки `rules`, `presentation`, чистые `helpers`, начальные `options`, необязательное `checkTypes:true`. Компилятор формирует нормализованный `sdk/source.json` с выбранными модулями, каталогами, support-кодом и resource closure внутри `playroom-pack`; произвольные файлы проекта не исполняются. `types` перечисляет локальные .d.ts, `support` — чистые модули правил/обучения, `origin` фиксирует создание или миграцию. Definition использует действующий GameModel contractVersion 1; объявления API находятся в `sdk/contracts.d.ts`. Шаблон копирует объявления, проверка использует канонические типы выбранного app checkout.

Правила получают состояние конкретной партии и явный RNG. Для каждого рендера создаётся свежая VM представления: глобальные переменные модуля не сохраняют проекции других игроков или предыдущих кадров. Отдельная VM представления получает только проекцию наблюдателя; в ней нет определения правил или полного состояния. Модули пака не импортируются в Node/Python хоста. UMD-проверки переключаются на браузерную ветку с сохранением координат исходника; Node require не предоставляется. Произвольные HTML/CSS/JS сцены не вставляются в документ.

Модули выполняются в strict mode. Экспортированные классы ядра, их собственные прототипы и используемые встроенные операции защищены от изменения: пак не может подменить валидацию GameModel. ID модели должен совпадать с manifest.json.

Нет доступа к DOM, сети, Auth, файлам, хранилищам, таймерам, Date и ambient Math.random. Запрещённое обращение фиксируется вне VM и проваливает вызов даже при catch внутри пака. Для обязательных полей использовать `SDK.read(object,key)`; ошибка показывает роль, этап, ресурс и исходную строку. Обычный optional JS-access не позволяет обнаружить всякое чтение отсутствующего поля: помогают типы и сценарии. Необязательные undefined-поля существующих сцен пропускаются с предупреждением; функции/NaN/Infinity запрещены. Произвольные сообщения, code/resource и поддельные stack-пути гостевых исключений не выводятся. Сохраняются известные коды SDK/core и координаты реально загруженных модулей; динамический ключ отсутствующего поля заменяется общим field:required. Закрытые значения не включаются в отчёт.

Ограничения на роль: WASM linear memory 64 MiB, QuickJS allocations 48 MiB, стек 512 KiB, вызов 2 секунды и внешний watchdog 5 секунд. RPC-сообщение и читаемый source-файл до 4 MiB, исходники суммарно до 12 MiB. Это защитные пределы загрузчика; бюджет сериализованного source-export отдельно ограничен 4 MB. Worker используется для остановки зависания, а не как самостоятельная защита доступа.

## Ввод, время и уведомления

`Definition.inputs(position, actor)` задаёт ограниченные text/integer/boolean/enum/ink поля. Actor, неизменные параметры (например roundId) и все значения проверяются до reduce; лишние поля отклоняются. `advance(position, now)` получает явное время хоста. Его переходы проходят те же события, durable commit, ACK и историю, что пользовательские действия. Пауза замораживает игровые часы. Отсутствие перехода не добавляет ход на каждый tick.

Общий canvas показывает незавершённые штрихи через авторизованный preview-порт, окончательные операции — через обычный журнал команд. Zoom/pan 100..400% локальны. `scene.vote` задаёт неблокирующее уведомление с голосами, порогом, deadline и разрешённой командой. Оно не ставит игру на паузу и не перехватывает фокус. По окончании неудачного голосования пак удаляет scene.vote; принятое решение ждёт установленной правилами границы. История отключает любые команды и фиксирует таймер по времени кадра. Подробности: [контракт ввода, часов и холста](SDK-DRAWING-CONTRACT.md).

## Правила, история и проверки

`check` проверяет структуру, пути/симлинки, синтаксис, известные запрещённые обращения, типы новых проектов и ассеты. `verify` реально исполняет ограниченные сценарии с seed 1/17: детерминизм, сцены наблюдателей, независимость результата от порядка просмотра игроков, допустимые бот-команды, checkpoint. Это не доказательство правильности всех правил.

Авторские проверки задаются данными в `sdk/scenarios.json`:

```json
{"contractVersion":1,"scenarios":[{"id":"first","steps":[{"actor":0,"command":{"type":"increment"},"expect":{"data.count":1}}],"expect":{"status":"playing"}}]}
```

`expect` сравнивает JSON-значение по пути. Шаблон содержит сценарий завершения партии. Для приватности подготовить закрытый JSON с `left`, `right`, `viewer`: валидные положения, отличающиеся только скрытой информацией. Запуск: `python3 sdk.py --app ../playroom privacy /tmp/my-game --fixture /tmp/private-pair.json`. Сравниваются проекция, подписи действий, сцены и события, включая описания звука/движения, публичный score hook и разрешённая память/контекст бота. Различие может означать ошибочную пару; отчёт не раскрывает сравниваемые значения. Это не исчерпывающее доказательство отсутствия утечек.

История выбирает сохранённый checkpoint и вызывает те же правила проекции и presentation.scene/event/action, что и игра. Правила повторно для просмотра не выполняются; менять партию в истории нельзя. Возврат сохраняет live-положение. Студия и приложение используют общие `presentation/transition.js`, EventPlan, PlanPlayer и Scheduler. Нет отдельного проигрывателя с логикой конкретной игры. История студии хранит контрольные состояния в сжатом закрытом временном журнале (каталог 0700, файл 0600), а в памяти держит до восьми прочитанных кадров. Она удаляется при закрытии студии; ограничение в 1000 действий не прерывает длинную партию. Обычное приложение использует свою общую сохраняемую историю.

Checkpoint привязан к hash исходников и содержит закрытые данные. Его экспорт и показ полного состояния доступны только явным действием автора. Экспорт создаётся только по запросу автора; рабочие контрольные состояния временно хранятся в закрытом журнале студии. Изменение исходников делает checkpoint несовместимым.

## Ресурсы

```sh
python3 sdk.py --app ../playroom import-asset /tmp/my-game /path/to/piece.svg --name piece.svg --license CC0-1.0 --provenance 'Original drawing'
```

Импорт копирует оригинал без перезаписи; лицензия, источник и SHA записываются в `sdk/assets.json`. Допустимы SVG/PNG/JPEG/WebP, WAV/OGG/MP3, JSON-анимации. SVG разбирается XML-парсером: ограниченный словарь, без DTD, скриптов, событий, встроенных стилей и внешних ссылок. Растр: максимум 2048 по стороне/4 000 000 пикселей. Анимация: `contractVersion:1`, `frames:[{time:0,values:{opacity:0}}]`; x/y/rotation/scale/opacity, до 10 секунд/1000 кадров. Галерея позволяет проиграть её с учётом reduced motion. Пользовательский звук прослушивается отдельно; события используют общую TabletopAudio с выключенным по умолчанию звуком.

До 256 runtime-ресурсов/2 000 000 байт суммарно. Изображение — до 512 kB (цель 128 kB); SVG и JSON-анимация — до 64 kB; аудио — до 128 kB. SVG ограничен 2000 узлами. Известная сумма decoded-растров — до 32 MiB. Markdown/text-заметки внутри assets перечисляются отдельно и в runtime/source-export resources не включаются; остальные исходные мастера держать вне assets. Импорт сначала проверяет кандидата вместе с текущим inventory и лишь затем пишет ресурс/метаданные. Encoded bytes и известные decoded image bytes считаются отдельно; память SVG/audio не выдаётся за измеренную. WAV PCM/float проверяется по RIFF/fmt/data и ограничен 10 секундами. Для OGG/MP3 длительность на source-check неизвестна и отмечена предупреждением SDK_AUDIO_DURATION_UNVERIFIED; галерея проверяет browser metadata и не проигрывает аудио дольше 10 секунд. Это не доказательство работы декодеров или производительности на телефоне. Исходные мастера и допустимые копии между автономными паками сохраняются.

## Бюджет полного артефакта

Цель — **500 kB**, жёсткий максимум — **4 MB = 4 000 000 байт UTF-8 до HTTP-сжатия**, без минимального размера. `check` и `build` используют один encoder и возвращают `budget`/`warnings`: подсчёт включает manifest, descriptor, locales, все выбранные модули, JSON escaping и base64 ресурсов. `SDK_PACK_TARGET_EXCEEDED` — предупреждение, а не ошибка. `SDK_PACK_SIZE_LIMIT` отклоняет экспорт до создания файла; существующий output не перезаписывается. Изменившийся после аудита ресурс отклоняется по SHA.

Тот же hard limit применяется к полному устанавливаемому `playroom-pack` в compiler, player parser и проверке импортируемых файлов сайта. Межъязыковой контракт проверяется на точной границе, включая многобайтовый UTF-8. SDK source-export и player-pack остаются разными форматами: размеры одного не доказывают размер другого. Source-мастера и расход памяти VM считаются отдельно.

`build --output FILE` экспортирует новый `playroom-sdk-source` для передачи/ревью. Это не устанавливаемый player-pack, не gameplay-проверка и не deployment. Устанавливаемый pack создаёт `compile`, а проверку обычного player, сети и offline выполняют отдельно от source-проверок. Публикация — отдельная операция.
