# LAN-01 — долговечный журнал браузера-хоста (первый блок RC7)

**Статус:** в разработке на `feature/lan-01-durable-host-session`, ещё не выпущен и не прошёл полный QA. Базовый релиз — [RC6](https://github.com/GraphGiraffe/boardgame-playroom/releases/tag/v0.15.0-rc.6). Полное ТЗ: [roadmap LAN-01](PlayRoom_Roadmap_and_Agent_Handoff_2026-10-08.md).

## Архитектура / ADR

В текущей browser-only WebRTC-архитектуре единственная authority остаётся в браузере хоста. Новый `app/network-session-store.js` хранит полную приватную сетевую Session и историю в IndexedDB **этого origin**, без Node, облачного сервиса или WebSocket-хоста.

База `playroom.network-host.v1`, схема 1: `sessions` — исходное состояние, ID комнаты, точная версия пака и состав на старте; `steps` — состояние каждого подтверждённого действия по `[sessionId,revision]`; `receipts` — результаты команд по `[sessionId,viewer,commandId]`. Авторитетное состояние и квитанция принимаются **одной readwrite-транзакцией**. Вычисление следующего состояния через `Session.prepare` не меняет live Session; только после `transaction.oncomplete` вызывается `commitPrepared`, публикация проекций и окончательный ACK.

Отклонённые игровые команды также получают сохраняемую квитанцию, пока доступен диск. При конфликте ID, версии или ревизии транзакция откатывается; при отказе IndexedDB пользователь получает ошибку и состояние не изменяется. Старые локальные сохранения `localStorage` не мигрируют. Хостовый архив не передаётся по RTC, QR или публичной истории.

## Первая доступная проверка

Из главного экрана: «Сетевые сохранения хоста» → запись партии → проверка `Session.restore` и полного числа состояний. Это **не** повторный запуск старой комнаты. Браузерная проверка `tests/network-session-store-browser.test.cjs` использует HTTP origin, настоящий IndexedDB, перезагрузку страницы и атомарное отклонение дубля. `tests/durable-authority.test.cjs` проверяет сохранение до ACK и отсутствие частичного применения при отказе.

## Следующие шаги LAN-01/03/04 и условия релиза

Нужно восстанавливать RoomService и приватные resume-токены с безопасной ротацией, epoch/leases, перепривязку прежних устройств к старым местам, lookup старых команд после host restart и реальный повторный запуск комнаты. Пока не хватает этого цикла, LAN-01 нельзя считать завершённым. Сетевые боты не используют синхронный обход durable журнала. Независимый набор и полный совместный тест с пятью паками, итоговые HTML/PWA, Android/ПК и ошибка quota обязательны до RC7.

IndexedDB зависит от стабильного origin; очистка site data уничтожает запись, а `file://`/`content://` и чужой origin могут не сохранять её. В случае блокировки сохранения нет тихого fallback. Не публиковать ни секреты, ни полные host snapshots гостям.
