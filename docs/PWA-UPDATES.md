# Обновление PWA · ХОД

Область применения: приложение **0.21.0** и коллекция **0.9.0**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; актуальное приложение доступно на [сайте](https://graphgiraffe.github.io/playroom-hod-test/).

Новая версия сначала сообщает о доступности. В этот момент браузер получает только код Service Worker с метаданными и его Push-зависимость, а не полный набор файлов приложения. Файлы скачиваются по отдельной иконке в окне обновлений. Первое создание offline-копии после новой установки по-прежнему происходит автоматически.

Прогресс и причина ошибки закреплены внизу окна: тонкая закруглённая полоса, процент и объём. Кнопки — иконки с title/aria-label. Окно закрывается крестиком, скачивание продолжается. На главном экране до установки остаётся кнопка: доступно — синяя со стрелкой, загрузка — с двумя стрелками, ошибка/обрыв — красная с предупреждением, готово — зелёная с галочкой. Нажатие открывает текущее состояние; установка выполняется отдельной кнопкой.

## Только изменившиеся файлы и набор обновлений

Перед загрузкой кандидат проверяет свой кеш и кеши предыдущих версий, включая частично загруженные обновления. Файл переносится в отдельный кеш кандидата только при совпадении SHA256 с манифестом целевой сборки. Файлы без закреплённой контрольной суммы между версиями не переиспользуются. Повреждённые и отсутствующие файлы скачиваются заново; активный кеш не изменяется.

Можно пропускать несколько версий: устанавливается полный комплект последней выбранной сборки, а не последовательность патчей. Даже если нужные файлы распределены между несколькими кешами, каждый проверяется по манифесту именно этой сборки. Устаревшие файлы в комплект не включаются. Новое обновление имеет отдельный кеш и собственное состояние; частично скачанная предыдущая версия может дать проверенные файлы новому кандидату.

Во время подготовки отображается «Проверка файлов…». Затем объём и процент относятся только к недостающим файлам, передаваемым по сети; локальное копирование не считается скачиванием. После обрыва оставшийся объём пересчитывается. Общий размер установленного приложения не уменьшается от повторного использования файлов. Перед активацией повторно проверяется весь комплект, старые кеши очищаются только после активации.

## Обрыв и продолжение

Каждый целиком полученный файл проверяется по SHA256 и сохраняется в отдельном кеше кандидата. Состояние записывается после завершения файла. После сбоя сети, перезагрузки страницы или остановки worker проверенные файлы используются повторно; недостающие догружаются. Частично переданный файл скачивается с начала: HTTP Range по отдельным кускам пока не используется.

Ошибки связи, отсутствия сети, 90 секунд без поступления данных, ответа HTTP, страницы входа вместо ресурса, контрольной суммы и места для кеша различаются в интерфейсе. После устранения причины можно продолжить. Закрытие только окна обновлений не останавливает процесс; при закрытии браузера/остановке ОС выполнение может прекратиться, но проверенные файлы сохраняются для продолжения.

## Установка и данные

Скачивание не блокирует текущую версию и не активирует worker. Только полный проверенный набор получает состояние готовности. При установке повторно проверяются все файлы и занятость всех окон этого приложения. Чужие приложения, локальные партии, IndexedDB и пользовательские настройки не удаляются. Старые кеши приложения очищаются после активации готового кандидата.

Окна preview.13 и старше используют прежнюю кнопку при первом переходе на preview.14; новый worker сохраняет совместимость с этой командой. Раздельный экран появляется в установленном preview.14 и работает для последующих обновлений. При медленном первом переходе прежнее окно может показать тайм-аут ожидания, пока worker продолжает загрузку; проверка занятости перед активацией остаётся обязательной.

## Код

- `sw.js`: отдельный кеш кандидата, прогресс по байтам, checkpoint, проверка файлов, безопасная активация.
- `app/pwa.js`: сообщения worker, прогресс, повтор и граница текущего кандидата; политика блокировки вкладок остаётся в `application/pwa-update-coordinator.js`.
- `app/update-dialog.js`: фиксированный прогресс и причины ошибок без пересоздания окна/прокрутки.
- `app/hub-action.js`: состояния главной кнопки без потери доступности при закрытии окна.
- `build.py`: точные размеры и SHA256 публичных ресурсов.

Изменений Supabase/SQL нет. Выпуск остаётся локальным preview; физическое поведение Android при остановке процесса требует отдельной проверки.


## Окно из комнаты · preview.27

Ручное нажатие кнопки обновления на главном экране открывает окно и позволяет скачивание при активной комнате. Автоматическое окно по-прежнему ждёт свободного главного экрана. Граница безопасной активации не ослаблена: установка при активной комнате сообщает, что нужно сохранить партию и выйти; worker и защита нескольких вкладок остаются прежними. Старое приложение до preview.27 ещё содержит прежнюю блокировку окна, поэтому для первого перехода с него потребуется выйти из комнаты после сохранения партии.


## Завершение установки · preview.29

Принятый запрос активации после проверки полного комплекта и готовности окон сохраняет ID допущенных документов. После успешного activate/claim и короткой паузы worker проверяет, остались ли эти документы: уже сменившиеся после обычного controllerchange не затрагиваются. Оставшиеся старые окна из того же scope автоматически переходят по своему URL через WindowClient.navigate. Новые окна, которых не было при проверке, не перенаправляются. Пауза и навигация удерживаются message.waitUntil, а не activate.waitUntil, чтобы не блокировать завершение активации. Механизм работает и со старым загруженным UI без нового обработчика. Произвольной перезагрузки по тайм-ауту до активации нет.

Механика WindowClient.navigate сверена с первичным примером Chromium: https://googlechrome.github.io/samples/service-worker/windowclient-navigate/; граница activated и waitUntil — https://www.w3.org/TR/service-workers/.
