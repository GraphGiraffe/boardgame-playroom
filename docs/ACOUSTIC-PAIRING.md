# ХОД 0.15 — звуковое сопряжение WebRTC (LAN)

## Назначение

Pairing без обмена длинными ссылками и QR: **хост воспроизводит Offer**, телефон слушает микрофоном, **телефон воспроизводит Answer**, хост слушает. После двух сообщений устанавливается штатный `RTCDataChannel`; **игровые данные и скрытые руки никогда не передаются звуком**. Интернет/RoomHub/Node-сервер не нужны для звуковой сигнализации или дальнейшего прямого подключения.

Это **альтернативный способ сигнализации**, а не отдельный игровой/сетевой движок. QR, Web Share и copy/paste остаются fallback. Существующие паки игр и протокол команд не изменяются.

## Пользовательский путь

1. Запустите **одну и ту же офлайн HTML/PWA PlayRoom** на устройствах одной локальной Wi-Fi сети; в поддерживаемых браузерах разрешите микрофон. Для PWA используйте HTTPS, localhost — для разработки.
2. На ПК/телефоне хоста создайте сетевую комнату и выберите **Добавить игрока**. В списке отображаются **все ICE-кандидаты, раскрытые браузером**, включая IPv4, IPv6, mDNS, TCP, публичные/частные адреса и тип кандидата с портом. Дополнительный поиск через WebRTC может выявить другие адреса. Ничего не удаляется из списка только из-за типа IP. Выбор остаётся за пользователем; предпочтительны частные адреса Wi-Fi, а Tx по умолчанию — `Fastest`. При скрытии адресов за mDNS выберите ввод IPv4 вручную. Не подставляйте вымышленный адрес.
3. На клиенте откройте **Присоединиться к комнате → Слушать звуковое приглашение** и разрешите микрофон. Нажмите на хосте **Передать**.
4. После звукового Offer выберите IP самого клиента (или введите вручную), при необходимости смените Tx protocol и нажмите **Отправить звуковой ответ**.
5. После открытия WebRTC DataChannel появится прежний экран лобби: вход, выбор места, готовность и старт партии. Повторите приглашение для каждого нового телефона.

**Важно:** два устройства должны находиться рядом в пределах слышимости и иметь прямую сетевую достижимость. Guest Wi-Fi с AP/client isolation может блокировать WebRTC. Пока ограничение WAN/NAT без relay сохраняется.

## Единый формат звука, QR и ссылок

Новый `PR3.<base64url>` содержит **в точности те же компактные байты ICE/DTLS SDP**, которые передаются через динамик (без текстового префикса `PR3.` в звуковой волне). Текст, Web Share, QR и `web+playroom:` используют один код, а не независимые представления. При смене IP/порта или повторном поиске пересоздаются **все** варианты текущего Offer/Answer.

Можно смешивать направления: Offer принять звуком, Answer отправить QR/Share, и наоборот. Функция `PlayroomPairing.decode()` принимает и `PR3`, и прежний `PR2`; прежние версии опубликованных приглашений сохраняют поддержку. Если текущий SDP нельзя закодировать компактно (например, только IPv6/mDNS или недопустимый адрес), QR/Share используют полный `PR2` — это честный fallback, а не обрезка кандидатов.


## Android: если виден только 192.0.2.1

`192.0.2.1` — зарезервированный TEST-NET, а **не** автоматически определённый локальный IP. Новая версия показывает число кандидатов текущего WebRTC-сеанса, результат независимого ICE/RTCStats-поиска и список отдельно сохранённых вручную IP. Это три разных источника; приложение не должно выдавать placeholder или вручную сохранённый адрес за обнаруженный.

Строка вроде «Например: 192.168.1.100» в ручном поле — **пример**. Узнайте свой фактический IPv4 в свойствах подключённой Wi-Fi-сети Android. После его ввода QR/ссылка должны переключиться с длинного PR2 на компактный PR3. Кнопка «Сохранить введённый IP в списке» добавляет этот адрес в выпадающий список только в том же браузере/origin; он помечается «внесён пользователем». Значение сохраняется добровольно и не передаётся на сервер. Если browser storage недоступен, разовый ручной ввод остаётся возможным.

Дополнительный поиск пробует ICE-кандидаты отдельного соединения и `RTCPeerConnection.getStats()`. Однако браузер не обязан раскрывать адреса Wi-Fi или VPN, особенно при `content://`, политике WebRTC IP-handling, mDNS или настройках VPN. **Никакой чисто браузерный код не способен гарантированно воспроизвести полный системный список IP**, который другой origin/сайт увидел при иных разрешениях. Для приёма звука важен secure context: рекомендуем установить HTTPS PWA и потом использовать offline app-shell.

Важно: когда IPv4 задан вручную, PR3 содержит его и UDP-порт ICE-сеанса, но реальная достижимость такого сочетания не проверена заранее. Если WebRTC использует исключительно виртуальную/синтетическую кандидатуру, подстановка адреса не гарантирует связь. Используйте QR/PR2 или другую сеть при отсутствии канала.

## Микрофон на Android: `Permission denied` и `content://`

Если HTML открыт из загрузок телефона как `content://media/external/...`, мобильный браузер обычно не считает эту страницу подходящим контекстом для разрешения микрофона. Это **не ошибка Wi-Fi, ggwave или IP**: WebRTC может работать по локальной сети, но звуковой приём через `getUserMedia()` недоступен. Приложение показывает предупреждение и не предлагает нажимать неработающие кнопки слушания.

**Для полноценного звукового обмена:** один раз откройте PlayRoom на доверенном **HTTPS-адресе**, предоставьте разрешение микрофону и установите PWA. После кеширования оболочки приложение может работать без интернета; сеть Wi-Fi между игроками остаётся необходимой. `http://<LAN-IP>` без HTTPS не считается защищённым контекстом для удалённого Android. Непроверенный самоподписанный сертификат тоже может не дать secure context; нужен сертификат, которому доверяет Android. `localhost` исключение только для устройства, на котором запущен сервер.

Если микрофон у хоста недоступен, используйте **«Только передать приглашение звуком (ответ по QR/ссылке)»**: динамик не требует разрешения на микрофон, но получатель должен слушать из доверенного контекста. Для ответа используйте QR/Share/текст с тем же компактным PR3, как и в звуковом сообщении. Обычный QR/Share также доступен как полный fallback.

Если HTTPS PWA уже открыта, но браузер всё равно отвечает `NotAllowedError`/`Permission denied`, проверьте разрешения сайта в браузере, системный доступ Chrome/PWA к микрофону и отсутствие его блокировки устройством. `NotFoundError` указывает на отсутствие микрофона, `NotReadableError` — на занятость/аппаратную ошибку.

Адреса `0.0.0.0`, `::` и полностью нулевой IPv6 удаляются **из пользовательского выбора** как неопределённые точки назначения, но валидные локальные/VPN/public/mDNS адреса остаются видимыми. Диагностика по-прежнему учитывает ограничения WebRTC IP privacy.

## Реализация

- `app/acoustic-pairing.js`: бинарный компактный ICE/DTLS SDP frame (не более 140 ASCII-байт после Base64URL), `pack/unpack`, полный список видимых ICE-кандидатов и дополнительный браузерный probe, восстановление SDP.
- `app/pairing.js`: общий `PR3` для звука, QR, Share и текста, legacy `PR2` для совместимости.
- `app/vendor/ggwave.js`: локальный JS+inline WASM ggwave 0.4.3, upstream commit `060aec73dd7123ccac200442f75bdc7369795ffe`, MIT; `app/vendor/LICENSE.ggwave` содержит обязательный текст лицензии.
- `app/network-ui.js`: общие окна приглашения/входа, выбор IP/Tx, передача/приём звука и несколько установленных WebRTC-подключений (новое приглашение не закрывает подключённого игрока).
- `index.html`, `sw.js`, `build.py`: модуль входит в автономный HTML и PWA offline bundle. Никаких runtime CDN для **ggwave**.

Звуковой пакет содержит IPv4, UDP-порт, ICE credentials, DTLS SHA-256 fingerprint и UUID приглашения. Фингерпринт обязателен для шифрованного WebRTC. Он не заменяет взаимную аутентификацию неизвестных участников: при подключении в присутствии чужих устройств проверяйте намерение присоединиться. Никнейм и IP не являются игровыми полномочиями.

Tx: `Fastest` по умолчанию, `Fast` / `Normal` по выбору. Слышимый диапазон выбран по умолчанию как более совместимый; ultrasound не включён по умолчанию из-за аппаратных ограничений.

### Ограничения и проверки

- **Все видимые браузеру, не обязательно все интерфейсы системы.** mDNS и политика приватности WebRTC могут скрывать IP. Дополнительный поиск выполняется без STUN-сервиса, но также ограничен браузером. Ручной ввод по-прежнему доступен.
- Диагностические адреса `192.0.2.x`, `198.51.100.x`, `203.0.113.x` (TEST-NET) остаются в списке, но не могут применяться для звукового IPv4. Из IP невозможно достоверно заключить, что именно это VPN.
- Звуковой компактный формат поддерживает IPv4 UDP host. Остальные ICE-кандидаты показаны, но для них используется совместимый полный SDP через PR2 QR/Share. Дополнительный найденный IPv4 может отсутствовать в текущем ICE-сеансе, поэтому подстановка его к порту текущего сеанса — попытка, а не гарантия соединения.
- При работающем VPN прямой LAN-путь возможен при разрешённой маршрутизации в локальную сеть (split tunneling / allow LAN), если точка доступа не включает изоляцию клиентов. Звук не обходит сетевые запреты.
- `content://` в Android может не быть secure context. При отсутствии микрофона в HTML-файле установите PWA через HTTPS.
- Некоторые браузеры могут не принять восстановленный SDP: это проверяется WebRTC smoke-тестом в Chromium и требует физических тестов Windows Chrome + Android Chrome, Android↔Android и iOS Safari. Результаты не следует выдавать за проведённые до фактических прогонов.
- Разрешение микрофона требуется явным действием. Не передавайте секреты доступа к игре непосредственно в звуковом пакете: звук доступен другим людям рядом.
- Автоматическая сигнализация после рестарта host вкладки остаётся в LAN-03. Хостовое сохранение и клиентская история реализованы в 0.15 отдельными модулями; см. [сетевой контракт](DEVELOPER-MULTIPLAYER.md).
- QR, Web Share и копирование длинных ссылок остаются способом подключения при ошибках звука, нестандартных ICE-кандидатах или несовместимых SDP.

### Проверки

`node --test tests/acoustic-pairing.test.cjs tests/acoustic-webrtc-browser.test.cjs`: двусторонний codec, частные IP, ручной IP при mDNS, отклонение ошибочных данных, WASM-энкодер и реальное Chromium RTCDataChannel.

Затем обычная независимая проверка и полный совместный прогон с установленными исходниками пяти паков. Для выпуска проверять финальные собранные offline HTML/PWA-артефакты и контрольные суммы после добавления внешних assets.
