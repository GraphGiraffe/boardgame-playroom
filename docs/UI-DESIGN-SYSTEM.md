# Визуальные правила 0.18

Общий стиль: спокойная светлая/тёмная палитра, округлые квадратные элементы, читаемая типографика, умеренная толщина/тень игровых объектов. Все размеры исходят из artboard и масштабируются вместе. Дизайн не изменяет состояние, RNG, legal actions и видимость.

Семантические цвета и сохранение тем принадлежат application/appearance.js; Web CSS получает palette variables. Скины выбираются через общий AssetResolver (catalog/skins/palette/renderers). Неизвестный вариант даёт default и missing, не ломает загрузку. Материал карты/кость/корабль используют свои semantic slots, UI — surface/text/border/interaction.

## Правила компонентов

- Аватар квадратный с одинаковым относительным скруглением в профиле, лобби, карточке, таблице, результатах и миниатюре; рисунок не растягивать. Цвета игроков: различимые зелёный, красный, синий, жёлтый, оранжевый, фиолетовый, голубой, серый.
- Карты: artboard одного отношения сторон; face/back и main/compact не меняют hit geometry. Сохранить одинаковый overlap; масштабировать толщину/тень, не добавлять вторую белую рамку.
- Кубик: всегда видимая грань, обводка действия повторяет округлую грань. Preview до первого броска не расходует игровой RNG.
- Иконка карт общая: две карты, передняя наклонена вправо, задняя почти вертикальна, уголок-блеск только на передней; цифры 7 нет. Толщина линии соответствует общему набору.
- Текст и значения из locales; ±1 использует стандартный шрифт счётчиков. У игрового элемента и его статуса одинаковый значок и смысловой цвет.
- Интерактивная область обычно не меньше 44 px; зрительная миниатюра может быть меньше. Видимый focus повторяет форму элемента: скругление кнопки/поля, компактный круг у «?», контур бегунка у слайдера вместо рамки вокруг прозрачной области. Сохраняются aria-label для кнопки без подписи и keyboard управление.
- Окно настроек имеет общую правую границу, симметричные отступы. Заголовок не переносится; full screen/help справа в одной строке. Быстрые действия слева, иконка тем справа.
- Списки без альтернатив скрыты, настройки руки/рассадки только при применимости. Слайдеры имеют видимые точки, недоступный участок серый и не выбирается.
- Диалог/справка выше игрового показа. Overlay не меняет layout; длинное содержимое скроллится внутри.

## Канонические ассеты

`playroom-paks/shared/components` — повторно используемая геометрия; `shared/asset-packs` — characters, cartoon-deck, mini-cards; `shared/assets/catalog.json` — семейства материалов/вариантов. Host хранит generated копии с digest. Изменение canonical → явная сборка companion → проверка parity. Исходные арты и принятые/отклонённые варианты сохраняются в design, оптимизированные runtime-файлы поставляются отдельно.

Новый скин добавляется в библиотеку ассетов/резолвер, а не в правила каждой игры. Пак сообщает семантическое лицо и скрытость; оформление получает их после projection. Пока будущие наборы не готовы, их нельзя показывать пустыми вариантами в меню. План следующих наборов — [NEXT-PATCHES](https://github.com/GraphGiraffe/boardgame-playroom-utils/blob/main/docs/project/app/NEXT-PATCHES.md).

## Настройки 0.18.1

«Игрок №1» и «Порядок» остаются наверху. Ниже правила группируются по смыслу через `ruleGroups` манифеста, по два параметра в строке; вертикальные интервалы компактные. Дискретный слайдер показывает выбранное значение и все точки; не создаёт промежуточных правил. Колоды остаются списками. Единственный вариант скрыт. Общие условия завершения находятся после разделителя в конце; безлимитная позиция `∞` последняя и доступна скринридеру как «Без ограничения».

Редактор правил сохраняет изменения только кнопкой Save. Отмена и открытие справки не меняют комнату или последние выбранные правила. Индексы слайдеров переводятся обратно в точные preset/option IDs до записи.

В персональных настройках «Отображение руки» (Прямо/Веером) и «Рассадка» располагаются в одной строке и скрываются при неприменимости. Справка «?» находится непосредственно у названия параметра и открывается по нажатию; общего блока «О настройках» и подписи о локальности рассадки нет. Справка поясняет область сохранения предпочтений. Эти изменения не меняют игровых команд, приватности и версии состояния.
