# Облачные сохранения · ХОД

Область применения: приложение **0.21.0** и коллекция **0.9.0**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; актуальное приложение доступно на [сайте](https://graphgiraffe.github.io/playroom-hod-test/).

В аккаунте есть переключатель «Облачные сохранения». Он задаёт значение по умолчанию для автоотправки после окончания партии и при выходе в главное меню. Изначально выключен. Для отдельной истории можно явно включить или выключить автоотправку в управлении сохранением; такое переопределение имеет приоритет над общей настройкой.

В «Мои партии» одна кнопка управления показывает статус облачной копии. В окне «Сохранение» — переключатель для этой истории и одна строка квадратных кнопок: удалить (красная), отправить, получить, синхронизировать (зелёная). Экспорт в файл — отдельная кнопка документа со стрелкой в верхней панели. Ручные облачные действия требуют подтверждения с названием действия; автоматические отправки разрешаются переключателем заранее. Статус показан мелко снизу, рядом с квотой указан размер самой истории. Файловый экспорт доступен без аккаунта. Импорт файла остаётся в верхних действиях списка. Иконки файлов следуют выбранной логике: импорт забирает данные из документа (стрелка наружу), экспорт сохраняет их в документ (стрелка внутрь).

## Данные и восстановление

Отправляется тот же компактный независимый файл, что при обычном экспорте: данные партии/разрешённая проекция гостя, идентификатор и точная версия пака с SHA256. Сам пак, пароли комнаты, SDP/ICE и токены возврата не отправляются. Для открытия нужна установленная точная версия пака; новая версия не подставляется автоматически.

Как и файловый перенос, облачное получение создаёт независимую локальную копию, а не подключается к старой онлайн-комнате. Полная Session хоста становится локальной партией; история участника остаётся только для просмотра. Старую локальную историю не удаляем: её автоматическое облачное сохранение выключается, чтобы резервная копия не затёрла полученную версию.

На новом устройстве список облачных историй появляется в общем фильтре «Мои партии». Можно получить историю или удалить облачную копию. Настройка аккаунта хранится на сервере; связи локальных записей с облачными UUID, базовые контрольные суммы и статусы — в локальных предпочтениях, раздельно по аккаунтам.

## Синхронизация и отказы

Сервер выдаёт номер ревизии. Каждая запись и удаление проверяют ожидаемую ревизию, поэтому одновременное изменение с другого устройства не перезаписывается молча. «Синхронизировать» отправляет только локальные изменения или получает только облачные; при изменении обеих сторон показывает конфликт. Явные отправка/получение и удаление запрашивают подтверждение.

При обрыве связи локальные данные остаются на месте; статус показывает ожидание, следующая попытка выполняется при возвращении связи/выходе в меню. Во время игры на каждый ход файлы в Supabase не отправляются. Закрытие браузера не может гарантировать завершение HTTP-запроса: при следующем открытии приложение повторит отправку доступной локальной истории.

Удаление в облаке оставляет лёгкую запись об удалении с новой ревизией. Это предотвращает автоматическое восстановление удалённого файла с другого устройства. Локальная история и другие устройства не очищаются. Повторно включить/отправить файл можно явно.

Смена аккаунта отсекает незавершённые операции. Проверка выполняется также внутри транзакции импорта перед записью локальной копии.

## Квота и доступ

Лимит — **10 485 760 байт (10 МиБ; в интерфейсе «10 МБ») на пользователя**. Считаются UTF-8 байты файлов, реально переданных в облако; удалённые файлы освобождают квоту. Метаданные и физический служебный размер PostgreSQL в пользовательский счётчик не входят.

В верхней части менеджера паков иконка облака с объёмом `0,1/10 МБ` стоит рядом с общей памятью, обозначенной чёрно-белой иконкой приложения. Системные файлы обозначены шестерёнкой, паки — стопкой, сохранения — дискетой; названия доступны в подсказках. Объёмы указаны в КБ/МБ, до 10 — с одним десятичным знаком, далее целыми. Голубая полоса облака расположена сразу над полосой памяти устройства; отдельной карточки нет. Без связи показывает последние известные данные с предупреждением; неизвестный размер не выдаётся за нулевой.

`server/cloud-saves.sql`: таблицы `playroom_cloud_save_settings`, `playroom_cloud_saves`; публичный RPC `playroom_cloud_saves_rpc` с `SECURITY INVOKER`. Запись выполняет закрытая функция `playroom_private.cloud_saves`, которая проверяет текущего владельца и запрещает анонимов. Прямой DML файлов для authenticated отозван; RLS ограничивает чтение владельцем. Блокировка строки настроек сериализует все изменения квоты пользователя, включая загрузки с разными UUID. Ни сервисный ключ, ни администраторский доступ клиенту не нужны.

## Владение кодом и установка

- `application/cloud-save-service.js`: синхронизация, CAS, очередь операций, настройки и граница аккаунта; без DOM и Supabase-протокола.
- `app/cloud-saves-ui.js`, `app/cloud-saves.css`: окна, статусы, квота, привязка библиотеки и событий сохранения.
- `platform/web/supabase-social.js`: существующий авторизованный RPC-адаптер, дополненный облачным endpoint.
- `application/save-transfer.js`: общий формат для файлов и облака, `createRecord` возвращает текст и стабильную контрольную сумму до транспортного gzip.
- `tooling/supabase_setup.py`: полный повторяемый setup; check проверяет и публичный RPC, и тело приватной реализации.

Для отдельной установки примените `server/cloud-saves.sql` после базовой схемы или `setup-supabase.sql` из preview. Дополнительных ключей, Vault-секретов, bucket или Edge Function не требуется.

## Общая синхронизация аккаунта

`application/account-sync-service.js` объединяет независимые чтения существующих RPC в `playroom_account_sync` (`server/account-sync.sql`). При запуске и возвращении в приложение одним запросом поступают профиль, новые сообщения/приглашения с прежними курсорами, настройки и метаданные сохранений. Полные файлы, загрузки/удаления, команды партии и RTC в этот запрос не входят. Ошибка одного раздела не отменяет остальные; смена аккаунта отсекает устаревший ответ.

Оба SQL-файла уже применены к тестовому проекту. Для другой установки они включены в общий `setup-supabase.sql`; `check-supabase.sql` проверяет точные тела функций, включая приватную облачную реализацию.
