# DEPLOY-01 · автоматизация защищённого Pages-деплоя

**Статус после 0.15:** ручной ZIP для существующего защищённого Pages-проекта подготовлен по [RELEASING](RELEASING.md). Автоматическая публикация/rollback пока не реализованы; это отдельный этап 0.16. Само размещение HTTPS не обеспечивает WebRTC signalling или TURN.

## Цель

Публиковать точный проверенный PWA из immutable GitHub Release на прежний production origin. Не создавать новый проект/hostname/scope при обычном обновлении: браузерные сохранения привязаны к origin. Аккаунт, имя проекта и production branch проверять в реальном Cloudflare, не угадывать по скриншоту.

## Будущий pipeline

1. Явный promote выбранного release tag/SHA; скачать PWA и проверить SHA256SUMS, пути и наличие пяти паков.
2. В чистую папку добавить контролируемую приватную password-обёртку. Проверять доступ до env.ASSETS.fetch: HTML/JS/данные без сессии недоступны, ошибка Worker не открывает файлы. Если manifest/иконки доступны для Android WebAPK без входа, это отдельное явное исключение.
3. Проверить неправильный пароль, подделку/истечение cookie, чужой Origin и допустимый Origin:null, прямой доступ к assets, вход и обновление PWA. Секреты не выводить в логи.
4. Развернуть preview, проверить установленную PWA/сохранения на прежнем origin; затем разрешённый promote production с release SHA/deployment ID и rollback.
5. После загрузки проверить живые HTTP-пути с авторизацией и без неё. При провале предыдущий защищённый deployment остаётся активным.

## Настройка перед реализацией

Cloudflare Account ID, API token с минимальными Pages Edit правами, project и production branch задаются в защищённой конфигурации CI. Worker, пароли/хэши/ключи и protected ZIP не хранятся в открытом Git или публичных assets. Если секретов нет, деплой прекращается. Workflow должен существовать на default branch; не включать безусловный deploy на каждый push.

Нужно сохранить текущую политику доступа ко всем production/preview URL, а не полагаться на неизвестность адреса. Кеш установленной PWA может оставаться доступным после истечения серверной сессии; отзыв уже скачанных копий — отдельная политика, не свойство password Worker.

## Приёмка

Один подтверждённый release становится доступен на прежнем URL только после проверки SHA/структуры/доступа. Обновление не удаляет IndexedDB, установленная PWA запускается на двух устройствах. Секреты не публикуются; fallback не отдаёт защищённые файлы открыто. Автоматическую публикацию не считать выполненной наличием ручного ZIP.
