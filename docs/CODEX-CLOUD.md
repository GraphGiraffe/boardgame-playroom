# Codex Cloud для приложения и движка

Эта инструкция подготавливает репозиторий к облачной работе. Она не означает, что Cloud-окружение уже создано или опубликовано. Локальный запуск скриптов и GitHub CI проверяются отдельно от запуска в облаке. Названия полей сверены с документацией 6 октября 2026 года.

Для подготовки используйте `dev`, содержащую `scripts/codex/` после объединения соответствующего PR. Новый релиз в `main` для этой настройки не требуется; прежний опубликованный тег может ещё не содержать скрипты.

## Выбор окружения

В актуальном интерфейсе: **Work in → Cloud → Select environment → Create environment**. Выберите оба GitHub-репозитория; после подготовки проверьте **Install script** и **Start skill**, затем **Publish**. Изменённые зависимости или инструменты включайте в обновлённый снимок через **Republish**. [Официальное руководство](https://learn.chatgpt.com/docs/environments/cloud-environments).

Для проекта нужны `GraphGiraffe/boardgame-playroom` и `GraphGiraffe/boardgame-playroom-paks`, доступные через подключённый GitHub. Выберите оба приватных репозитория в одном окружении. Не добавляйте PAT и команды клонирования с токенами в скрипты. Для исходной настройки предпочтительна `dev`, если она доступна; уже созданную рабочую ветку задачи сохраняйте.

## Текст для настройки окружения

Вставьте в разговор настройки Cloud:

```text
Подготовь окружение для двух выбранных checkout:
GraphGiraffe/boardgame-playroom и GraphGiraffe/boardgame-playroom-paks.
Определи их реальные абсолютные пути по Git remotes; не предполагай
фиксированный /workspace или соседство каталогов. Используй dev как
исходную ветку, если она доступна при настройке; не переключай и не
сбрасывай уже созданные рабочие ветки задачи.

Используй Node.js 22 и Python 3.12 (минимум Python 3.9).
Из корня приложения выполни bash scripts/codex/setup.sh с --packs-dir,
указав реальный каталог packs второго checkout. Из корня паков выполни
bash scripts/codex/setup.sh. Не создавай .env, конфигурацию модели,
API-ключи или другие секреты: они проекту не нужны.

Выполни bash scripts/codex/check.sh в checkout паков, затем в приложении
bash scripts/codex/check.sh --full с тем же --packs-dir. Не выдавай
самостоятельную проверку одного репозитория за совместную.
Если браузеру нужны системные библиотеки, используй предусмотренный
флаг --install-system-deps и опиши результат; не меняй глобальные настройки
машины.

Запиши проверенные команды подготовки в Install script. Для Start skill
используй bash scripts/codex/serve.sh из корня приложения и проверь
http://127.0.0.1:4173/. Если порт уже занят, проверь, что это нужный сервер;
не запускай дубликат. Покажи пути checkout, версии инструментов,
результаты проверок и оставшиеся ограничения перед публикацией окружения.
```

## Команды проекта

Из корня checkout приложения:

```sh
bash scripts/codex/setup.sh
bash scripts/codex/check.sh
bash scripts/codex/serve.sh
```

`setup.sh` устанавливает закреплённые npm dev-зависимости через `npm ci`, находит Chrome/Chromium или загружает совместимый Chromium через Playwright. Внешний браузер можно задать `CHROME_BIN`; ошибочный явный путь считается ошибкой настройки. `--install-system-deps` — отдельное явное включение установки системных библиотек; без флага apt не запускается.

Для явного расположения паков назначьте `PACKS_CHECKOUT` реальному абсолютному пути второго checkout, затем:

```sh
bash scripts/codex/setup.sh --packs-dir "${PACKS_CHECKOUT:?Укажите путь к checkout паков}/packs"
bash scripts/codex/check.sh --full --packs-dir "$PACKS_CHECKOUT/packs"
```

`--packs-dir` указывает на каталог **packs**, а не его родительский репозиторий. Подготовка создаёт исключённые из Git `installed-packs.js` и локальную зависимость `packs/`. `check.sh --full` обновляет данные разработки перед тестами и требует все пять паков; у `check.sh` флаг `--packs-dir` допустим только вместе с `--full`. Если выбран только репозиторий приложения, доступны его самостоятельная сборка и независимые проверки; полный игровой прогон недоступен.

Обычный `check.sh` намеренно подготавливает хаб без игр, даже если рядом есть паки. Чтобы затем просматривать игры, снова выполните setup с нужным `--packs-dir` либо полный check.

Сервер по умолчанию слушает `127.0.0.1:4173`; другой порт задаётся `bash scripts/codex/serve.sh 4174`. Это статическое приложение без backend, базы данных и обязательных runtime-секретов.

## Сеть и повторная настройка

Для установки зависимостей начните с сетевого профиля **Package managers**, добавляя только необходимые домены. [Настройки сети Cloud](https://learn.chatgpt.com/docs/environments/cloud-environments#connect-to-services).

Для закреплённого `playwright-core` 1.63.0 метаданные загрузки Chromium указывают `cdn.playwright.dev`; резервный адрес для FFmpeg — `playwright.download.prss.microsoft.com`. Проверьте адреса после изменения lockfile командой из корня приложения после `npm ci`:

```sh
node node_modules/playwright-core/cli.js install --dry-run chromium
```

Если загрузка сообщает о заблокированном перенаправлении, добавьте конкретный требуемый хост из её журнала. Не включайте неограниченный доступ для исправления одного домена. Приложение и подготовленные тесты не требуют внешнего API. Изменение lockfile или браузерной версии требует повторной подготовки и проверки; сохранённые зависимости не заменяют её.

Интерфейс **Legacy** использует setup script и необязательный maintenance script для возвращения к кэшированному окружению; это отдельный механизм. Не переносите его поля в текущую инструкцию с Install script / Start skill. [Legacy-документация](https://learn.chatgpt.com/docs/environments/cloud-environment).

Проектные указания находятся в корневом [AGENTS.md](../AGENTS.md). Более близкие к рабочему каталогу инструкции могут их дополнять; детали обнаружения описаны в [официальном руководстве AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Личные локальные правила автора для подготовки проекта не нужны.

- Самостоятельное приложение без паков: **48/48**, без пропусков. Полный режим без паков завершился понятной ошибкой.
- Совместный прогон через скрипт паков: **330/330**, без пропусков.

Это проверка переносимой подготовки в контейнере, не запуск в Codex Cloud. Доступ GitHub-интеграции к обоим приватным репозиториям и публикация конкретного Cloud-окружения проверяются при его создании.
