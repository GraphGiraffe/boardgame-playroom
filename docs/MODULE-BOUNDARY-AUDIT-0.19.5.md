# Проверка границ модулей и объектов · 0.19.5

Проверены исходники приложения и 15 паков в текущих рабочих ветках. Это аудит структуры и выбранных сценариев, а не доказательство отсутствия любых архитектурных проблем или проверка реального сетевого обрыва на телефонах.

## Исправлено

| Область | Было | Теперь |
| --- | --- | --- |
| Обучение | Прогресс, localStorage, курсор и DOM-события в одном файле | `application/tutorial-controller.js` владеет прогрессом; `platform/web/guide-preferences.js` хранит настройку; `app/first-turn-guide.js` обслуживает Web-курсор |
| Сценарии паков | Определения целей внутри `view.js` | `presentation/tutorial.js` во всех 15 паках; renderer только регистрирует полученную функцию |
| Настройки игрока | Значения по умолчанию, миграция, фильтрация и сохранение в `app.js` | `application/player-settings.js` задаёт схему; `platform/web/player-settings-store.js` отвечает за storage; оболочка связывает настройки с UI и применяет эффекты |
| Владение прогрессом | Web-слой мог менять Set напрямую | Приватные поля контроллера, отдельные методы локального выбора и успешной команды; наружу выдаётся копия прогресса |
| Завершение обучения | Наблюдатель и обработчики оставались установленными | `stop` отключает observer/listeners, отменяет timer/rAF и удаляет курсор; повторный запуск устанавливает их заново |

Контроллер получает порт хранилища прогресса; он не обращается к DOM, localStorage, сети, звуку или игровым командам. Захваченный токен принадлежит конкретному экземпляру, партии, игроку и поколению обучения. Другой экземпляр не может его применить; перезапуск аннулирует старое подтверждение. Токен обрабатывается однократно. WeakMap не удерживает завершённую партию после освобождения внешних ссылок.

Настройки и освоенные действия сохраняются по пользователю и паку в playroom.learning.v1.<userId>. Подтверждённый сброс очищает список и включает обучение. Общие настройки также сохраняют прежний ключ, значения и миграции. Игровые правила и формат сетевого протокола не изменены.

## Проверенные границы

| Владелец | Допустимая ответственность | Что не должно попадать сюда |
| --- | --- | --- |
| `pack/domain` | Чистые правила, переход состояния, разрешённые действия, RNG модели, оценка бота | DOM, storage, таймеры, тексты UI, обучение, проигрывание эффектов |
| `pack/presentation` | Разрешённая проекция → сцена, описания эффектов, определения обучения | Команды в authority, изменение модели, чтение закрытой руки вне projection |
| `TutorialController` | Достигнутые цели, редкие этапы, перезапуск, подтверждения | Самостоятельное выполнение действия за игрока |
| Web-слой обучения | Поиск видимого элемента, курсор, пауза ввода 500 мс | Изменение правил и прогресса через прямую запись |
| Settings schema/store | Значения, нормализация, миграция / чтение и запись | Управление сетевым соединением или анимационным циклом |
| `Authority` / `CommandProcessor` | Проверка прав, очередь, revision, durable commit, ACK | Ожидание декоративной анимации |
| `ClientConnectionService` / WebRTC / recovery | Доставка, повторы, восстановление и синхронизация | DOM-подсказки, визуальная геометрия, воспроизведение звука |
| `GameScreenController` | Связать поступающие снимки с историей и презентацией через порты | Пересчитывать игровые правила |
| `PlanPlayer` / scheduler | Последовательные группы, одновременные эффекты, ожидание и отмена | Изменение authority или отправка ходов |
| `game-feedback` / motion / audio | Web-адаптеры эффектов и аудио | Решение результата хода |

Поиск запрещённых платформенных зависимостей в domain и проверка зависимостей сети/презентации не обнаружили прямого вызова обучения из игровых правил, WebRTC или проигрывателя анимаций. Передача описаний эффектов из presentation — контракт, а не смешение с проигрыванием. Ожидание показа семантического окна реакции — отдельный игровой протокол; оно не означает, что heartbeat должен ждать анимацию.

## Объектное разделение

- Состояние и жизненный цикл принадлежат объектам: TutorialController, GameScreenController, ClientConnectionService, RecoveryCoordinator, PlanPlayer, хранилища.
- Изменяемые коллекции нового контроллера закрыты private-полями; зависимости storage передаются конструктору адаптера. Объекты разных экземпляров не разделяют прогресс.
- Правила, нормализация настроек и описание обучения остаются чистыми функциями. Класс без собственного состояния не добавляет изоляции; наследование ради сходных названий не вводилось.
- Web-слой обучения остаётся одним адаптером на документ. Для нескольких независимых поверхностей нужен отдельный mount/экземпляр, а не общий текущий viewer; существующий сценарий одной активной поверхности сохранён.

## Оставшийся архитектурный долг

1. `app/app.js` всё ещё большой composition root: модальные окна, локальная навигация, рендер настроек и применение их эффектов находятся рядом. Схема и storage уже вынесены, но весь экран настроек не объявляется выделенным компонентом. Следующий безопасный шаг — SettingsPresenter с callback-портами без копии Session.
2. `application/rooms.js` и `client-connection-service.js` формируют некоторые ошибки через глобальный `PlayroomMessages`. Это зависимость от локализации. Отдельная миграция на коды ошибок/MessageRef должна сохранить пользовательские сообщения и сетевые контракты.
3. У существующих Room/Client/Screen объектов остаются публичные изменяемые поля. Вводить private-поля следует после инвентаризации вызывающего кода; механическая замена может сломать адаптеры и диагностику. Новый контроллер не повторяет эту схему.
4. Каталог сценариев определяет условия через публичные поля SceneModel. При изменении projection необходимо обновлять соответствующий сценарий и проверять реальный UI, а не только тип команды.

Эти пункты отмечены как долг, а не как выполненный рефакторинг. Переписывание сетевых и игровых объектов целиком в данный патч не входит.

## Проверки

В существующем `domain-foundation.test.cjs` закреплены изоляция экземпляров/токенов, неизменяемость наружного прогресса, отсутствие платформенных портов у сценариев, включение сценариев только во view-bundle и отдельное хранение настроек. Дополнительно выполняются шесть браузерных сценариев обучения, settings-help и motion-settings. Проверяется готовая автономная сборка с точными companion-паками; source и production остаются разными состояниями.

## Финальная проверка

Каталог и ревизии целей принадлежат presentation/tutorial.js каждого пака; пользовательский журнал — GuidePreferences; смысловые события — TutorialController; курсор и диалоги — Web-адаптеры. Копируются только набор целей и небольшой checkpoint, а не игровые состояния. Повторная запись уже освоенной ревизии пропускается.

BotReactionDelay вычисляет чистое решение в паке; модель валидирует его; Authority владеет таймером и отсчётом эпизода. Пак не создаёт таймеров и не отправляет сетевые сообщения. Автоочистка версий — application/pack-update-cleanup.js с портами локальных/сетевых ссылок; UI только вызывает её после успешной установки. При ошибке чтения архивов версии сохраняются.

Аудит готовых JSON 0.8.5: нет authoring-файлов и дублированных встроенных JS/CSS; шесть кандидатов identical-files — одна рубашка в отдельных скинах колоды (standard/mini/cartoon), пути используются контрактом скинов. Межпаковые shared-ресурсы оставлены для самостоятельной установки каждого пака. Отчёт: tmp_files/release-0.8.5-local/asset-audit.json.
