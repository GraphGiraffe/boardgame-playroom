# Контракты RC.4

Дополнение к API 2, применяется с приложением 0.16.0-rc.4 и коллекцией 0.5.0-preview.3. Старые версии паков остаются самостоятельными; опубликованные JSON не переписываются.

## Каталог

`core/tags.json` — закрытый реестр с `id`, `kind` (`type` / `mechanic`), `label`, `icon`. `core/tag-registry.js` генерируется сборкой для браузера; паки хранят совпадающую копию `shared/tags.json`. Новый пак содержит `tags`: 1–3 уникальных ID, минимум один тип. Незнакомые ID отклоняются при сборке и импорте. Старый пак без tags отображается через category.

`playModes: [{id, players: [2,3,4], teams: false}]` описывает реальные составы, а не наличие ботов. Соло — поддержка одного человека без соперников; дуэль — весь пак строго на двоих; три — строго на троих; N+ — хотя бы один доступный состав не меньше N. Допустимы только 2+, 3+, 4+, 6+. Команды требуют реализованного командного режима. При отсутствии playModes используется min/max (или playerCounts).

Порядок фильтров: Все/звезда, состав, тип, механика. Каждая группа начинается с новой строки и отделена тонкой линией; видимых заголовков нет. Типы и Соло/Дуэль/Три/Команды — иконки с aria-label и title, механики — текст. Состав — светлый с рамкой, тип — темнее, механика — светлая. Выбранное — тёмное/белое. Группы пересекаются по AND; повторный выбор снимает фильтр. Все/звезда не сбрасывают остальные группы. Зарезервированные пустые типы/механики не показываются, недоступные составы отключены.

У карточек те же теги и цвета; метаданные количества игроков остаются. Механики назначаются консервативно: «комбинации» у Ятзи, Рыбы, Акулины; «память» у Пексесо; «логика» у Шашек и крестиков-ноликов.

## Лобби и восстановление

`firstPlayerMode`: rules (по умолчанию), random, assigned; `seatOrder`: normal (по умолчанию), random. В редакторе две колонки radio с общими иконками. Настройки запоминаются для каждого пака. Назначенный игрок — `firstParticipantId`, не номер места: жёлтый жетон 1 перетаскивают либо нажимают жетон и карточку игрока.

`prepareStart` перемешивает только занятые места один раз перед локальным запуском или сетевым countdown. `startOrderResolved` сохраняется вместе с комнатой; повторное продолжение не перемешивает. Изменения лобби и новая партия снимают маркер. Первый ход определяется после порядка; команды зависят от итоговых позиций.

При уменьшении лобби отказ происходит только при превышении вместимости. Сначала сохраняются все занятые места внутри нового диапазона. Затем переполнение по старому индексу занимает первые свободные места: 1/3/5/7 → 1/3/2/4. Учитываются боты, локальные, сетевые и временно отключённые игроки; зрители не занимают места. ID, соединение и назначение первого игрока сохраняются, готовность сбрасывается. Ниже минимума можно находиться в лобби, запуск запрещён.

`rulesNotice` привязан к участнику и снимается после подтверждения готовности, старта и возврата к новой партии. Toast истекает через 6 секунд и очищается при смене/закрытии диалога. Потеря связи остаётся отдельным статусом соединения.

## Компоновка и персональные настройки

- `fieldSizing: 'scroll'` выделяет полю весь доступный прямоугольник без изменения пропорций игровых объектов. Внутри можно создать собственный scroll container со sticky заголовком/итогом. Нельзя сочетать с fieldAspect.
- Ятзи: очковые столбцы ровно 56px, имена представлены `H.avatar(person,index)` с доступной подписью; первая колонка, шапка и итог закреплены. Предварительные очки — кнопки с пунктирной рамкой, подтверждённые — текст. Горизонтально движутся очковые столбцы, категории остаются.
- `H.indicators([{icon,value,label,size?}])` и `playerContent.indicators` рисуют компактные подписанные для доступности иконки. До восьми, value — неотрицательное целое, size — 1–8. `ship/cards/pieces/dice`; size обозначает длину корабля, value — количество.
- `ui.preferences` — локальные настройки текущего пака/игрока. `data-view-preference` + `data-view-value` сохраняют значение без команды authority и без сброса готовности. `ui.viewState` временный, сбрасывается на смене хода/viewer.
- `ui.presentationTurn` удерживает поле предыдущего хода во время представления результата. Морской бой использует его для показа выстрела быстрого бота перед возвратом к полю противника. Ручной выбор поля действует до смены хода; followOpponent включён по умолчанию.
- `targetChoice: 'card'` показывает закрытые карты в области поля сеткой 5:7, без перекрытия, в исходном порядке. Передаются только target/cardIndex. Есть аватар и отмена; переключение соперника — его карточкой. Размеры аватарок внутри кнопок не увеличивают высоту кнопки.

## События, звук и движения

Перемещения задаются `event(..., {transfer:{player,count,from:'stock'|'hand'|'table',fromPlayer?,to?:'table'}})`. Только количество и разрешённые участники, без card ID/ранга. `privateTo` может быть индексом или массивом адресатов; закрытый `transfer` попадает в эффекты только их live/history snapshot и локальную анимацию. Authority собирает новые события в их порядке; затем добавляет не дублирующиеся разницы рук. Для пары сначала transfer в руку, затем публичный transfer на стол. Один move/revision не проигрывается дважды.

`extra.sound: {id,target?}` — собственный сигнал; `sound:null` явно отключает fallback. `privateTo` скрывает звук и перемещение от остальных, если не заданы отдельные публичные метаданные. Проекция сохраняет sound:null, поэтому повторное вычисление cues на клиенте не возвращает скрытый fallback. Публичные пары/комплекты остаются публичными со звуком успеха; личность закрытой карты не кодируется звуком или движением. Публичное изменение числа карт в руке остаётся наблюдаемым.

`extra.presentation: {type,...}` задаёт публичный тип/координату эффекта для сетевой стороны. Секреты туда не входят. Нормальные действия не требуют задержки authority: представление идёт после подтверждённого изменения. Reduced motion отключает движение, звук управляется отдельно. Акценты до 250ms, маршруты фишек могут быть длиннее. motionSequence.entry=lift приподнимает выходящую фишку; arrival=settle подчёркивает финиш. data-slide-key задаёт порядок полей для короткого горизонтального перехода при смене ключа. Общая библиотека: success, success.special, success.yatzy, mismatch, error и существующие move/draw/dice/attack/defend/etc. Ятзи звучит при записи категории, а не броске или наведении.

Морской бой использует паковые sea.start/miss/hit/sunk; sunk заменяет hit. При выключенном объявлении — обычный hit. Финальный сигнал следует после игрового. Источники WAV и воспроизводимый генератор хранятся в репозитории паков.

## Проверка

Полный совместный gate: `bash scripts/codex/check.sh --full --packs-dir ../playroom-paks/packs`. Для итераций выбираются существующие блоки и регрессии, не новый параллельный harness. Измерить 320/390/768 px, короткий landscape, увеличенный текст, собственную/чужую руку, фиксированные итоги и доступность действий. Сохранить и посмотреть скриншоты; геометрическая проверка сама по себе не подтверждает удобство. Сетевая проверка сравнивает разрешённые проекции и эффекты, включая повтор snapshot и reconnect.

| --- | --- | --- |

| Змеи и лестницы | кубик, маршрут, подъём/падение, финал | поле публичное |

| Ятзи | кубики; запись числовой/особой/Ятзи/нулевой категории, бонус, финал | выбор кубика/предпросмотр не звучат как успех |
| Морской бой | сирена, вода, попадание или потопление, финал; переход полей | при отключённом объявлении нет чужого остатка и особого сигнала потопления |

Ошибочный локальный ввод может использовать `error`; отказ не превращается в публичное событие. Повторные snapshots, просмотр закрытой информации и история не создают новых игровых сигналов.

## Уточнения 0.16.1

Управление паками и таблицы сохраняют позицию прокрутки при обновлении. Удаление версии с локальными или сетевыми историями требует двух подтверждений; все её истории удаляются вместе с ней. Полная очистка «Моих партий» требует отдельного подтверждения. При сетевой ошибке нельзя считать список историй полным.

Публичная анимация закрытого обмена допускает только `player`, `fromPlayer`, `count`, `from: hand` и рубашку карты. Содержимое карты остаётся в частной проекции руки. Акулина показывает имена участников, но не значение карты; начисление очков определяется порядком выхода.

Пексесо держит несовпавшую пару открытой до первого действия следующего игрока. Ятзи резервирует высоту строк под кнопки и сохраняет DOM/прокрутку таблицы при удержании кубика.
