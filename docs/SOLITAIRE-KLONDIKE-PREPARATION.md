# Косынка: правила, соло-режим и подготовка реализации

Дата исследования: 19.10.2026. Проверенная исходная пара: app 0.18.2 (`7c1f48372a5e5294ad7acaab788a50cc64b3f9d9`), packs 0.7.1 (`ae2e030cf3f709b0388fc846de4c699b2c15c3bc`).

**Это проектная спецификация для обсуждения, а не реализованный пак и не утверждённый состав релиза.** Windows XP Solitaire — главный ориентир. Современные удобства и другие варианты явно отделены от исторической совместимости. Сообщение про тесты скорости к этой работе не относится.

## 1. Итоговое предложение

Один человек, одна обычная колода из 52 карт, семь столбцов и четыре дома. Один непрерывный игровой процесс: нет бота, соперников, руки, передачи устройства, очередности или кнопки окончания хода. Новая игра сначала показывает компактную настройку правил, а затем сразу поле. Профиль и общие настройки приложения сохраняются; второй участник для запуска не нужен.

Базовый профиль предлагается назвать «Классический». Его правила опираются на Windows Solitaire. Рабочее значение добора — 3 карты, счёт Standard, проходы не ограничены. **Это предложение для ХОД, а не доказанный набор заводских флажков чистой Windows XP:** найденная первичная справка не фиксирует их начальные значения. Для надписи «точно как XP» нужна проверка оригинальной установки по чек-листу ниже.

Второй профиль пока не обязателен: дополнительные варианты можно собрать из настроек. Не следует превращать каждую перестановку опций в самостоятельный режим или смешивать Косынку с Пауком/Свободной ячейкой.

## 2. Основные правила

| Область | Базовое правило |
| --- | --- |
| Карты | 52 карты, 4 масти, без джокеров. Внешний вид колоды не меняет состав |
| Расклад | 7 столбцов: 1, 2, …, 7 карт. Последняя карта каждого открыта; остальные закрыты. На поле 28 карт, в запасе 24 |
| Столбцы | Убывание ранга, чередование красного/чёрного; переносится открытая правильная последовательность или её нижняя часть |
| Пустой столбец | Только король либо последовательность, начинающаяся с короля |
| Дома | По мастям, от туза до короля; в пустой дом — туз. В дом переносится одна доступная карта |
| Закрытая карта | Нельзя перемещать или смотреть заранее. После освобождения её можно открыть |
| Сброс | Играть можно только доступной верхней картой, а не любой из показанной тройки |
| Добор | Из запаса в сброс по 1 или 3 карты; остаток меньше трёх переносится целиком |
| Новый проход | При пустом запасе сброс переворачивается без тасования; ранее сыгранные карты не возвращаются |
| Победа | Все 52 карты в четырёх домах; неполная сборка не считается победой |

Основа: [правила из справки классического Windows Solitaire][S1], управление последовательностями — [Playing the Game][S2]. У справки на зеркале нет надёжной привязки к конкретной сборке XP; это первичный текст классической Windows-реализации, а не подтверждение всех деталей XP.

### Важные пограничные случаи

- Туз в домах — младший. В общем `standardDeck` тузы имеют `rank = 14`; нужен доменный порядок Косынки A=1, 2…K=13 без изменения общих card/asset ID.
- Рабочая семантика переноса: выбранная карта и все открытые карты под ней в столбце; нельзя вытащить карту из середины, оставив лежащие на ней карты.
- Проверять цвета мастей, а не просто неравенство мастей: ♠ и ♣ имеют один цвет.
- В доме доступна только верхняя карта. Возврат из дома на столбец предполагается разрешить в классическом профиле; точное поведение XP/штраф проверяется отдельно, см. раздел 5.
- Дома могут заполняться в любом порядке мастей. Пустой дом принимает туз; для стабильного ввода можно выбирать первый подходящий дом, но не менять уже начатую масть.
- Если изображаются три карты сброса, первые две не становятся отдельными legal targets. После снятия верхней открывается предыдущая карта реального сброса, в том числе из предыдущей порции.
- Нельзя вернуть в запас уже открытый неполный пакет отдельно от общего сброса или заново перемешать его ради удобного порядка.
- Для проверки порядка: запас сверху вниз A,B,C,D,E,F; после двух доборов верх сброса F. Сняли F,E,D — снова доступна C, а не A. После полного оборота неснятых карт порядок следующего прохода должен совпасть с физическим переворотом сброса.
- Первичная раздача не должна сама приносить очки за размещение/открытие начальных карт. Это отдельный сценарий совместимости, а не побочный эффект повторного использования обычного move/flip.

Эти пункты превращаются в явные инварианты будущей модели; спорные исторические детали не объявляются уже проверенными.

## 3. Варианты и настройки

Ниже — **предлагаемые** блоки редактора. По два контрола в строке; справка у заголовка. Неприменимые параметры скрываются. Установки действуют на новую партию; редактирование draft не меняет текущую.

| Блок / строка | Параметр | Значения | Предложение по умолчанию | Статус |
| --- | --- | --- | --- | --- |
| Раздача и счёт / 1 | Добор | 1 / 3 | 3 | Оба значения есть в Windows; начальный XP-флажок проверить |
| Раздача и счёт / 1 | Счёт | Без счёта / Обычный / Vegas | Обычный | Три варианта описаны в Windows-справке |
| Раздача и счёт / 2 | Проходов колоды | 1 / 3 / ∞ | ∞ при обычном счёте | ∞ последним; это число **полных проходов**, первый уже включён |
| Раздача и счёт / 2 | На время | Выкл / Вкл | Вкл, предварительно | Это правило счёта, не просто видимость часов |
| Удобства / 1 | Открытие карт | Вручную / Авто | Вручную | Ручное открытие описано в классической справке; Авто — дополнительное удобство |
| Удобства / 1 | Отмена | Выкл / Последнее действие / История | Последнее действие, предварительно | Границы XP-отмены ещё проверить; История — расширение ХОД |
| Удобства / 2 | Автосбор | Выкл / По кнопке | Выкл | Автоматическое стратегическое перекладывание по умолчанию не включать |
| Vegas / 1 | Общий счёт | Выкл / Вкл | Выкл | Показывать только в Vegas; состояние нескольких партий отделить от текущего расклада |

**Ограничения сочетаний:**

- В обычном счёте и без счёта базовый вариант — неограниченные проходы. 1/3 прохода можно предложить как пользовательское ограничение, явно помечая изменённый профиль.
- Для Vegas распространён вариант: добор 1 → один проход; добор 3 → три прохода. Он описан разработчиками [MobilityWare][S5] и [Brainium][S6], но эти современные реализации не доказывают идентичность XP. После проверки XP лимит следует закрепить в профиле Vegas, а не давать противоречивый независимый слайдер.
- В терминах счётчика: лимит 1 = ноль переворотов сброса; лимит 3 = не больше двух переворотов. Третий переворот запускает уже четвёртый проход. Не смешивать «проход» и «пересдачу».
- В Vegas таймер можно показывать как статистику, но временные бонусы/штрафы Standard туда не переносить.
- Автооткрытие вместе с «Отмена: последнее действие» требует определённой транзакционной границы. Предложение для удобного режима ХОД — перемещение + автоматическое открытие отменяются вместе. Это не утверждение о XP.
- Колода всегда 52 карты: нет вариантов 36/54, двух колод, свободной ячейки или «любая карта в пустой столбец» в первом объёме. Иное заполнение столбцов можно обсуждать как отдельный house rule позже.
- Расклад по seed — обычный случайный, без обещания решаемости. Отбор гарантированно решаемых раскладов требует отдельного генератора/решателя и не входит в базу.

У KDE KPat есть собственные варианты добора 1/3 и правила повторного просмотра запаса; это полезное подтверждение существования вариантов, не замена XP-эталона: [руководство разработчика][S7].

### Что не надо показывать в правилах Косынки

«Игрок №1», «Порядок», число игроков/команды, открытые руки, рассадку, передачу устройства, лимит раундов, «до первого победителя/до всех мест». Здесь один расклад и один критерий завершения. Если позже добавится серия раскладов, это отдельная настройка серии, а не несколько игроков или круг очередности.

Внешний вид карт/рубашки, тема и масштаб остаются общими персональными настройками. «Показывать часы» меняет только отображение; «На время» влияет на правила и фиксируется при создании партии.

## 4. Счёт: подтверждённое и требующее контрольной партии

В первичной [Windows-справке о счёте][S3] описаны Standard/Vegas/без счёта, стоимость переноса в дом +10, из запаса на столбец +5, из дома обратно −15, штрафы повторных проходов и отсутствие временного бонуса в Vegas. Там же описаны виртуальная ставка 52 и +5 за карту в дом в Vegas.

| Операция | Standard: рабочая таблица | Надёжность для точной XP-копии |
| --- | --- | --- |
| Сброс → столбец | +5 | Есть в классической справке |
| Столбец / сброс → дом | +10 | Стоимость помещения в дом подтверждена |
| Дом → столбец | −15 | Есть в классической справке |
| Столбец → столбец | 0 | Рабочее ожидание; включить в контроль |
| Открыть закрытую карту столбца | +5 | Есть у современных разработчиков; проверить непосредственно в XP |
| Повторный проход, добор 1 | −100 | Windows-справка; проверить момент списания и нижнюю границу |
| Повторный проход, добор 3 | −20 после первых трёх проходов | Формулировка справки неоднозначна для номера первого штрафного переворота; нужен пример по шагам |
| Каждые 10 секунд | −2 | Есть в современной опубликованной реализации; точную XP-границу проверить |
| Отмена | Отдельный штраф пока не закреплён | Не импортировать автоматически −2 из MobilityWare |
| Минимум очков | Предполагается 0 | Проверить XP; в Vegas отрицательные значения допустимы |
| Выигрыш на время | Бонус по времени | Формулу, порог 30 с и округление подтвердить оригиналом |

[Архив Microsoft KB101766][S4] содержит формулу `700000 / seconds` и различает игры короче/дольше 30 секунд, но относится к Windows 3.x. Он **не подтверждает** XP, точный случай 30 секунд или машинное округление. Исторический «максимальный счёт» из KB не использовать как эталон теста XP.

В Vegas предлагаем считать баланс через текущий вклад домов и анте, чтобы возврат/повторное помещение одной карты не создавали бесконечный заработок. Конкретный штраф возврата и влияние Undo/Restart должны соответствовать выбранному профилю, поэтому сначала контрольная партия. «Общий счёт» хранится отдельно, с защитой от повторного начисления результата при reload/ACK/retry. Это условные очки, не платёжная механика.

## 5. Что ещё нужно проверить именно на Windows XP

Найденная справка — надёжная основа классических правил, но недостаточное основание обещать побитовую совместимость с sol.exe XP. Исполняемый файл XP здесь не запускался. До реализации строгого профиля нужна короткая ручная контрольная сессия оригинала, а не перенос особенностей клона.

| Проверка оригинала | Что записать |
| --- | --- |
| Чистый профиль пользователя XP | Начальные Draw/Scoring/Timed/Keep Score; установленная игра могла сохранить чужие опции |
| Ручное открытие и отмена | Можно ли отменить раскрытие карты; сбрасывает ли flip доступность Undo; можно ли отменить draw/recycle; только ли одно действие |
| Пять оборотов Draw 3 | Число полного прохода, факт переворота, очки до/после; где начинается −20 |
| Draw 1 и конец запаса | Штраф каждого переворота, score floor, пакет из 1–2 карт в Draw 3 |
| Foundation → tableau | Законность и точные очки в Standard и Vegas; повторное помещение той же карты |
| Стандартные очки и время | Начальная раздача, flip, undo, ноль очков, границы 9/10/11 и 29/30/31 секунд |
| Правый/двойной клик и конец партии | Какие карты XP переносит автоматически; когда допустим финальный автосбор |
| Vegas | Лимиты проходов при Draw 1/3; момент исчерпания; Keep Score, новая игра и повтор того же расклада |

На время проверки предложение default — Draw 3 / Standard / ∞ / ручной flip. Детали из таблицы не следует молча закреплять догадками. Если точная XP-совместимость не требуется, можно отдельно утвердить однозначный вариант ХОД и назвать отличия.

### Предлагаемое обобщение, ещё не существующий API

Отделить три независимых факта: число управляемых участников, наличие руки, характер игрового взаимодействия. `solo` не должен автоматически означать «нет руки» для всех будущих игр: у других соло-игр она бывает. Правиловой противник/среда также не становится fake seat или ботом только ради интерфейса.

Минимальная первая задача — поддержка одного участника на существующем Session и общий board-only layout policy: поле без player panels/hand zones, без turn UI. Название и schema этого расширения выбрать по существующим layout-контрактам до кода; здесь не объявляется уже доступное `capabilities.continuous` или иной выдуманный флаг. Обычные многопользовательские паки по умолчанию сохраняют прежний интерфейс.

Косынка задаёт legal moves сама. Автооткрытие/автосбор — domain effects одной команды или явно разрешённая последовательность, а не действие BotScheduler. Для местной игры не нужны сетевой reconnection onboarding, приглашение второго места или подтверждение готовности гостей. Наблюдатель/Стол позже может быть отдельным read-only подключением, не соперником; в первом объёме он не нужен для запуска.

## 7. Поле и управление

### Основная схема

```text
Косынка                 [история] [пауза] [настройки]
Очки 0 · Время 00:00 · В домах 0/52

[Запас] [Сброс → →]      [♠] [♥] [♣] [♦]

[ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ] [ 6 ] [ 7 ]
       [ • ] [ • ] [ • ] [ • ] [ • ] [ • ]
             [открытые последовательности вниз]

                 [Отмена] [Подсказка*]
```

`*` Подсказка планируется по [общему контракту](SOLITAIRE-HINTS.md): только по запросу и только одна рекомендация, без обещания solver. Финальный автосбор по кнопке появляется лишь при доказанно безопасном состоянии; для первого строгого профиля выключен.

- Верхний ряд фиксирован: слева запас и сброс; справа четыре дома. Резерв слота под тройку сброса есть и до первого добора. Карты 5:7, канонические рисунки приложения и общий выбранный back.
- Ни панели «Игрок 1», ни своей руки снизу, ни мини-рук сверху, ни аватара соперника. Имя владельца остаётся метаданными сохранения/профиля, не съедает игровое поле.
- На 390px семь столбцов помещаются с картой около 50px при отступах 8px и gap4px. На 320px — около 40px. Семь непересекающихся touch targets по 44px плюс нормальные промежутки физически не помещаются: не обещать это. Для карт — точный тап/drag и preview; для toolbar — минимум 44px.
- В портрете семь столбцов сохраняются одновременно. В коротком landscape размер карт ограничивается также доступной высотой (в макете около 52px по ширине), а не только шириной экрана. Верхний ряд не превращается в «места игроков»; оболочка использует существующее компактное разделение header/status, а поле получает центральную высоту.
- Размер карты и шаг перекрытия выбираются по viewport/масштабу, а не меняются после каждого открытия. `fixed layout` сохраняется. Длинные стопки прокручиваются внутри ограниченного поля, верхний ряд остаётся доступен; страница не прыгает.
- В коротком landscape нельзя одновременно сохранить крупные карты и показать любую длинную стопку целиком. Явный локальный вертикальный scroll лучше бесконечного уменьшения всех карт или скрытых недостижимых карт. Нужны edge-autoscroll для drag и сохранение scroll anchor.
- На закрытой карте видна рубашка, на открытых перекрытых — ранг и масть; шаг задаётся с учётом corner канонического face/mini-art. Выбор нижней части последовательности не сдвигает соседние столбцы.
- Тап по источнику выбирает карту/группу; тап по цели выполняет действие. Все legal targets при этом рамками не показываются: [принятая политика подсказок](SOLITAIRE-HINTS.md) разрешает обводку только объектов конкретного запрошенного совета. Перетаскивание — альтернатива, не единственный способ. Неоднозначный тап не должен сам выбирать стратегический перенос.
- Тап по запасу делает один добор. Тап по пустому запасу делает один допустимый переворот. Счётчик проходов и недоступность переворота видны без модального окна.
- Двойной клик / отдельный понятный жест могут отправлять карту в дом; не назначать каждому одиночному тапу сразу автоперенос и выбор источника одновременно.
- Неверный перенос возвращает карту на место без confirm-dialog, ошибки в истории и смены хода. Тихая подсветка достаточна.
- На обычные move/draw/flip нет кнопки «Далее», Toast-модалки, handoff-screen, паузы «думает бот» или ожидания озвучки. Общий конвейер commit/animation сохраняется, но задержка не должна быть временем очередности.
- Новый расклад и restart текущего seed — разные действия; оба требуют предупреждения о потере текущего прогресса. Профиль правил фиксируется при старте, новые настройки сохраняются как draft.

Рядом со спецификацией подготовлен самостоятельный offline HTML-макет размеров и длинной стопки: `BoardGames/tmp_files/klondike-preparation-2026-10-19/field-study.html`. Это схема, не готовая игра и не новый набор карточных ассетов.

## 8. Домен, команды и данные

Предлагаемый id пака — `klondike`, отображаемое имя «Косынка». Проверить принятую схему ID до регистрации. EngineApi 3 / viewApi 2, отдельный начальный stateVersion; точные версии выпуска определяются при реализации. Нельзя заранее присвоить версии чужим установленным сохранениям.

- `stock`, `waste`, `tableau[7]` с числом/границей открытых карт, `foundations[4]`, preset/options, seed/RNG, число начатых проходов, счёт, статистика действий, terminal outcome. Единственный `playerCount=1`, `turn=0`.
- Команды: draw, recycle, move-tableau, waste-to-tableau, to-foundation, foundation-to-tableau, flip; undo/restart/finish требуют согласованного отдельного контракта. Выбор карты/hover/preview остаются viewState без revision.
- Конкретная случайность только при начальном shuffle; повторный проход не расходует RNG. Одинаковые seed+options+commands дают одинаковые позиции и факты.
- Все 52 instance ID встречаются ровно один раз в игровых стопках. Изменение рангов для сравнения не меняет ID лица/ассета.
- Публичная/личная projection не раскрывает faces/order запаса и закрытого tableau. Общие deck ID кодируют масть/ранг: их нельзя выдавать для закрытых карт как якобы безопасные data-entity. Использовать адрес стопки/позиции или непрозрачные ссылки без face ID.
- draw-команда не содержит будущие card ID. Никакой preview/подсказка не получает скрытый хвост из authority state. Даже владелец не должен заранее видеть закрытые лица через обычную projection.
- Повторный commandId/старый revision не двигает карту повторно. Проверяются доступность источника, непрерывность открытой последовательности, цель, лимит проходов и текущий actor.
- Обычные reduce возвращают `turnEnded=false`; revision и история всё равно растут. Подписывать статистику «Действия», а не «Ходы игрока».
- Domain не читает Date.now, DOM, storage или layout. Активное время приходит через принадлежащий authority clock/service, учитывает паузу и сохраняется без секундного засорения истории. Точный wire/domain контракт времени — отдельное решение перед реализацией scoring.

### Undo, история и время

Не реализовывать Undo через открытие history frame и замену сохранения. Нужна авторизованная новая команда/операция с монотонным revision, сохраняющая квитанции и ветвление. Отмена восстанавливает карты, открытия, счёт и проходы выбранного атомарного действия; время не отматывается. Политику score penalty задаёт профиль.

Для режима «История» предусмотреть контроль размера стека: не сохранять внутри каждого кадра ещё раз все предыдущие полные кадры. Повторная загрузка не теряет границу допустимой отмены. Просмотр replay остаётся read-only и не засчитывает повторную победу.

Таймер стартует по явному правилу (предложение: первое игровое действие, не чтение стартового окна), останавливается на паузе/при уходе с игры и не учитывает sleep устройства. Идентичность XP-момента старта проверяется отдельно. Скрытие отображения часов не выключает scoring time.

### Завершение и тупики

Победа — 52 карты в домах. Недостаток ходов в текущем tableau ещё не означает математически неразрешимый расклад: могут оставаться доборы, другой проход, возврат из дома или Undo. Бесконечный повтор состояния при ∞ проходах — повод показать ненавязчивое «за проход новых возможностей не появилось», а не объявить поражение решателем, которого нет.

Результат проигрыша/сдачи надо отличать от «ничья»: сейчас общий renderer при winner=null использует общий текст, который для соло может быть неверен. Прогресс в домах, очки и время важнее турнирной таблицы одного игрока. После финального перемещения не показывать экран «передайте устройство»; можно коротко завершить анимацию и открыть общий адаптированный результат с действиями «Новый расклад», «Повторить», «Библиотека».

Автосбор не должен использовать скрытые карты или обещать решение. Простое безопасное условие для позднего завершения: нет закрытых карт, запас и сброс пусты, оставшиеся переносы в дома выполняются только через обычные legal commands. Это дополнительная кнопка, не бот и не обязательная пауза.

## 10. План адресной приёмки — пока не запускался

1. Domain: состав 52/28/24; начальные 21 закрытая/7 открытых; Ace rank14→1; цвета; правильные/неправильные последовательности; пустые столбцы; открытие; foundation return; draw3 остаток; порядок recycle; лимиты и off-by-one.
2. Матрица вариантов: draw1/3 × Standard/None/Vegas; отдельные точечные сценарии timed/untimed, Undo и autoFlip. Не запускать полный suite на каждую комбинацию автоматически.
3. Privacy: в projection/choices/data-entity нет закрытых лиц/рангов/порядка; preview и hints не читают authority state.
4. Непрерывность: серия из 30 легальных действий одним игроком; нет bot timers, handoff, autoPass, turnEnded, блокирующих подтверждений; анимация не съедает следующие клики, не создаёт двойные команды.
5. Persist: exact-version save/restore, replay без мутаций, Undo после reload, новая ветвь после Undo, одноразовая фиксация результата/общего Vegas balance.
6. Поле: 320×640, 390×740, 740×390, планшет/desktop; исходное и максимальное число карт в одном столбце, тройка сброса, масштаб, touch, клавиатура, reduced motion, сохранение scroll во время drag/re-render.
7. Время: первый input, пауза/справка/история, скрытая вкладка/sleep, restore; scoring boundaries из XP-эталона, время не отматывается Undo.
8. Integration: `playModes.players=[1]` виден через фильтр solo; min/max/SDK launch, saved library, single-player result, default builders, PWA offline; regression одного обычного no-hand пака и одной многопользовательской карточной игры.
9. Publication inventory: `playroom-paks/scripts/publish-packs.py` сейчас имеет фиксированные 12 IDS, а `playroom/scripts/pages-smoke.cjs:132` требует length=12. Это уже известный blocker добавления 13-й игры, не готовая автоматическая поддержка. Обновить список/проверки содержательно, не просто ослабить контроль полноты.

Будущие малые cases регистрировать в существующем `tests/blocks.cjs`, например `case/klondike-rules`, `case/solo-game-flow-browser`, `case/klondike-layout-browser`, с типами screen:phone:portrait / landscape. Это предложения имен, а не уже имеющиеся команды. Нынешний анализ не выдаёт список/план за успешно пройденные тесты.
