# Mage Brawl: согласованная реализация

Основа: prototype 97d984a, правила A/v3.0. Адаптация v3.1: щит проверяется у каждого участника поезда; лечение и урон одной скорости суммируются. Исходный Python и физические арты не изменять.

Цель: автономный пак на 2–8 игроков, боты/передача телефона/сеть/публичный Стол; минималистичные квадратные карты, ориентация и тайное одновременное планирование с отменой готовности до общего раскрытия.

Общие механики: окно решений, геометрия клетки/луча/шаблона, цепочка сдвига, пакет эффектов, воспроизводимая политика ботов, квадратная карта и последовательность публичных кадров.

Боты: aggressor/fighter/mind/tactician/defender/random. По умолчанию auto — независимый равновероятный выбор одного из шести на новую партию; random — отдельный «Непредсказуемый». Ошибки 0–100%, шаг 5%, default 10%, тактические альтернативы без очевидного самоубийства. Настройка по тапу слота бота, изменения черновые до применения; хост до старта, в восстановленной партии только просмотр. Уровни сложности и миграция Пексесо отложены.

Порядок: общие контракты → модель/боты → окно настроек → сцена → локальные правила/приватность/сеть/браузер/сборка. Сохранения старых паков не мигрировать; Actions/релиз/деплой не запускать.

## Проверка

Фиксированные состояния Python/JS; составы 2–8; очереди возрождения и сжатие; повторы/готовность/restore; отсутствие чужих рук и планов в public projection и истории. Портрет/альбом телефона, планшет, desktop. Закрытые планы не зависят от скорости анимации.

## Поле, жетоны и сохранение ориентации · 23 октября 2026

Пол/стена/провалы/колья показаны сверху. Базы — каменная круглая площадка с неизменным цветом стартового игрока; начальная привязка startingBases публична, сохраняется в состоянии и не меняется при занятии/возрождении. Старое состояние без привязки принимается с нейтральной площадкой. Подсветка клеток/своей фишки соответствует стихии, треугольники — направлению выбранного действия (Воздух при движении диагонален). Фаерболл имеет ведущую голову и хвост позади.

Слева от трёх сердец один жетон запасной жизни (в domain всего две жизни); после первой смерти он заменяется короной доступной ульты. Израсходованная ульта не отображается. Счётчики следуют публичному кадру, затем конечному состоянию. Исправлено обновление content HTML-template в общем DOM patch: прежний обход оставлял старые схемы справки и снимки карточек участников. Справка показывает выбранное действие тонкими схемами в текущем направлении; цифры урона остаются вертикальны.

Локальный выбор Mage Brawl имеет viewStateScope=match: направление переживает смену раунда, стихии, действия и открытие истории; при передаче устройства выбор хранится отдельно для каждого зрителя. Новая партия очищает выбор. История и архивы не показывают руку, выбор действия/направления, готовность, выбор награды и личную подсветку. Очередь закрытых наград сохранена.

Проверка щита: 16 сочетаний четырёх направлений щита и прямого фаерболла; фронт блокируется, бок/тыл наносят урон. На присланном видео белая дуга обращена к атакующему — фронтальное блокирование соответствует правилам, domain щита не менялся.

## 23 октября: сохранение накопленной руки после первой смерти

По уточнению владельца оставшиеся после закрытого выбора наград карты возвращаются погибшему и сохраняются при возрождении. Сыгранная карта заменяется ровно один раз; при возрождении добор минимум до трёх, без ограничения накопленной руки. При падении без убийцы сохраняется вся несыгранная рука. Очередь наград, порядок получателей, приватность и окончательное выбывание прежние. Это уточнение заменяет старое описание сброса всей руки в prototype/docs/game-design.md, разделы 13–14; исходный прототип не переписывался.


## 23 октября: лимит руки и темп публичного показа

Последнее уточнение владельца: отдельный `maxHand` начинается с 3 и увеличивается на 1 каждому получателю награды за убийство, в том числе при окончательном выбывании жертвы. При возрождении добор до этого максимума, без потери оставшихся карт и без повторной замены сыгранной карты. Это заменяет предыдущую формулировку «минимум три».

Выбор/отмена скрытого плана — quietActions: готовность других игроков не блокирует кнопку человека. Локальный планировщик ботов продолжает после уже начатого публичного показа; domain и сетевой authority не получают зависимости от renderer. Обычный показ: старт 250 мс, раскрытие 750 мс, эффект 650 мс; быстрый режим использует 180/320 обычной длительности (раскрытие 422 мс, эффект 366 мс), чтобы успевать прочитать действие. Обновление того же публичного кадра не запускает его анимацию заново.

## 23 октября: независимые правила и два действия

В классике четыре слайдера: `actionsPerTurn` (1–2), `health` (1–6), `lives` (1–4), `handLimit` (2–8). Жизни по умолчанию 2. Для здоровья/руки «Авто (3 / 4)» выбирает 3 при одном действии и 4 при двух; явные значения независимы. Колода расширяется под стартовую раздачу. Конфигурация сохраняется в domain state; старые состояния без config используют прежние 1/3/2/3.

При двух действиях первая подтверждённая физическая карта остаётся личным draft, закрепляется слева, исключается из второго выбора. Сброс очищает оба действия. Готовность наступает только после второго подтверждения. Domain проектирует только собственный предварительный маршрут без чужих планов; view показывает призраки, следы и арты атак. Прогноз предполагает неизменные действия других игроков и может отличаться после общего раскрытия.

Все первые действия (движения, затем атаки по стихиям) предшествуют всем вторым. Щит действует в своём цикле. Обе выбранные карты расходуются при раскрытии; погибший пропускает оставшиеся действия. Награды, возрождение, добор и сжатие выполняются после обоих циклов. Максимум лечения и здоровье возрождения берутся из настроек, лимит руки увеличивается за убийства как прежде. При нескольких запасных жизнях показывается их фактическое количество рядом с ультой, когда она есть.

Общий локальный планировщик может выполнить несколько частных команд бота в одном decision window до готовности, с ограничением 16 шагов и остановкой при отсутствии прогресса; следующий раунд не запускается тем же пакетом. История объединяет последовательные изменения версий только ботов внутри того же окна. Настройки/два действия проверены в `tmp_files/mage-brawl/two-actions-2026-10-23`; публикации нет.

Правило `differentActionTypes` (по умолчанию 0) при двух действиях запрещает повтор типа movement/attack/ultimate. Действует в legal actions, проверке состояния и выборе ботов; сброс снимает ограничение. UI отмечает использованный тип жетоном 1, блокирует его и выбирает доступный тип. При одном действии опция не влияет.

Жетоны (23.10): запасные жизни остаются контуром после потери; короны — отдельный накопительный счётчик после убийств, без пустых слотов. Сердца и короны имеют обводку и шаг 46% ширины; заполненные сердца выше пустых. Общий player content поддерживает четыре счётчика. Ульта расходуется в фазу исполнения, а не при фиксации плана. При смерти сохранённые ульты переходят живым получателям награды по одной по кругу от погибшего (рабочее допущение до уточнения владельцем совместного убийства); возрождающийся получает одну новую. При смерти без убийц сохранённые ульты остаются у возрождающегося.
