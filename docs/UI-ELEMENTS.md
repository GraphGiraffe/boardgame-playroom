# Общие элементы игрового интерфейса

| Название | Данные и назначение | Размещение |
| --- | --- | --- |
| Карточка игрока | Открытые имя, показатели и рука из проекции | Углы или ряд; без сокращения имени |
| Метка очередности | 1–8, постоянный номер места; публичное `scene.players[].orderPosition` может переопределить его при изменении порядка правилами | Правый верхний угол карточки; одинаково в копиях |
| Метка первого игрока | `firstPlayer`, начало отсчёта круга | Верх аватара |
| Командный жетон | Публичная команда игрока | Верх аватара |
| Бейдж состояния аватара | `badges[].position = avatar-bottom`, подпись и необязательная иконка | Внизу по центру; UNO вытянутый, роль квадратная |
| Счётчик флота | Публичные остатки кораблей по длинам | Поле и карточка; одна геометрия, число справа |
| Игровой бабл | Открытое событие речи игрока | Около видимой карточки, в координатах viewport |
| Меню игрока | Разрешённые действия по выбранному игроку | Отдельный слой, ограниченный экраном |
| Окно выбора карты | Разрешённые скрытые индексы карт | Компактная сетка над полем; прокрутка лишь при переполнении |
| Прямая рука / веер | Одинаковые исходные размеры карт и области руки | Меняются положения и углы; домино всегда прямо |
| Углы / ряд | Предпочтение устройства и доступная геометрия | Автоматический переход в ряд при конфликте с собственной рукой |

Направление UNO не меняет номера мест. Переопределение порядка принимает только публичная модель сцены, не внутренние данные правил. В Дураке роль атакующего принадлежит инициатору атаки; остальные подкидывающие не получают меч. Бейдж не заменяет разрешённые действия.

Веер симметричен относительно видимой области руки. Единственная карта вертикальна; крайние карты наклонены на противоположные углы. При небольшом количестве увеличивается угловой шаг, но сохраняется перекрытие. Прокрутка пересчитывает позы в одной системе координат, не меняя пропорции карт.

Компоновка резервирует место действий, руки и управления прокруткой. Поля с `layout.focus: hands` отдают больше ширины боковым зонам; расчёт не зависит от имени игры. Число колонок ряда выбирается по фактическому переполнению участников. Уменьшение видимой высоты чужой руки обрезает viewport, а не карты.

Карты в прямой и дуговой руке, а также миниатюры оппонентов частично перекрываются даже при избытке места. Шаг ограничен 65% ширины карты; свободное место не растягивает ряд. После изменения числа колонок шаг миниатюр пересчитывается по новой ширине.

## RC15: окна и применимость настроек

Мини-справка — общий `fieldHelp`, нативный top-layer popover, который не занимает место в форме. Выбор закрытой карты — `card-choice-dialog`, модальный dialog относительно viewport. Список фиксированного значения — select с одним вариантом: поле скрыто, значение остаётся в FormData. Форма карточной руки и рассадка показываются только при наличии выбора. Прокручиваемая рука ограничивает собственный viewport, не размер игровых элементов; длинность определяется по фактическому переполнению.

### Показ публичного набора (card-set reveal)

`reveal: {kind:'cards', cards:[...], entity}` описывает уже публичные карты пары или сета, сохраняет их порядок и использует общий цикл вход → пауза → перемещение к entity сброса. Передача руки остаётся отдельным `transfer` с рубашкой; скрытые лица не входят в её публичные события. Очередь скрывает будущую карту на поле, пока набор не показан. «Спроси рыбу» сохраняет первую карту каждого сета в `bookCards` и показывает её рядом с именем владельца.

Номер очередности отсчитывается от `firstPlayer`; явный публичный `orderPosition` имеет приоритет. Угловые места идут по периметру; западные вертикальные группы читаются снизу вверх, восточные — сверху вниз.

## Отложенный эффект и последовательное перемещение (RC17)

Отложенный эффект — публичный значок на карточке игрока с tooltip/aria описанием. Использует тот же UI icon, что и его источник на поле: adjustDie (±1), lessDie (−кубик), skipTurn, shield. Срок и расход определяются domain пака; UI не вычисляет исходы. secondDie и extraTurn обозначают немедленные клетки.

`presentation.sequence` публичного события задаёт отдельный маршрут тем же форматом anchors/steps/jump, что и motionSequence сцены. Feedback последовательно показывает reveal, затем маршрут; удерживает фишку, счётчик и активного игрока между сегментами. Очистка/выход восстанавливают финальную сцену, не меняя состояние игры. Это позволяет показать несколько автоматических перемещений одного действия без промежуточных пользовательских команд.

## Фиксированная компоновка партии

По умолчанию приложение запоминает размеры строк и колонок сцены и собственной зоны игрока. Бросок, выбор карты/фишки, смена игрока и появление кнопок не перераспределяют место поля. Содержимое обновляется внутри закреплённых зон; переполнение собственной зоны прокручивается. Новая партия, другой viewer/surface, явное изменение рассадки и размер окна создают новый снимок геометрии. Выход из партии освобождает снимок.

Динамическая компоновка разрешается **только конкретным действием**, не настройкой пака: `H.actionAttr(command, {allowLayoutChange:true})`. Это атрибут представления `data-allow-layout-change`, не поле domain-команды, сохранения или сетевого протокола. Общий ввод передаёт его в context; после принятого действия приложение вызывает `GameScreen.allowLayoutChange(host, context)` и следующая отрисовка закрепляет новую геометрию. Без явного `true` вызов ничего не меняет. Для программных действий используется тот же вызов после успешного применения. По умолчанию ни одно игровое действие не разрешает перекомпоновку.

## Цель хода и маршрут

`H.boardTarget(action,{kind:'move'|'capture'|'home',color})` возвращает className/attrs/style общей интерактивной цели. `H.routeDot()` — промежуточный узел маршрута. Цель обычного хода золотая, благоприятная зелёная, отрицательная красная; специальная клетка сохраняет свой смысловой цвет с усилением яркости. Hover, active и keyboard focus общие. Иконка клетки остаётся сверху, номера и точки не закрывают её.

ЗиЛ+: пропуск — красный, щит — синий, уменьшение кубика — оранжевый, ±1 — фиолетовый, второй кубик — бирюзовый, дополнительный ход — зелёный. Белая иконка занимает клетку; номер скрыт. Бейдж эффекта получает тот же hex-цвет через `badges[].color`.

Поправка ЗиЛ+ выбирается одной парой кнопок −1/+1 до хода и может переключаться: цели обоих кубиков пересчитываются, но поправка применяется только к выбранному. Автоматический второй кубик остаётся без поправки. Иконки спецклеток занимают 64% стороны; ±1 использует system-ui 800, как счётчики.
