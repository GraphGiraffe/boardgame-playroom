# Актуальность онлайн-комнат

Область применения: приложение **0.21.0** и коллекция **0.8.10**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; текущая приёмка хранится в [utils](https://github.com/GraphGiraffe/boardgame-playroom-utils/blob/main/docs/project/app/reports/ACCEPTANCE-0.21.0.md).

Supabase хранит host_epoch и host_until. Хост продлевает lease через poll-host, обычный период — 2 секунды, срок активности — 20 секунд. Если обращения перестают приходить, новые запросы соединения отклоняются как host-offline. Открытый каталог включает только не закрытые комнаты с действующим lease. Это серверное ограничение, а не только скрытие кнопки.

Список комнат участника сохраняет членство и дополнительно возвращает available и hostUntil, номер и признак пароля. Каталог отфильтровывает недоступные или уже просроченные записи, включая сохранённые в памяти. Обновление списка каждые 5 секунд во время открытого окна выполняет list+discover параллельно через общий account_sync. Участники, пароль и номер при истечении lease не удаляются; host может возобновить публикацию той же комнаты. Работающий RTC не зависит от наличия записи в каталоге, поэтому временный сбой Supabase не должен останавливать саму партию.

Новый host_epoch получает право публикации после истечения старого lease; старый epoch не может продлевать чужой. Полный перезапуск приложения хоста по-прежнему требует восстановления локального состояния партии, одного heartbeat недостаточно. Поле available означает наличие недавнего heartbeat, а не гарантию прохождения NAT/WebRTC до каждого игрока. RTT, мобильный фон и временные расхождения часов остаются отдельными факторами.

Изменены playroom_social, playroom_online и read-only whitelist playroom_account_sync. Новые таблицы, Cron, Realtime и права не добавлены. setup-supabase.sql и check-supabase.sql генерируются из тех же источников. Миграция room_directory_host_lease_status применена к тестовому Supabase; отпечатки сверены после применения.
