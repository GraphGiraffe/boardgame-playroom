# Навигация и установка

Крестик, Escape и системная кнопка Назад закрывают верхнее окно и возвращают к вызвавшему его экрану. Комната, открытая поверх партии, закрывается обратно в партию, без выхода из комнаты или перехода в меню. Выход из комнаты — отдельное явное действие. Вложенные правила или справка настроек возвращают в настройки, затем — на исходный экран. Из Моих партий возвращает на Все игры. В партии системный Назад требует подтверждения, явная кнопка приложения выходит сразу.

На главном экране обычный браузер (включая offline HTML) выходит без диалога и без промежуточного экрана. Это же правило действует в установленной PWA: подтверждения выхода нет. При возврате на главный экран служебная запись истории меню снимается заранее, чтобы следующий Назад обрабатывался браузером/ОС. Браузер управляет фактическим закрытием; приёмка на установленной Android PWA остаётся отдельной проверкой. До первого взаимодействия браузер может пропускать записи истории.

На зашифрованной GitHub Pages странице приглашение beforeinstallprompt может прийти до ввода пароля. Страница входа сохраняет исходный объект в краткоживущем PlayroomInstallHandoff, а PWA-модуль после расшифровки забирает и очищает его. Событие не подделывается и не пересылается повторно.

Установка доступна только после beforeinstallprompt и вызывает его prompt/userChoice; appinstalled или потреблённое приглашение убирает кнопку. Тестовые глобальные флаги и фиктивная установка в релиз не входят. Пульс меняет только фон, не размеры/фильтр/тень/иконку; при reduced motion выключен. Возврат из окон снова запускает пульс.

В темах равные зоны темы и аватаров. Общие действия окон закрепляются, но действия отдельного поля/способа (никнейм, ответ на приглашение) остаются внутри соответствующего блока. Сброс настроек, правил и скинов подтверждается собственным диалогом. Справка прокручивается отдельно от нижнего действия.

В настройках партии кнопка правил находится в шапке вместо справки комнаты и не дублируется среди быстрых действий. В настройках лобби справка комнаты остаётся. Контекст возврата сохраняется при повторном открытии настроек; программное закрытие с `ignoreBack` явно завершает цепочку.

Полные правила используют общий `PlayroomLobbyView.gameRulesMarkup`: первая строка многострочного пункта — заголовок, остальные — абзацы с экранированием. В конце, после разделителя, идут пояснения настроек и сохранённые значения текущей партии. Для локальной партии берётся её собственная конфигурация, а не последняя комната; сетевой стол получает публичные правила своей комнаты. При отсутствии контекста значения не выдумываются. Редакционный контракт находится в [коллекции](https://github.com/GraphGiraffe/boardgame-playroom-paks/blob/dev/docs/PLAYER-RULES.md).

## Несколько PWA на одном origin

Стабильный идентификатор ХОД — `/playroom`. Значение `id` разрешается относительно origin `start_url`, а не каталога манифеста: `id: "./"` превращается в корень домена и конфликтует с соседними PWA. `start_url` и `scope` остаются относительными `./`, чтобы ограничить запуск и навигацию каталогом установки. Разделение кешей и Service Worker не заменяет уникальный manifest ID.

Изменение ранее ошибочного ID создаёт новую установочную идентичность. На Linux старую конфликтующую установку может понадобиться удалить и установить приложения заново; не выбирать удаление данных сайта, если нужны сохранения. Миграция установленных Android WebAPK этим исправлением автоматически не подтверждается; не требовать очистки данных браузера.

Обнаружение, отдельная загрузка, продолжение и установка новой версии описаны в [PWA-UPDATES](PWA-UPDATES.md).


### Прокрутка внутренних страниц

Приложение управляет прокруткой своей SPA через `history.scrollRestoration = manual` с начальной записи истории. Это предотвращает восстановление чужой позиции при удалении служебной записи Back и при внутреннем forward. Слайдер «Все игры / Мои партии» хранит независимые позиции; не следует компенсировать навигацию задержками или отключением CSS scroll anchoring. Внешние документы имеют собственные записи и режим прокрутки.

Цель возврата фокуса окна одноразовая: после окончательного закрытия очищается. Переход без открытого окна не фокусирует старый контрол. Первичный и обратный фокус используют preventScroll; открытие/закрытие окна не должно сдвигать фон или портить независимую позицию страниц. Регрессия проверяется с многократным открытием паков/настроек между переключениями страниц, а не только переключением двух вкладок.

Шапка двух страниц библиотеки закрепляется относительно viewport, а её место сохраняет hub-topbar-slot. Ширина/левая граница берутся из фактической колонки при render/resize/изменении масштаба и fullscreen; обработчик scroll их не пересчитывает. Верхняя безопасная зона рисуется фоном шапки, а не зазором с карточками. В document fullscreen она освобождается и возвращается после выхода. Проверка включает покадровые координаты во время touch, а не только положение после остановки прокрутки.
