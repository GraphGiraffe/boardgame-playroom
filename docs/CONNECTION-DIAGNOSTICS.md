# Временная диагностика соединений

Область применения: приложение **0.21.0** и коллекция **0.8.9**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; текущая приёмка хранится в [utils](https://github.com/GraphGiraffe/boardgame-playroom-utils/blob/main/docs/project/app/reports/ACCEPTANCE-0.21.0.md).

Онлайн использует WebRTC ICE: прямые маршруты, публичный STUN Cloudflare и TURN с временными ключами. ICE проверяет кандидатов автоматически, в том числе параллельно. QR/звук в режиме «Сеть» сохраняют независимость от Интернета и не используют облачную сигнализацию. При наличии облачного аккаунта временная диагностика может записывать результат локального подключения.

`playroom-ice` проверяет JWT через `playroom_ice_access(room_id)`: доступ только владельцу открытой комнаты или её участнику при действующей аренде хоста. Ключи Cloudflare `CF_TURN_KEY_ID` / `CF_TURN_API_TOKEN` задаются только в Edge Function secrets. Клиент получает временные ICE credentials на 24 часа; постоянного Cloudflare API token в сборке нет. При недоступности выдачи TURN приложение продолжает пробовать прямые маршруты и STUN. Недоступный TURN виден в индикаторе.

Экран показывает найденные типы кандидатов и проверяемые пары. Выбранный метод определяется по выбранной ICE-паре: relay → TURN, srflx/prflx → STUN, host → напрямую. Если браузер не предоставляет статистику, показывается WebRTC без выдуманного метода. После принятия в комнату успешный метод показывается с галочкой 500 мс. Фоновое восстановление не открывает этот экран.

## Записи

`public.playroom_connection_traces`: один пакет на попытку, включая передачу хоста. Записываются UUID попытки, аккаунта и облачной комнаты, режим/роль, результат, OS/семейство браузера/основная версия, относительное время этапов и разрешённые коды ошибок. Не сохраняются SDP, IP-адреса, ICE-candidates целиком, email, сообщения, resume-token, JWT, TURN credentials или состояние игры. SQL повторно фильтрует поля по белому списку.

Приложение не ждёт записи и не повторяет её при сбое. Не более 48 событий / 16 КиБ событий на пакет и 20 попыток аккаунта в минуту. Дубликат UUID игнорируется. Прямой доступ `anon`/`authenticated` к таблицам запрещён; RPC проверяет аккаунт и членство в комнате, включая завершившуюся попытку. Локальный режим записывается только для существующего облачного профиля; вход в аккаунт для игры по сети не требуется.

Срок хранения — 48 часов. Очистка выполняется при записи и ежечасным `pg_cron` job `playroom-connection-trace-prune`, если расширение установлено. На рабочем сервере job включён. Эти записи читаются точечным SQL по индексу; Supabase Logs Query для этого не нужен.

## Выключение после проверки

Оператор выполняет:

```sql
update public.playroom_connection_config
set diagnostics_enabled = false where singleton;
```

RPC сразу перестаёт сохранять пакеты. Новые ответы ICE также сообщают клиенту выключенный флаг; уже закешировавшие включённый флаг клиенты могут до обновления кеша отправить пустой по эффекту запрос. Повторная установка миграции не включает диагностику заново. Оставшиеся записи автоматически истекут; для немедленного удаления только диагностических данных:

```sql
delete from public.playroom_connection_traces;
```

Пример узкого чтения (подставить UUID известной попытки):

```sql
select role, result, device, events
from public.playroom_connection_traces
where attempt_id = '00000000-0000-4000-8000-000000000000';
```

Проверка двумя RTC в одной среде, даже с `iceTransportPolicy: relay`, не заменяет проверку входа с физических iPhone/Pixel в разных сетях.

## Текущий пользовательский интерфейс диагностики

«Настройки → Поведение → Диагностика»: переключатель записи со справкой, количество событий и итоговый размер подготовленного лога; «Скачать» и «Очистить» расположены рядом. Очистка останавливает запись и удаляет буферы из памяти, не удаляя сохранения. Отключение без очистки оставляет накопленный лог доступным. Автоизмерение размера не записывает новые sample-события.

Буфер ограничен 5000 событиями и отдельным baseline, шумные фазы одного касания объединяются. Обратная связь принимает gzip-лог до 128 KiB, отмечая пропуски при обрезке, и до трёх сжатых изображений. Число событий и размер различаются; большое число записей само по себе не является объёмом сетевой передачи. Скачивание диагностики — явный локальный экспорт, а не автоматическая отправка разработчику.
