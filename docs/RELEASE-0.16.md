# 0.16 · восстановление связи, история и публикация

Кандидат **0.16.0-rc.1**, стабильная база — 0.15.0. Коллекция 0.4.0 и точные версии пяти паков не меняются. До стабильного выпуска нужны успешные CI, проверка живого защищённого Pages и приёмка на телефонах. Наличие кода не означает прохождение этих этапов.

## Изменения

- Клиент проверяет существующее RTC-соединение при возврате из фона и периодически в активной вкладке. Состояния: подключение, связь установлена, восстановление, требуется новое приглашение. Ввод включается после сверки состояния.
- Неподтверждённая команда повторяется с прежним commandId. Авторитетный журнал/receipt предотвращает повторный ход. Новое приглашение сохраняет pending и выбранную историю внутри текущей вкладки только при совпадении комнаты, участника, Session, epoch, viewer и версии пака.
- Возврат из фона показывает актуальную позицию без очереди пропущенных анимаций. Открытая история остаётся на выбранном ходе; «К текущему ходу» возвращает к live.
- Архив дозагружает только отсутствующие кадры и прерывает старый запрос при смене канала. receivedRevision — последний непрерывно сохранённый кадр; presentedRevision — максимальная показанная live-ревизия; reviewedRevision — выбранный исторический кадр. Показ не означает просмотр всей предшествующей истории.
- Диагностика клиента показывает ICE/канал, время последнего ответа, тип маршрута и коды ошибок. Копируемый отчёт не содержит SDP, IP, resumeToken и чужих карт.
- PWA содержит только используемые хешированные JS/CSS. Отпечаток всего shell изолирует кеш повторной сборки; прежние ресурсы и страницы входа не подхватываются как код. IndexedDB не очищается.
- Ручной workflow Pages берёт опубликованный ZIP и SHA256SUMS, добавляет приватную обёртку из Secrets, проверяет preview и публикует на прежний origin. Ошибка проверки production вызывает rollback. Отдельная операция rollback принимает только успешный production deployment.

## Границы

После полного закрытия RTC нужно новое приглашение. Внешнего discovery/signalling/STUN/TURN-сервиса не добавлено. Фоновая заморозка хоста ограничена браузером/ОС. Pending не становится новым правом на место: resume-права проверяются отдельно. Данные IndexedDB и установленная PWA привязаны к прежнему origin.

API правил 1, UI 2, wire protocol 1 и формат игровых сохранений не меняются. Новые поля клиентского архива добавлены без смены версии IndexedDB; старые кадры читаются, отсутствующие курсоры показа трактуются как неизвестные.

## Приёмка перед стабильным выпуском

1. Полный совместный `bash scripts/codex/check.sh --full --packs-dir ../playroom-paks/packs`, CI точного HEAD и проверка скачанных RC assets.
2. Два телефона: сон/возврат клиента и хоста, временный обрыв, закрытый RTC и новое приглашение, потерянный ACK, открытая история. Ни повторного хода, ни чужой руки, ни отката live-ревизии.
3. Wi-Fi/LAN, точка доступа и VPN проверить отдельно; записать ОС/браузер и результат, не объявлять поддержку всех маршрутов по одному успешному примеру.
4. Живой Pages: неверный/верный пароль, прямые ресурсы без входа, preview, production, возврат к предыдущему deployment. После обновления установленная PWA запускается offline и открывает прежние сохранения.
5. Только после приёмки заменить RC на стабильную версию и выполнить обычный релиз dev → main. Не перезаписывать опубликованные теги/архивы.

Расширенные инструменты авторов, новые игры, квоты пауз, часы, команды и расширенные боты остаются в [Roadmap](ROADMAP.md).

## Дополнительные сообщения после деплоя 0.15

12 октября получены сообщения о возврате Offline/Online и штрафе после UNO с одной картой (пак 0.4.6). Оба сохранённых архива 0.15 содержат русское лобби. Отдельная мобильная браузерная регрессия с тремя ботами подтверждает корректное объявление без штрафа на текущем коде. Причина конкретного штрафа по видео истории не установлена: на нём не видно самого нажатия и исходной команды. Проверка живого сайта отдельно сверяет названия лобби; появление старой версии/смешанного кеша нельзя считать подтверждённым до этой проверки.

Диагностика Pages 12 октября подтвердила Git source с автоматическими production/preview builds и пустым destination_dir. Живой сайт отдавал canonical JS без пароля; свежий lobby-view.js содержал русские подписи. Pipeline проверяет защиту точки отката и перед переключением отключает конкурирующие Git builds. Наличие старых ресурсов на конкретном телефоне и причина конкретного UNO-штрафа требуют отдельной приёмки.

Сервисные Secrets Cloudflare Access настроены и проверены: запрос проходит до формы сайта, неверный пароль получает 401, верный — 303. Прямой запрос с выданной cookie открывает приложение. Для редиректов и Service Worker проверка использует обычные запросы браузера с заголовками Access; CONNECT-прокси ограничивает их точным HTTPS origin без отключения TLS. Полная проверка deployment, публикация RC и физическая приёмка фиксируются отдельными результатами; этот факт не означает, что сайт уже обновлён.

- Выполнить полный совместный прогон и CI окончательного SHA, скачать и проверить RC assets, опубликовать RC через dev.
- Проверить на двух телефонах восстановление, сохранения, обе ориентации и обновление установленной PWA; отдельно повторить сообщение UNO 0.4.6. До подтверждения причина конкретного штрафа остаётся открытой.
- После приёмки пользователем выполнить стабильный выпуск dev → main и обновить статусы документации. API правил 1, UI 2, wire protocol 1 и опубликованные версии паков сохраняются.
