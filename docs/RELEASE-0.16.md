# 0.16 · восстановление связи, история и публикация

Стабильная пара **0.16.0 / 0.5.0** готовится из rc.4 и preview.3. Коллекция содержит 12 паков, включая семь новых игр и обновлённого Дурака. Статус проверки, GitHub Release и Pages фиксируется отдельно: наличие кода не означает завершения публикации. Физическая проверка на двух телефонах не является блокером этого выпуска; замечания после публикации идут в 0.16.x или следующую линию.

## Добавлено в rc.2

- Семь независимых паков: крестики-нолики, морской бой (два флота), пексесо, лудо (личный и командный режим), классический Ятзи, «Спроси рыбу» и «Акулина».
- Дурак 0.4.0: 36/52/54 карты, 2–6 игроков, подкидывание всеми, кроме защитника, цветной и универсальный режим джокеров.
- Главный экран показывает последнюю игру отдельным блоком, затем избранные и остальные видимые паки; порядок и скрытие сохраняются локально, карточки адаптируются к телефону.
- Последние настройки правил запоминаются отдельно для каждого пака и подставляются при создании новой комнаты; старые значения сверяются с доступными вариантами.
- Общие ресурсы находятся в репозитории паков и встраиваются в автономные файлы. Несколько победителей оформляются через engineApi 2; опубликованные версии старых паков не меняются.

## Сохранено из rc.1

- Клиент проверяет существующее RTC-соединение при возврате из фона и периодически в активной вкладке. Состояния: подключение, связь установлена, восстановление, требуется новое приглашение. Ввод включается после сверки состояния.
- Неподтверждённая команда повторяется с прежним commandId. Авторитетный журнал/receipt предотвращает повторный ход. Новое приглашение сохраняет pending и выбранную историю внутри текущей вкладки только при совпадении комнаты, участника, Session, epoch, viewer и версии пака.
- Возврат из фона показывает актуальную позицию без очереди пропущенных анимаций. Открытая история остаётся на выбранном ходе; «К текущему ходу» возвращает к live.
- Архив дозагружает только отсутствующие кадры и прерывает старый запрос при смене канала. receivedRevision — последний непрерывно сохранённый кадр; presentedRevision — максимальная показанная live-ревизия; reviewedRevision — выбранный исторический кадр. Показ не означает просмотр всей предшествующей истории.
- Диагностика клиента показывает ICE/канал, время последнего ответа, тип маршрута и коды ошибок. Копируемый отчёт не содержит SDP, IP, resumeToken и чужих карт.
- PWA содержит только используемые хешированные JS/CSS. Отпечаток всего shell изолирует кеш повторной сборки; прежние ресурсы и страницы входа не подхватываются как код. IndexedDB не очищается.
- Ручной workflow Pages берёт опубликованный ZIP и SHA256SUMS, добавляет приватную обёртку из Secrets, проверяет защиту и публикует на прежний origin; preview доступен отдельной явной операцией. Ошибка проверки production вызывает rollback. Отдельная операция rollback принимает только успешный production deployment.

## Границы

После полного закрытия RTC нужно новое приглашение. Внешнего discovery/signalling/STUN/TURN-сервиса не добавлено. Фоновая заморозка хоста ограничена браузером/ОС. Pending не становится новым правом на место: resume-права проверяются отдельно. Данные IndexedDB и установленная PWA привязаны к прежнему origin.

Приложение принимает API правил 1 и 2, UI 2; wire protocol 1 и формат игровых сохранений не меняются. Новые поля клиентского архива добавлены без смены версии IndexedDB; старые кадры читаются, отсутствующие курсоры показа трактуются как неизвестные.

## Приёмка перед стабильным выпуском

1. Полный совместный `bash scripts/codex/check.sh --full --packs-dir ../playroom-paks/packs` на точной паре SHA; необходимые обязательные CI; проверка скачанных стабильных assets и SHA256SUMS.
2. Браузерные регрессии приватности Акулины, гарантированного выхода Лудо, освобождения кубика Ятзи, сохранений и сетевого восстановления. Компоновка 320/390 px и короткий landscape, включая оба поля Морского боя, все счётчики и резерв области действий.
3. Обновление PWA: одно свободное окно, второе занятое окно, неответившее окно, offline и сохранённые данные. Активная партия не прерывается.
4. После публикации релизов — единственный production-деплой защищённого Pages с проверкой входа, ресурсов и offline. Preview и физическая проверка двух телефонов не задерживают выпуск.

Расширенные инструменты авторов, квоты пауз, часы и расширенные боты остаются в [Roadmap](ROADMAP.md).

## Дополнительные сообщения после деплоя 0.15

12 октября получены сообщения о возврате Offline/Online и штрафе после UNO с одной картой (пак 0.4.6). Оба сохранённых архива 0.15 содержат русское лобби. Отдельная мобильная браузерная регрессия с тремя ботами подтверждает корректное объявление без штрафа на текущем коде. Пользователь уточнил: нажата собственная кнопка UNO возле руки. Причина конкретного штрафа по видео истории не установлена: на нём не видно самого нажатия и исходной команды. Проверка живого сайта отдельно сверяет названия лобби; появление старой версии/смешанного кеша нельзя считать подтверждённым до этой проверки.

Диагностика Pages 12 октября подтвердила Git source с автоматическими production/preview builds и пустым destination_dir. Живой сайт отдавал canonical JS без пароля; свежий lobby-view.js содержал русские подписи. Pipeline проверяет защиту точки отката и перед переключением отключает конкурирующие Git builds. Наличие старых ресурсов на конкретном телефоне и причина конкретного UNO-штрафа требуют отдельной приёмки.

Сервисные Secrets Cloudflare Access настроены и проверены: запрос проходит до формы сайта, неверный пароль получает 401, верный — 303. Прямой запрос с выданной cookie открывает приложение. Первоначальный запрос Service Worker не получал заголовки Access и возвращал 302; браузерная проверка теперь использует локальный мост с точным ограничением origin и проверкой TLS Cloudflare. Подробности в [плане деплоя](CLOUDFLARE-PAGES-DEPLOY-PLAN.md). RC опубликован на GitHub и слит в dev; полный защищённый preview и физическая приёмка фиксируются отдельными результатами.

## Финальные доработки стабильной 0.16

- Лудо: гарантированный выход без шестёрки перемещает ровно одну фишку и завершает ход, включая варианты с двумя или тремя кубиками. Обычный выход по шестёрке не ограничен этим правилом.
- Ятзи: после второго броска удержанный кубик можно освободить перед третьим, как предусмотрено классическими правилами. Подсказка и резерв зоны действий не изменяют масштаб таблицы.
- Акулина: сведения и анимация закрытой передачи доступны только участникам; публичная пара по-прежнему видима и озвучена. Изменения публичных счётчиков рук остаются наблюдаемыми.
- Морской бой: счётчики показывают силуэт корабля с числом труб по палубам и количеством оставшихся; ноль красный. Поле после переключения центрируется и помещается целиком, в том числе в коротком landscape.
- Аватары Лудо, Шашек, Змей и лестниц используют общую светлую палитру. Игровые цвета поля и фишек остаются прежними. Обновление PWA предлагается постоянно и требует свободных окон.

## Проверки 12 октября

Полный локальный совместный прогон: 759/759. На защищённом deployment 0.15 `7570474d-63f6-451b-a3ea-ececf22d5b15` подтверждены пароль, запрет прямого доступа к ресурсам и русские подписи лобби. Проверка offline не прошла: Cloudflare возвращает 308 для `index.html`. Хеш документа на корневом URL совпадает с архивом 0.15. Кандидат запрашивает корень, проверяя хеш и сохраняя прежний ключ кеша; браузерная регрессия воспроизводит перенаправление. Уведомление об обновлении берёт версию из текущего кеша вместо прежней 0.15.0.

Операция `preview` проверяет опубликованный RC на отдельном защищённом deployment, не переключая production и не меняя Git builds. Обычный `deploy` по-прежнему требует полностью прошедшую проверку точки отката; этот барьер не ослаблен ради старой сборки с ошибкой offline.

## rc3: приёмка интерфейса

Семь паков: tictactoe, battleship, pexeso, ludo, yatzy, gofish, oldmaid — 0.1.1. Перудо не входит в выпуск. Дурак 0.4.1 получает общую рубашку 5:7; варианты колод 36/52/54 и 2–6 участников из rc2 сохраняются.

Приёмка: правильные пропорции всех элементов; постоянная область управления; поле и рука без перекрытий; прямой выбор игрока/карты; один флот на телефоне; классическое поле Лудо; текущие очки Ятзи; единая плитка последней игры; предпочтения паков в лобби; автономные графические и звуковые ресурсы. Дизайн-система и руководство автора содержат требования к этим сценариям.

Выпуск проверяется локально совместно с паками. GitHub CI — только на финальном выпускном SHA. Production публикуется один раз после готовности; при недоступной авторизации передаются проверенные архивы и локальный скрипт, без заявления об успешном деплое.
