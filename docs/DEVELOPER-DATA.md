# Данные и совместимость · ХОД

Область применения: приложение **0.21.0** и коллекция **0.9.0**, engineApi 4 / viewApi 3 / protocol 3. Исторические этапы ниже поясняют совместимость; актуальное приложение доступно на [сайте](https://graphgiraffe.github.io/playroom-hod-test/).

| Данные | Владелец |
|---|---|
| Position / RNG / turn / result | Domain/GameModel |
| Полная история и receipts | Session/authority + repository |
| Разрешённый клиентский архив | HistorySync / client history |
| Имя, аватар, тема, скины, масштаб, звук | Локальные profile/appearance/preferences |
| Каталог, установленные точные версии | Library / pack-loader |
| Выбор карты, прокрутка, история UI | ScreenController / Web view state |

Локальные предпочтения не входят в game commands. Изменение формы руки, масштаба или темы не создаёт ход. Редактирование профиля сохраняется явным подтверждением; отмена не записывает черновик.

## Сохранение

Архив указывает точный packVersion. Library пишет librarySummary и Session одной операцией; список читает заголовок, а open выполняет полную проверку. Заголовок не даёт игровых прав. Отсутствующая версия предлагает установить нужный пак; повреждённые/неподдерживаемые данные не удаляются молча.

Сетевое хранение delta-v1 записывает новые события с eventBase/eventTail, header eventCursor и receipt в одной IndexedDB transaction. Восстановление сверяет цепочку курсоров. Web Locks и repository ports отделяют владение данными от UI.

## Переход с

0.19 исполняет **только engineApi 4**; API 1/2/3 не имеют legacy runtime. UpgradeService обнаруживает несовместимую библиотеку и предлагает явное полное обновление с предварительным экспортом. Принятие фиксирует accepted-engine-api=3, но не конвертирует старые правила и не удаляет архивы. Старые опубликованные JSON/теги сохраняются неизменными; данные старого API открываются совместимой прежней версией приложения. Точные RC-версии API 3 также не подменяются стабильными версиями автоматически.

## PWA и паковые обновления

Оболочка и каталог публикуются независимо. Каталог проверяет SHA256, engineApi/viewApi/stateVersion; установка атомарна. Активная партия использует закреплённую версию. Offline использует проверенный локальный каталог и паки.

Service Worker проверяет полный shell до предложения «Обновить». Окна подтверждают безопасное состояние меню без активной комнаты; занятое или неответившее окно блокирует активацию. После активации окна перезагружаются, старые shell caches удаляются, IndexedDB остаётся. Не очищать данные сайта ради обновления. Origin сайта сохраняется при deploy.

Экспорт профиля/перехода не должен включать resume credentials. Trusted pack-loader исполняет установленный JS и не является sandbox.


## Единое обновление

«Обновить всё» сохраняет в localStorage `playroom.update-all.v1` целевую версию приложения и ID установленных игр (включая распознаваемые архивы quarantine). При обновлении PWA сначала подготавливается и активируется приложение через существующий multi-window guard; новая загрузка документа автоматически продолжает задание. Только установленные ID обновляются из свежего каталога; новые игры не устанавливаются, более новые локальные версии не понижаются.

RemoteCatalog.prepare проверяет SHA/manifest/исполнение совместимого пака без установки. Все нужные загрузки завершаются перед активацией. Ошибка сохраняет задание и старые версии для повторного запуска; частично завершённая установка повторно использует уже установленные версии. Это возобновляемый процесс, не одна транзакция приложения и всех паков через перезапуск.

После успешной установки выполняется PackUpdateCleanup.plan/removeUnused: точные версии, закреплённые локальными сохранениями и сетевыми архивами, остаются; при нечитаемом архиве очистка прекращается. Комната/партия блокируют продолжение. Координатор ожидает собственную очередь записи; её pending не считается чужой игровой активностью. Удаляется только неиспользуемый код паков, не сохранения.
