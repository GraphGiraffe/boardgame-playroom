# Тесты: блоки, подблоки и целевые запуски

Источник состава — `tests/blocks.cjs`: каждый сценарий принадлежит одному из семи блоков и одному подблоку. Сохраняется изоляция файлов Node и последовательный запуск браузеров.

| Блок | Подблоки |
| --- | --- |
| core | state, session-runtime, model, domain, appearance, localization, packs, screen |
| input | gestures, motion, hands, feedback |
| games | layout, actions |
| ui | navigation, history, room, appearance |
| storage | profile, journal, history |
| network | authority, table, transport, resume |
| pairing | codes, audio, pwa |

Примеры:

```bash
node scripts/codex/test.cjs ui/history
node scripts/codex/test.cjs ui/history,ui/room
node scripts/codex/test.cjs case/rc2-hub-browser
node scripts/codex/test.cjs case/rc2-hub-browser,ui/room
node scripts/codex/test.cjs pairing/codes --list
npm run test:changed
node scripts/codex/test.cjs --changed origin/dev --list
```

`--changed` сравнивает текущую рабочую копию с указанной базой (по умолчанию origin/dev), включая незакоммиченные изменения и неигнорируемые новые файлы. `tests/affected.cjs` связывает изменённые модули с зависимыми подблоками. Один файл выполняется один раз при объединении выборок. Изменение только сценария запускает этот сценарий; документы не требуют продуктовых тестов. Изменение неизвестного пути или инфраструктуры запуска выбирает полный набор — отсутствие правила не означает отсутствие зависимостей.

Селектор `case/ИМЯ` запускает один зарегистрированный файл `tests/ИМЯ.test.cjs`. Его можно объединять с блоками и подблоками через запятую. Неизвестный селектор завершает запуск с ошибкой; пустой успешный прогон не считается проверкой. Для небольшой независимой правки выбирайте сценарии по затронутому поведению и фиксируйте выбор в выпуске. Например, изменение подписи счётчика в меню проверяется `case/rc2-hub-browser`; для изменений правил, сохранений или сетевого контракта добавляйте соответствующие блоки и совместную проверку паков.

Целевой запуск нужен для быстрых итераций и небольших выпусков. Профили app/core-ui/layout/smoke/rtc сохраняют прежние проверочные наборы. `npm test` запускает все блоки. Для локального полного совместного прогона используйте `bash scripts/codex/check.sh --full --packs-dir ../playroom-paks/packs`. В ручном `Release candidate build` поле `checks` обязательно и не имеет значения по умолчанию. Укажите `none`, если продуктовые тесты сознательно не нужны, или список блоков, подблоков и сценариев, например `case/rc2-hub-browser,ui/room`. Для запуска всех семи блоков явно перечислите `core,input,games,ui,storage,network,pairing`; сокращения `all` и `full` в релизном workflow запрещены. Пустое или неизвестное значение отвергается до подготовки паков. При `none` отдельный шаг фиксирует сознательный пропуск тестов; сборка и сверка `SHA256SUMS` всё равно выполняются. Для операций Pages через этот gateway указывайте `checks=none`: исходные тесты уже относятся к кандидату, а защищённый Pages smoke при публикации обязателен. Зелёный целевой запуск подтверждает только выбранное поведение.

Подробные TAP-логи находятся в `dist/test-results/`. В консоли — сводка по выбранным блокам; при ошибке выводится полный протокол и ненулевой exit status. Новый сценарий регистрируется ровно один раз; незарегистрированные файлы и дубли блокируют запуск.

`core/session-runtime` проверяет независимую историю/события/codec без платформы и порт часов Session. Для изменения Session добавляйте `case/session`, authority/durable-authority, нужные storage/recovery и `network/table`; браузерный импорт IndexedDB проверяется отдельно. Сам этот подблок не является приёмкой всей сети или всех паков.

## Аудит и очистка

Удалена строковая проверка DOM-каркаса `local and network use one GameScreen DOM contract...` из game-screen: настоящий браузерный unified-game-screen уже проверяет единую сцену, игроков, руку, историю и её доступность. Проверки viewer/revision перенесены в этот браузерный сценарий, там же проверяется постоянный порядок справки/настроек. Повторные проверки наличия строк replay-кнопок убраны из unit; браузерный сценарий реально двигает ползунок и нажимает кнопки. Проверки прав на выбор игрока и содержимого результатов сохранены.

Схожие drag/swipe unit и реальные app E2E оставлены: они проверяют разные уровни. Проверки приватности, точных версий сохранений, отказа для неподдерживаемого API, восстановлений authority и реальных RTC-переходов не сокращаются ради меньшего числа тестов. Удалять сценарий можно при указании сохраняющей его поведение проверки, а не по похожему названию.

Базовый game-layout-browser проверяет контракт общих элементов и готовые сцены пяти паков на 13 размерах пользовательского архива, в мобильных режимах и в истории. Сетевой сценарий network-same-origin объединяет WebRTC, ботов, приватность и паузу для всех пяти игр. Геометрия игрового поля и действия сохраняют отдельные проверки: domino-layout, compact-hand, checkers-drag, uno-drag и views. Публичная длинная рука прокручивается внутри компонента; проверяется достижимость каждого номинала, а не одновременная видимость ста карт.

В rc3 существующий `rc2-games-browser` дополнен семью новыми паками до/после хода на пяти размерах, измерением пропорций и отсутствия перекрытий. `rc2-hub-browser` проверяет одинаковую плитку последней игры, избранное/скрытие/порядок в лобби и сохранение правил. `rc2-games` проверяет выбор закрытой карты, промежутки флота и итог Ятзи; `player-target` — связь выбранной карты с соперником. Скриншоты сохраняются при заданном `PLAYROOM_QA_DIR`. Эти целевые проверки дополняют полный совместный прогон.
