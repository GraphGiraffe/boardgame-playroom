# Переносимый игровой пак · формат 1

Файл UTF-8 с расширением `.playroom-pack.json` — обычный JSON, который содержит исходники и ресурсы одной игры. ZIP из релиза предназначен для скачивания нескольких файлов; в интерфейсе выбирается отдельный JSON.

```json
{
  "format": "playroom-pack",
  "formatVersion": 1,
  "manifest": {
    "id": "my-game",
    "name": "Моя игра",
    "version": "0.1.0",
    "engineApi": 1,
    "viewApi": 2,
    "stateVersion": 1,
    "category": "board",
    "capabilities": {"hands": false},
    "rules": "rules.js",
    "view": "view.js",
    "styles": "styles.css"
  },
  "files": {
    "rules.js": "... код регистрации правил ...",
    "view.js": "... код регистрации представления ...",
    "styles.css": ".my-game-scene { ... }"
  }
}
```

Это пример контейнера, не исполняемая демонстрационная игра. Исполняемый минимальный пример и цикл сборки доступны в [руководстве автора](https://github.com/GraphGiraffe/boardgame-playroom-paks/blob/v0.4.0/docs/AUTHORING.md).

## Поля и ограничения

- `id`: латинская строчная буква, затем буквы, цифры, `_` или `-`; до 64 символов.
- `version`: SemVer. Новый код публикуется с новой версией. В опубликованной линии `engineApi` равен `1` или `2`; ветка 0.18 также поддерживает `3`, обязательный `viewApi` — `2`; `stateVersion` — положительное целое число.
- `name`: непустое название до 120 символов. `category`, `tagline`, `badge`, `estimatedDuration`, `capabilities` и `settings` определяют карточку и форму запуска.
- Обязательны `rules.js`, `view.js`, `styles.css`; необязательный звуковой вход — `sounds.js`. Имена точек входа сейчас фиксированы.
- До 128 файлов, суммарный JSON до 4 MiB. У библиотеки дополнительно есть внутренний лимит 20 MiB, но реальная квота браузерного хранилища может быть ниже. При отказе записи установленная версия не заменяется.
- Пути относительные, без `..`, абсолютного пути, обратного слеша и пустых компонентов. Внешние CSS-загрузки и `@import` не поддерживаются; паки предназначены для офлайн-работы.

Текстовые ресурсы находятся в `files` строками; двоичные — строками `data:` с MIME и Base64. Во view/rules доступен `globalThis.PlayroomPack.asset('assets/file.svg')`: он возвращает встроенный URL ресурса. CSS `url(assets/file.svg)` обрабатывает загрузчик; путь считается от корня пака. Сборщик исходников добавляет содержимое `assets/` в файл пака. Для общих ресурсов пак может указать `sharedUi: true` и `sharedAssets` со списком имён SVG из каталога `shared/assets/` репозитория паков; сборщик включит их и общий UI-код в автономный JSON.

## Исполнение

`rules.js` регистрирует ровно одну игру через `globalThis.TabletopCore.register(...)`. `view.js` регистрирует тот же ID через `globalThis.PlayroomViews.register(id, render, cover)`. Звуковой файл заполняет `globalThis.PlayroomCatalog[id].sounds`. Рендереры возвращают [элементы API 2](GAME-ELEMENTS-API.md); строки готовой сцены не поддерживаются. CSS не размещает общие компоненты приложения. Код выполняется после явной установки доверенного файла; предварительный разбор JSON не исполняет скрипты.

Общие компоненты доступны через `PlayroomViews.helpers`; описание правил, жестов и представления находится в PACKS.md. Для общих эффектов используйте стабильные `data-entity` и маркеры `data-motion-table`, `data-motion-stock`, `data-motion-static`. Не встраивайте пути к соседнему репозиторию или приложению в игру.

Представление может задать `PlayroomCatalog[id].playerBadge(state, playerIndex)` — текстовую подпись игрока. Реакция может содержать текст `confirmation` для подтверждения и `notify: true` для показа новых событий. Это UI-метаданные, не параметры проверки игрового действия.

## Обновления

Загрузчик сначала проверяет формат, совместимость, правила и представление, затем сохраняет новую версию и подключает её. Совместимые версии API 2 остаются в библиотеке. API 1 отклоняется; опубликованные старые файлы и сохранения не переписываются и не конвертируются автоматически. Новая партия получает текущую версию; сохранение явно хранит `packVersion`. Старые сохранения без этого поля относятся к `0.1.0`.

Удаление через интерфейс блокируется, пока версия используется сохранённой партией или её повтором. Если версия отсутствует, сохранение остаётся в библиотеке и предлагает установить нужный пак. Удалять партии ради обычного обновления не требуется.

Подготовка/регистрация — проверка контракта и восстановление после обычных ошибок, а не защита от враждебного JavaScript. Код установленного пака работает с доверием пользователя. Автоматические миграции сохранений, сетевой каталог и подпись авторов — будущие отдельные возможности.

## Цвет плитки · rc3

Необязательный `manifest.tileTheme`: `green`, `coral`, `blue`, `gold` или `violet`. Неизвестное значение отклоняется Python-сборщиками и JS-загрузчиком. При отсутствии темы приложение использует палитру категории. Поле не разрешает произвольные CSS/URL. Паки 0.1.1 новой коллекции используют возможности интерфейса приложения 0.16.0-rc.3 при сохранении viewApi 2.

## Разработка 0.18: engineApi 3 и исходные модули

Новый API правил использует независимую GameDefinition contractVersion=1, а представление по-прежнему viewApi 2. Эталон — Крестики-нолики 0.2.0 в companion ветке. Старая оболочка API 3 не принимает; опубликованные паки не переписываются. Контракты и ограничения временного адаптера: [REFACTOR-0.18-CONTRACTS](REFACTOR-0.18-CONTRACTS.md).

Исходный manifest может содержать:

```json
{
  "sourceModules": {
    "rules": ["domain/game.js", "presentation/scene.js"],
    "view": ["presentation/scene.js"],
    "locales": {"ru": ["locales/ru/game.json"]}
  }
}
```

Это инструкция source builder, не runtime fetch. Модули только из domain/presentation/ui и с расширением .js, локали — locales/<locale>/*.json; до 32 файлов в каждом списке/32 локалей. Повторы, неверные пути, одинаковые ключи в каталогах одной локали отклоняются. Builder включает ресурсы в PlayroomPackResources.locales, модули в порядке списка перед соответствующим entrypoint, сохраняет исходные файлы в files и удаляет sourceModules из поставленного manifest.

Web bootstrap предоставляет PlayroomModelAdapter и PlayroomLocalization. Загрузчик внедряет порт modelAdapter; API 3 вызывает PlayroomPack.adaptModel(specification), затем scoped TabletopCore.register. Если порта нет или pack не объявил modelContractVersion=1, prepare отклоняется до установки. Для raw Node источников bootstrap приложения загружает app/model-adapter.js перед rules.js; core ZIP сам не импортирует Web/application код.
