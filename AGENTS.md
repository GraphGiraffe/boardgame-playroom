## Текущая реализация RC6 (QR и возврат)

В RC6 встроен offline сканер QR через системную камеру Android и локальный jsQR; PR3 не менять без требования пользователя. Механизм возвращения использует приватный room-scoped 256-битный resumeToken (только после WebRTC), а не публичный UUID или nickname. Не публиковать токен в QR/SDP/room snapshot, не смешивать viewer чужих рук. Возврат после host restart/автоматическое ICE restart отложены до LAN-01/03. Документ: docs/QR-PAIRING-AND-RESUME.md. Для любых исправлений обязательны network-resume/qr-pairing-browser и совместные сетевые тесты.

## Проверки

- Подготовка: `bash scripts/codex/setup.sh`; явный путь к играм — `--packs-dir PATH`, где PATH указывает на каталог `packs` другого checkout. Системные пакеты устанавливаются только с `--install-system-deps`.
- Проверка этого репозитория: `bash scripts/codex/check.sh`. При изменении правил взаимодействия, загрузчика, сохранений или UI выполните полный совместный прогон: `bash scripts/codex/check.sh --full --packs-dir PATH`.
- Если второй checkout недоступен, выполните самостоятельную проверку и явно сообщите, что совместные тесты не выполнены. Не называйте такой результат полной проверкой игр.
- Для изменений сцены проверьте портретный телефон 320/390 px и короткий горизонтальный экран, видимые номиналы/масти, достижимость кнопок, отсутствие обрезки поля и руки. Сохраните смысл click/touch/drag/swipe, скрытые руки, replay и reduced motion. Используйте существующие проверки и точечные регрессии.
- Просмотр: `bash scripts/codex/serve.sh` — локальный сервер на `127.0.0.1:4173`. Не запускайте второй сервер поверх занятого порта.

## Ветки и результат

`main` — релизы, `dev` — интеграция. Обычная задача: отдельная ветка от `dev`, PR в `dev`; выпуск — PR `dev` → `main` по [CONTRIBUTING.md](CONTRIBUTING.md). Сохраняйте рабочую ветку, созданную Cloud для задачи: не переключайтесь принудительно на `dev` и не сбрасывайте изменения. Предпочитайте `dev` при выборе исходной ветки новой задачи, если пользователь не указал другое.

Изменения, проверки и ограничения сообщайте конкретно. Подготовка файлов, локальный тест, работающий Cloud и опубликованный релиз — разные результаты; не подменяйте один другим.
