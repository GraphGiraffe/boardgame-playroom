# Работа с приложением ХОД

Текущая опубликованная пара — приложение **0.17.4** и коллекция **0.6.2**, см. [сведения о выпуске](docs/RELEASING.md). Начните с [индекса](docs/DEVELOPER-INDEX.md), [Roadmap](docs/ROADMAP.md) и профильного контракта. История RC находится в Git/CHANGELOG; старые планы не определяют текущее состояние.

## Границы изменений

- Проверьте корень Git, ветку и рабочее дерево. Сохраните постороннюю работу; соседние проекты вне задачи.
- `app/` — хаб, комнаты, библиотека и адаптеры; `core/` — независимые механизмы. Правила и ресурсы игр принадлежат отдельному `boardgame-playroom-paks`. Общие компоненты не должны знать названия игр.
- JavaScript без framework; браузерные модули и поддерживаемый CommonJS ядра. Сохраняйте API правил 1, UI 2 и совместимость точных packVersion. Изменения контракта документируйте и проверяйте.
- Не изменяйте содержимое опубликованного пака/тега. Сохранения и повторы требуют свою версию. Ошибка пака не блокирует управление библиотекой.
- Браузер хоста — authority. Сеть получает проекции, не Session.export. Resume-токен передаётся только через установленный WebRTC и не входит в QR, room snapshot или журнал клиента. Успешный ACK следует за durable commit; повтор commandId не создаёт второй ход.
- После полного закрытия RTC может требоваться новое приглашение. Не объявляйте отсутствие внешней сигнализации исправленным при успешном тесте живого соединения.
- Не коммитьте генерируемые `packs/`, `installed-packs.js`, `dist/`, зависимости, личные данные, секреты, закрытый Worker и protected ZIP. Настройки защищённого деплоя остаются вне публичных релизов.

## Проверки

```sh
bash scripts/codex/setup.sh --packs-dir ../playroom-paks/packs
bash scripts/codex/check.sh --full --packs-dir ../playroom-paks/packs
```

Самостоятельная проверка: `bash scripts/codex/check.sh`. Для выпуска выбирайте проверочные блоки по фактическому изменению; отдельные сценарии доступны через `case/ИМЯ`. Полный совместный прогон нужен при сквозных изменениях взаимодействия приложения и паков, загрузчика, сохранений или сетевого контракта. Сборку и контрольные суммы выпускных файлов проверяйте всегда. Без companion честно сообщайте, что игры не проверены. Для окружения используйте [CODEX-CLOUD](docs/CODEX-CLOUD.md), для блоков — [TESTING](docs/TESTING.md).

Сцена: 320/390 px, короткий landscape, читаемые значения, достижимые кнопки, обе оси прокрутки, touch/drag/swipe, скрытые руки, история и reduced motion. Сначала используйте существующие проверки; добавляйте регрессию только для нового риска. `bash scripts/codex/serve.sh` слушает 127.0.0.1:4173; не занимайте уже используемый порт.

## Ветки и релиз

`main` — стабильные выпуски; `dev` — интеграция. Обычная работа: ветка от dev → PR в dev → squash. Сохраняйте активную ветку задачи Cloud. Релиз: отдельный PR dev → main с merge-коммитом, затем fast-forward dev, без force-push. [CONTRIBUTING](CONTRIBUTING.md), [RELEASING](docs/RELEASING.md).

PR держите Draft до готовности; Ready и push не запускают Actions. Основные проверки выполняйте локально; выпускной workflow запускайте вручную при необходимости на точном HEAD. Опубликованный релиз подтверждается тегом, assets и скачанными SHA256, а не только слиянием PR.
