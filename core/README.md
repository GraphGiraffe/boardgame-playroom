# Tabletop Core · 0.13.0

Независимое JavaScript-ядро пошаговых настольных игр. Исполнение правил и сессии не используют DOM, браузерное хранилище, сетевой транспорт или внешние зависимости. UI и ввод доступны отдельными необязательными модулями. Игра подключается через `register(pack)`. Сессия хранит снимки состояния для сохранений и просмотра ходов.

## Node.js

Запустите пример из папки ядра. Этот минимальный пакет не зависит от пяти демонстрационных игр:

```js
const Core = require('./engine.js');
const Session = require('./session.js');

Core.register({
  id: 'race', name: 'До трёх', min: 2, max: 2,
  description: 'Первым наберите три очка.', rules: ['За ход прибавьте одно очко.'],
  presets: [{id: 'standard', label: 'До трёх'}], scoreLabel: 'очки',
  create(state) { state.data.counts = state.players.map(() => 0); },
  legal() { return [{type: 'advance', label: '+1'}]; },
  apply(state, actor) {
    state.data.counts[actor]++;
    Core.event(state, `${state.players[actor].name}: +1`, actor);
    if (state.data.counts[actor] === 3) Core.finish(state, actor);
    else state.turn = (actor + 1) % state.players.length;
  }
});

const session = new Session(Core, 'race', {seed: 'example'});
session.act(0, Core.legalActions(session.current, 0)[0]);
console.log(session.view(0));
const saved = session.serialize();
const restored = Session.restore(Core, JSON.parse(saved));
console.log(restored.current.move); // 1
```

В составе полного проекта можно вместо примера подключить готовые пакеты:

```js
const Core = require('./engine.js');
require('../packs/snakes/rules.js');
const state = Core.createGame('snakes', {seed: 'demo'});
const next = Core.applyAction(state, state.turn, Core.botAction(state));
```

`private: true` предотвращает случайную публикацию npm-пакета. Это исходный SDK для локального подключения, а не опубликованный пакет npm.

## Браузер

```html
<script src="core/engine.js"></script>
<script src="packs/snakes/rules.js"></script>
<script src="core/session.js"></script>
<script>
  const session = new TabletopSession(TabletopCore, 'snakes', {seed: 'demo'});
  const playerView = session.view(0);
</script>
```

Глобальное имя ядра — `TabletopCore`; `PlayroomEngine` является алиасом того же объекта. Нужные пакеты необходимо зарегистрировать перед созданием или восстановлением сессии. Ядро не загружает файлы самостоятельно.

`createGame` создаёт полное состояние; `legalActions` определяет доступные ходы; `applyAction` проверяет действие и возвращает новое состояние; `project` создаёт проекцию конкретного игрока. `createZone`, `moveComponent`, `reveal` и `projectZones` доступны для нескольких колод, сброса и зон с разной видимостью. `rollDie(sides, state)` поддерживает от 2 до 1000 граней.

`validateState(state)` проверяет общую схему и вызывает `pack.validateState(state)`, если пакет предоставил такую функцию. Встроенные пять пакетов дополнительно проверяют собственные колоды, поля и игровые ограничения. При восстановлении сессии проверяются все снимки, параметры и непрерывность истории; повреждённое сохранение отклоняется.

У сессии `options`, `current` и `states` глубоко заморожены. Переход состояния выполняется через `act`; `view` возвращает независимую проекцию, а `export()` — независимую копию полного сохранения версии 1. Конструктор допускает отсутствие `options`.

Для регулярного сохранения используйте `serialize()`: компактный формат версии 2 хранит повторяющиеся JSON-объекты один раз, инкрементально кэширует снимки и сохраняет всю историю. `serialize({compact: false})` выдаёт читаемый JSON версии 1. `restore` принимает обе версии и восстанавливает те же позиции, приватные проекции и полный журнал. Декодер отклоняет циклы, некорректные ссылки, чрезмерную глубину и развёрнутый объём.

Снимки сохраняют каждую позицию; полный журнал событий находится в текущем состоянии, предыдущие снимки содержат до четырёх последних событий. В синтетической проверке 1200 ходов со 108 картами компактный файл занял 0,78 MiB UTF-16 вместо 11,27 MiB. Размер всё ещё зависит от уникальных данных конкретной игры; ядро оставляет выбор хранилища приложению.

Полные состояния и экспорт содержат скрытую информацию. Для будущего сетевого режима сервер должен хранить полное состояние, определять игрока по аутентифицированному соединению и отдавать только его `project`/`view`. Локальный SDK не реализует аутентификацию, защиту от читов или сетевое переподключение.

Подробный контракт пакетов находится в `../docs/PACKS.md` полного проекта или в `docs/PACKS.md` отдельного архива ядра.

Пакеты могут предоставить `reactions(state, actor)` и `botReaction(state, actor, actions)` для действий вне очереди. `legalActions` объединяет обычные ходы текущего игрока с его реакциями; `reactions` и `botReaction` также доступны отдельно на ядре. `botAction` выбирает только обычный ход. Реакции проходят ту же проверку, сохранение и воспроизведение, что и остальные действия.


## Автономная библиотека звуков

`audio.js` работает независимо от движка, DOM и игровых правил. В браузере он экспортирует класс `TabletopAudio`, в Node.js — `module.exports`. Процедурные звуки создаются через Web Audio; загрузки файлов и сетевых запросов нет. Приложение само выбирает звук по публичным событиям и игроку.

```js
const audio = new TabletopAudio({enabled: false, volume: .6});
// В обработчике пользовательского нажатия:
audio.setEnabled(true);
await audio.unlock();
await audio.sequence(['move', 'attack.light'], {pack: 'uno'});
// При паузе, переходе со стола или скрытии вкладки:
audio.stop();
```

До успешного `unlock()` библиотека молчит. Этот метод создаёт или возобновляет `AudioContext` только при включённом звуке; для изолированной проверки можно передать `contextFactory: () => context`. Конструктор и `setEnabled(true)` сами контекст не создают. Если Web Audio недоступен или воспроизведение запрещено браузером, `unlock()` возвращает `false` без исключения.

- `play(id, {pack, volume: 1})` возвращает `Promise<boolean>` после завершения звука; `false` означает отсутствие звука, ошибку или отмену. Дополнительная громкость умножается на общую.
- `sequence(ids, {pack, gapMs: 45})` отменяет прежнее воспроизведение и поочерёдно запускает до 12 звуков. Пауза между ними ограничена 250 мс. Обещание завершается после всей последовательности.
- `stop()` немедленно останавливает и отсоединяет активные и ещё не начавшиеся источники, отменяет паузы и продолжение очереди. Обещания отменённых воспроизведений получают `false`; уже начатое декодирование браузером может завершиться в кэше, но звук после отмены не запускается.
- `setEnabled(false)` также вызывает `stop()`. `setVolume(value)` ограничивает общую громкость диапазоном 0–1; нулевая громкость не создаёт новых источников. Эти методы и `registerPack()` возвращают экземпляр.
- `catalog(pack?)` возвращает независимый массив `{id, label}` для прослушивания библиотеки в интерфейсе.

Встроены `move`, `draw`, `victory`, `defeat`, `draw-game`, `attack.light`, `attack.heavy`, `attack.skip`, `attack.capture`, `attack`, `defend`, `reverse`, `dice`, `climb`, `fall`, `penalty`, `notify`. Короткие огибающие, компрессор и ограничитель сглаживают резкие переходы. Одновременно разрешены не более 8 воспроизведений и 32 запланированных голосов; при превышении отменяются старые.

Игровой пак может переопределить звук только в своём пространстве или добавить новый идентификатор:

```js
audio.registerPack('race', {
  move: {label: 'Шаг фишки', notes: [
    {at: 0, frequency: 600, to: 400, duration: .1, gain: .15, wave: 'triangle'}
  ]},
  'race.finish': {label: 'Финиш', notes: [
    {at: 0, frequency: 660, duration: .2},
    {at: .1, frequency: 880, duration: .3}
  ]}
});
await audio.play('move', {pack: 'race'}); // звук этого пака
await audio.play('move'); // общий звук сохранён
```

Вместо `notes` допустим `{label, src: 'data:audio/wav;base64,...'}`. `src` принимает только встроенные аудиоданные до 2 MiB; декодирование ленивое, кэшируется, ошибки не прерывают игру. Продолжительность ограничена пятью секундами. Идентификаторы пака и звука соответствуют `/^[a-z][a-z0-9_.-]{0,63}$/`. Повторный `registerPack` заменяет звуковой словарь указанного пака; некорректные определения отклоняются сразу.

У каждой ноты `at` — задержка в секундах, `frequency` и необязательный `to` — начальная и конечная частота в герцах, `duration` — секунды, `gain` — амплитуда до .35, `attack` — длительность нарастания; `wave` принимает `sine`, `triangle`, `square`, `sawtooth` или `noise`. В определении не более 24 нот, общая длительность не более пяти секунд. Библиотека не знает о победителях или скрытых руках: выбор события и видимость остаются ответственностью приложения.

`Core.soundCues(state, viewer, afterEventId)` выбирает звуковые метки новых событий без обращения к браузеру. Результат — `{id, eventId, target?}[]`: приватные события других игроков исключаются, победа/поражение вычисляются относительно зрителя, ничья общая. Без звуковых меток старые события используют нейтральный сигнал своего `kind`. При обычной отрисовке эту функцию не вызывают; оболочка передаёт последний ID события до действия и запускает `audio.sequence(cues.map(c => c.id), {pack: state.game})`. Правила и сохранения не содержат аудиоконтекста; `audio.js` можно подключить отдельно, в том числе через экспорт `@playroom/core/audio`.


## Общий UI и ввод

`ui.js` экспортирует `TabletopUI` (или `require('./ui.js')`), `input.js` — `TabletopInput` (или `require('./input.js')`). При импорте этих файлов DOM не требуется; только `TabletopInput.attach()` подключает обработчики в браузере. Они не импортируют хаб, каталог или игровые паки. `engine.js` и `session.js` можно по-прежнему использовать отдельно на сервере.

Для браузерной сцены подключите `ui.css`, `input.css`, `ui.js` и `input.js` из этой папки, затем оформление своего пака. `TabletopUI.createRegistry()` создаёт независимый реестр с `register(id, render, cover)`, `render(state, viewer, actions, ui)` и `cover(id)`. В демонстрационном хабе `app/views.js` создаёт такой реестр под совместимым именем `PlayroomViews`.

Общие функции находятся в `TabletopUI.helpers`:

- `hand(cardHTMLArray, count, hint, controlsHTML, {layout: 'fan'})` строит руку постоянной высоты с адаптивным перекрытием. Угол каждой карты остаётся доступным; чрезмерно большая рука прокручивается внутри своей области. `opponents(state, viewer, renderCard, options)` строит закрытые руки или все открытые карты в нескольких рядах.
- `source(id, actions, selected, options)` находит допустимые действия компонента и возвращает `{choices, className, attr}`. Параметры задают поле идентификатора (`key`, по умолчанию `card`), режим `select` либо `immediate`, осмотр `preview`, перетаскивание `drag`, свайп `swipe` и возможность осмотреть неходовую карту `inspect`. Немедленный режим отправляет ход только при единственном варианте; несколько вариантов требуют дальнейшего выбора.
- `target(pieceId, action)` описывает цель конкретного компонента. При отсутствии действия она сохраняет выбор для следующего шага, например выбора цвета. Цели и их расположение определяет пак из уже допустимых действий; общий ввод не угадывает правила.
- `actionAttr`, `actionButton`, `actionBar` оформляют сериализованные действия; `esc` экранирует текст. Переданный HTML компонентов считается доверенным кодом пака.

Оболочка связывает ввод с выбранным компонентом и сессией:

```js
let selected = null;
const input = TabletopInput.attach({
  getSelected: () => selected,
  canStart: () => hostCanInteract(),
  canSelect: () => hostCanInteract(),
  canCommit: () => hostCanInteract(),
  select(id) { selected = id; render(); },
  commit(action) {
    session.act(viewer, action); // Повторная проверка по правилам ядра.
    selected = null;
    render();
  }
});
scene.addEventListener('click', event => input.handleClick(event));
// При паузе/смене сцены: input.cancel(); при удалении оболочки: input.destroy().
```

`scene`, `render`, `session`, `viewer` и `hostCanInteract` в примере принадлежат приложению. Последняя функция учитывает очередь, паузу и просмотр истории. `handleClick` вызывается после обработки навигации оболочки; он поддерживает клавиатурный клик, отмену повторного выбора и выбор цели. Мышь и палец используют тот же контракт источника/цели; свайп может работать без drag-and-drop. После жеста совместимый клик подавляется, чтобы ход не повторился. `cancel` снимает незаконченный жест, визуальную копию и отложенный ход; `destroy` дополнительно удаляет обработчики.

CSS пака может переопределять размеры карт и общие классы в пределах своей сцены. На низком горизонтальном экране общая рука использует несколько перекрытых рядов; `--fan-row-step` управляет их шагом. Если она переполняется по вертикали, движение пальца прокручивает руку, а удержание по-прежнему начинает перенос. Для ряда с перекрытием доступны `--fan-card-width`, `--fan-card-height`, `--fan-peek`, `--fan-gap` и `--fan-lift` на `.hand-track.is-fan`. Пак также может создать собственное представление или ввод и отправлять обычные действия через `session.act`; общий UI не является обязательным условием исполнения правил. Подробности атрибутов и примеры игровых целей описаны в контракте пакетов.


## Установка и версии паков

`packs.js` предоставляет `TabletopPacks` для загрузки независимых `.playroom-pack.json`. Разбор файла не исполняет код; подготовка выполняется только после выбора доверенного пакета пользователем. Менеджер хранит версии, проверяет API и регистрирует правила, представление, стили и метаданные. Это не JavaScript-песочница.

Состояния и сессии сохраняют `packVersion`; `Core.get(id, version)` выбирает точные правила. Старые сохранения без версии относятся к `0.1.0`. Выбор актуального пака для новой партии не меняет правила уже сохранённой партии.

`motion.js/css` и `tooltips.js/css` — необязательные браузерные модули. Анимация использует идентификаторы компонентов и общие маркеры зон; названий конкретных игр в ней нет. Подсказки подключаются в браузере после DOM и служебных UI-стилей.
